# 0152 실행 도중 끊긴 자막 작업을 `중단됨`으로 멈추고 사람이 다시 시작하게 해요

- 상태: 대기
- 출처: [구조 가볍게 하기 명세의 끊긴 자막 작업](lighter-structure.md#끊긴-자막-작업), [끊긴 작업 ADR](../adr/0020-interrupted-jobs-wait-for-a-restart.md)
- 막는 티켓: [0145](0145-merge-web-and-worker-crates.md)(크레이트 합치기)

## 작업

지금은 worker가 다시 시작하면 효과별 기록과 디스크를 대조해, 실행 도중이던 자막 작업을 이어 해요. [끊긴 작업 ADR](../adr/0020-interrupted-jobs-wait-for-a-restart.md)에 따라, 이제는 받기·보관·적용·교체·재배치 단계를 실행하던 중에 끊긴 작업이 `중단됨`이 되고, 사람이 `다시 시작`을 눌러 끊긴 단계부터 다시 해요.

이 티켓은 상태와 화면, 다시 시작하는 경로를 만들어요. `다시 시작`이 끊긴 단계를 다시 하는 데는 지금의 이어 하기 코드를 그대로 써요. 효과별 기록을 없애고, 기록 없이 단계를 다시 해도 안전하게 만드는 일은 [0153](0153-no-effect-records.md)이 해요. 이렇게 나누면 사용자가 보는 동작은 이 티켓에서 명세대로 바뀌고, 0153은 안쪽만 바꿔요.

- `중단됨`인 작업은 할 일로 올리지 않고, 할 일 화면의 `자막 작업` 맨 위에 실패한 작업과 함께 보여요(사용자 결정, 2026-10-21).
- 작업을 다시 시작하는 API 경로를 더해요. 명세가 더하기로 한 경로예요.

## 완료 기준

- [ ] 받기·보관·적용·교체·재배치 단계를 실행하던 중에 프로세스가 멈춘 작업은, 다시 시작한 뒤 `중단됨`이 돼요. 단계마다 실행 도중의 작업이 남은 DB로 시작하는 테스트가 확인해요.
- [ ] 인증·배치 확인·교체 승인·영상 대기·자막 대기처럼 사람을 기다리던 작업은 다시 시작한 뒤에도 그대로 기다려요.
- [ ] `중단됨`인 작업은 할 일로 올라가지 않고, 할 일 화면의 `자막 작업` 맨 위에 실패한 작업과 함께 보여요.
- [ ] `중단됨`은 `held`와 다른 상태예요. 할 일 개수, 작업 목록과 상세, 라이브러리 배지, 작품 상세의 적용 상태, 영상 대기 판정은 이 상태를 끝나지 않은 실패로 다뤄요. 각 판정을 그 규칙을 가진 크레이트의 테스트가 확인해요.
- [ ] `중단됨`인 작업의 목록 행과 작업 상세에 `다시 시작` 버튼이 있고, 누르면 끊긴 단계부터 다시 해요. 수신 영역에 이미 받아 둔 묶음은 다시 받지 않아요.
- [ ] API 테스트가 다시 시작하는 경로의 요청과 응답 모양, `중단됨`이 아닌 작업을 거절하는 응답을 확인해요.
- [ ] 같은 커밋에서 [작업과 인증 명세](../specs/jobs.md)의 [작업 결과](../specs/jobs.md#작업-결과)와 [체크포인트와 중단 복구](../specs/jobs.md#체크포인트와-중단-복구)에서 다시 시작할 때의 동작을 고쳐요. 할 일 화면과 라이브러리 배지를 적은 명세가 작업 상태를 나열하면 그곳도 고쳐요.
- [ ] 화면 테스트와 `npm run typecheck`가 통과해요.
- [ ] [명세의 동작 보존 조건](lighter-structure.md#동작-보존)을 지켜요. 다시 시작할 때 자동으로 이어 하는 것을 확인하던 테스트는 `중단됨`이 되는 것을 확인하게 고치고, 결과에 적어요.
- [ ] 구현이 [끊긴 작업 ADR](../adr/0020-interrupted-jobs-wait-for-a-restart.md)과 맞아요. 다르게 해야 하면 마치기 전에 사용자 결정을 받아 ADR을 고쳐요.
