# 0025 영상 수정본이 나오면 확인한 뒤 이전 영상을 대체해요

- 상태: 완료 (실제 Transmission으로는 확인하지 않았고, 할 일 화면이 아직 없어 `받기 실패`는 원천 API와 작품 상세까지만 봤어요. 아래 "검증하지 못한 것")
- 출처: [영상 수정본의 대체](../specs/collection.md#영상-수정본의-대체), [영상 수정본 ADR](../adr/0010-replace-video-revisions.md), [할 일](../specs/jobs.md#할-일)(`받기 실패`), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록)(버전 줄)
- 막는 티켓: 없음

## 작업

폴더에 있는 회차 영상보다 높은 수정본(`14v2` 등)이 RSS에 나오면, 같은 규칙으로 받아 CRC32를 확인한 뒤 이전 영상을 지우고 새 영상에 회차 이름을 붙여요. 명세의 순서·실패 처리·재시작 이어하기를 그대로 따르고, 이름이 겹치는 두 파일을 덮어쓰지 않아요.

- 버전 판정: 받은 영상의 버전은 수집 이력의 원래 릴리스 이름과 CRC32로 알고, 버전을 모르는 기존 영상은 파일 내용의 CRC32를 계산해 대조해요(구버전과 같음 → 대체, 최신과 같음 → 건너뜀, 다름 → `버전 미상`). Erai-raws처럼 대괄호가 여러 개면 확장자 앞의 8자리 16진수 대괄호가 CRC 값이에요. CRC32 계산은 파일을 스트림으로 읽어 컨테이너 메모리(128M)를 넘지 않아요.
- 수신: 이름에 CRC 값이 없는 수정본은 자동으로 받지 않고 이력에 `버전 미상`으로 남겨 `다시 받기`로만 받아요(그때는 수신 뒤 CRC32 확인만 건너뛰어요). 수정본 토렌트는 추가 직후의 이름 변경을 건너뛰어요.
- 대체: 수신 완료 → CRC32 확인 → 이전 영상 제거(trss가 추가한 단일 파일 토렌트면 Transmission에서 데이터와 함께 제거, 토렌트에 속하지 않으면 파일만 삭제, 소속은 Transmission의 모든 토렌트 파일 목록과 이력의 해시로 판단) → 새 영상 이름 변경(목적지가 비어 있을 때만). 배치·다파일 토렌트나 trss가 추가하지 않은 토렌트에 속한 이전 영상은 대체하지 않아요.
- 실패는 할 일의 `받기 실패` 원천과 작품 상세 회차 줄에 두 파일의 상태와 까닭으로 남겨요. 할 일 화면은 아직 없으므로 원천 API와 작품 상세 표시까지 해요. 대체가 끝난 회차 줄에는 자막 타이밍을 알리는 버전 줄이 조용히 생겨요.
- 이 일은 worker만 해요(미디어 폴더 쓰기는 worker 하나). 진행 상태는 재시작해도 이어지도록 저장하고, 마이그레이션이 필요하면 번호는 그때 master의 다음 번호예요.
- 지금 worker가 수정본을 받으면 이름 바꾸기가 실패해 두 파일이 남는다는 명세의 추정을 구현 전에 시험으로 재현해 보고 결과를 남겨요.

## 완료 기준

명세 [영상 수정본의 대체](../specs/collection.md#영상-수정본의-대체)의 표 아홉 행이 이 티켓의 완료 기준이에요. 각 행을 가짜 Transmission과 임시 폴더로 된 통합 시험으로 확인하고, 다음도 확인해요.

| 입력·상태 | 기대 결과 |
| --- | --- |
| 이름에 CRC 값이 없는 `14v2`를 사용자가 `다시 받기` | 받은 뒤 CRC32 확인 없이 같은 순서로 대체해요. |
| 1 GiB 영상의 CRC32 계산 | 파일을 통째로 메모리에 올리지 않아요(스트림 읽기). |
| 수정본 대체가 끝난 회차 | 작품 상세 회차 줄에 버전 줄이 조용히 보여요. |
| 대체 실패 | `받기 실패` 원천 API에 두 파일의 상태와 까닭이 있고, 작품 상세 회차 줄에도 보여요. |

## 결과

### 재현

구현 전에 가짜 Transmission이 libtransmission의 `renamePath`처럼 움직이게 하고(목적지 이름에 파일이 있으면 디스크의 파일은 그대로 두고 성공으로 답해요. 2026-10-01에 소스로 확인했어요) `d4129fa`의 worker로 `14`를 받은 뒤 `14v2`를 RSS에 냈어요.
worker는 `14v2`를 추가하고 곧바로 `Show S01E14.mkv`로 이름을 바꿨고, 이름 변경은 성공으로 끝났지만 폴더에는 `Show S01E14.mkv`(이전 영상)와 `[SubsPlease] Show - 14v2 (1080p) [8F2EFECC].mkv`가 함께 남았어요. 새 토렌트의 이름은 `Show S01E14.mkv`가 되어 이전 영상 파일을 가리켰어요.
명세의 추정(이름 바꾸기가 실패해 두 파일이 남음)과 결과는 같지만, 이름 바꾸기는 실패로 드러나지 않아요. 명세의 그 문장을 이 결과로 고쳤어요. 실제 Transmission으로는 재현하지 않았어요.

### 구현한 것

- 판정(`src/revision.rs`, `src/worker/revisions.rs`의 `plan`): 이름의 `14v2`에서 수정본 번호를, 확장자 앞의 8자리 16진수 대괄호에서 CRC 값을 읽고, 두 값을 뺀 나머지(그룹·제목·회차·화질)가 같으면 같은 릴리스로 봐요. 규칙이 고른 수정본(2 이상)의 회차 이름에 파일이 있으면, 그 파일이 들어 있는 토렌트를 Transmission의 모든 파일 목록에서 경로로 찾아 이력의 해시와 원래 이름으로 버전을 알아요. 버전을 모르면(토렌트가 없거나 이력이 모르는 토렌트) 파일의 CRC32를 1 MiB씩 읽어 계산하고 새 이름과 채널 이력의 낮은 수정본 이름의 값에 대조해요(구버전 → 대체, 최신 → 건너뜀, 어느 것도 아님 → `버전 미상`).
- 수신: 대체할 수정본은 추가하되 추가 직후의 이름 변경을 건너뛰어요. 이름에 CRC 값이 없거나 버전을 모르면 추가하지 않고 이력에 새 결과 `version_unknown`(`버전 미상`)으로 남기고, `다시 받기`로 받으면 그 요청을 확인으로 삼아요(이름에 CRC 값이 없으면 수신 뒤 확인을 건너뛰어요). 이미 같은 수정본이 있거나 더 높은 수정본이 있으면 이력에 `duplicate`와 까닭으로 남겨요.
- 대체(`src/worker/revisions.rs`의 `advance`, 주기마다): 수신 완료(단일 파일, 규칙 폴더) → CRC32 확인 → 이전 영상 제거(trss가 추가한 단일 파일 토렌트는 데이터와 함께 제거, 토렌트가 없는 파일은 삭제, 배치·다파일·trss가 추가하지 않은 토렌트는 실패) → 목적지가 비어 있을 때만 Transmission의 이름 변경(새 토렌트가 없어졌으면 `RENAME_NOREPLACE`). 각 단계는 실행 전에 저장해요(마이그레이션 25, `video_revisions`). 대체가 진행 중이거나 끝난 이전 항목은 피드에 남아 있어도 다시 받지 않고, 대체 중인 토렌트는 피드를 떠나도 정리하지 않아요.
- 이름 변경 보호(`src/transmission/mod.rs`, `src/worker/commands/receive_once.rs`): 모든 이름 변경(추가 직후, `다시 받기`, 대체)이 폴더에 목적지 이름이 있으면 바꾸지 않아요. 옛 바이너리도 같은 함수를 써요.
- `받기 실패` 원천: `GET /api/todo/receive-failures`(`src/web/todo_api.rs`)가 대체 실패(두 파일의 상태 `kept`·`removed`·`received_name`·`not_received`와 까닭, 작품·시즌·회차)와 규칙이 고른 `추가 실패` 항목(최근 200개)을 돌려줘요. 대체 실패는 두 파일 중 하나가 없어지면 사라져요.
- 작품 상세(`src/web/library_work_api.rs`, `EpisodeList.tsx`): 회차에 `revision`(버전 줄)과 `failure`를 더했어요. 회차 줄에 `받기 실패` 배지, 펼친 자리에 까닭과 두 파일, 대체가 끝난 회차에 `v1 › v2` 태그와 흐린 `9월 2일 02:05 수정본으로 교체`가 보여요. 이전 영상이 지워져 회차 이름의 파일이 없는 동안에도 그 회차 줄은 남아요.
- 수집 이력 화면: `버전 미상` 이름표, 개수, `다시 받기`.
- 운영 안내: `readme.md`의 Video revisions(삭제 동작, CRC32 비용, 이름 변경 보호).

### 결정

- 마이그레이션은 25번이에요. 이 브랜치에서는 0023·0024의 자리를 빈 항목으로 두었다가, master(0023·0024가 23·24번)를 합치며 빈 항목을 뺐어요.
- 이미 같거나 더 높은 수정본이 있어 건너뛴 항목은 새 결과를 만들지 않고 `중복`과 까닭으로 남겨요.
- 다른 그룹의 같은 회차와 다른 화질의 수정본은 수정본이 아니라고 보고 지금처럼 받아요. 이름 변경 보호 때문에 받은 이름 그대로 남아 두 파일이 함께 있어요.
- 수신 완료 판정은 토렌트의 파일이 하나이고 다운로드 폴더가 규칙 폴더와 같을 때만 해요. 그 밖의 모양은 이전 영상을 남기고 실패로 알려요.
- `다시 받기`로 받은 버전 미상 수정본도 이름에 CRC 값이 있으면 수신 뒤 CRC32를 확인해요. 건너뛰는 것은 이름에 값이 없을 때뿐이에요.

### 검증하지 못한 것

- 실제 Transmission과 실제 미디어 폴더로는 확인하지 않았어요. 이름 변경과 데이터 삭제의 동작은 libtransmission 소스를 읽고 가짜에 옮긴 것이에요.
- 할 일 화면이 없어서 `받기 실패`는 원천 API와 작품 상세까지만 봤어요.
- 브라우저에서 수집 이력의 `버전 미상` 줄, 라이트 모드, 실제 휴대폰·스크린 리더는 보지 않았어요. 이 저장소에는 웹 자동 시험 도구가 없어요.
- 하드디스크에서 큰 파일의 CRC32가 걸리는 시간은 재지 않았어요(운영 안내의 시간은 추정이에요).

### 남은 일

- 명세의 "받은 영상의 버전은 수집 이력의 원래 릴리스 이름과 파일의 CRC32로 알아요"에서, 받은 모든 영상의 CRC32를 이력에 남기지는 않아요. 버전은 원래 이름과 토렌트 해시로 알고, CRC32는 수정본 대체와 버전 모르는 영상에서만 계산해 `video_revisions`에 남겨요. 모든 수신 파일을 다시 읽을지는 사용자 결정이에요.
- 수집 이력의 `실패·중복` 필터와 수집 현황의 `실패·중복 N개`에 `버전 미상`은 들어 있지 않아요. 넣을지, 할 일 화면에 맡길지는 사용자 결정이에요.
- 지난 회차 검색의 수정본·`버전 미상` 표시(명세의 지난 회차 검색)는 [0026](0026-past-episode-search.md)의 일이에요.
