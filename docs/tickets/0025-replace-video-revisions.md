# 0025 영상 수정본이 나오면 확인한 뒤 이전 영상을 대체해요

- 상태: 대기
- 출처: [영상 수정본의 대체](../specs/collection.md#영상-수정본의-대체), [영상 수정본 ADR](../adr/0010-replace-video-revisions.md), [할 일](../specs/jobs.md#할-일)(`받기 실패`), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록)(버전 줄)
- 막는 티켓: 없음

## 작업

폴더에 있는 회차 영상보다 높은 수정본(`14v2` 등)이 RSS에 나오면, 같은 규칙으로 받아 CRC32를 확인한 뒤 이전 영상을 지우고 새 영상에 회차 이름을 붙여요. 명세의 순서·실패 처리·재시작 이어하기를 그대로 따르고, 이름이 겹치는 두 파일을 덮어쓰지 않아요.

- 버전 판정: 받은 영상의 버전은 수집 이력의 원래 릴리스 이름과 CRC32로 알고, 버전을 모르는 기존 영상은 파일 내용의 CRC32를 계산해 대조해요(구버전과 같음 → 대체, 최신과 같음 → 건너뜀, 다름 → `버전 미상`). Erai-raws처럼 대괄호가 여러 개면 확장자 앞의 8자리 16진수 대괄호가 CRC 값이에요. CRC32 계산은 파일을 스트림으로 읽어 컨테이너 메모리(128M)를 넘지 않아요.
- 수신: 이름에 CRC 값이 없는 수정본은 자동으로 받지 않고 이력에 `버전 미상`으로 남겨 `다시 받기`로만 받아요(그때는 수신 뒤 CRC32 확인만 건너뛰어요). 수정본 토렌트는 추가 직후의 이름 변경을 건너뛰어요.
- 대체: 수신 완료 → CRC32 확인 → 이전 영상 제거(trss가 추가한 단일 파일 토렌트면 Transmission에서 데이터와 함께 제거, 토렌트에 속하지 않으면 파일만 삭제, 소속은 Transmission의 모든 토렌트 파일 목록과 이력의 해시로 판단) → 새 영상 이름 변경(목적지가 비어 있을 때만). 배치·다파일 토렌트나 trss가 추가하지 않은 토렌트에 속한 이전 영상은 대체하지 않아요.
- 실패는 할 일의 `받기 실패` 원천과 작품 상세 회차 줄에 두 파일의 상태와 까닭으로 남겨요. 할 일 화면은 아직 없으므로 원천 API와 작품 상세 표시까지 해요. 대체가 끝난 회차 줄에는 자막 타이밍을 알리는 버전 줄이 조용히 생겨요.
- 이 일은 worker만 해요(미디어 폴더 쓰기는 worker 하나). 진행 상태는 재시작해도 이어지도록 저장하고, 마이그레이션이 필요하면 번호는 그때 master의 다음 번호예요.
- 지금 worker가 수정본을 받으면 이름 바꾸기가 실패해 두 파일이 남는다는 명세의 추정을 구현 전에 시험으로 재현해 보고 결과를 남겨요.

## 완료 기준

명세 [영상 수정본의 대체](../specs/collection.md#영상-수정본의-대체)의 표 아홉 행이 이 티켓의 완료 기준이에요. 각 행을 가짜 Transmission과 임시 폴더로 된 통합 시험으로 확인하고, 다음도 확인해요.

| 입력·상태 | 기대 결과 |
| --- | --- |
| 이름에 CRC 값이 없는 `14v2`를 사용자가 `다시 받기` | 받은 뒤 CRC32 확인 없이 같은 순서로 대체해요. |
| 1 GiB 영상의 CRC32 계산 | 파일을 통째로 메모리에 올리지 않아요(스트림 읽기). |
| 수정본 대체가 끝난 회차 | 작품 상세 회차 줄에 버전 줄이 조용히 보여요. |
| 대체 실패 | `받기 실패` 원천 API에 두 파일의 상태와 까닭이 있고, 작품 상세 회차 줄에도 보여요. |
