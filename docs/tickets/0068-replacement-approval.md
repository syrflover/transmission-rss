# 0068 자막이 있는 회차를 승인받아 교체해요

- 상태: 대기
- 출처: [교체 비교와 승인](../specs/subtitles.md#교체-비교와-승인), [승인 증거와 반영 직전 검사](../specs/subtitles.md#승인-증거와-반영-직전-검사), [체크포인트와 중단 복구](../specs/jobs.md#체크포인트와-중단-복구), [할 일](../specs/jobs.md#할-일)의 `교체 승인`
- 막는 티켓: [0063](0063-store-and-first-apply.md)

## 작업

기존 자막을 바꾸는 안전한 반영을 만들어요. 대사·타이밍·스타일·폰트의 내용 비교는 [0069](0069-replacement-diff.md), 여러 회차의 목록은 [0070](0070-multi-episode-replacement.md)이에요.

- 새 자막을 적용할 회차에 자막이 있으면(trss가 적용한 것이든 아니든) 불변 계획을 만들고 작업을 `교체 승인`에서 멈춰요. `교체 승인` 할 일이 생겨요.
- 작업 상세의 주 영역은 머리의 대상과 결정 카드예요. 결정 카드는 `현재`·`새 자막` 버전 줄(받은 시각·크기·줄 수)과 `현재 유지`·`새 자막으로 교체`예요.
  PC에서는 스크롤하면 화면 위쪽에 붙고, 휴대폰에서는 버튼 두 개만 하단 메뉴 위에 고정해요.
  제작자·형식·게시물이 다르거나 기존 파일의 출처를 모르면 두 파일의 정보를 나란히 보여줘요. 예상과 다른 변경(관리하지 않는 파일 덮어쓰기, 이전 적용본 제거)일 때만 경로를 경고로, 실제 조건이 있을 때만 판단 한계를 보여줘요.
- 승인 기록은 계획 ID·판, 대상과 대응 근거, 영상 식별 정보(경로, 일반 파일 여부, inode, 크기, 변경 시각), 기존 파일과 새 자산의 경로·크기·SHA-256, 경로별 동작에 묶어요.
  반영 직전에 다시 검사해 달라졌으면 결정 카드에 `새 수정본 발견`·`다시 비교 필요`와 까닭을 보이고 반영하지 않아요.
- 반영할 때는 기존 바이트의 보호 복사본을 `.trss/` 안에 만들어 검증한 뒤 교체하거나 제거해요.
  trss가 관리하지 않는 기존 자막은 지우거나 덮어쓰기 전에 `제작자 알 수 없음` 보관본으로 들여요(사용자 결정, 2026-10-04). 제작자·형식이 바뀌어 지울 이전 적용본의 경로도 계획에 넣고, 적용본을 지워도 보관본은 남아요.
- 파일 효과마다 의도 → 증거 → 완료를 기록하고, 보호 자료는 확인된 완료 뒤에 정리해요. 같은 경로를 바꾸는 반영은 직렬화해요.
- 앞 티켓들이 "자막이 있는 회차"라서 보관만 하고 남긴 회차(0063 첫 적용, 0064 자동 수신의 다른 회차, 0066 배치 확인, 0067 영상 대기)를 이 흐름으로 이어요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 같은 제작자·같은 게시물의 수정본(시험과 만든 사례) | 결정 카드와 버전 줄만 있고 나란한 비교·경로·판단 한계는 없어요. `새 자막으로 교체`로 바뀌고, 이전 보관본은 지난 자막으로 남아요. |
| `현재 유지` | 영상 옆 파일이 그대로이고 작업이 끝나요. 새 보관본은 남아요. |
| trss가 관리하지 않는 `X.ass`가 있는 회차 | 덮어쓸 경로가 경고로 보이고, 승인하면 그 바이트가 `제작자 알 수 없음` 보관본으로 남아요. |
| SRT 적용본이 있는 회차에 다른 제작자의 ASS로 교체 | SRT 제거가 계획과 경고에 있어요. 승인하면 SRT 적용본만 지워지고 그 보관본은 남아요. |
| 승인 뒤 반영 전에 영상이 대체됨, 같은 크기·다른 바이트로 기존 자막이 바뀜, 새 보관 자산이 바뀜, 대응이 바뀜, 추가할 경로에 파일이 생김(시험) | 각각 반영하지 않고 다시 비교를 요구하며, 기존 파일은 그대로예요. |
| 보호 복사, 교체, 제거, 완료 기록의 각 사이에서 worker를 죽였다 살림(시험) | 중복 효과, 승인 없는 변경, 거짓 완료가 없어요. 결과를 확인할 수 없으면 보호 자료를 남기고 보류해요. |
| 보호 복사할 공간이 없음(시험) | 파괴적인 효과 전에 멈추고 기존 파일이 그대로예요. |
| 두 작업이 같은 경로를 바꾸려 함(시험) | 한 번에 하나만 반영되고, 뒤 작업은 새 상태로 다시 비교해요. |
| 휴대폰 폭 | 버튼 두 개가 하단 메뉴 바로 위에 고정돼요. |
