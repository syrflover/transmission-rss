# 0044 Naver 블로그 첨부를 받아요

- 상태: 대기
- 출처: [출처별 다운로드](../specs/subtitles.md#출처별-다운로드)(Naver 블로그 첨부), [Naver 블로그 첨부 조사](../brainstorm/web-gui-subtitles.md#naver-블로그-첨부)
- 막는 티켓: [0038](0038-receive-result-tistory.md), [0039](0039-browser-container-lifecycle.md)(0033이 브라우저 경로가 필요하다고 정하면)

## 작업

Naver 블로그 게시물(내부 프레임 포함)에서 유효한 첨부 경로를 얻어 실제 파일을 받아요.
2026-09-26에는 HTTP로 받았지만 관리형 Chromium의 다운로드는 확인하지 못했으므로, 어느 경로를 쓸지는 0033의 관찰로 정하고, 구현한 경로를 실제로 검증해요.
이전 HTTP 표본의 성공으로 구현한 경로가 검증됐다고 표시하지 않아요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 첨부가 내부 프레임에 있는 게시물(가짜 출처) | 첨부 경로를 얻어 파일을 받아요. |
| 첨부 대신 안부게시판 CAPTCHA·오류 페이지 | 첨부 다운로드와 섞지 않고 분류된 실패예요. |
| 실제 게시물 하나 | 구현한 경로로 실제 서버에서 받은 파일의 크기·형식(예: UTF-16LE SAMI)을 확인한 결과가 있어요. |
