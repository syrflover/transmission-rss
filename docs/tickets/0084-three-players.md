# 0084 세 재생기에서 적용본, 폰트, 다시 읽기를 확인해요

- 상태: 완료 (2026-10-07, Infuse의 관찰과 사용자 결정. 아래 "결과")
- 출처: [실제 재생 환경](../specs/subtitles.md#실제-재생-환경), [폰트](../specs/subtitles.md#폰트)
- 막는 티켓: [0081](0081-deploy-new-release.md), [0061](0061-infuse-placement-check.md)

## 작업

주 재생기는 Infuse, IINA, 팟플레이어이고, 미디어 디스크를 NFS로 읽어요.
[0061](0061-infuse-placement-check.md)은 Infuse 하나로 적용본과 `.trss/`가 어떻게 보이는지만 봐요. 세 재생기의 폰트 렌더링, 다시 읽기, 여러 형식의 선택은 목표 4에서 이 목표로 넘겼어요.
실제 서버가 적용한 자막으로 세 재생기를 확인해요. 사용자가 재생기에서 보고, 저는 표본 준비와 기록을 맡아요.

- 폰트는 기본 글꼴과 구별되는 서체를 쓰는 자막과 폰트 표본으로 봐요. 그 폰트를 쓸 수 있을 때와 없을 때를 견주거나, 재생기가 고른 글꼴 정보를 봐서 대체 글꼴과 가려요.
- 파일을 바꾼 뒤에는 재생기의 자막 다시 읽기나 영상 다시 열기를 거쳐요. 이미 재생 중인 앱의 캐시가 바로 바뀐다고 가정하지 않아요.

## 완료 기준

재생기마다 다음을 관찰해 결과 절의 표에 적어요. 재생기, 버전, 기기, 공유 경로, 자막 검색 설정도 함께 적어요.

| 관찰 | 기록할 것 |
| --- | --- |
| 영상과 같은 이름의 적용본 | 트랙으로 보이는지 |
| `.trss/` 안의 보관본 | 자막 목록에서 빠지는지 |
| 형식이 둘 이상인 회차 | 어떤 형식이 고르는지, 사용자가 바꿀 수 있는지 |
| 같은 제작자 폴더의 폰트 | 그 폰트로 그려지는지, 대체 글꼴인지 |
| 적용본을 바꾼 뒤 | 다시 읽기나 다시 열기 뒤에 새 내용이 보이는지 |

- 관찰하지 못한 재생기나 조합은 까닭과 함께 남은 일에 있어요.
- 어느 재생기에서 `.trss/`의 보관본이 목록에 나오면 배치를 다시 정할 사용자 결정을 받아요.

## 결과

### Infuse (2026-10-07)

[0061](0061-infuse-placement-check.md)에서 사용자가 실제 서버의 `FX Senshi Kurumi-chan`을 Infuse로 열어 봤어요. 영상과 같은 이름의 적용본(SMI)은 자막으로 보였고, `.trss/` 안의 보관본은 자막 목록에 나오지 않았어요.

### 사용자 결정 (2026-10-07)

사용자는 Infuse만 확인했어요. IINA와 팟플레이어는 trss 전부터 같은 배치(영상과 같은 이름의 자막을 영상 옆에 둠)로 잘 쓰던 재생기라, Infuse에서 된 것으로 확인한 것으로 두고 이 티켓을 닫기로 했어요.

### 확인하지 않은 것

- IINA와 팟플레이어의 관찰이에요. 재생기 버전, 기기, 공유 경로, 자막 검색 설정도 어느 재생기에서도 기록하지 않았어요.
- 형식이 둘 이상인 회차의 선택, 적용본을 바꾼 뒤의 다시 읽기는 어느 재생기에서도 보지 않았어요.
- 폰트는 보지 않았어요. 명세대로 폰트는 `.trss/subtitles/<제작자>/`에만 보관되고 영상 옆에 두지 않으므로, 재생기가 그 폰트를 쓰는지 대체 글꼴로 그리는지는 알 수 없어요. 실제 서버의 보관본에는 아직 폰트가 없어요(2026-10-07).
