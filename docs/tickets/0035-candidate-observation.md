# 0035 연결한 시즌의 자막 후보를 2시간마다 관찰해 쌓아요

- 상태: 대기
- 출처: [자막 후보 조회](../specs/subtitles.md#자막-후보-조회), [지난 회차 ADR](../adr/0012-past-subtitles-find-and-upload.md), [자막 출처 연결](../glossary.md)
- 막는 티켓: [0034](0034-season-anissia-link.md)

## 작업

Anissia 자막 정보는 작품마다 제작자 한 명당 마지막 회차 표시·게시물 주소·갱신일 한 줄뿐이에요(2026-10-02 확인).
trss는 조회할 때마다 이 줄을 관찰로 남기고, 바뀐 줄은 새 후보로 더해 회차별 후보 기록을 쌓아요.

- worker가 화면과 상관없이 2시간마다 연결한 시즌의 Anissia 작품 자막 정보를 조회해요. RSS 수집 주기와 별개이며, 기존 Anissia 큐처럼 자기 잠금과 요청 간격을 써요.
- 반복 조회의 나이 기준은 후보의 `updDt`(시간대 없는 값은 `Asia/Seoul`)이며 30일 이내(경계 포함)만 조회해요. 날짜가 없거나 읽지 못하면 그 회차 영상을 앱이 처음 발견한 시각을 쓰고, 날짜 해석 실패는 구분해 남겨요.
- 사용자의 새로고침과 처음 조회에는 기간 제한이 없어요.
- 후보는 제작자·게시물 주소·회차 표시(원래 문자열)·`updDt`·처음 본 시각으로 남기고, 제작자와 게시 경로의 출처 맥락은 앱 ID를 가진 자막 출처 연결로 묶어요. 제작자 표시명이나 웹사이트 주소를 전역 ID로 쓰지 않아요.
- 기간이 지나도 후보 기록은 지우지 않아요.
- 이 티켓은 후보를 모으고 조회 API로 내놓는 데까지예요. 화면은 [0037](0037-candidate-section.md)이에요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 연결한 시즌 둘, 연결 안 한 시즌 하나(가짜 Anissia) | 2시간 주기에 연결한 둘만 조회되고, 같은 주기 안에 다시 조회하지 않아요. |
| 같은 제작자의 줄이 `3화 게시물 A`에서 `4화 게시물 B`로 바뀜 | 두 후보가 모두 남아요. |
| 같은 줄의 `updDt`만 바뀜(한 게시물을 고침) | 같은 게시물의 갱신으로 남고 이전 관찰도 남아요. |
| `updDt`가 정확히 30일 전 / 30일 1초 전 (제어된 시각, 서버 시간대 `UTC`와 `Asia/Seoul` 각각) | 앞의 것은 조회 대상이고 뒤의 것은 아니며, 두 시간대에서 결과가 같아요. |
| `updDt` 없음·잘못된 날짜 | 영상을 처음 발견한 시각을 쓰고, 잘못된 날짜는 해석 실패로 구분돼요. |
| 회차 표시 `0`·`13.5` | 원래 문자열로 남고 숫자 회차로 바꾸지 않아요. |
| 사용자 새로고침(웹 명령) | 기간과 상관없이 바로 조회돼요. |
| `429`·실패 | 다음 시도를 미루고 기존 후보가 남아요. |
