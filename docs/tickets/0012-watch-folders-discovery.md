# 0012 감시 폴더를 등록하고 작품·시즌·회차를 발견해요

- 상태: 진행 중
- 출처: [작품 발견과 감시 폴더](../specs/library.md#작품-발견과-감시-폴더), [설정 화면](../specs/settings.md#설정-화면), [보관과 복원의 폴더 이동](../specs/collection.md#보관과-복원의-폴더-이동), [라이브러리 화면](../specs/library.md#라이브러리-화면)의 추가 시각
- 막는 티켓: 없음(작품 폴더 따라가기는 [0011](0011-archive-folder-move.md)의 이동 명령에 붙여요)

## 작업

설정에서 감시 폴더를 등록하면 앱이 그 안의 trname 구조에서 작품·시즌·회차와 영상·자막 파일을 찾아 DB에 기억하고, 라이브러리·작품 상세([0013](0013-library-screen.md), [0014](0014-work-detail-video.md))가 그 기록을 읽어요.
이 티켓은 발견과 감시 폴더 관리까지이며, 파일을 만들거나 옮기거나 지우지 않아요.

- **구조**: trname이 만드는 `감시 폴더/작품/Season 01/작품 S01E01.mkv`예요.
  감시 폴더 바로 아래 폴더 하나가 작품이고, 그 안의 `Season NN` 폴더가 시즌(번호는 0 이상 정수)이며, 시즌 폴더 안의 `SxxEyy`(`E` 뒤 숫자는 원래 문자열 보존) 파일이 회차예요.
  같은 이름 줄기(stem)의 자막 파일(`작품 S01E01.ass`, `작품 S01E01.ko.smi`처럼 언어 조각이 붙은 것 포함)은 그 회차의 자막이에요.
  파일 이름의 `SxxEyy`가 시즌 폴더 번호와 다르거나, 구조에 맞지 않는 파일(여러 파일 토렌트의 하위 폴더, 받는 중인 `.part` 등)은 회차에 붙이지 않고 작품의 `회차를 확인하지 못한 파일`로 세요.
  `.trss/`와 숨김 항목은 발견 대상이 아니에요.
- **작품의 정체**: 작품은 앱이 발급한 ID를 갖고, 작품 폴더의 경로로 다음 확인과 이어져요.
  [0011](0011-archive-folder-move.md)의 보관·복원이 작품 폴더를 옮기면 그 명령이 끝날 때 작품의 경로를 새 위치로 바꿔 같은 ID가 이어지게 해요. 목적지에 이미 같은 이름의 작품이 있어 합쳐지면 목적지 작품의 ID가 남고, 옮겨 온 작품의 기록은 그리로 합쳐요.
  손으로 옮긴 폴더는 이름이 같다는 이유로 이어 붙이지 않아요. 옛 경로의 작품은 `폴더 없음`으로 남고 새 경로는 새 작품이에요(자막 기록이 생기는 결과 목표 3·4 전에는 잃는 기록이 없어요).
- **추가 시각**: 영상·자막 파일의 추가 시각은 앱이 그 파일을 처음 본 확인의 시각이에요.
  감시 폴더를 등록할 때의 첫 확인에 이미 있던 파일은 언제 들어왔는지 모르므로 `미상`이에요. 파일시스템의 수정·생성 시각으로 채우지 않아요([라이브러리 화면](../specs/library.md#라이브러리-화면)의 정렬 조건).
  작품 추가 시각도 같은 규칙으로, 첫 확인 뒤 새로 나타난 작품 폴더만 시각을 가져요.
- **확인 시점**: worker가 주기마다 모든 감시 폴더를 다시 확인하고, 설정의 `다시 확인`은 웹 명령으로 worker에 맡겨요.
  감시 폴더 추가는 웹이 읽기 전용으로 바로 한 번 확인해 발견한 작품 수를 알려요. 두 곳은 같은 발견 모듈을 써요.
  폴더 하나를 읽지 못해도 다른 감시 폴더와 수집 주기는 계속되고, 그 폴더의 줄에 까닭이 보여요. 읽지 못한 확인은 이전 기록을 지우지 않아요.
- **설정의 `감시 폴더` 항목**: 목록 줄 값은 `폴더 2개`처럼 읽을 수 있는 현재 값이에요.
  폴더마다 경로, 작품 수, 연결한 작품 수(Anissia 연결 전이라 지금은 0), 새로 발견한 작품 수(첫 확인 뒤 최근 7일 안에 나타난 작품), 마지막 확인 시각, `다시 확인`·`등록 해제`를 보여줘요.
- 수집 폴더와 보관 폴더를 감시 폴더로 자동 등록할지는 사용자 결정을 기다려요(아래). 결정 전에는 사용자가 두 폴더를 직접 등록할 수 있어요.

### 사용자 결정 대기

- 수집·보관 폴더의 자동 감시 여부. 명세는 보관한 작품이 라이브러리에서 빠지지 않으려면 두 폴더가 모두 감시 폴더여야 한다고 적고 있어요([보관과 복원의 폴더 이동](../specs/collection.md#보관과-복원의-폴더-이동)). 추천은 두 폴더를 항상 감시하고 등록 해제를 막는 것이에요.

## 결과

### 구현한 것

- 발견(`src/discovery.rs`): 웹과 worker가 같은 `discovery::scan`으로 감시 폴더를 읽어요. 읽기만 하고 파일을 만들거나 옮기거나 지우지 않으며 DB도 건드리지 않아요.
  - 작품은 감시 폴더 바로 아래 폴더, 시즌은 `Season NN`(0 이상 정수), 회차는 시즌 폴더 안의 이름 끝 `SxxEyy`(`yy`는 `01`·`17.5`처럼 적힌 그대로), 자막은 같은 회차의 자막 확장자 파일(언어 조각 `.ko`·`.ko.forced`까지 허용)이에요. 영상 확장자는 mkv·mp4·avi·m4v·webm·ts·mov·wmv·flv·m2ts, 자막은 ass·ssa·smi·srt·vtt·sup이에요.
  - 이름의 시즌이 폴더와 다름, 시즌 폴더 밖의 영상·자막, 시즌 폴더 안 하위 폴더의 것, `SxxEyy`가 없는 이름, 어디든 `.part`는 회차에 붙이지 않고 작품의 `회차를 확인하지 못한 파일`(이유 코드 `season_mismatch`·`outside_season`·`in_subfolder`·`no_episode`·`partial`)로 기록해요. 그림·`.nfo` 같은 미디어 아닌 파일은 세지 않아요.
  - `.`으로 시작하는 항목(`.trss/` 포함)과 NAS·파일시스템이 만드는 `@eaDir`·`#recycle`·`$RECYCLE.BIN`·`lost+found`·`System Volume Information`은 건너뛰어요. 링크는 감시 폴더 안을 가리킬 때만 따라가고(상위로 되돌아가는 링크는 건너뛰어요) 밖으로 나가는 링크는 건너뛰어요.
- 저장(설정 DB 마이그레이션 8, `src/store/library/`): `watch_folders`(앱이 발급한 ID, 경로, 마지막 확인 시각, 마지막 오류, 기준선 여부), `works`(앱이 발급한 ID, 감시 폴더, 작품 폴더 이름, 처음 본 시각, 폴더 없음), `seasons`, `episodes`(시즌+회차 문자열), `media_files`(작품 폴더 기준 상대 경로, 종류, 추가 시각), `unrecognized_files`. 추가 시각이 미상이면 NULL이에요.
  - 기준선: 폴더를 오류 없이 처음 끝까지 읽은 확인이 기준선이에요. 그 확인에서 처음 본 파일·작품은 시각이 미상이고, 이후 확인에서 처음 나타난 것만 그 확인의 시각(worker의 시계)을 가져요. 한 번 정해진 시각은 바뀌지 않고 파일 수정·생성 시각은 읽지 않아요. 작품 폴더 하나를 읽지 못한 확인은 기준선이 아니에요(그 작품은 기록하지 않고 다음 확인을 기다려요. 기준선 전에 나타난 파일이 시각을 받는 일이 없도록 해요).
  - 사라진 파일은 기록에서 지우고 파일이 없어진 회차도 함께 사라져요. 작품 폴더가 사라지면 작품은 `missing`으로 표시되고 ID와 기록은 그대로 남아요(다시 나타나면 같은 작품). 읽지 못한 확인은 폴더에 오류 문장만 기록하고 이전 기록을 지우지 않아요. 작품 폴더 하나만 못 읽으면 그 작품의 기록은 그대로 두고 폴더 줄에 오류 문장이 나와요.
- 웹 API(`src/web/watch_folders_api.rs`): `GET`/`POST /api/library/watch-folders`, `DELETE /api/library/watch-folders/{id}`. 목록은 폴더마다 `works`·`missing_works`·`linked_works`(지금은 0)·`new_works`(기준선 뒤 7일 안에 나타난 작품)·`checked_at`·`error`예요. 추가는 이미 등록한 폴더(링크로 같은 곳 포함), 등록한 폴더의 안쪽, 등록한 폴더를 품은 폴더, 없는·폴더가 아닌·읽을 수 없는·상대 경로를 해요체 문장과 함께 `400`으로 거절하고, 받으면 웹이 읽기 전용으로 한 번 읽어 `works_found`를 답해요(폴더 등록과 첫 기록은 한 트랜잭션). 등록 해제는 폴더와 그 작품 기록만 지우고 디스크를 건드리지 않아요.
- worker: 매 주기의 RSS 작업 뒤 같은 잠금 안에서 모든 감시 폴더를 다시 읽고(`src/worker/watch.rs`) 읽기와 기록에 걸린 시간을 로그에 남겨요. 한 폴더가 읽히지 않아도 다른 폴더와 RSS 작업은 그대로예요. 새 웹 명령 `watch_rescan`(`{folder_id}`, 폴더마다 열린 명령 하나, 같은 명령 ID는 한 번만 실행)이 `다시 확인`을 worker에 맡겨요. 읽었으면 `done`, 읽지 못하면 까닭과 함께 `failed`로 끝나요.
- 보관 이동 따라가기(`rule_archive`): 작품 폴더가 옮겨졌거나 이미 옮겨져 있으면 옛 감시 폴더의 그 이름 작품이 목적지 감시 폴더로 넘어가 ID가 이어지고, 목적지에 같은 이름의 작품이 이미 있으면 목적지 작품의 ID를 남기고 옮겨 온 작품의 기록을 그리로 합쳐요. 수집·보관 폴더 중 하나가 감시 폴더가 아니면 따라가지 않아요. 이름으로 손으로 옮긴 폴더를 잇지 않아요.
- 설정 화면: `라이브러리` 묶음의 `감시 폴더` 항목(목록 줄 `폴더 N개`, 없으면 `등록한 폴더 없음`). 패널은 폴더마다 경로·작품·연결한 작품·새로 발견한 작품(폴더 없음이 있으면 그 수도)·마지막 확인 시각·오류 문장, `다시 확인`(웹 명령을 보내고 끝날 때까지 따라가요. 응답을 잃으면 같은 ID로 묻고, 서버가 저장하지 않았을 때만 같은 ID로 다시 보내요), `등록 해제`(디스크 파일은 그대로 두고 이 폴더의 작품만 라이브러리에서 뺀다는 제자리 확인)를 보여주고, 추가 칸에 거절 까닭이나 `작품 N개를 찾았어요`를 제자리에 보여줘요. 수집·보관 폴더는 자동으로 등록하지 않았어요.

### 검증한 것

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`가 통과했어요(510개 통과, 2개는 기존 무시 항목). 웹은 `npm run typecheck`와 `npm run build`가 통과했어요(웹에 lint 스크립트는 없어요).
- `src/discovery.rs`의 단위 시험(회차 이름·시즌 폴더·언어 조각·맞지 않는 파일과 이유·숨김/제외 폴더·링크·읽지 못하는 작품 폴더), `src/store/library/tests.rs`(기준선과 시각, 사라진 파일·작품, 읽지 못한 확인, 작품 폴더 하나만 못 읽음, 중복 경로·등록 해제 연쇄 삭제, 요약 수와 7일 창, 이동 따라가기·합치기, 맞지 않는 파일 기록 교체).
- `tests/library_watch.rs`(실제 웹 API·worker·임시 폴더·가짜 Transmission)가 완료 기준 표의 행마다 다음을 확인해요.
  - Lycoris Recoil 폴더 등록: 작품 1개, 시즌 2개, S1 1·2화 영상과 1화 자막, S2 1화 영상, 응답의 `works_found` 1, 모든 추가 시각이 미상이고 폴더 안에 아무것도 만들지 않아요.
  - 거절: 이미 등록한 폴더(끝의 `/`·링크 포함), 안쪽, 품은 폴더, 없는 경로, 폴더가 아닌 것, 상대 경로, 빈 입력, 읽을 권한이 없는 폴더. 각각 문장이 나오고 등록되지 않아요.
  - 맞지 않는 파일(이름의 시즌 다름·시즌 폴더 밖·하위 폴더·`.part`)이 이유와 함께 작품에 세어지고, `.trss/`와 숨김 폴더의 파일은 세어지지 않아요.
  - 첫 확인 뒤 새 회차 파일과 새 작품만 worker 주기의 시각을 가져요. 기존 파일은 미상으로 남고, 파일 수정 시각을 2001년으로 바꿔도 기록이 바뀌지 않으며, 한 번 받은 시각은 다음 확인에서도 바뀌지 않아요.
  - 회차 파일을 지우면 그 회차가 사라지고, 작품 폴더를 지우면 작품이 `missing`이 되며 ID와 기록이 남고, 폴더가 돌아오면 같은 작품이 돼요.
  - 권한 오류로 읽히지 않는 감시 폴더: 폴더 줄에 까닭, 이전 작품 기록이 그대로, 다른 감시 폴더는 읽히고, 같은 주기의 RSS 읽기는 그대로예요. 권한을 돌려주면 오류가 사라져요.
  - `등록 해제`: 폴더와 작품 기록이 지워지고 디스크의 파일 목록은 그대로예요. 같은 폴더를 다시 등록하면 처음부터 읽어요.
  - `다시 확인`: 명령이 접수되고(아직 읽지 않음), worker가 읽은 뒤 마지막 확인 시각과 작품 수가 바뀌고, 같은 명령 ID를 다시 보내도 한 번만 돌고, 같은 폴더의 열린 명령이 있으면 거절하고, 없는 폴더·잘못된 내용도 거절해요. 읽지 못하는 폴더의 `다시 확인`은 까닭과 함께 `failed`로 끝나고 기록은 그대로예요.
  - 규칙 보관(수집·보관 폴더 모두 감시 중): 작품 ID가 같고 보관 폴더 아래로 옮겨지며 다음 주기의 확인 뒤에도 같은 작품이에요. 보관 폴더에 같은 이름 작품이 있으면 그 ID 하나로 시즌·회차가 합쳐지고 작품 행이 하나만 남아요. 같은 폴더를 손으로 옮기면 옛 작품은 `missing`, 새 경로는 새 작품이에요.
- 약 520개 작품·1만 개 파일(작품마다 영상 12·자막 6·`.part` 1·그림 1, 합계 10 400개) 시험(`a_library_of_520_works_and_10_000_files_is_read_and_recorded`, 디버그 빌드, 이 개발 머신의 tmpfs 임시 폴더): 읽기만 약 56–61 ms, 웹의 첫 등록(검사·읽기·기록)이 약 323–331 ms, 새 파일 하나가 생긴 worker 주기 한 번(RSS 없음, 읽기와 기록 포함)이 약 158–171 ms였어요(네 번 측정). 판정에 쓰지 않고 작품 수·회차 수·새 파일의 시각만 단언해요.
- 브라우저(로컬 `trss-web`·`trss-worker`, 1280px과 390px, 스크래치 DB, 2026-10-01): 설정의 `감시 폴더` 항목과 빈 목록 문장, 없는 경로를 추가하면 까닭이 입력칸 아래에 나오고 입력이 남는 것, 있는 폴더를 추가하면 `작품 1개를 찾았어요`와 목록 줄 `폴더 1개`, 폴더 줄의 경로·작품·연결한 작품·새로 발견한 작품·마지막 확인, 디스크에 작품을 더한 뒤 `다시 확인`이 작품 2개·새로 발견 1개와 `다시 확인했어요.`로 바뀌는 것, 폴더 권한을 없앤 뒤 `다시 확인`이 오류 문장 하나를 보여주는 것(같은 문장이 두 번 나오지 않아요), `등록 해제`가 디스크 파일은 그대로라는 제자리 확인 문장과 `등록 해제`·`취소`를 보여주는 것, 390px에서 가로 넘침이 없는 것(`scrollWidth == innerWidth`).

### 검증하지 못한 것

- 제자리 확인 뒤 `등록 해제`를 눌러 목록에서 빠지는 것은 브라우저에서 누르지 않았어요. API 시험(폴더와 작품 기록 삭제, 파일 그대로)과 패널 코드로만 봤어요. 라이브러리 화면이 아직 없어(0013) `라이브러리에서 빠진다`는 화면에서는 볼 수 없고 기록이 지워지는 것까지만 확인했어요.
- 520개·1만 개 측정은 tmpfs(메모리)에서 했어요. NAS(SMB·NFS)나 회전 디스크에서의 시간은 재지 않았고, 그쪽은 디렉터리 읽기가 훨씬 느릴 수 있어요. 배포 뒤 worker 로그의 `Watch folder … scan took N ms`로 확인해요.
- 읽기 전용 미디어 마운트(`/downloads:ro`)의 컨테이너 안에서 웹의 첫 읽기를 해 보지 않았어요. 웹은 읽기만 하지만 마운트 권한은 로컬 폴더로만 봤어요.
- 웹 화면의 자동 시험은 없어요(이 저장소에 웹 시험 도구가 없어요). 라이트 모드와 키보드 조작은 보지 않았어요.
- 실제 운영 DB(0.4.1)에 대한 마이그레이션 8은 돌려 보지 않았어요(테이블만 더하고 기존 데이터를 건드리지 않아요. 새 DB와 마이그레이션 시험 경로로만 확인했어요).
- 링크가 많은 실제 폴더 구조(감시 폴더 안의 링크 작품 폴더)는 임시 폴더의 링크로만 시험했어요.

### 남은 일

- 사용자 결정 대기: 수집·보관 폴더를 감시 폴더로 자동 등록하고 등록 해제를 막을지. 지금은 사용자가 두 폴더를 직접 등록해야 하고, 둘 중 하나가 감시 폴더가 아니면 보관 이동이 작품을 따라가지 않아요.
- 명세의 `등록 해제` 확인은 `저장한 자막 기록은 남긴다`도 말하지만, 자막 기록이 아직 없어서 확인 문장에 넣지 않았어요. 자막을 보관하는 티켓(결과 목표 3·4)이 생기면 등록 해제가 그 기록을 남기도록 하고 문장도 더해야 해요(지금의 등록 해제는 작품 행과 딸린 기록을 함께 지워요).
- 폴더 없음(`missing`) 작품과 회차의 보유 표시는 라이브러리·작품 상세([0013](0013-library-screen.md), [0014](0014-work-detail-video.md))가 정해요. 저장은 폴더 없음 작품의 파일 기록을 그대로 두고 `missing`으로 표시하기만 하므로, 읽는 쪽이 `missing`을 보고 보유를 세지 않아야 해요.
