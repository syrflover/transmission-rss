# 0012 감시 폴더를 등록하고 작품·시즌·회차를 발견해요

- 상태: 대기
- 출처: [작품 발견과 감시 폴더](../specs/library.md#작품-발견과-감시-폴더), [설정 화면](../specs/settings.md#설정-화면), [보관과 복원의 폴더 이동](../specs/collection.md#보관과-복원의-폴더-이동), [라이브러리 화면](../specs/library.md#라이브러리-화면)의 추가 시각
- 막는 티켓: 없음(작품 폴더 따라가기는 [0011](0011-archive-folder-move.md)의 이동 명령에 붙여요)

## 작업

설정에서 감시 폴더를 등록하면 앱이 그 안의 trname 구조에서 작품·시즌·회차와 영상·자막 파일을 찾아 DB에 기억하고, 라이브러리·작품 상세([0013](0013-library-screen.md), [0014](0014-work-detail-video.md))가 그 기록을 읽어요.
이 티켓은 발견과 감시 폴더 관리까지이며, 파일을 만들거나 옮기거나 지우지 않아요.

- **구조**: trname이 만드는 `감시 폴더/작품/Season 01/작품 S01E01.mkv`예요.
  감시 폴더 바로 아래 폴더 하나가 작품이고, 그 안의 `Season NN` 폴더가 시즌(번호는 0 이상 정수)이며, 시즌 폴더 안의 `SxxEyy`(`E` 뒤 숫자는 원래 문자열 보존) 파일이 회차예요.
  같은 이름 줄기(stem)의 자막 파일(`작품 S01E01.ass`, `작품 S01E01.ko.smi`처럼 언어 조각이 붙은 것 포함)은 그 회차의 자막이에요.
  파일 이름의 `SxxEyy`가 시즌 폴더 번호와 다르거나, 구조에 맞지 않는 파일(여러 파일 토렌트의 하위 폴더, 받는 중인 `.part` 등)은 회차에 붙이지 않고 작품의 `회차를 확인하지 못한 파일`로 세요.
  `.trss/`와 숨김 항목은 발견 대상이 아니에요.
- **작품의 정체**: 작품은 앱이 발급한 ID를 갖고, 작품 폴더의 경로로 다음 확인과 이어져요.
  [0011](0011-archive-folder-move.md)의 보관·복원이 작품 폴더를 옮기면 그 명령이 끝날 때 작품의 경로를 새 위치로 바꿔 같은 ID가 이어지게 해요. 목적지에 이미 같은 이름의 작품이 있어 합쳐지면 목적지 작품의 ID가 남고, 옮겨 온 작품의 기록은 그리로 합쳐요.
  손으로 옮긴 폴더는 이름이 같다는 이유로 이어 붙이지 않아요. 옛 경로의 작품은 `폴더 없음`으로 남고 새 경로는 새 작품이에요(자막 기록이 생기는 결과 목표 3·4 전에는 잃는 기록이 없어요).
- **추가 시각**: 영상·자막 파일의 추가 시각은 앱이 그 파일을 처음 본 확인의 시각이에요.
  감시 폴더를 등록할 때의 첫 확인에 이미 있던 파일은 언제 들어왔는지 모르므로 `미상`이에요. 파일시스템의 수정·생성 시각으로 채우지 않아요([라이브러리 화면](../specs/library.md#라이브러리-화면)의 정렬 조건).
  작품 추가 시각도 같은 규칙으로, 첫 확인 뒤 새로 나타난 작품 폴더만 시각을 가져요.
- **확인 시점**: worker가 주기마다 모든 감시 폴더를 다시 확인하고, 설정의 `다시 확인`은 웹 명령으로 worker에 맡겨요.
  감시 폴더 추가는 웹이 읽기 전용으로 바로 한 번 확인해 발견한 작품 수를 알려요. 두 곳은 같은 발견 모듈을 써요.
  폴더 하나를 읽지 못해도 다른 감시 폴더와 수집 주기는 계속되고, 그 폴더의 줄에 까닭이 보여요. 읽지 못한 확인은 이전 기록을 지우지 않아요.
- **설정의 `감시 폴더` 항목**: 목록 줄 값은 `폴더 2개`처럼 읽을 수 있는 현재 값이에요.
  폴더마다 경로, 작품 수, 연결한 작품 수(Anissia 연결 전이라 지금은 0), 새로 발견한 작품 수(첫 확인 뒤 최근 7일 안에 나타난 작품), 마지막 확인 시각, `다시 확인`·`등록 해제`를 보여줘요.
- 수집 폴더와 보관 폴더를 감시 폴더로 자동 등록할지는 사용자 결정을 기다려요(아래). 결정 전에는 사용자가 두 폴더를 직접 등록할 수 있어요.

### 사용자 결정 대기

- 수집·보관 폴더의 자동 감시 여부. 명세는 보관한 작품이 라이브러리에서 빠지지 않으려면 두 폴더가 모두 감시 폴더여야 한다고 적고 있어요([보관과 복원의 폴더 이동](../specs/collection.md#보관과-복원의-폴더-이동)). 추천은 두 폴더를 항상 감시하고 등록 해제를 막는 것이에요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| `Lycoris Recoil/Season 01/Lycoris Recoil S01E01.mkv`·`…S01E01.smi`·`…S01E02.mkv`와 `Season 02/…S02E01.mkv`가 있는 폴더를 등록 | 작품 1개, 시즌 2개, S1은 1·2화 영상과 1화 자막, S2는 1화 영상으로 기록돼요. 추가 알림에 `작품 1개`가 보여요. |
| 이미 등록한 폴더, 등록한 폴더의 안쪽 폴더, 등록한 폴더를 안에 품은 폴더, 없는·읽을 수 없는 경로를 추가 | 각각 까닭을 문장으로 알리고 추가하지 않아요. |
| 시즌 폴더 번호와 다른 `S03E01` 파일, 시즌 폴더 밖 영상, 하위 폴더 안 영상, `.part` 파일 | 회차에 붙지 않고 작품의 `회차를 확인하지 못한 파일` 수에 들어가요. `.trss/` 안 파일은 세지 않아요. |
| 첫 확인 뒤 새 회차 파일이 생기고 worker가 다음 주기를 돌림 | 그 파일만 추가 시각을 갖고, 첫 확인 때 있던 파일은 `미상`으로 남아요. 파일 수정 시각을 바꿔도 기록이 바뀌지 않아요. |
| 회차 파일을 지운 뒤 다시 확인 | 그 회차의 영상 보유가 사라져요. 작품 폴더를 통째로 지우면 작품은 `폴더 없음`이 되고 ID는 남아요. |
| 수집 폴더의 작품을 규칙 보관으로 보관 폴더로 옮김(두 폴더 모두 감시 중) | 작품 ID가 같고 경로만 보관 폴더로 바뀌어요. 보관 폴더에 같은 이름 작품이 있었으면 그 ID 하나로 합쳐져요. |
| 같은 작품 폴더를 손으로 다른 감시 폴더로 옮김 | 옛 작품은 `폴더 없음`, 새 경로는 새 작품이에요. |
| 감시 폴더 하나가 권한 오류로 읽히지 않음 | 그 폴더 줄에 까닭이 보이고, 이전 작품 기록과 다른 감시 폴더의 확인, RSS 수집이 그대로예요. |
| `등록 해제` | 제자리 확인(디스크 파일은 건드리지 않고 이 폴더의 작품만 라이브러리에서 뺀다는 문장)을 거친 뒤 목록과 라이브러리에서 빠지고, 디스크 파일은 그대로예요. |
| `다시 확인` | 웹 명령으로 접수되고, worker가 확인한 뒤 마지막 확인 시각과 수가 바뀌어요. 같은 명령 ID를 다시 보내도 한 번만 돌아요. |
| 약 520개 작품·1만 개 파일의 폴더 | 한 번의 확인이 수집 주기를 눈에 띄게 늦추지 않아요(시간을 기록해 두어요). |
