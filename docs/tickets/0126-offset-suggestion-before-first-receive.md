# 0126 지난 회차를 처음 받기 전에 받을 이름과 회차 변환 제안을 보여줘요

- 상태: 대기
- 출처: [0123](0123-collect-moves-archived-work-folder.md)의 실제 서버 관찰(2026-10-08), [영상 회차 변환](../specs/collection.md#영상-회차-변환), 사용자 결정(2026-10-08)
- 막는 티켓: 없음. 0092 전에 고치고, 이것만으로 배포하지는 않아요(0124와 같이, 사용자 결정 2026-10-08).

## 작업

구독 규칙의 회차 변환은 규칙이 처음 고른 항목의 번호로 정해요. 번호가 이전 시즌 합계 + 1이면 앱이 정하고, 시즌 중간 번호면 받은 뒤 규칙 상세에서 제안만 해요.
방영이 끝난 속편을 구독하면 새 회차가 오지 않아서, 사용자가 고른 지난 회차가 첫 항목이 돼요. 2026-10-08 실제 서버의 `정반대의 너와 나` 2기는 지난 회차가 SubsPlease `- 24`, `- 25`였고, 1기가 12화라 −12가 맞아요. 그런데 `- 24`를 받으면 제안만 나오고 영상은 `S02E24`로 받아져요.
사용자는 받기 전에 제안을 보기로 했어요(사용자 결정, 2026-10-08). 번호만으로 추측해 정하지 않는 지금의 원칙은 그대로 둬요.

- 규칙 화면의 미리보기와 구독 확인 단계의 지난 항목 목록에 항목마다 받을 이름의 회차(`S02E24`)를 보여줘요. 지금 회차 변환으로 계산해요.
- 아직 아무것도 받지 않았고 앱이 정할 수 있는 구독 규칙이면, 받을 수 있는 지난 회차 가운데 가장 앞선 번호를 첫 릴리스로 보고 지금의 판단으로 값을 구해요. 값이 있으면 받기 전에 그 값과 까닭, `적용`을 보여줘요. 규칙 화면은 회차 변환 칸 아래의 제안 자리에, 구독 확인 단계는 지난 항목 목록 위에 보여요.
- 구독 확인 단계의 `적용`은 만들 규칙의 회차 변환을 정하고, 구독하면 그 값으로 만들어요. 규칙 화면의 `적용`은 지금처럼 바로 저장해요.
- 구독 확인 단계는 작품이 아직 보관 폴더에 있어도 그 작품의 이전 시즌으로 계산해요. `start`가 그 작품을 같은 ID로 수집 폴더에 옮기기 때문이에요.
- 여러 항목을 함께 받으면 번호가 앞선 항목부터 보내요. 앱이 첫 항목으로 회차 변환을 정할 때 가장 앞선 번호를 보게 하려는 거예요.

## 완료 기준

| 상태 | 기대 결과 |
| --- | --- |
| 1기 12화, 지난 회차 `- 24`, `- 25`인 2기를 구독하는 확인 단계 | 두 항목에 `S02E24`, `S02E25`가 보이고, 목록 위에 −12와 까닭, `적용`이 보여요. `적용`하면 `S02E12`, `S02E13`이 되고, 구독하면 규칙의 회차 변환이 −12예요. 1기 작품이 보관 폴더에 있어도 같아요. |
| 같은 규칙이 아무것도 받지 않은 채 규칙 화면을 엶 | 회차 변환 칸 아래에 같은 제안과 `적용`이 있고, 미리보기의 지난 회차에 받을 이름이 있어요. |
| 지난 회차가 `- 13`부터 있음 | 받기 전에 −12를 보여줘요. `적용`하지 않고 `- 13`을 받으면 지금처럼 앱이 −12로 정해요. |
| 이미 받은 항목이 있는 규칙 | 지금처럼 처음 받은 항목으로 제안해요. |

- 판단은 trss-collect에, 미리보기와 규칙 보기의 모양은 trss-web에 둬요([테스트 나눔 ADR](../adr/0015-test-a-rule-once-in-its-crate.md)).
- 실제 서버 확인은 다음 배포 뒤 시즌 중간 번호로 이어지는 속편을 구독할 때 해요.
