# 0080 실제 서버 DB의 복사본으로 새 마이그레이션을 확인해요

- 상태: 완료 (2026-10-07)
- 출처: [구현 경계와 실행 순서](../specs/web-app.md#구현-경계와-실행-순서), [앱 상태 저장소 ADR](../adr/0005-local-sqlite-app-state.md)
- 막는 티켓: 없음

## 작업

실제 서버는 0.5.0(2026-10-02, `c801731`)을 돌리고 있어요.
0.5.0의 마이그레이션은 29개이고, 지금은 62개예요. 0.5.0의 29개는 지금 목록의 앞부분과 순서·내용이 같아요. 바뀐 것은 `artwork/schema.sql`의 주석 한 곳뿐이에요(2026-10-07 확인).
그래서 새 릴리스를 올리면 실제 서버 DB에서 뒤의 33개가 처음 돌아요. 대부분 자막 작업의 테이블이에요.
개발 환경의 서버 DB 복사본을 언제 떴는지는 기록이 없고, 지금 실제 서버에 쌓인 데이터로 마이그레이션을 돌려 본 기록도 없어요.
새 복사본을 떠서 새 릴리스를 올리기 전에 확인해요.

- 복사본은 사용자가 서버(j4105)에서 실행 중인 DB를 `sqlite3 trss.db ".backup <복사본>"`으로 떠서 개발 PC로 옮겨요. 서버 명령은 서버 터미널에서 실행한다고 명령 위에 적어 드려요.
- 복사본은 git이 무시하는 개발 데이터 폴더(`dev/local/`)에만 두고, 저장소에 넣지 않아요.

## 완료 기준

- 지금 코드로 새 복사본을 열면 마이그레이션이 끝까지 돌고, `PRAGMA user_version`이 최신 값이에요. 걸린 시간을 결과 절에 적어요.
- 마이그레이션 전후로 채널, 규칙, 수집 이력, 감시 폴더, 작품, 시즌 연결의 행 수가 같아요. 견준 표가 결과 절에 있어요.
- 마이그레이션한 복사본으로 개발 환경의 web과 worker가 떠요. worker가 한 주기를 돌고, 웹의 라이브러리와 수집 화면이 그 데이터를 보여줘요.
- 실패하면 원인을 고치고, 다시 뜬 복사본으로 위를 다시 확인해요.

## 결과

### 복사본 (2026-10-07)

- 복사본은 계획한 `.backup` 대신 `dev/compose.sh pull --force`로 떴어요(사용자 결정, 2026-10-07). 서버의 trss-worker와 trss-web을 잠깐 멈춘 채 앱 데이터 폴더를 복사해서, DB와 WAL이 한 상태예요. 미디어 폴더의 파일 이름도 함께 가져와요(폴더 2,003개, 파일 13,312개, 표지 61개).
- 마이그레이션하기 전의 DB를 `dev/local/0080/before.db`로 남겼어요. `PRAGMA user_version`은 0.5.0의 29예요.

### 마이그레이션

이 시점의 코드(`06e63df`)로 `before.db`의 사본 3개를 각각 열었어요. 개발 PC에서 trss-core의 DB 열기를 glibc release로 빌드한 작은 프로그램으로 돌렸어요.

- 세 번 모두 끝까지 돌았고, 걸린 시간은 100.22–102.16 ms예요.
- `PRAGMA user_version`이 62가 됐고, `integrity_check`는 `ok`, `foreign_key_check`는 위반이 없었어요.
- 개발 환경의 worker(musl 이미지)가 띄울 때 마이그레이션한 시간은 따로 측정하지 않았어요. 그 DB도 62가 됐고 `quick_check`는 `ok`였어요.

### 개발 환경

`dev/compose.sh up`으로 띄운 web과 worker가 마이그레이션한 복사본으로 떴어요.

- worker가 한 주기를 돌았어요. 채널 2개를 읽어 250개를 봤고, 실패는 0개예요. 감시 폴더 2개를 읽었고, Anissia 자막 관찰이 5쪽을 읽었어요. 로그에 오류나 panic은 없었어요.
- 웹의 이번 주 편성, 라이브러리(작품 88편과 표지), 작품 상세(시즌 정보와 표지), 수집 화면(채널 2개 정상, 구독 1개와 그 Anissia 연결)이 복사본의 데이터를 보여줬어요.
- 주기 뒤에 `media_files`가 3,567개가 됐어요. 더해진 1개는 개발 환경의 가짜 자막 출처(`TRSS_FAKE_SUBTITLE_SOURCE`)로 자막 작업이 놓은 `S01E01.smi`예요. 마이그레이션과는 상관없어요.

실패한 것이 없어서 다시 뜬 복사본으로 반복하지 않았어요.
