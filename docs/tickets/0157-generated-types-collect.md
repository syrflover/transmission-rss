# 0157 화면 타입 생성 도구를 들이고 수집 화면이 쓰는 API의 타입을 생성해요

- 상태: 대기
- 출처: [구조 가볍게 하기 명세의 화면 타입 생성](lighter-structure.md#화면-타입-생성), [웹 앱 공통 명세의 공통 라이브러리의 모듈 구성](../specs/web-app.md#공통-라이브러리의-모듈-구성)
- 막는 티켓: [0145](0145-merge-web-and-worker-crates.md)(크레이트 합치기)

## 작업

화면의 TypeScript 타입은 Rust 응답과 손으로 맞춰요. 2026-10-21에 `trss-web`에는 `Serialize`를 붙인 구조체·열거형이 206개, 테스트 밖의 `json!` 호출이 75곳 있었어요. 이 티켓은 Rust 타입에서 화면 타입을 생성하는 길을 만들고, 수집 화면이 쓰는 API부터 옮겨요. 수집 화면은 구독, 규칙, 수집 기록, 지난 회차 검색, 수집 상태판, 이번 주 편성이에요. 라이브러리 화면은 [0158](0158-generated-types-library.md)이, 나머지 화면과 이벤트는 [0159](0159-generated-types-rest-and-events.md)가 옮겨요.

이 티켓 뒤에 새로 만드는 API 타입은 처음부터 생성해요.

명세를 쓰며 정한 것은 다음과 같아요.

- 생성 도구는 serde 속성을 읽는 ts-rs예요.
- 정수는 TypeScript에서 `number`로 생성해요. 지금 화면이 정수를 `number`로 받고 있어서예요.
- 생성한 파일은 저장소에 커밋해요. 화면을 빌드하는 Docker 단계에는 Rust가 없어서예요.

`json!`으로 만들던 응답을 구조체로 바꿀 때, 빠진 필드와 `null`인 필드의 차이까지 지금 JSON과 같게 해야 해요. API의 JSON 모양은 그대로라는 조건 때문이에요.

## 완료 기준

- [ ] 명령 하나로 Rust 타입에서 화면 타입을 생성하고, 그 명령이 [웹 앱 공통 명세의 공통 라이브러리의 모듈 구성](../specs/web-app.md#공통-라이브러리의-모듈-구성)이나 readme의 개발 환경에 있어요.
- [ ] 생성한 파일은 저장소에 있고, 생성 결과가 커밋한 파일과 다르면 Rust 테스트가 실패해요. 타입 하나를 바꾸고 생성하지 않은 채 테스트를 돌려 실패하는 것을 확인해요.
- [ ] 정해진 문자열만 오는 필드는 TypeScript에서 문자열 리터럴 유니언이고, `string`으로 넓히지 않아요. 정수 필드는 `number`예요.
- [ ] 수집 화면이 쓰는 API의 응답과 요청 본문은 모두 Rust 구조체나 열거형이고, 그 타입은 생성돼요. `json!`으로 만들던 응답과, 모든 화면이 함께 쓰는 오류 본문도 구조체가 돼요.
- [ ] 수집 화면에서 손으로 쓴 같은 뜻의 타입은 지우고, 화면은 생성한 타입을 써요. 생성한 이름끼리 겹치지 않아요.
- [ ] 지금 API 테스트가 고치지 않고 통과해요. 바꾼 `json!` 응답은 결과에 적고, 빠진 필드와 `null`의 차이를 확인한 방법을 적어요.
- [ ] 화면 테스트와 `npm run typecheck`가 통과해요.
- [ ] [명세의 동작 보존 조건](lighter-structure.md#동작-보존)을 지켜요.
