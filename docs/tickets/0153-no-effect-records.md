# 0153 자막 작업의 효과별 기록을 없애고 단계를 기록 없이 다시 해도 안전하게 해요

- 상태: 대기
- 출처: [구조 가볍게 하기 명세의 끊긴 자막 작업](lighter-structure.md#끊긴-자막-작업), [끊긴 작업 ADR](../adr/0020-interrupted-jobs-wait-for-a-restart.md)
- 막는 티켓: [0151](0151-probe-rename-exchange.md)(서버의 `RENAME_EXCHANGE` 지원), [0152](0152-interrupted-jobs-stop.md)(`중단됨`과 다시 시작)

## 작업

[0152](0152-interrupted-jobs-stop.md) 뒤 `다시 시작`은 효과별 기록과 디스크를 대조해 끊긴 단계를 이어 해요. 이 티켓은 기록 없이 단계를 다시 해도 안전하게 파일을 쓰는 방법을 바꾸고, 기록과 대조 코드를 없애요. 2026-10-21에 이 기록을 담는 테이블은 `jobs/store_apply.sql`에만 9개였어요.

- 파일을 쓰는 단계는 새 파일을 끝까지 쓴 뒤 이름을 바꿔 제자리에 둬요.
- 교체는 새 파일과 지금 파일을 `RENAME_EXCHANGE`로 한 번에 맞바꾸고, 밀려난 파일이 승인한 원래 파일과 다르면 다시 맞바꿔요. 효과별 기록 없이도 경로가 비는 순간을 없애려는 거예요. 서버의 미디어 파일시스템이 이를 지원하는 것은 [0151](0151-probe-rename-exchange.md)이 확인했어요.
- 끊겨서 옆으로 옮긴 채 남은 파일은 자동으로 지우지 않아요. 사용자 자막의 하나뿐인 사본일 수 있어서예요.
- 수신 영역에 받아 둔 묶음은 작업의 `받음` 상태로 알 수 있어서, 기록이 없어도 다시 받지 않아요(명세의 가정).

## 완료 기준

- [ ] 파일을 쓰는 단계는 새 파일을 끝까지 쓴 뒤 이름을 바꿔 제자리에 둬요. 이름을 바꾸기 전과 뒤에 끊는 테스트가, 원래 파일이나 새 파일 중 하나가 제자리에 있는 것을 확인해요.
- [ ] 교체는 `RENAME_EXCHANGE`로 맞바꾸고, 밀려난 파일이 승인한 원래 파일과 다르면 다시 맞바꿔요. 승인한 뒤 지금 파일이 바뀐 경우에, 다시 맞바꿔서 바뀐 파일이 제자리에 남는 것을 테스트가 확인해요.
- [ ] 재배치의 제거나 교체가 끊겨 옆으로 옮긴 파일이 남으면, trss는 그 파일을 지우지 않아요. 테스트가 확인해요.
- [ ] 앱 데이터 폴더의 `receive/.tmp/`와 `subtitle-files/.tmp/`는 시작할 때 비우고, 작품 폴더의 `.trss/tmp/`는 그 폴더에 다음에 쓸 때 비워요. 테스트가 확인해요.
- [ ] 받기·보관·적용·교체·재배치의 단계마다, 끊긴 뒤 `다시 시작`하면 기록 없이 그 단계를 다시 해서 끝나는 것을 테스트가 확인해요. `받음`인 묶음은 다시 받지 않아요.
- [ ] 효과별 기록 테이블과 기록·디스크 대조 코드가 없어지고, 마이그레이션이 테이블을 지워요.
- [ ] 업그레이드 때 실행 도중이던 작업은 `중단됨`이 돼요. 실행 도중의 작업과 효과별 기록이 든 지금 DB를 마이그레이션하는 테스트가 확인해요.
- [ ] 같은 커밋에서 [작업과 인증 명세의 체크포인트와 중단 복구](../specs/jobs.md#체크포인트와-중단-복구)를 기록 없이 다시 하는 방식으로 고쳐 써요. 교체·재배치·임시 파일을 적은 다른 명세의 절도 고쳐요.
- [ ] [명세의 동작 보존 조건](lighter-structure.md#동작-보존)을 지켜요. 지운 테스트는 없어진 기록과 대조만 확인하던 것이어야 하고, 결과에 그 까닭과 짝지어 적어요.
- [ ] 구현이 [끊긴 작업 ADR](../adr/0020-interrupted-jobs-wait-for-a-restart.md)과 맞아요. 다르게 해야 하면 마치기 전에 사용자 결정을 받아 ADR을 고쳐요.
