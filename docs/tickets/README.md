# 실행 계획과 티켓

웹 재설계 명세([웹 앱 공통 명세](../specs/web-app.md)와 주제별 명세)를 구현하는 순서와, 지금 실행할 티켓을 담아요.
전체 범위는 [구현 순서](../specs/web-app.md#구현-순서)의 다섯 결과 목표로 나누고, 실행 가능한 티켓은 지금 시작할 결과 목표 1만 자세히 적어요.
2–5는 결과 목표 1에서 정한 DB 구조와 웹 명령 계약에 따라 모양이 달라지므로, 그 앞 목표가 끝나 갈 때 티켓으로 나눠요.
티켓이 없는 목표도 범위에서 빠진 것이 아니며, 티켓을 닫았다고 결과 목표나 명세의 완료 조건이 확인된 것은 아니에요.

## 티켓 문서의 관례

- 티켓 하나가 파일 하나이고, 이름은 `0001-짧은-영문-이름.md`처럼 번호와 이름이에요.
- 맨 위에 `상태`(`대기`·`진행 중`·`완료`·`보류`), 출처 명세, 막는 티켓을 적어요.
  막는 티켓이 없으면 바로 시작할 수 있어요.
- 본문은 `작업`과 `완료 기준`이에요.
  완료한 티켓에는 `결과` 절을 더해 검증한 것·검증하지 못한 것·남은 일을 적고, 그 뒤에 내용을 나중 작업으로 고쳐 쓰지 않아요.
- 구현 중에 명세와 어긋나는 것을 발견하면 티켓이 아니라 명세의 요구를 기준으로 삼고, 사용자 결정이 필요한 차이는 티켓에 적어 결정을 받아요.

## 결과 목표

### 1. 앱 소유 설정과 수집 기반

외부 YAML과 5분 cron으로 한 번씩 돌던 수집을, 앱 DB의 채널·규칙으로 상시 실행하는 worker와 웹 화면으로 옮겨요.
미리보기와 실제 처리가 같은 규칙 판정을 쓰고, 모든 RSS 항목이 수집 이력에 남아 이후의 한 번 받기·구독·지난 회차 검색의 바탕이 돼요.

완료는 다음을 모두 관찰한 때예요: 기존 YAML을 가져온 앱이 cron 없이 같은 항목을 같은 폴더로 받고, 웹에서 고친 규칙이 다음 처리에 쓰이며, 미리보기와 실제 처리의 결과가 같고, 수집 이력에서 한 번 받기를 할 수 있어요.

### 2. 작품 발견과 방영작 구독

세 종류 영상 입력에서 작품·시즌·회차를 발견하고, 방영작을 구독해 수집을 시작하며, 영상 쪽의 확장 수집을 연결해요.

- [감시 폴더와 작품 발견·연결](../specs/library.md#작품-발견과-감시-폴더), [처음 실행](../specs/settings.md#처음-실행)
- [라이브러리 화면](../specs/library.md#라이브러리-화면)과 [작품 상세](../specs/library.md#작품-상세-화면)의 영상 쪽, [작품 표지](../specs/library.md#작품-표지)
- [방영작 구독](../specs/collection.md#방영작-구독)(제목 대기·제목 후보, 수집 화면 구독 탭), [기존 YAML 주석의 구독 제안](../specs/settings.md#기존-yaml), [이번 주 편성](../specs/web-app.md#이번-주-편성)
- [지난 회차 검색](../specs/collection.md#지난-회차-검색), [영상 회차 변환](../specs/collection.md#영상-회차-변환), [영상 수정본의 대체](../specs/collection.md#영상-수정본의-대체), [규칙 보관](../specs/collection.md#규칙-보관)

알려진 불확실성: nyaa 추가 검색의 묶음 크기·요청 간격, 구독 규칙과 시즌을 잇는 저장 방식이에요. 보관 제안의 "새 항목 없음" 기간은 4주로 정했어요(사용자 결정, 2026-10-01).

순서는 보관 이동, 라이브러리(감시 폴더·작품 발견·라이브러리와 작품 상세·표지), 방영작 구독과 편성이에요(사용자 결정, 2026-10-01).
분기가 끝나 보관할 작품이 쌓이는 때라 보관 이동을 먼저 하고, 구독이 작품·시즌에 이어지도록 라이브러리를 그 앞에 둬요.
라이브러리는 0012–0017(시즌 정보는 0017), 구독과 편성은 0018–0022로 나눴어요.
[처음 실행](../specs/settings.md#처음-실행) 체크리스트는 편성 화면과 함께 0021이에요.

### 3. 자막 후보와 수신

자막 후보를 찾고, 구독 제작자는 자동으로, 그 밖에는 사용자가 골라 받으며, 인증은 trss 안에서 끝내요.

- [자막 후보 조회](../specs/subtitles.md#자막-후보-조회), [구독 제작자 자동 수신](../specs/subtitles.md#구독-제작자-자동-수신)과 구독 제작자 출처의 [회차 대응 자동 결정](../specs/library.md#자막의-회차-대응)
- [출처별 다운로드](../specs/subtitles.md#출처별-다운로드) 여섯 경로(공통 결과·실패 표현을 정한 뒤 병행 가능)
- [서버 브라우저 인증과 수명](../specs/jobs.md#작업-화면-안의-인증과-브라우저-수명), [할 일](../specs/jobs.md#할-일)과 [할 일 화면](../specs/jobs.md#할-일-화면), [작업 상세](../specs/jobs.md#작업-상세)
- [공통 정책](../specs/settings.md#공통-정책)(브라우저 유휴 시간·동시 작업 수, 자막 형식 우선순위)과 설정 화면

알려진 불확실성: 출처별 실제 수신 경로의 재현성, 서버 Chromium 창 크기를 기기에 맞추는 기준이에요.
