# 0031 웹 명령을 접수하자마자 실행해요

- 상태: 대기
- 출처: [웹 명령과 상태 갱신](../specs/web-app.md#웹-명령과-상태-갱신)의 즉시 실행, [웹·작업 바이너리 분리 ADR](../adr/0006-separate-web-worker-binaries.md)
- 막는 티켓: [0030](0030-feature-crates.md)(worker 코드가 옮겨지는 중이라서예요)

## 작업

사용자는 웹 명령이 바로 실행되기를 기대해요(사용자 결정, 2026-10-02).
2026-10-02에 코드에서 확인한 지연의 원인은 세 가지예요. 측정한 값은 아니에요.

- worker가 명령을 3초마다 찾아요(`DEFAULT_COMMAND_POLL`).
- 명령은 수집 주기와 같은 잠금 아래에서만 실행돼서, RSS 읽기나 감시 폴더 읽기가 끝날 때까지 기다려요.
- 명령은 하나씩 실행돼서, 폴더를 옮기는 규칙 보관처럼 오래 걸리는 명령이 뒤의 명령을 막아요.

목표 3의 자막 작업은 인증을 오래 기다리므로 이 잠금 밖에서 돌아야 해서, 이 티켓이 그 실행 기반이기도 해요.
0030은 worker의 `CycleContext`를 `trss-collect`의 `CollectContext`와 `trss-library`의 `WatchContext`로 나눴지만, 수집 명령들(한 번 받기·지난 회차 받기·되돌리기·보관·영상 수정본·회차 변환·시즌 연결)은 아직 `CollectContext` 하나를 함께 받아요. 명령 실행 기반을 고치는 이 티켓에서 명령마다 쓰는 저장소만 받도록 나눠요.

- 웹이 명령을 저장하면 worker가 곧바로 알아채요. 웹이 worker를 깨우는 수단은 같은 호스트의 데이터 폴더를 쓰는 범위에서 구현 때 정해요.
- 수집 주기의 잠금은 정말 겹치면 안 되는 구간으로 좁혀요. Transmission에서 사라진 토렌트를 지우는 판단이 명령의 토렌트 추가와 엇갈리지 않아야 해요(지금 모듈 문서의 근거).
- 대상이 겹치지 않는 명령은 동시에 실행하고, 같은 토렌트·작품 폴더·파일을 건드리는 명령과 수집 처리는 그 구간만 차례로 실행해요.
- worker 두 개가 같은 명령을 실행하지 않는다는 기존 보장(OS 잠금, 명령 재시도 상한, `running` 명령이 있을 때 지우지 않는 주기)을 유지해요.

동시성 불변식을 바꾸는 변경이라 독립 리뷰(`claude-chan:complex-reviewer`)를 거쳐요. 리뷰는 잠금 범위, 주기와 명령의 엇갈림, 재시작 뒤 재실행을 다뤄요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 수집 주기가 쉬는 동안 `한 번 받기`를 접수 | 1초 안에 worker가 실행을 시작해요(접수 시각과 시작 기록으로 확인). |
| 오래 걸리는 수집 주기(가짜 Transmission이 늦게 답함) 중에 `한 번 받기`를 접수 | 주기가 끝나기를 기다리지 않고 실행돼요. 주기의 사라진 토렌트 제거가 그 토렌트를 지우지 않아요. |
| 규칙 보관(폴더 이동)이 도는 중에 다른 작품의 감시 폴더 다시 읽기를 접수 | 기다리지 않고 함께 실행돼요. |
| 같은 작품 폴더를 건드리는 두 명령 | 차례로 실행되고, 둘 다 기록된 결과가 맞아요. |
| worker 두 개를 띄움 | 한 명령은 한 번만 실행돼요(기존 테스트 유지). |
| 명령 실행 중 worker를 강제로 종료하고 다시 시작 | 기존 재실행 계약대로 이어지고 토렌트가 지워지거나 두 번 추가되지 않아요. |
| 독립 리뷰 | 잠금 범위와 엇갈림에 대한 리뷰 결과와 처리가 결과에 있어요. |
