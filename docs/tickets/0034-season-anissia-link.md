# 0034 시즌을 Anissia 작품에 연결해요

- 상태: 완료 (아래 "결과", 화면은 브라우저로 보지 못함)
- 출처: [작품 연결과 제외](../specs/library.md#작품-연결과-제외), [작품·회차 대응 필드](../specs/settings.md#작품회차-대응-필드)의 `seasons[].anissia_anime_no`, [채널과 규칙 필드](../specs/settings.md#채널과-규칙-필드)의 `subscription.season_id`
- 막는 티켓: [0030](0030-feature-crates.md)

## 작업

자막 후보 조회는 연결한 작품만 대상으로 하므로 이 연결이 목표 3의 첫 기반이에요.
지금 Anissia 연결은 구독 규칙(`rule_subscriptions.anissia_anime_no`)에만 있어 구독하지 않은 작품을 연결할 자리가 없어요.

- 연결을 시즌마다 저장해요. 구독이 이어진 시즌(`season_id`)은 그 구독의 Anissia 작품에 연결된 것으로 옮기고, 이후에도 둘이 어긋나지 않게 해요. 구독의 시즌이 아직 없으면 그 구독은 연결된 시즌 없이 남아요.
- 작품 상세의 시즌에서 `Anissia 연결`로 연결·바꾸기·끊기를 해요. 구독이 이어진 시즌의 연결은 구독 쪽에서만 바꿔요.
- 찾기는 Anissia 전체 애니 목록 검색이 기본이고(사용자 결정, 2026-10-02), 이번 분기 편성표에서도 고를 수 있어요. 연결 창은 검색어를 비워 두고 검색하지 않은 채 열며, 시즌의 참고 제목(AniList 한국어 별칭·원제·영어·로마자 제목, 작품 폴더 이름)을 누를 수 없는 글자로 보여줘요. 사용자가 그걸 보고 한국어 제목을 직접 써요(사용자 결정, 2026-10-02. 처음 검색어를 폴더 이름이나 원제로 하려던 결정을 실제 Anissia 표본을 보고 바꿨어요. 결과 참고).
- 전체 목록 검색은 공식 문서에 없는 `/anime/list/<page>?q=` 응답(2026-10-02 확인: 한 쪽 30개, `content`·`last` 등의 쪽 정보, 종영작 포함)을 써요. 응답을 읽지 못하면 검색 실패로 알리고, 편성표 고르기와 저장된 연결은 영향을 받지 않아요. 요청은 기존 Anissia 요청 간격·`429` 대기·응답 크기 한도를 함께 지켜요.
- 연결한 시즌은 작품 상세에서 Anissia 작품 이름과 링크를 보여줘요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 구독 규칙이 이어진 시즌이 있는 기존 DB를 올림 | 그 시즌이 구독의 Anissia 작품에 연결돼 있고, 구독·편성 화면은 이전과 같아요. |
| 구독하지 않은 종영작 시즌에서 `Anissia 연결` → 한국어 제목으로 검색(가짜 Anissia) | 창은 참고 제목과 빈 검색어로 열리고, 종영작이 결과에 있고, 골라서 저장하면 작품 상세에 연결이 보여요. 빈 검색어는 거절돼요. |
| 검색어를 고쳐 다시 검색, 다음 쪽 | 고친 검색어의 결과와 다음 쪽이 보여요. |
| 편성표 탭에서 고름 | 같은 방식으로 연결돼요. |
| 전체 목록 응답의 형식이 바뀜·실패·`429`(가짜 Anissia) | 검색 실패를 알리고 편성표 탭은 동작하며, 저장된 연결이 바뀌지 않아요. `429` 뒤에는 기다린 다음 요청해요. |
| 구독이 이어진 시즌에서 연결을 바꾸려 함 | 작품 상세에서는 바꿀 수 없고 구독에서 바꾸라고 알려요. |
| 두 화면에서 같은 시즌의 연결을 바꿈 | 늦은 저장은 버전 충돌로 거부되고 입력이 남아요. |
| 실제 Anissia | 실제 서버에서 종영작 하나를 검색해 연결한 결과가 있어요. |

## 결과

### 만든 것 (2026-10-02)

- **시즌 연결 저장**: 마이그레이션 31이 `season_anissia(work_id, season, anime_no, version)`을 더하고, 구독이 이어진 시즌을 그 구독의 Anissia 작품으로 채워요(한 시즌에 구독이 둘이면 규칙 ID가 앞선 쪽). 끊으면 행이 `anime_no` 없이 남고 버전이 올라요. 바뀌지 않는 저장은 버전을 올리지 않아요.
- **구독과 맞추기**: 구독이 시즌에 이어질 때 같은 트랜잭션에서 시즌 연결을 구독의 작품으로 써요. 다른 작품에 연결된 시즌은 구독이 잡지 않고 규칙에 `season_blocked`(무엇이 잡고 있는지: 구독 또는 연결)를 남겨요. 작품 상세는 구독이 잡은 시즌의 연결을 거절하고, 구독을 먼저 지우면 바꿀 수 있다고 알려요. 구독을 지워도 시즌 연결은 남아요(사용자 결정, 2026-10-02). 보관 이동으로 두 작품이 합쳐지면 옮겨 온 작품의 연결은 남는 작품에 행이 없는 시즌만 채우고, 구독의 `season_id`도 남는 작품으로 옮겨요. 옮긴 구독이 다른 작품에 연결된 시즌을 만나면 이어지지 않고 `season_blocked`가 남아요.
- **찾기**: `trss-anissia`가 `/anime/list/<page>?q=`를 읽어요(기존 요청 간격·`429` 대기·응답 크기 한도 공유, 형식이 다르면 거절, 찾은 쪽 5분 보관). 웹의 저장 요청은 작품 번호를 그대로 믿지 않고, 방금 받은 검색 쪽이나 편성표 주 안에 있는지 확인해 그 응답의 작품 정보를 저장해요.
- **참고 제목**: AniList 항목을 받을 때 동의어 중 한글이 든 것을 `anilist_entries.korean_titles`(마이그레이션 32)에 저장하고, 연결 보기의 `reference_titles`에 한국어 별칭·원제·영어·로마자 제목·폴더 이름을 겹치지 않게 담아요.
- **화면**: 작품 상세의 시즌마다 Anissia 작품 이름·상태·Anissia 링크와 연결·바꾸기·끊기, 연결 창의 `전체 목록`·`편성표` 탭이 있어요. 버전 충돌이면 검색어와 고른 작품이 남고, 그사이 구독이 시즌을 잡으면 그렇게 알려요.

커밋: `99b518a`, `51be0eb`, `4fdd114`, `6a5ad88`, `0e835e6`, `609e722`, `f7659d3`, `d9feb37`, `880c482`, `87d50d8`, `c2b2109`, `f08295e`, `35c99fe`, `a5023dc`, `00b8922`. `d9feb37`·`880c482`·`87d50d8`의 원제 검색어는 뒤의 `f08295e`·`35c99fe`·`a5023dc`가 바꿨어요.

### 처음 검색어 결정이 바뀐 근거

처음에는 시즌·작품 폴더 이름(티켓 원문), 이어서 AniList 원제(사용자 결정)로 하려 했어요. 개발 환경에서 실제 Anissia로 재 보니 Anissia 전체 목록 검색은 한국어 제목에만 맞아요. 원제 칸은 보지 않고, 가나는 한국어 발음으로 바꿔 맞는 경우가 있어요(`ヒロイン` → "히로인"). `이세계 실격`의 원제 `異世界失格` 그대로도 0건이었고, api.anissia.net에 직접 물어도 같았어요.

AniList에 연결된 시즌 20개(폴더 이름순) 표본에서 결과가 나온 검색어는 이랬어요.

| 검색어 | 찾은 시즌 |
| --- | --- |
| 작품 폴더 이름(전부 영어·로마자) | 0/20 |
| AniList 원제 | 1/20(전부 가타카나인 Girls Band Cry) |
| AniList 한국어 별칭 | 별칭이 있는 2개 중 1개(`외톨이 THE ROCK!`은 Anissia의 `봇치 더 록!`과 달라 0건) |

그래서 자동 검색어나 누르면 검색하는 제목 칩 없이, 참고 제목을 보여주고 사용자가 한국어 제목을 쓰게 했어요(사용자 결정, 2026-10-02).

### 독립 리뷰

`claude-chan:reviewer`가 마이그레이션 31·32, 구독과 시즌 연결의 모든 쓰기 경로, 동시 수정, 저장 요청의 신뢰 경계, Anissia 클라이언트를 세 번 봤어요. P0·P1은 없었고 아래를 고쳤어요.

| 지적 | 처리 |
| --- | --- |
| 거절 문장이 없는 "구독에서 바꾸기"를 가리킴 | 구독을 먼저 지우면 바꿀 수 있다고 알려요 |
| 합치기가 남는 작품의 끊은 연결을 덮어씀 | 남는 작품에 행이 없는 시즌만 채워요 |
| 합치기가 구독의 `season_id`를 옮기지 않아(예전부터) 구독과 연결이 어긋남 | 같은 트랜잭션에서 옮기고, 다른 작품에 연결된 시즌이면 `season_blocked`를 남겨요 |
| 마이그레이션 시험이 엣지를 안 봄 | 구독 둘·보관한 규칙·시즌 행 없음을 더했어요 |
| 충돌 응답에 구독이 실려 오면 창이 말없이 닫힘, 다음 쪽 상한, 실패 안내, 잡은 구독 고르는 순서 | 각각 고쳤어요 |
| 구독을 지우면 시즌이 풀리지 않음 | 사용자 결정으로 연결을 남겨요 |
| `429`가 편성표도 막음 | 위 해석대로 남겼어요 |
| 한국어 제목을 뒤에 둠, 끝난 항목에 한국어 별칭이 비어 있음 | 한국어 제목을 앞에 두고, 창 안내에 `정보 다시 받기`를 적었어요 |

### 남은 한계

- 화면은 브라우저로 보지 못했어요(이 환경의 브라우저 창이 `localhost`로 가지 못해요). 타입 검사·빌드와 API 확인만 했어요.
- 이미 저장된 AniList 항목은 다시 받을 때 한국어 별칭이 채워져요. 끝난 항목은 저절로 다시 받지 않아서 `정보 다시 받기`를 눌러야 해요. AniList 한국어 별칭은 표본 50개 중 10개에만 있었어요.
- 보관 이동이 합치면서 구독을 이을 수 없는 시즌을 만나면 구독이 시즌 없이 남고, 그 규칙의 토렌트가 Transmission에 없으면 다시 이어지지 않아요.
- 예전 합치기로 이미 지워진 작품을 가리키는 구독은 고치지 않았어요.
- `korean_titles`의 CHECK는 JSON인지만 봐요. 앱은 항상 문자열 배열로 써요.
