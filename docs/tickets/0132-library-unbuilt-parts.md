# 0132 라이브러리 명세에만 있고 만들지 않은 것을 만들어요

- 상태: 대기
- 출처: [작품 발견과 감시 폴더](../specs/library.md#작품-발견과-감시-폴더), [자동 판정](../specs/library.md#자동-판정), [라이브러리 화면](../specs/library.md#라이브러리-화면), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록), [오른쪽 카드 열](../specs/library.md#오른쪽-카드-열), [0113](0113-remaining-area-tests.md)에서 만든 [검증 표](../specs/library.md#검증-표)(2026-10-10)
- 막는 티켓: [0114](0114-refactor-final-check.md)(리팩터링 마지막 확인)

## 작업

라이브러리 명세의 요구 여섯 가지가 2026-10-10 `51c7ad0`에 만들어져 있지 않았어요. 리팩터링을 마친 뒤 만들어요(사용자 결정, 2026-10-10). 사용자가 정한 것은 처음 세 가지예요. 나머지 세 가지(표지 자동 판정의 힌트, `자막 확인 필요`의 원인, 극장판의 `본편`)는 같은 날 검증 표를 쓰며 찾았고, 같은 종류라서 리드가 이 티켓에 더했어요.

- **감시 폴더 줄의 `연결한 작품 수`**: 명세는 폴더마다 작품 수와 함께 연결한 작품 수를 보여준다고 해요.
  trss-web `watch_folders_api.rs`는 `linked_works`를 늘 `0`으로 보내요. 모듈 주석은 작품을 Anissia에 이을 수 있을 때까지 `0`이라고 적었지만, 시즌마다 Anissia에 잇는 길은 [0034](../archive/tickets/3-subtitle-candidates-and-receiving/0034-season-anissia-link.md)부터 있어요.
  시즌 하나라도 이은 작품을 셀지처럼 무엇을 셀지 이 티켓에서 정하고 명세에 적어요.
- **회차 목록의 방영 전 회차**: 명세의 회차 목록 표는 방영 전 회차에 영상 `방영 전`과 `자막 대기`를 조용하게 둔다고 해요.
  `web/src/screens/library/detail/EpisodeList.tsx`는 방영 요일만 보여주고, `방영 전`·`자막 대기`는 이번 주 편성의 카드에만 있어요.
- **`최근 활동` 카드**: 명세는 몇 줄만 보여준 뒤 전체 기록을 따로 열어 종류별로 걸러 보고 해당 회차로 이동한다고 해요.
  만든 코드가 없어요. [0014](../archive/tickets/2-work-discovery-and-subscriptions/0014-work-detail-video.md)가 뒤 티켓의 몫으로 남겼고, 그 뒤 맡은 티켓이 없었어요.
  기록할 활동의 종류와 어디에서 읽을지는 이 티켓에서 정해요.
- **표지 자동 판정의 힌트와 시즌마다의 관찰**: 명세는 연결이 확인된 Anissia의 `subject`, `originalSubject`, `startDate`를 힌트로 쓰고, 시즌마다 확인된 제목 관찰이 서로 다른 후보를 가리키면 자동으로 고르지 않는다고 해요.
  trss-library `artwork/queue.rs`는 작품 폴더 이름 하나만 AniList 제목과 견줘 `decide`에 넘겨요. 같은 제목의 후보가 여럿이면 비워 두는 것은 만들어져 있어요. 시즌 정보의 첫 시즌 자동 연결도 폴더 이름만 쓰고, [0017](../archive/tickets/2-work-discovery-and-subscriptions/0017-season-info.md)이 그 판정에 Anissia 힌트를 더하는 일을 남은 일로 적었어요.
- **`자막 확인 필요`의 원인**: 명세는 파일 누락·검증 실패·회차를 확인하지 못한 기록이 있으면 `자막 확인 필요`를 표시하고 상세에서 원인을 보여준다고 해요.
  trss-library `store/library/overview.rs`의 `subtitle_check_needed`는 회차에 붙이지 못한 자막 파일만 봐요. 파일 누락과 검증 실패로는 이 표시가 뜨지 않아요.
- **극장판의 `본편`**: 명세는 회차 목록에서 극장판을 `본편`으로 구분한다고 해요. `본편`을 쓰는 코드가 없어요.

## 완료 기준

- 여섯 요구가 명세대로 보이고, 각 요소의 값이나 판정을 그 규칙을 가진 크레이트의 테스트가 확인해요.
- [라이브러리 명세의 검증 표](../specs/library.md#검증-표)에서 여섯 요구의 행을 고쳐요.
