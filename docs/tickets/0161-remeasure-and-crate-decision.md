# 0161 바뀐 구조에서 다시 측정하고 기능 크레이트를 묶을지 결정을 받아요

- 상태: 완료
- 출처: [구조 가볍게 하기 명세의 다시 측정과 기능 크레이트 결정](lighter-structure.md#다시-측정과-기능-크레이트-결정)
- 막는 티켓: [0149](0149-no-worker-in-texts.md)(문구), [0160](0160-test-setup-costs.md)(테스트 고정 비용). 둘을 마치면 코드를 바꾸는 티켓을 모두 마친 거예요.

## 작업

코드를 바꾸는 마지막 티켓을 마친 커밋에서, [0144](0144-lighter-structure-baseline.md)와 같은 명령과 스크립트로 다시 측정해요. 견준 값을 사용자에게 보이고, 기능 크레이트를 묶을지 사용자 결정을 받아요. 묶는 일은 이 명세의 범위 밖이에요.

빌드 시간은 [명세의 기준값에서 `trss-core`를 고친 뒤의 빌드 시간](lighter-structure.md#trss-core를-고친-뒤의-빌드-시간)처럼 warm은 warm끼리, cold는 cold끼리 견줘요. 증분 캐시를 얼마나 다시 쓰는지에 따라 같은 고침의 빌드가 11.9초에서 99.2초까지 달라졌기 때문이에요.

인계 코드의 줄 수는 `trss-core`의 같은 파일들과 `trss` 크레이트를 세어, 0144의 `trss-core` 파일들과 `trss-web`·`trss-worker` 크레이트에 견줘요.

## 결과

사용자는 2026-10-22에 아래 값을 보고 기능 크레이트를 묶지 않고 그대로 두기로 정했어요. 결정과 그 까닭은 [명세의 결정](lighter-structure.md#결정)과 [티켓 목록의 구조 가볍게 하기](README.md#구조-가볍게-하기)에 있어요.

2026-10-22에 `ace59821`을 [0144](0144-lighter-structure-baseline.md)와 같은 PC, 명령, 스크립트, 빌드 상태로 측정했어요. 명령은 모두 `-j 4`이고, 테스트 시간은 빌드 뒤 다시 실행한 값이에요. 바이너리마다와 크레이트마다의 값, 값이 달라진 까닭은 [명세의 다시 측정한 값](lighter-structure.md#다시-측정한-값)에 있어요. 원본 로그와 `--timings` 결과는 이 PC의 `dev/local/measure/0161/`에 있어요.

| 값 | 0144 (`d8432c8a`) | 0161 (`ace59821`) |
| --- | ---: | ---: |
| 테스트 바이너리의 `finished in` 합, 두 번 | 43.0초, 43.0초 | 37.0초, 36.8초 |
| 테스트 바이너리 | 31개 | 27개 |
| 통과·실패·무시 | 3,086·0·14 | 3,201·0·12 |
| `trss-core`를 고친 뒤의 빌드, 증분 캐시를 다시 쓴 warm | 13.7초 | 15.7초 |
| `trss-core`를 고친 뒤의 빌드, 증분 컴파일을 끈 cold | 81.2초 | 53.1초 |
| 인계 코드, `trss-core`의 여섯 곳 | 3,873줄 | 2,676줄 |
| 인계 코드, web과 worker의 크레이트 | `trss-web` 47,827줄, `trss-worker` 10,503줄 | `trss` 64,671줄 |

테스트 시간과 cold 빌드가 줄어든 것은 대부분 [0160](0160-test-setup-costs.md)의 수정 덕분이에요. web과 worker를 합치고 그 뒤의 기능도 들어간 `a19eb94b`에서 0160이 측정한 값은 테스트 합 43.6·43.7초, cold 82.6초, warm 16.9초였어요. warm은 합친 `trss` 크레이트의 단위 테스트가 다른 단위가 모두 끝난 뒤 1.5초를 혼자 돌아서 0144보다 길어요.

처음 한 빌드 측정 두 번과 테스트 측정 두 번은 다른 세션이 다른 저장소를 빌드하고 테스트하던 13:43–13:52와 겹쳤어요. 그 저장소의 `target/`에 그동안 파일이 쓰였고, 두 측정 스크립트는 시작할 때만 다른 빌드를 확인해서 이것을 잡지 못했어요. 그래서 측정하는 동안에도 확인하는 `dev/measure/when-quiet.sh`를 만들어 다시 측정했어요. 이 스크립트는 다른 저장소의 cargo·rustc·테스트 바이너리와 이 저장소의 rust-analyzer check가 90초 동안 없을 때 측정을 시작하고, 측정하는 동안 1초마다 확인해 하나라도 보면 3으로 끝나요. 가짜 `cargo`를 다른 폴더에서 돌려, 측정 도중의 것은 3으로 잡고 먼저 돌던 것은 끝날 때까지 기다리는 것을 확인했어요. 다시 한 빌드 측정과 테스트 측정은 둘 다 첫 시도에서 아무것도 보지 않았어요. 겹친 측정의 값은 warm 15.9·14.8초, cold 53.3·54.7초, 테스트 합 37.7·37.8초와 37.5·37.5초로, 쓴 값과 1.6초 안에서 달랐어요.

musl 대상과, 빈 `target/`에서 처음부터 하는 빌드는 측정하지 않았어요. 명세가 견주는 값이 아니어서예요.
