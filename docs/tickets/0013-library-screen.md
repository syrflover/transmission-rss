# 0013 라이브러리 화면에서 작품을 둘러보고 찾아요

- 상태: 진행 중
- 출처: [라이브러리 화면](../specs/library.md#라이브러리-화면), [웹 앱 공통 명세](../specs/web-app.md)
- 막는 티켓: [0012](0012-watch-folders-discovery.md)

## 작업

[0012](0012-watch-folders-discovery.md)가 기록한 작품을 라이브러리 화면에 한 목록으로 보여주고, 보기·정렬·필터·검색으로 둘러보고 작품 상세로 들어가요.
지금 비어 있는 라이브러리 화면을 대신해요.

- 보기는 표지 격자와 목록이고, 표지는 [0015](0015-work-artwork.md) 전까지 작품명 첫 글자 같은 빈 표지 자리예요. 이미지가 없어도 작품명과 상태로 찾고 열 수 있어야 하는 요구와 같은 모양이에요.
- 상태 두 줄은 최신 로컬 시즌 기준의 영상 보유 범위와 자막 보유 범위(`자막 1–10화`, 빈 회차는 구간을 나눔, 시즌마다 구분)이며, 자막은 0012가 영상 옆에서 찾은 파일로 세요. 회차를 확인하지 못한 자막 파일이 있으면 `자막 확인 필요`예요.
- 정렬 다섯 가지와 필터 여섯 가지는 명세대로 두고, 기본은 `최근 자막 추가순`이에요. 날짜가 미상인 작품은 알려진 날짜 뒤에 두고 같은 값은 제목순이에요.
- 방영 정보(방영연도·방영 중)와 원제·영문명은 시즌마다 AniList 항목을 연결하는 티켓(0015 다음, [README](README.md#2-작품-발견과-방영작-구독))이 붙을 때까지 없어요. 그동안 `방영연도순`은 모두 미상이라 제목순과 같고, `방영 중` 필터는 방영 정보를 아직 모르는 까닭을 빈 상태 문장으로 알려요. 검색은 작품명(폴더 이름)으로 해요.
- 할 일 배지는 할 일이 생기는 결과 목표 3부터 붙어요.
- 보기·정렬은 브라우저에 기억하고, 상세에 다녀오거나 뒤로 가기를 해도 검색·필터·스크롤 위치가 남아요.
- 목록은 서버 페이지네이션이에요(사용자 결정, 2026-10-01): 정렬·필터·검색을 서버가 하고, 마지막으로 받은 항목 다음부터 받는 커서로 끝에 닿으면 다음 페이지를 이어 불러와요. 검색은 입력이 멈춘 뒤 보내요. 처음 구현은 520개를 한 번에 받아 그렸고, 이것으로 바꿔요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 표지 격자에서 목록으로 바꾼 뒤 새로고침·같은 브라우저의 새 페이지 | 목록 보기로 열려요. 정렬도 같아요. |
| 목록 보기의 한 줄 | 48px 표지 자리, 제목, 영상·자막 상태가 한 줄이에요. 항목 전체가 눌리고 올려 두면 배경이 밝아져요. |
| 영상 1–12화, 자막 1–3·5–12화인 시즌 | `자막 1–3·5–12화`처럼 구간을 나눠 보여줘요. |
| 두 시즌이 있는 작품 | 상태는 최신 시즌(번호가 가장 큰 시즌) 기준이에요. |
| 회차를 확인하지 못한 자막 파일이 있는 작품 | 확인된 범위와 별개로 `자막 확인 필요`가 보이고 `확인 필요` 필터에 걸려요. |
| 추가 시각이 서로 다른 작품·영상·자막과 미상이 섞인 자료 | 다섯 정렬마다 기대 순서대로이고, 미상은 뒤에서 제목순이에요. 정렬을 바꿔도 작업이 생기지 않아요. |
| 검색어 입력 후 작품 상세에 들어갔다가 뒤로 가기 | 검색어·필터·스크롤 위치가 그대로예요. |
| 약 520개 작품의 자료(격자·목록 각각) | 정렬·검색·스크롤이 눈에 띄게 멈추지 않고, 상세에 다녀와도 위치를 잃지 않아요. |
| 520개 작품을 목록으로 열고 끝까지 스크롤 | 처음에는 한 페이지만 받고, 끝에 닿을 때마다 다음 페이지를 받아 중복·누락 없이 520개가 이어져요. 페이지를 받는 사이 작품이 더해져도 이미 본 항목이 다시 나오지 않아요. |
| 세 페이지째까지 내려 상세에 갔다가 뒤로 가기 | 받은 페이지와 스크롤 위치가 그대로예요. |
| 검색어를 빠르게 입력 | 입력이 멈춘 뒤 한 번만 요청하고, 늦게 온 이전 검색 결과가 새 결과를 덮지 않아요. |
| 휴대폰 너비 | 가로 스크롤 없이 격자·목록이 보여요. |

## 결과

### 구현한 것

- 읽기 API `GET /api/library/works`(`src/web/library_api.rs`, 계산은 `src/store/library/overview.rs`): 작품마다 ID, 작품명(폴더 이름), `missing`, 감시 폴더, 최신 시즌 번호, 최신 시즌의 영상·자막 회차 범위, `subtitle_coverage`(`all`·`some`·`none`), `subtitle_check_needed`, 작품 추가 시각, 모든 시즌에서 가장 최근에 알려진 영상·자막 추가 시각(모르면 `null`)을 한 번에 답해요. 쿼리는 작품·파일·미확인 파일 세 개로 고정이에요.
  - 회차는 적힌 그대로 두고 숫자로만 견줘요(`013`과 `13`은 한 회차이고 더 작은 적힌 글자가 대표예요. `f64`로 바꾸지 않고 정수 `u128`로 비교해요). 연속한 번호는 한 구간이고 빈 번호에서 나눠요(`1–3`, `5–12`). 정수가 아닌 회차(`17.5`)는 따로 한 구간으로 숫자 구간 뒤에 놓아요.
  - `자막 다 갖춤`은 영상이 있고 영상이 있는 모든 회차에 자막이 있는 때, `일부`는 자막이 있으나 그렇지 않은 때(영상 없이 자막만 있는 시즌 포함), `없음`은 자막이 없는 때예요.
  - `subtitle_check_needed`는 회차를 확인하지 못한 파일 중 자막 확장자인 것이 있을 때예요. `.part`(받는 중)와 회차를 못 읽은 영상은 해당하지 않아요(그래서 `discovery::kind_of`를 공개했어요).
  - 폴더가 없는 작품(`missing`)은 이름과 기록된 추가 시각을 남기되 영상·자막 보유를 세지 않고 `subtitle_coverage`·`subtitle_check_needed`는 비워요(0012 결과가 읽는 쪽에 남긴 일이에요).
- 화면(`web/src/screens/LibraryScreen.tsx`, `web/src/screens/library/`): 표지 격자(작품명 첫 글자를 제목에서 정한 색조의 블록에 얹은 표지 자리, 제목, 영상·자막 두 줄)와 목록(48px 표지 자리, 제목, 영상·자막이 한 줄), 항목 전체가 작품 상세 링크, 올려 두면 배경이 밝아지고 밑줄은 없어요. 정렬 다섯 가지(기본 `최근 자막 추가순`, 알 수 없는 날짜는 알려진 날짜 뒤에 제목순, `방영연도순`은 모두 미상이라 제목순), 필터 여섯 가지, 작품명 검색(NFC로 맞추고 대소문자를 가리지 않음), `작품 N편`. `방영 중` 필터의 빈 상태는 한 문장으로 까닭을 알리고, 그 밖의 빈 결과는 `검색과 필터 지우기`를 둬요.
  - 영상 줄은 `영상 1–12화`·`영상 없음`·`폴더 없음`, 자막 줄은 `자막 1–3·5–12화`·`자막 없음`이고 `자막 확인 필요` 배지가 확인된 범위 옆에 따로 붙어요. 폴더가 없는 작품은 영상 줄 자리에 `폴더 없음`, 자막 줄 자리에 `자막 확인 불가`를 보여줘요. 화면은 정수 회차의 앞 `0`을 떼어 보여줘요(`01`→`1`).
  - 보기·정렬은 `localStorage`(`trss-library-v1`, 모든 접근을 `try/catch`로 감쌈)에 두고, 검색·필터는 페이지가 사는 동안 메모리에 둬요(새로고침하면 사라져요). 목록은 `useCached`(`library:works`)의 답을 첫 렌더에 보여줘서 상세에서 돌아오면 스크롤 위치(`useScrollOnNavigate`)가 맞는 높이로 바로 그려져요. 감시 폴더를 추가·해제·다시 확인하면 이 캐시를 버려요.
  - 작품 상세 경로 `/library/<작품 ID>`와 최소 화면(`WorkDetailScreen.tsx`: 작품명과 `라이브러리로` 링크, 라이브러리에서 들어왔으면 브라우저의 뒤로 가기와 같게 동작해서 위치가 남아요)을 더했어요. 0014가 이 화면을 채워요.

### 검증한 것

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`(라이브러리 364개 + 통합 시험 전부)가 통과했어요. 웹은 `npm run typecheck`와 `npm run build`가 통과했어요.
- Rust 시험: `overview.rs`의 구간(빈 번호에서 나눔, `013`=`13`, 숫자 순서와 글자 순서의 차이, `f64`로 표현할 수 없는 큰 번호, 정수가 아닌 회차, `u128`을 넘는 글자), 범위·시간·보유(`all`/`some`/`none`) 계산, `src/store/library/tests.rs`의 목록 시험(최신 시즌만의 보유와 구간, 확인 필요 자막과 `.part`·영상, 폴더 없는 작품, 모든 시즌에 걸친 최신 시각과 미상, 시즌 없는 작품), `tests/library_watch.rs`의 API 시험(실제 폴더·worker 주기로 만든 시각과 `missing`, 빈 라이브러리).
- 520개 작품·10 400개 파일: `GET /api/library/works`가 디버그 빌드에서 약 44 ms, 릴리스 빌드에서 약 11 ms(프로세스 안의 라우터 호출, `a_library_of_520_works_and_10_000_files_is_read_and_recorded`).
- 브라우저(로컬 `trss-web`, 스크래치 DB, 작품 520개·파일 11 299개, 영상·자막 시각이 알려진 것·같은 값·미상이 섞이고 `폴더 없음` 2개, 2026-10-01):
  - 격자→목록으로 바꾼 뒤 새로고침, 같은 브라우저의 새 탭: 목록 보기와 같은 정렬로 열려요.
  - 목록의 한 줄: 표지 자리 폭 48px, 제목·영상·자막이 한 줄(520개 모두), 항목 전체가 링크, 올려 두면 배경이 밝아져요(라이트 모드 화면으로 확인).
  - `Gap Test`(영상 1–12, 자막 1–3·5–12)는 `자막 1–3·5–12화`, `Two Seasons`는 2시즌 기준(`영상 1–4화`·`자막 1–2화`), `Zero Pad`(영상 013·14·15·17.5, 자막 13·014·015)는 `영상 13–15·17.5화`·`자막 13–15화`예요.
  - `Unconfirmed Sub`는 `자막 1–4화`와 `자막 확인 필요`가 따로 보이고, `Only Unconfirmed`는 `자막 없음`과 `자막 확인 필요`가 함께 보이며 둘 다 `확인 필요` 필터에 걸려요.
  - 필터별 개수가 API에서 따로 센 값과 같아요(전체 520, 다 갖춤 212, 일부 180, 없음 126, 확인 필요 54 = 확인 필요 자막 + 폴더 없음, 방영 중 0과 한 문장의 빈 상태). 212+180+126+폴더 없음 2 = 520이에요.
  - 정렬 다섯 가지: 제목·방영연도는 제목 오름차순, 추가·영상·자막 추가순은 520개 모두에서 시각이 내림차순이고 미상이 뒤이며 같은 시각은 제목순이에요(화면 순서를 읽어 인접한 두 작품씩 견줬어요). 정렬을 바꾸는 동안 `:8099`로 나간 요청은 모두 `GET`이었고 DB의 `commands`는 0행이에요.
  - 검색: 대문자 질의가 소문자 이름에, NFC로 친 질의가 NFD로 만든 폴더 이름에 맞고, 대괄호로 시작하는 이름도 찾아요.
  - 검색어 `이야기 1`+필터 `자막 일부`(스크롤 426px)에서 작품을 열었다가 `라이브러리로`를 누르면 검색어·필터·위치가 그대로이고, 전체 목록 6 000px에서 열었다가 브라우저 뒤로 가기와 `라이브러리로` 두 방법 모두 6 000px로 돌아와요.
  - 1280px에서 목록·격자, 390px와 320px에서 격자·목록(라이트·다크 일부) 모두 `scrollWidth == innerWidth`이고 폭을 넘는 요소가 없어요.
  - 520개 작품에서 자바스크립트와 레이아웃에 든 시간(그리기 제외, 개발 머신): 정렬 변경 30–46 ms, 필터 변경 9–69 ms, 검색어 한 글자 9–12 ms, 검색어 지우기(520개 복귀) 48–54 ms, 다른 메뉴에서 라이브러리로 돌아와 520개가 나타나기까지 약 80 ms(격자·목록 비슷)예요. DOM은 목록 보기에서 약 5 000개예요. 이 정도라 가상화는 넣지 않았어요.

### 검증하지 못한 것

- 520개에서의 스크롤·그리기가 눈에 띄게 멈추지 않는지는 사람이 본 확인이 아니에요. 브라우저 창이 가려져 있어 프레임 시간을 재지 못했고(`requestAnimationFrame`이 돌지 않았어요), 위 시간은 스크립트와 레이아웃뿐이에요. 이 행은 실제 기기(특히 휴대폰)에서 스크롤해 보고 닫아요.
- 실제 휴대폰·터치·가상 키보드, 키보드 조작과 초점 표시, 라이트·다크 모드마다의 글자 대비 측정은 하지 않았어요(다크는 320px 화면 하나를 봤어요).
- 자동 화면 시험은 없어요(이 저장소에 웹 시험 도구가 없어요). 정렬·필터·구간 문구는 위 브라우저 확인으로만 봤고, 정렬의 기대 순서는 시험 자료에서 따로 손으로 계산하지 않고 정렬 기준(시각 내림차순·미상 뒤·같으면 제목순)을 화면 순서에서 읽어 확인했어요.
- 영상·자막 추가 시각은 시험 자료의 DB 값을 직접 바꿔 섞었어요(worker의 감시 폴더 확인이 만든 시각은 `tests/library_watch.rs`로 확인했어요).
- 실제 NAS 폴더나 운영 DB로는 보지 않았어요.
