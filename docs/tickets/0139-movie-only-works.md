# 0139 극장판만 있는 작품을 알아보고 자막을 받아요

- 상태: 완료 (2026-10-14, 개발 환경에서 확인. 서버 확인은 [0143](0143-deploy-feedback-fixes.md)에서 해요. 아래 "결과")
- 출처: [작품 발견과 감시 폴더](../specs/library.md#작품-발견과-감시-폴더), [작품 연결과 제외](../specs/library.md#작품-연결과-제외), [자막의 회차 대응](../specs/library.md#자막의-회차-대응), [시즌 정보](../specs/library.md#시즌-정보), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록), [자막 후보 구역](../specs/library.md#자막-후보-구역)의 극장판(2026-10-11에 더한 요구), [극장판 ADR](../adr/0017-movies-by-place-and-anissia-link.md), 0.7.0을 써 본 사용자 피드백(2026-10-11)
- 막는 티켓: [0138](0138-work-title-from-anissia.md)(작품명 규칙)

## 작업

라이브러리는 `Season NN` 폴더 안의 영상만 회차로 알아봐요. 2026-10-10 서버의 `Chou Kaguya-hime!`는 극장판만 있는 작품이고, 작품 폴더 바로 아래의 `Chou Kaguya-hime!.mkv`를 0.7.0이 알아보지 못해요. 그래서 자막을 받을 길도 없어요.

[극장판 ADR](../adr/0017-movies-by-place-and-anissia-link.md)과 라이브러리 명세의 극장판 요구대로 만들어요. 사용자가 정한 것은 다음과 같아요(2026-10-11).

- 극장판은 라이브러리에서 알아보고 자막 후보를 받는 것까지 지원하고, RSS 규칙으로 받지는 않아요.
- 극장판만 있는 작품은 작품 폴더 바로 아래에 영상을 둬요. 지금 서버의 파일은 옮기지 않아요.
- 극장판은 Anissia 연결을 극장판마다 가져요.

명세에 리드가 적은 것도 있어요. 사용자가 다르게 정하면 명세와 함께 고쳐요.

- 시즌 폴더가 없고 바로 아래 영상이 하나뿐일 때만 극장판이에요. 영상이 여럿이면 지금처럼 알아보지 않아요.
- 극장판에 이은 Anissia 작품의 후보는 회차 표시와 상관없이 그 극장판에 붙어요.
- 극장판에도 후보 받기와 자막 올리기가 되고, `직접 찾기`와 `회차 대응 정하기`는 없어요.
- 극장판에 AniList 항목을 이어 시즌 정보와 자동 표지를 채워요. 작품명은 그 극장판에 이은 Anissia 제목이에요.

다음은 이 티켓에서 정해요.

- **극장판을 DB에 담는 꼴.** 시즌과 회차의 자리에 무엇을 둘지 정해요. 예를 들어 영상이 바로 아래에 있는 작품을 시즌 없는 회차 하나로 둘 수도 있고, 시즌 0이나 다른 번호를 빌릴 수도 있어요. Anissia 연결, AniList 연결, 회차 대응, 자막 작업이 시즌 번호를 키로 쓰므로 쓰는 곳을 먼저 모두 찾아요. 이 꼴은 [0140](0140-movies-in-season-00.md)의 `Season 00` 극장판 연결과 함께 쓸 수 있어야 해요. 고르기 전에 안을 사용자에게 보여줘요.
- **적용본의 이름과 자리.** 영상 옆에 두는 적용본의 이름을 정해요(예: `Chou Kaguya-hime!.ko.ass`). [보관본과 적용본](../specs/subtitles.md#보관본과-적용본)의 규칙을 따라요.
- **마이그레이션.** DB를 바꾸면 데이터를 보존하는 마이그레이션으로만 바꾸고, 배포 전에 서버 DB의 새 복사본으로 확인해요([티켓 목록의 운영](README.md#운영)).

## 완료 기준

- `Chou Kaguya-hime!`와 같은 꼴의 작품을 라이브러리가 알아보고, 회차 목록에 `본편` 한 줄이 보여요. 시즌 타일과 `시즌 변경`은 없어요.
- 극장판을 Anissia 작품에 잇고 바꾸고 끊을 수 있어요. 이은 작품의 후보가 자막 후보 구역에 보이고, 받으면 영상 옆에 적용돼요. 회차 표시가 `0`인 후보도 붙어요.
- 극장판에 자막을 올릴 수 있어요.
- 다음 경우를 규칙을 가진 크레이트의 테스트가 확인해요.
  - 시즌 폴더가 없고 바로 아래 영상이 하나인 작품은 극장판이에요.
  - 바로 아래 영상이 둘이면 극장판이 아니에요.
  - 시즌 폴더가 있는 작품의 바로 아래 영상은 극장판이 아니에요.
  - 극장판의 후보는 회차 표시(`0`, `1`, 빈 값)와 상관없이 그 극장판에 붙어요.
- 작품명과 자동 표지가 극장판의 연결을 따라요. 이것을 trss-library 테스트가 확인해요.
- [라이브러리 명세의 검증 표](../specs/library.md#검증-표)에서 극장판 행을 고쳐요. [0140](0140-movies-in-season-00.md)과 함께 다루는 행은 이 티켓의 몫만 적어요.

## 결과

### 정한 것

- **극장판을 DB에 담는 꼴.** 사용자가 시즌 0과 극장판 연결을 골랐어요(2026-10-14, [극장판을 담는 꼴의 ADR](../adr/0018-movies-in-season-zero-with-their-own-link.md)). 극장판만 있는 작품의 영상은 시즌 0의 회차 1로 담고, Anissia 연결은 시즌 0의 회차마다 하나씩 두는 극장판 연결(`movie_anissia`)로 해요. 극장판만 있는 작품인지는 따로 적지 않고, 시즌 0의 영상이 작품 폴더 바로 아래에 있고 시즌 1 이상이 없는지로 알아봐요. 화면은 그 회차를 `본편`으로 보여요.
- **적용본의 이름과 자리.** 회차의 적용본과 같은 규칙이에요. 영상 옆에 영상 이름 줄기와 형식의 확장자로 둬서, `Chou Kaguya-hime!.mkv`의 ASS 적용본은 `Chou Kaguya-hime!.ass`예요. 언어 표시(`.ko`)는 붙이지 않아요.
- **마이그레이션.** 63번(`movies.sql`)이 `movie_anissia` 표와 자막 작업의 `movie` 칸을 더하고, 극장판만 있는 작품이 처음 기록될 때 AniList 자동 연결을 요청해요. 기존 행은 바꾸지 않아요. 서버 DB의 새 복사본으로 확인하는 것은 [0143](0143-deploy-feedback-fixes.md)에서 해요.

리드가 정한 것도 있어요. 사용자가 다르게 정하면 명세와 함께 고쳐요.

- 극장판은 시즌 폴더가 없고 작품 폴더 바로 아래의 완성된 영상이 꼭 하나일 때예요. 받는 중인 `.part` 파일은 영상으로 세지 않고, 이름을 DB에 담을 수 없는 영상도 하나로 세서 다른 영상이 극장판이 되지 않게 해요. 영상 이름 줄기가 같은 바로 아래 자막(`<줄기>.*`)은 극장판의 자막이에요.
- 극장판의 작업(후보 받기와 자막 올리기)은 묶음의 자막을 이름의 번호나 후보의 회차 표시와 상관없이 모두 그 극장판에 직접 정한 연결로 붙여요. 극장판에는 `직접 찾기` 작업을 만들지 않아요.
- 극장판만 있는 작품의 `제작자 지정`은 시즌 대신 그 극장판에 이은 Anissia 작품의 제작자 중에서 골라요. 이은 작품이 없으면 극장판에 먼저 연결하라고 알려요.
- 라이브러리 격자와 할 일, 교체 비교, 배치 확인은 극장판의 회차를 `본편`으로 적어요.

### 개발 환경 확인 (2026-10-14)

0137(b2bd904) 위에 이 변경을 얹은 작업 트리의 `trss-web`을 로컬 개발 환경 DB의 복사본으로 띄우고, 감시 폴더로 시험 폴더를 등록했어요. 시험 폴더에는 `Chou Kaguya-hime!`(바로 아래 영상 하나), `Mixed`(시즌 폴더와 바로 아래 `Root.mkv`), `Two Movies`(바로 아래 영상 둘)를 뒀어요. 내장 브라우저(1024px, 375px)로 본 것은 다음과 같아요.

- `Chou Kaguya-hime!`만 극장판이 됐어요. 회차 목록은 `본편` 한 줄이었고 시즌 타일과 `시즌 변경`이 없었어요. 라이브러리 격자는 `영상 본편`이었어요. `Mixed`의 `Root.mkv`와 `Two Movies`의 두 영상은 `회차를 확인하지 못한 파일`에 남았어요.
- `극장판 Anissia 연결` 창에서 실제 Anissia를 `극장판`으로 찾아 3198(`극장판 하이큐!! 쓰레기장의 결전`)을 이었어요. 머리, 탭 제목, 할 일의 작업 카드가 바로 그 제목이 됐어요.
- 이은 작품의 자막 줄로 회차 표시가 `0`, `1`, `극장판`인 줄 셋을 DB에 넣자 자막 후보 구역이 셋 모두 `본편`으로 보였어요. `직접 찾기`와 `회차 대응 정하기`는 없었어요. 하나를 받자 `본편` 작업이 만들어졌고, 화면의 올리기 코드로 자막 하나를 보내자 시즌 0의 극장판 작업이 됐어요.
- `제작자 지정`이 3198의 제작자 `스모모`·`난장`을 보였어요. `스모모`를 고르자 머리가 `자막 제작자 스모모`가 되고 `파일` 카드의 자막에 `스모모`가 붙었어요.
- `극장판 AniList 연결` 창이 폴더 이름으로 찾기 시작했고, 실제 AniList의 `Cosmic Princess Kaguya!`를 잇자 시즌 정보 칸과 원제 `超かぐや姫！`가 채워졌어요.

### 테스트

2026-10-14에 `cargo test --workspace -j 4`가 모두 통과했어요(3,086개 통과, 14개 무시). `npm run typecheck`와 `npm test`(238개)도 통과했어요. 새 테스트는 다음과 같아요.

- `trss-library`(21개): `discovery.rs`의 6개는 극장판을 알아보는 규칙과 그 예외(바로 아래 영상 둘, 시즌 폴더가 있는 작품, `.part`, 이름을 담을 수 없는 영상, 이전 목록에서 다시 읽기)를 겨눠요. `store/seasons/movie_tests.rs`의 15개는 극장판만 있는 작품의 판정, 극장판 연결의 버전과 스캔·보관 폴더 합치기에서의 유지, 회차 0의 거절, 가장 앞 시즌·자동 연결·표지, 작품명, 목록의 `movie_only`를 겨눠요.
- `trss-core` `db.rs`(2개): 마이그레이션 63이 기존 행을 지키는 것과 극장판만 있는 작품의 자동 연결 요청을 겨눠요.
- `trss-collect` `store/channels/season_anime_tests.rs`(1개): 극장판 연결의 잇기·바꾸기·끊기와 Anissia 작품 사본을 겨눠요.
- `trss-jobs`(5개): `place/package/tests.rs`의 3개와 `tests/it/placement.rs`의 2개가 극장판 작업이 모든 자막을 극장판에 붙이고 적용하는 것을 겨눠요.
- `trss-web`(11개): `seasons_anissia_api`(4개), `jobs_api`(3개), `subtitle_upload_api`(2개), `seasons_api`(1개), `subtitle_creator_api`(1개)가 극장판 연결 경로, 후보, 작업, 올리기, 시즌 정보, 제작자 지정의 응답을 겨눠요.
- `web`(8개): `src/screens/library/detail/movie.test.ts`의 5개와 `subtitles.test.ts`, `todo/episodeLine.test.ts`, `todo/replacementView.test.ts`의 1개씩이 `본편` 표기와 후보를 붙이는 규칙을 겨눠요.

### 한계

- worker를 돌리지 않아서, 받거나 올린 자막이 영상 옆에 적용되는 것과 AniList 자동 연결·표지 받기는 `trss-jobs`와 `trss-library` 테스트로만 봤어요. 실제 Anissia의 극장판 자막 줄로도 보지 않았어요.
- 시험 폴더는 웹이 감시 폴더를 등록할 때 읽었어요. worker의 실시간 읽기와 서버의 `Chou Kaguya-hime!`는 [0143](0143-deploy-feedback-fixes.md)에서 봐요.
- 극장판의 연결을 바꾸거나 끊는 것은 화면에서 보지 않았어요. API와 저장소 테스트만 있어요.
- RSS 규칙으로 극장판을 받지 않는 것은 테스트가 없어요.
- 시즌이 있는 작품의 `Season 00` 극장판은 [0140](0140-movies-in-season-00.md)이 맡아요.
