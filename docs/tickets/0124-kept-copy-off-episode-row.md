# 0124 `현재 유지`로 정한 보관본은 회차 줄에서 빠져요

- 상태: 완료 (2026-10-08)
- 출처: [0122](0122-imported-copy-choosable.md)의 서버 확인(2026-10-08), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록), [교체 비교와 승인](../specs/subtitles.md#교체-비교와-승인)
- 막는 티켓: 없음. 리팩터링의 [0092](0092-refactor-baseline.md) 전에 고치고, 이것만으로 배포하지는 않아요(사용자 결정, 2026-10-08).

## 작업

0.6.1을 올린 뒤 사용자가 `All Works Maid` 1화의 들인 보관본으로 `교체 비교`를 열고 `현재 유지`를 골랐어요. 그 뒤에도 1화 줄에는 그 보관본과 `교체 비교`가 남았어요.
명세대로였어요. `현재 유지`는 보관본을 남기고, 회차 줄은 적용되지 않은 보관본을 모두 버튼과 함께 보여줬어요. 사람이 이미 정한 비교를 줄이 계속 내놓으면 정할 일이 남은 것처럼 보여요.

- 사람이 `현재 유지`로 정한 보관본은 그 회차에 자막이 있는 동안 회차 줄에 보여주지 않아요. `보관본 있음`도 그 보관본 때문에는 붙지 않아요(사용자 결정, 2026-10-08).
- `자막` 카드에는 그대로 남고, 거기서 다시 고를 수 있어요.

## 완료 기준

| 상태 | 기대 결과 |
| --- | --- |
| 보관본을 비교하고 `현재 유지` | 회차 줄에 그 보관본이 없어요. `자막` 카드에는 `교체 비교`와 함께 있어요. |
| 카드에서 다시 고름 | 줄에 `교체 승인`을 기다리는 보관본으로 돌아와요. |
| 다시 `현재 유지`한 뒤 회차의 자막이 없어짐 | 줄에 `적용`과 함께 다시 보여요. |

- 규칙은 회차 줄의 보관본 목록을 가진 trss-jobs에서 시험해요([테스트 나눔 ADR](../adr/0015-test-a-rule-once-in-its-crate.md)).

## 결과

### 만든 것 (2026-10-08)

- `place/records.rs`의 `stored_only`(작품 상세 회차 줄의 보관본)가 보관본마다 마지막 교체 계획(`subtitle_replacements`, 만든 시각과 넣은 순서로)을 읽어요. 그 상태가 `kept`이고 회차에 자막이 있으면 목록에서 빼요. `kept`는 사람의 결정(`decide_all`)만 만들어요.
- 마이그레이션은 없어요. 0.6.1에서 이미 `현재 유지`로 정한 보관본(서버의 `All Works Maid` 1화)도 이 판으로 올리면 바로 빠져요.
- [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록)의 보관본 줄과 [교체 비교와 승인](../specs/subtitles.md#교체-비교와-승인)의 `현재 유지`에 이 규칙을 적었어요. API 문서 주석(`library_work_api.rs`)과 웹의 응답 타입 주석도 고쳤어요. 웹 코드는 바꾸지 않았어요. 서버가 보내는 목록이 줄어요.

### 구현 결정 (2026-10-08)

- 보관본의 마지막 계획을 봐요. 카드에서 다시 고르면 새 판(`open`)이 생겨 줄에 `교체 승인`으로 돌아오고, 승인하면 적용본이 되어 원래 목록에서 빠져요.
- "회차에 자막이 있는 동안"은 버튼이 `교체 비교`인지 정하는 값(`compare`: 라이브러리가 기록한 자막이나 앱의 적용본이 있음)과 같아요.

### 한계

- `현재 유지`는 그때의 현재 자막과 견준 결정이에요. 뒤에 다른 보관본을 승인해 현재 자막이 바뀌어도, 유지로 정한 보관본은 줄에 다시 나오지 않아요. 카드에서는 고를 수 있어요.

### 검증한 것

- trss-jobs의 `replace::a_copy_kept_off_the_episode_leaves_its_row_until_chosen_again_or_the_subtitle_goes`가 위 표의 세 상태를 차례로 확인해요. 교체하며 들인 보관본을 고르고 `현재 유지`하면 줄에 없고 카드의 `apply`는 `Ok(true)`(교체 비교)예요. 다시 고르면 줄에 `awaiting_approval`로 있어요. 다시 유지한 뒤 영상 옆 자막을 지우고 적용본 기록을 끝내면 줄에 `compare: false`로 돌아와요.
- 거르는 조건을 끄고 돌리면 이 시험이 첫 확인에서 실패하는 것을 봤어요.
- 2026-10-08 `cargo test -p trss-jobs -p trss-web -j 4`: trss-jobs는 단위 101개, `extract_process` 15개, `tests/it` 416개가 통과하고 5개는 원래대로 무시됐어요. trss-web은 단위 470개와 나머지 테스트가 통과했어요.

### 실제 서버 (2026-10-08, 0.6.2)

0.6.2를 올린 뒤 개발 PC에서 실제 서버의 작품 상세 API를 읽었어요(04:00 UTC 무렵, 읽기만 했어요).

- `All Works Maid` 1화 줄의 보관본 목록(`stored`)이 비었어요. 0.6.1에서는 `현재 유지`로 정한 들인 보관본(`제작자 알 수 없음`)이 `교체 비교`와 함께 있었어요.
- `자막` 카드에는 그 보관본이 그대로 있고, `choice`가 `compare`(교체 비교)예요.
- 5–8화 줄의 `에루샤` 보관본은 정한 적이 없어 지금처럼 `교체 비교`와 함께 남아요.

### 확인하지 않은 것

- 브라우저로 화면을 보지 않았어요. 서버에서는 화면이 그리는 API 응답만 읽었어요.
