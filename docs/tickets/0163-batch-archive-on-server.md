# 0163 `모두 보관`·`N개 보관`을 명령 하나로 받아 서버가 규칙 순서대로 보관해요

- 상태: 대기
- 출처: [구조 가볍게 하기 명세의 명령](lighter-structure.md#명령), [명세의 결정](lighter-structure.md#결정), [수집 명세의 보관 이동](../specs/collection.md)의 `모두 보관`·`N개 보관`
- 막는 티켓: [0154](0154-change-events-and-command-reads.md)(SSE 경로)

## 작업

보관 제안의 `모두 보관`·`N개 보관`은 화면이 규칙마다 규칙 보관 명령을 하나씩 보내고, 그 명령이 끝나기를 기다린 뒤 다음 규칙을 보내요. 순서를 화면이 쥐고 있어서, 화면이 기다리기를 멈추면 일괄 보관 전체가 멈춰요. [0154](0154-change-events-and-command-reads.md) 전에는 1초 주기 조회가 숨겨진 탭에서도 느리게나마 돌아 다음 규칙으로 넘어갔어요. 0154 뒤로는 숨겨진 탭이 이벤트 연결을 닫아서, 탭을 숨기면 지금 규칙 하나는 서버가 끝까지 옮기지만 남은 규칙은 다시 보일 때까지 보내지 않아요. 화면을 닫으면 남은 규칙은 보내지 않아요.

사용자는 일괄 보관을 서버가 순서대로 처리하게 하기로 했어요(2026-10-21, [명세의 결정](lighter-structure.md#결정)). 이 티켓은 화면이 고른 규칙을 요청 하나로 보내고, 서버가 명령 하나 안에서 규칙을 그 순서대로 보관하게 해요. 화면은 그 명령의 진행을 이벤트로 받아 다시 읽어요.

지금 일괄 보관이 지키는 것은 그대로예요.

- 규칙마다 같은 순서로 처리하고, 같은 작품 폴더의 규칙들을 한꺼번에 보관하면 마지막 규칙에서 한 번 옮겨요.
- 규칙 하나가 잘 끝나지 않으면 거기서 멈추고, 화면은 그 규칙의 이름과 까닭을 보여 줘요.
- 규칙 하나를 보관하는 동작(규칙 끄기, 폴더 이동, 까닭 문장)과 명령 안의 다시 시도 횟수·대기는 지금과 같아요.

명령의 모양(새 종류인지, 지금 규칙 보관 명령이 규칙 목록을 받는지), 진행을 어디에 적는지, 이미 열린 규칙 보관 명령과 겹칠 때 무엇을 하는지는 이 티켓에서 정해요. 화면에 보이는 것이 바뀌는 선택이면 사용자에게 물어요.

## 완료 기준

- [ ] `모두 보관`·`N개 보관`은 고른 규칙을 요청 하나로 보내고, 서버가 명령 하나 안에서 그 순서대로 보관해요. 탭을 숨기거나 화면을 닫아도 남은 규칙을 이어서 보관해요.
- [ ] 규칙 하나가 잘 끝나지 않으면 남은 규칙은 보관하지 않고 명령이 끝나요. 화면은 지금과 같은 문장으로 그 규칙의 이름과 까닭을 보여 줘요.
- [ ] 같은 작품 폴더의 규칙들은 지금처럼 마지막 규칙에서 한 번 옮겨요. 기능 크레이트 테스트가 순서, 멈춤, 한 번 옮기기를 확인해요.
- [ ] 프로세스가 도중에 멈추면 다시 시작한 뒤 이미 보관한 규칙은 건너뛰고 남은 규칙부터 이어서 보관해요. 테스트가 확인해요.
- [ ] 화면은 전체 수, 끝난 수, 지금 규칙을 그 명령의 이벤트를 받을 때 다시 읽어 보여 주고, 주기 조회를 하지 않아요. 진행 중에 화면을 다시 열면 진행 중인 일괄 보관을 보여 줘요.
- [ ] API 테스트가 요청과 응답의 모양을 확인하고, 화면 코드의 진행 표시에는 테스트가 있어요. 화면 테스트와 `npm run typecheck`가 통과해요.
- [ ] 같은 커밋에서 [수집 명세](../specs/collection.md)의 `모두 보관`·`N개 보관` 줄과 검증 표, [구조 가볍게 하기 명세의 화면 알림](lighter-structure.md#화면-알림) 표의 `일괄 보관` 행을 고쳐요.
- [ ] 개발 환경에서 규칙 둘 이상을 `N개 보관`으로 보관하는 동안 탭을 숨겼다가 다시 보이게 해서, 숨긴 동안에도 보관이 이어졌는지 확인하고 결과에 적어요.
- [ ] [명세의 동작 보존 조건](lighter-structure.md#동작-보존)을 지켜요.
