# 0037 작품 상세의 자막 후보 구역에서 골라 받아요

- 상태: 완료
- 출처: [자막 후보 구역](../specs/library.md#자막-후보-구역), [자막 후보 조회](../specs/subtitles.md#자막-후보-조회), [할 일과 회차 목록](../specs/library.md#할-일과-회차-목록)
- 막는 티켓: [0035](0035-candidate-observation.md), [0036](0036-subtitle-jobs-foundation.md)

## 작업

작품 상세에서 자막을 한 번에 또는 골라 받게 해 달라는 요청(2026-10-02)을 명세의 자막 후보 선택과 합쳤어요. 선택한 시즌의 `할 일`과 회차 목록 사이에 `자막 후보` 구역을 둬요.

- 후보는 제작자·출처별로 접힌 줄이고, 펼치면 회차별 후보와 Anissia 갱신일이 보여요. 누락 회차 후보와 수정 후보(같은 회차에 같은 제작자의 자막이 이미 있음)를 구분해요.
- 제작자 단위의 `모두 받기`와 회차를 골라 받는 선택이 있고, 받기는 웹 명령으로 자막 작업을 만들어요. 선택은 행 위치가 아니라 후보 ID로 유지하고, 새로 나타난 후보를 자동으로 고르지 않아요.
- 회차 줄에는 구독 제작자가 올리지 않은 회차의 다른 제작자 후보를 조용히 적고, 펼친 자리의 `받기`가 같은 후보를 가리켜요.
- `새로고침`은 그 작품의 Anissia 자막 정보를 바로 읽어요(0035). `updDt`를 자막 공개일이나 방영일로 표시하지 않아요.
- 구독 제작자의 수정 후보는 자동으로 받으므로(0045) 구역에서는 받는 중이나 받음으로 보여요.
- Anissia 연결이 없는 시즌에는 후보 대신 `Anissia 연결`(0034)을 둬요.
- 출처별 수신이 아직 없는 후보로 만든 작업은 그 까닭(`자막 대기`)으로 기다려요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 두 제작자의 후보가 있는 시즌 | 접힌 줄 둘에 제작자·회차 범위·누락·수정 개수가 있고, 펼치면 회차별 후보가 보여요. |
| 한 제작자의 1–4화 가운데 2·3화만 골라 받기 | 2·3화만 담은 작업 하나가 생기고 작업 상세로 이어져요. 고르지 않은 후보는 받지 않아요. |
| `모두 받기` | 그 제작자의 누락 회차 후보 전체를 담은 작업이 생겨요. 수정 후보는 빠져요. |
| 같은 받기를 두 번 누르거나 응답이 끊겨 다시 보냄 | 같은 명령 ID로 작업이 하나만 생겨요. |
| 고르는 중에 새 조회로 후보가 늘어남 | 고른 것이 유지되고 새 후보는 고르지 않은 상태로 나타나요. |
| 구독 제작자가 올리지 않은 6화에 다른 제작자 후보만 있음 | 6화 줄에 색 없이 후보가 있다고 적히고, 펼친 자리의 `받기`로 받을 수 있으며, 할 일은 생기지 않아요. |
| Anissia 연결이 없는 시즌 | 후보 대신 `Anissia 연결`이 있어요. |
| 휴대폰 너비 | 구역과 펼친 후보에 가로 스크롤이 없어요. |

## 결과

### 만든 것 (2026-10-03)

- **수정 후보 판단**: 0035의 잠정 기준을 받은 자막 기록으로 바꿨어요. 같은 출처(`source_id`)·같은 회차 표시에서, 이 후보보다 먼저 본 관찰을 담은 작업 회차가 `받음`이면 수정 후보예요. `of`는 그런 관찰 가운데 가장 나중 것이고, `same_post`는 게시물 주소가 같은지예요. 받은 적이 없는 회차는 몇 번 다시 보여도 누락 회차 후보예요. 명세는 [자막 후보 조회](../specs/subtitles.md#자막-후보-조회)에 맞췄어요.
- **후보 API**: `GET /api/works/{id}/seasons/{n}/anissia/candidates`의 관찰마다 `job`(그 관찰을 담은 가장 나중 작업의 ID·회차 상태·대기 사유)이 붙어요. `JobStore::picks_of_anime`가 작품의 작업 회차를 한 번에 읽어요.
- **자막 후보 구역**: 작품 상세에서 Anissia 연결 다음에 있어요. 제작자마다 접힌 줄(이름·출처·회차 범위·`누락 N`·`수정 N`, 구독 제작자가 먼저)이고, 펼치면 회차마다 가장 나중 관찰과 종류(`누락`·`수정`·`받음`·`있음`), 작업 상태 링크, `Anissia 갱신` 시각, 게시물 링크가 보여요. `모두 받기`(수정 후보와 열린 작업이 쥔 후보는 빠짐)와 `고른 N개 받기`가 그 제작자의 후보로 작업 하나를 만들고 `작업 보기`로 이어져요. 한 작업은 서버와 같이 200개까지예요.
- **선택**: 후보 ID의 집합이에요. 새 조회가 후보를 더하거나 회차의 가장 나중 관찰을 바꿔도 고른 것은 그대로이고, 고른 이전 관찰은 `이전 관찰`로 그 아래에 남아요. 열린 작업이 쥔 후보는 고를 수 없고, 실패하거나 보류된 작업의 후보는 다시 고를 수 있어요.
- **다시 보내기**: 받기는 요청 ID를 응답(200·202)이나 거절을 받을 때까지 쥐고, 응답이 끊기면 `다시 보내기`가 같은 ID로 보내요. 보내는 동안 버튼이 꺼져 두 번 눌러도 요청은 하나예요.
- **회차 줄**: 자막 파일이 없는 회차에 다른 제작자의 후보가 있으면 `자막 후보 · 카이란`이나 `자막 후보 2명`을 색 없이 적고, 펼친 자리에서 제작자마다 `받기`가 그 후보 하나로 작업을 만들어요. 구독 제작자가 그 회차를 올렸거나 이미 받은 후보는 적지 않아요. 할 일은 만들지 않아요.
- **새로고침**은 0035의 `anissia.captions` 명령을 보내고, 이미 읽는 중이면 그 읽기를 따라가요. 구역은 열린 작업이나 읽기가 있으면 3초, 없으면 60초마다 읽어요.
- Anissia 연결이 없는 시즌에는 `Anissia 연결`(0034의 대화상자)을 둬요.

### 검증한 것

| 완료 기준 | 근거 |
| --- | --- |
| 두 제작자의 후보가 있는 시즌 | 개발 환경의 실제 데이터(작품 Kimi ga Shinu made Koi wo Shitai, Anissia 3223)에서 카이란(13화)·공룡이(8화) 두 줄과 회차 범위·`누락 1`, 회차 줄의 `자막 후보 · 카이란`·`자막 후보 · 공룡이`를 확인했어요. 수정 개수는 브라우저에서 응답을 바꿔 넣어 봤어요. |
| 2·3화만 골라 받기 | 브라우저에서 두 줄을 골라 `고른 2개 받기`: 요청 하나에 고른 두 후보 ID만 담겼고, 작업이 생겨 `작업 보기`로 이어졌어요. 실제 출처 수신은 아직 없어 그 작업은 `자막 대기`(`이 출처에서 받는 방법을 아직 몰라요`)로 기다려요. |
| `모두 받기` | 그 제작자의 누락 회차 후보 전체로 요청 하나가 갔어요. 수정 후보는 `missingOf`에서 빠지고 화면에 `수정 후보는 빼고 담아요`라고 적어요. |
| 두 번 누르기·다시 보내기 | 두 번 눌러도 요청이 하나였어요. 응답을 끊으면 `다시 보내기`가 같은 요청 ID로 보냈고 작업은 하나였어요. 서버 쪽은 0036의 `the_same_browser_id_finds_its_job_and_another_request_with_it_is_refused`예요. |
| 새 조회로 후보가 늘어남 | 선택이 후보 ID 집합이라 새 후보는 고르지 않은 채 나타나요. 고른 회차에 새 관찰이 생긴 경우를 응답을 바꿔 넣어 봤어요: 고른 이전 관찰이 `이전 관찰`로 고른 채 남고, 새 관찰은 고르지 않은 상태였어요. |
| 구독 제작자가 올리지 않은 회차 | 회차 줄 메모와 펼친 자리의 `받기`를 실제 데이터에서 봤어요. 구독 제작자가 그 회차를 올렸으면 메모가 없는 것은 `candidatesOf`를 따로 묶어 확인했어요. 할 일은 만들지 않아요. |
| Anissia 연결이 없는 시즌 | 응답을 바꿔 넣어 `Anissia 연결` 버튼과 안내를 확인했어요. |
| 휴대폰 너비 | 320px·390px에서 구역과 펼친 후보, 회차 줄에 가로 스크롤이 없어요. |

수정 후보 판단은 `a_candidate_revises_the_creators_episode_only_once_its_subtitle_was_received`, `another_creators_post_of_a_received_episode_is_not_a_revision`, API의 `a_fix_of_a_received_post_is_a_revision_and_each_candidate_says_how_its_job_stands`(관찰마다 작업 상태 포함)로 확인해요. 회차 표시 `0`과 `13.5`, 400 거절 메시지도 브라우저에서 응답을 바꿔 넣어 봤어요. 작업 공간 시험이 모두 통과하고 웹 빌드가 돼요.

### 남은 한계

- **회차는 표시 그대로 비교해요.** 앞의 0과 소수점 뒤의 0만 무시해요. 실제 Anissia에서 같은 주에 제작자마다 회차 번호가 달랐어요(애니 3495: 스모모 `12`, C소라 `24`). 2쿨 작품의 통산 번호는 다른 회차로 보여요. 출처별 회차 대응은 뒤 티켓의 일이에요.
- 동영상도 자막도 없는 회차는 회차 목록에 줄이 없어서, 그 회차의 후보는 구역에서만 보여요.
- 구역 끝의 `직접 찾기`(0046)와 `자막 올리기`(0047), 머리에서 구독 제작자를 고르는 동작은 아직 없어요.
- 구독 제작자의 수정 후보를 자동으로 받는 것은 0045예요. 지금은 다른 수정 후보처럼 보여요.
- 열린 작업이 이미 쥔 후보로 작업을 만드는 요청을 서버는 거절하지 않아요. 화면만 그 후보를 고를 수 없게 해요.
- 사용자가 제작자를 정해 준 자막(0048)은 받은 자막 기록이 아니어서 수정 후보 판단에 들어가지 않아요.
