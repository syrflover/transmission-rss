# 0083 실제 서버에서 구독부터 자막 적용까지 이어 봐요

- 상태: 진행 중(구독 제작자의 자막, 고른 후보와 erulabo, 교체 승인, 파일의 바이트를 봤어요. 2화의 구독 흐름이 남았어요)
- 출처: [검증 근거와 완료 판정](../specs/web-app.md#검증-근거와-완료-판정), [보관본과 적용본](../specs/subtitles.md#보관본과-적용본), [방영작 구독](../specs/collection.md#방영작-구독)
- 막는 티켓: [0081](0081-deploy-new-release.md)

## 작업

목표 3·4의 관찰은 개발 환경에서 실제 외부 사이트와 서버 DB 복사본으로 했어요(사용자 결정, 2026-10-04). 명세는 실제 배포 이미지에서도 자막 기능과 화면이 동작하는지 확인하라고 해요.
새 릴리스가 올라간 실제 서버에서 사용자가 쓰는 흐름을 한 번씩 끝까지 이어 봐요. 결과는 웹 화면과 미디어 디스크의 파일로 함께 확인해요.

- 실제 방영작과 실제 제작자를 써요. 새 회차가 나오기를 기다려야 하는 관찰은, 이미 있는 회차로 같은 경로를 탈 수 있으면 그것으로 대신하고 그렇게 했다고 적어요.
- 원격 화면의 인증은 사용자가 휴대폰에서 해요.
- 0081의 배포 첫 주기(2026-10-07)에 구독 제작자(코코렛)의 자막 작업이 `FX Senshi Kurumi-chan` 1화에 돌아, 영상 옆의 적용본과 `.trss/`의 보관본을 1000:1000으로 만들었어요([0081 결과](0081-deploy-new-release.md#자막-작업과-미디어-디스크)). 이것을 "구독 제작자의 자막" 흐름의 관찰로 쓰려면 두 파일의 바이트 비교와 작품 상세의 화면 확인이 남았어요.

## 완료 기준

| 흐름 | 확인할 것 |
| --- | --- |
| 구독에서 첫 수집까지 | 편성에서 구독한 작품의 회차가 Transmission에 들어가고, 받은 영상이 라이브러리의 그 작품·시즌에 나타나요 |
| 구독 제작자의 자막 | 구독 제작자의 자막이 선택 없이 받아져 `.trss/`의 보관본과 영상 옆의 적용본이 돼요 |
| 고른 후보의 자막 | 작품 상세에서 고른 후보가 같은 곳까지 가요 |
| erulabo | 휴대폰의 원격 화면에서 사람이 CAPTCHA만 풀고, 파일이 적용본까지 가요 |
| 교체 승인 | 자막이 있는 회차에 새 자막이 오면 교체 승인에서 멈추고, 승인한 회차만 바뀌어요 |
| 영상 대기 | 영상이 없는 회차의 자막은 영상이 들어온 뒤 다시 받지 않고 적용돼요. 기다릴 회차가 없으면 확인하지 않은 것으로 남겨요 |

- 보관본과 적용본은 1000:1000이고, 영상 옆 적용본의 바이트가 보관본과 같아요.
- 흐름마다 날짜, 작품, 관찰한 화면과 파일이 결과 절에 있어요. 관찰하지 못한 흐름은 까닭과 함께 남은 일에 있어요.

## 결과

### 서버의 상태 (2026-10-07)

LAN의 개발 PC에서 실제 서버의 웹 API를 읽었어요(13:30 UTC 무렵, 읽기만 했어요).

- 구독은 `FX Senshi Kurumi-chan` 하나예요. Anissia 3424(목요일 21:30), subsplease.org, 구독 제작자 코코렛을 따라 받기예요. 구독은 2026-10-02 01:00 UTC에 만들었고, 1화 영상은 01:07 UTC에 라이브러리에 들어왔어요. 둘 다 0.5.0 때예요.
- 라이브러리의 시즌 140개 가운데 Anissia에 연결된 시즌은 이 작품의 시즌 1 하나예요. 그 시즌의 Anissia 제작자는 코코렛 한 명이에요. 그래서 고른 후보, erulabo, 교체 승인 흐름에는 다른 시즌의 Anissia 연결이 먼저 필요해요.

### 구독 제작자의 자막 (2026-10-07)

0081의 배포 첫 주기에 자동 작업(`bb5950bb`, 코코렛, felia.tistory.com, 1화)이 12:00:31 UTC에 생겨 3초 뒤 끝났어요. 사용자가 서버에서 본 작품 폴더예요. 모두 1000:1000이에요.

| 파일 | 크기(바이트) |
| --- | --- |
| `.trss/subtitles/코코렛/[SubsPlease] FX Senshi Kurumi-chan - 01 (1080p) [99D53D33].smi` | 35186 |
| `Season 01/FX Senshi Kurumi-chan S01E01.smi` | 35186 |

- 작품 상세(개발 PC의 브라우저, 13:35 UTC 무렵)에서 1화 줄은 영상 `보유`, 자막 `보유`였어요. `자막` 카드는 `제작자 1명 · 자막 1개`였고, 코코렛의 보관본이 그 적용본에 적용된 것으로 나왔어요.
- 결함: 머리의 자막 제작자가 `코코렛, 제작자 알 수 없음`이에요. 적용 단계가 영상 옆 파일에 제작자(`media_files.creator_source_id`)를 붙이지 않아서, 머리(`headNames`)가 trss가 적용한 이 파일을 제작자 모르는 파일로 세요. [머리와 시즌](../specs/library.md#머리와-시즌)은 직접 넣은 파일처럼 제작자를 모를 때만 `제작자 알 수 없음`을 보여 달라고 해요. 적용본의 제작자를 보관본에서 읽도록 [0118](0118-applied-copy-creator.md)에서 고쳐요(사용자 결정, 2026-10-07).
- 두 파일의 SHA-256이 같아요(아래 "파일의 바이트").

### 고른 후보와 erulabo (2026-10-07)

사용자가 `All Works Maid` 시즌 1을 Anissia 3492에 연결하고, 에루샤의 12화 후보(erulabo.com)를 골라 받았어요. 휴대폰으로 했고, 받은 것은 게시물의 1–12화 묶음이에요. 아래 시각은 웹 API에서 읽었어요(UTC).

| 시각 | 일 |
| --- | --- |
| 13:34:01 | 고른 후보 작업 `f2403635`(`pick`, 에루샤, erulabo.com, 12화)이 생겼어요. |
| 13:35:54 | 1–12화의 `.ko.ass` 12개가 `.trss/subtitles/에루샤/`에 보관됐고, 12화는 확인 없이 `Season 01/All Works Maid S01E12.ass`로 적용됐어요. |
| 13:36:11–13:36:17 | 사용자가 9–11화의 보관본을 회차 줄에서 적용했어요. 그 회차들에는 자막이 없었어요. |
| 13:36:17 | 작업이 `done`이 됐어요. |

- 1–8화의 보관본은 적용되지 않고 `교체 비교`로 남았어요. 그 회차에는 관리하지 않던 자막이 있었어요. 고르지 않은 회차는 보관만 한다는 목표 4의 결정대로예요.
- 적용 직후 화면이 바로 바뀌지 않았어요. [0119](0119-refresh-after-stored-apply.md)로 남겼어요.
- 받은 직후 머리의 자막 제작자가 `제작자 알 수 없음`이었어요. 1–8화의 관리하지 않던 자막과 함께 9–12화의 적용본도 제작자 모르는 파일로 세어졌어요([0118](0118-applied-copy-creator.md)). 사용자가 `제작자 지정`으로 에루샤를 붙인 뒤 머리는 `에루샤`예요.
- 작품 상세의 `자막` 카드는 `제작자 1명 · 자막 12개`, `파일` 카드는 `정리할 수 있는 파일 8개`예요(13:45 UTC 무렵, 개발 PC의 브라우저).
- erulabo의 확인은 Cloudflare Turnstile이었고, 13:34:04에 원격 화면에 떴어요. 사용자가 LAN에서 iPhone의 iOS 27 Safari로 풀었고, 13:35:52에 서버 브라우저가 ZIP을 받았어요. 터치, 확대, 회전은 [0085](0085-phone-and-tablet-flows.md)에 적었어요.
- ZIP 안의 파일 24개 가운데 `__MACOSX/`의 `._*.ko.ass` 12개는 "이름은 ASS 파일인데 받은 바이트는 ASS 형식이 아니에요"로 보관하지 않았어요. macOS가 만든 부속 파일이라 맞는 결과예요.
- 1화의 `교체 비교`를 하려고 1화 줄을 펼쳤는데 보관본이 없었어요. 명세와 달리 웹이 자막이 있는 회차의 줄에서 보관본을 숨겨요([0120](0120-stored-copy-on-subtitled-row.md)). 같은 버튼은 `자막` 카드에 있어요.

### 파일의 바이트 (2026-10-07)

사용자가 서버의 수집 폴더에서 두 작품의 보관본과 영상 옆 자막을 `sha256sum`으로 읽었어요. All Works Maid의 1–8화 자막은 trss가 들이기 전부터 있던 파일이에요.

| 파일 | 결과 |
| --- | --- |
| Kurumi-chan 1화의 보관본과 적용본 | 같아요. |
| All Works Maid 9–12화의 보관본과 적용본 | 회차마다 같아요. |
| All Works Maid 2·3·4·5·8화의 에루샤 보관본과 원래 자막 | 회차마다 같아요. 원래 자막도 에루샤의 지금 게시물과 같은 파일이에요. |
| All Works Maid 1·6·7화의 에루샤 보관본과 원래 자막 | 회차마다 달라요. 원래 자막이 에루샤의 예전 판인지 다른 출처인지는 파일로 가르지 못해요. |

### 교체 승인 (2026-10-07)

사용자가 `자막` 카드에서 에루샤 보관본의 `교체 비교`를 눌렀어요. 아래 시각은 작업 `f2403635`의 기록을 웹 API에서 읽은 거예요(UTC).

| 시각 | 일 |
| --- | --- |
| 13:52:02 | 1화: 회차에 자막이 있어 작업이 교체 승인을 기다렸어요. |
| 13:52:30 | 1화: 사용자가 승인했어요. 원래 자막을 `.trss/subtitles/제작자 알 수 없음/All Works Maid S01E01.ass`로 들인 뒤 새 자막으로 교체했어요. |
| 13:53:41, 13:54:06 | 2화: 두 번 모두 "이 회차에 같은 자막이 이미 있어 그대로 두고 보관만 했어요"로 끝났어요. 2화의 원래 자막은 에루샤 보관본과 바이트가 같아요(위 "파일의 바이트"). |

- 1화는 명세대로예요. 사용자가 원래 자막에 에루샤를 붙였지만, 들인 보관본의 제작자는 `제작자 알 수 없음`이에요.
- 결함: 들인 1화 보관본을 `자막` 카드에서 다시 고를 수 없어요. "이 보관본을 받은 작업의 기록이 없어 적용할 수 없어요"가 나와요([0122](0122-imported-copy-choosable.md)).
- 결함: 2화는 고른 뒤 새로고침해도 `교체 비교`가 남아요. 작업 화면의 적용 단계는 1화 때의 설명 "기존 자막을 새 자막으로 교체했어요"를 보여줘서, 사용자에게는 적용된 것처럼 보였어요([0121](0121-identical-copy-becomes-applied.md)).

### 남은 일

- 구독에서 첫 수집까지: 2화(2026-10-08 목요일 방영)가 0.6.0에서 Transmission과 라이브러리에 들어오는지 봐요. 같은 회차로 구독 제작자의 자막도 한 번 더 봐요.
- 고른 후보, erulabo, 교체 승인은 `All Works Maid` 시즌 1을 Anissia 3492에 연결해서 위에서 봤어요(사용자 결정, 2026-10-07).
- 영상 대기: 기다릴 회차가 생기지 않으면 확인하지 않은 것으로 남겨요.
