# 0053 서버 브라우저가 LAN에 닿지 못하게 하고, 웹이 다른 출처의 요청을 거절해요

- 상태: 대기
- 출처: [작업 화면 안의 인증과 브라우저 수명](../specs/jobs.md#작업-화면-안의-인증과-브라우저-수명), [접근 경계와 기기](../specs/web-app.md#접근-경계와-기기), [0039의 한계](0039-browser-container-lifecycle.md#한계)
- 막는 티켓: 없음

## 배경

서버 브라우저는 사용자가 고른 외부 게시물과 그 페이지의 스크립트를 LAN 안의 서버에서 실행해요. 0039는 브라우저를 `trss_net`에서 떼어 `browser_net`에 뒀지만, `browser_net`은 bridge라서 호스트의 LAN 주소에 게시된 포트에 닿아요(0039의 한계).

2026-10-03에 개발 환경에서 확인했어요. `browser_net`에 붙인 컨테이너에서 호스트 LAN 주소(`192.168.1.116:9091`)와 Docker 게이트웨이의 Transmission이 `200`으로 답했어요. 같은 경로로 `trss_net`의 컨테이너에 연결하면 받는 쪽에는 출발 주소가 `trss_net` 게이트웨이(`172.19.0.1`)로 보였어요. 그래서 받는 쪽이 출발 주소로 `browser_net`을 가려낼 수 없어요. 운영에서는 trss-web이 LAN 주소 `:8080`에, Transmission이 `9091`에 게시돼 있어요.

trss-web은 로그인이 없고 Host·Origin을 검사하지 않아요. 다른 출처의 페이지는 응답을 읽지 못하고 JSON 본문 요청도 쉽게 보내지 못하지만, 공격자 도메인을 LAN 주소로 풀리게 하는 DNS 재바인딩이면 웹 API를 모두 쓸 수 있어요. 이 경로는 서버 브라우저뿐 아니라 사용자의 PC·휴대폰 브라우저로도 열려요.

## 작업

두 겹으로 막고, 다음 릴리스 전에 끝내요(사용자 결정, 2026-10-03). 0040보다 먼저 해요.

- **브라우저의 송신 제한**: 서버 브라우저의 모든 연결이 실행기(`trss-browserd`) 안의 프록시를 거쳐요. 프록시는 이름을 풀어 본 뒤 그 주소로 연결하고, 사설·루프백·링크 로컬·CGNAT(Tailscale 포함)·멀티캐스트·예약 주소(IPv4·IPv6, IPv4 대응 IPv6 포함)로 가는 연결을 거절해요. 풀린 주소로 판정하므로 DNS 재바인딩도 막혀요. Chromium이 루프백을 프록시 없이 보내는 기본 예외를 없애고, 프록시 밖 UDP(WebRTC)를 쓰지 않게 해요. 거절은 연결 단위의 오류이고, 거절한 목적지 주소나 URL은 로그에 남기지 않아요.
- **웹의 출처 검사**: trss-web은 Host가 허용 목록에 없는 요청을 모두 거절해요. IP 주소와 `localhost`는 설정 없이 허용하고, 이름은 `.env`의 허용 목록에 적은 것만 받아요. 사용자는 지금 LAN IP:포트로 들어가요. 상태를 바꾸는 요청과 WebSocket 연결은 Origin이 있으면 요청 자신의 출처와 같아야 하고, `null`은 거절해요. WebSocket은 Origin이 반드시 있어야 해요.
- 호스트 방화벽 규칙은 앱이 확인할 수 없어서 필수로 두지 않고, 배포 설명에 덧붙이는 선택 방어로 적어요.
- 0040에서 정한 'browser_net에서 온 연결 거절'은 그대로 둬요. 이 티켓은 호스트 LAN 주소를 거치는 경로를 막아요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 실제 서버 브라우저 이미지에서 호스트 LAN 주소, Docker 게이트웨이, 루프백(실행기 포트 포함), 사설 주소로 풀리는 이름으로 이동·`fetch`·WebSocket | 모두 연결되지 않아요. |
| 같은 실행에서 공개 HTTPS 사이트를 엶 | 열려요. 실제 Tistory 게시물의 WinPNG 읽기(0043)가 그대로 돼요. |
| 이름이 처음엔 공개 주소, 다음엔 사설 주소로 풀림 | 사설 주소로 풀린 연결은 거절돼요. |
| 허용 목록에 없는 Host로 웹에 요청(API·화면) | 거절돼요. IP 주소와 `localhost`는 받아요. |
| 다른 Origin·`null` Origin의 상태 변경 요청과 WebSocket | 거절돼요. 같은 출처의 웹 화면은 그대로 동작해요. |
| 개발 환경 전체 흐름 | 웹 화면을 `localhost:8080`으로 쓸 수 있고, 개발 환경의 가짜 출처와 WinPNG 작업이 그대로 돼요. |
