# 0147 명령과 자막 작업을 적은 곳에서 바로 실행을 시작해요

- 상태: 대기
- 출처: [구조 가볍게 하기 명세의 명령](lighter-structure.md#명령), [한 프로세스와 이름](lighter-structure.md#한-프로세스와-이름)의 쓰기 확인 목록과 API 처리기, [한 프로세스 ADR](../adr/0019-one-process-for-web-and-worker.md)
- 막는 티켓: [0146](0146-one-trss-process-and-container.md)(한 프로세스)

## 작업

[0146](0146-one-trss-process-and-container.md) 뒤에도 web 쪽은 명령을 적은 뒤 깨우기 소켓으로 같은 프로세스의 worker 쪽을 깨우고, worker 쪽은 3초마다 찾아보며 worker 잠금 아래에서 명령을 집어요. 이 티켓은 이 전달을 없애고, 적은 곳에서 같은 프로세스의 실행을 바로 시작해요. 명령은 지금처럼 `commands` 테이블에 기록으로 남아요(사용자 결정, 2026-10-21).

web이 worker를 깨우는 곳은 명령만이 아니에요. 2026-10-21에 깨우기(`wake_worker`)를 보내는 곳은 15곳이었어요. 명령 접수, 규칙의 수집 폴더와 회차 대응의 저장, 자막 작업을 만들거나 진행시키는 동작(배치, 교체, 올리기, 끝내기 등), 보관본의 적용과 정리, 원격 화면의 준비가 보내요. 이 곳들이 모두 실행을 바로 시작해요.

- 명령 안에서 다시 시도하는 대기와 횟수는 지금과 같아요. 기능 안의 규칙을 그대로 두기로 한 결정을 따른 거예요.
- 대상이 겹치는 명령의 차례 규칙과 토렌트를 함께 건드리는 일의 차례는 그대로예요.
- worker 잠금과 하트비트는 이 티켓 뒤에도 남고, [0148](0148-one-instance-lock-and-cycle-stall.md)이 없애요. 실행이 그 잠금을 함께 잡는 방식은 지금 그대로 써도 돼요.

## 완료 기준

- [ ] API는 명령을 `commands` 테이블에 적은 뒤 같은 프로세스에서 곧바로 실행을 시작하고, 끝나기를 기다리지 않고 적은 명령으로 응답해요. 실행 중인 수집 주기가 있어도 명령이 그 주기가 끝나기를 기다리지 않는 것을 프로세스 테스트가 확인해요.
- [ ] 대상이 겹치는 명령만 [웹 명령과 상태 갱신](../specs/web-app.md#웹-명령과-상태-갱신)의 차례 규칙대로 기다리고, 관계없는 명령은 기다리지 않아요.
- [ ] 명령 말고 깨우기를 보내던 곳도 모두 같은 프로세스의 실행을 바로 시작해요. 결과에 그 곳들과 각각 시작하는 실행을 적어요.
- [ ] 같은 ID와 같은 내용으로 다시 보낸 명령은 적은 명령을 돌려주고, 같은 ID에 다른 내용이면 409로 거절해요. 같은 종류와 대상으로 열린 명령은 하나뿐이에요.
- [ ] 명령 안에서 다시 시도하는 경우(Transmission이 새 폴더를 늦게 보고할 때, 토렌트 추가에 응답이 없을 때, DB 오류)의 대기와 횟수가 지금과 같아요. 실행을 시작할 때마다 시도 횟수가 하나 늘고, 다섯 번째 시작에서 이유와 함께 끝나요.
- [ ] 다음 확인을 기다리던 경우는 실행 안에서 기다려요. 결과에 그런 경우를 모두 적어요.
- [ ] 동시에 실행하는 명령은 8개까지예요.
- [ ] 프로세스가 다시 시작하면 끝나지 않은 명령을 다시 실행하고, 이것도 시도 한 번으로 세요. 열린 명령이 남은 DB로 시작하는 테스트가 업그레이드 직전에 남은 명령도 같은 길로 실행되는 것을 확인해요.
- [ ] 프로세스가 다시 시작하면, 사람을 기다리지 않고 실행 차례를 기다리던 자막 작업도 지금처럼 다시 시작해요.
- [ ] 깨우기 소켓, 3초 주기 조회, worker 잠금 아래의 claim이 코드에서 없어지고, 시작 처리가 남은 소켓 파일을 지워요.
- [ ] 시작할 때 쓸 수 있는지 확인하는 목록에서 깨우기 소켓이 빠지고, 나머지 확인은 그대로예요.
- [ ] 명령의 지난 결과를 읽는 곳은 그대로 `commands` 테이블을 읽어요. 규칙의 마지막 폴더 이동과 폴더 편집 막기, 회차 되돌리기, Anissia 새로고침의 결과, 수집 주기가 세는 응답 없던 토렌트 추가예요.
- [ ] 보관 파일 정리는 요청하면 곧바로 실행해요. 프로세스가 다시 시작하면 `asked`인 정리를 다시 실행하고, 파일마다 길이와 SHA-256을 확인하는 지금 규칙은 그대로예요.
- [ ] API 처리기는 미디어 파일을 직접 바꾸지 않아요. 파일을 바꾸는 일은 명령, 자막 작업, 보관 파일 정리의 실행 경로에서만 하고, 그 경로가 쓰기 직전에 계획·승인·현재 파일을 확인하는 지금 규칙은 그대로예요. 결과에 확인한 방법을 적어요.
