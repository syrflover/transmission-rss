# 자막 보관본과 영상 옆 적용본을 분리해요

여러 제작자·형식·수정본을 모두 영상 옆에 두면 재생기가 어느 파일을 선택할지 일관되게 제어하기 어려워요.
파일명의 `.default` 표식에 의존하는 대신, 작품 폴더 안의 `.trss-subtitles/` 한 곳에 보관하고 선택한 파일만 영상 옆에 같은 파일명 줄기로 적용하기로 했어요.
[보관본과 적용본](../glossary.md)은 구분하며, 웹에서 보관본을 비교하고 적용 파일을 교체할 수 있게 해요.
적용본은 보관본에서 독립된 파일로 복사해 만들며, 보관본을 이동하거나 하드 링크·심볼릭 링크로 연결하지 않아요.
적용본을 수정·교체·삭제해도 보관본은 유지되며, 이전 수정본 복원도 해당 보관본을 다시 복사해 적용하는 방식이에요.

영상 폴더 밖의 앱 전용 보관 루트는 재생기 검색과 분리하기 쉽지만, 작품을 옮기거나 백업할 때 보관본도 따로 챙겨야 해요.
작품과 보관본을 한곳에 두는 숨김 폴더 방식을 선택했어요.
[IINA v1.4.4의 기본 하위 폴더 검색](https://github.com/iina/iina/blob/v1.4.4/iina/AutoFileMatcher.swift)은 숨김 항목을 제외하지만, 명시적인 검색 경로 설정과 다른 재생기의 동작까지 보장하는 것은 아니에요.
점으로 시작하는 폴더명은 접근 권한 보호를 대체하지 않으며, Infuse·팟플레이어와 실제 공유 경로의 검색 제외는 검증이 남아 있어요.

처음에는 선택한 제작자·회차·언어·용도에서 우선 형식 하나만 적용해요.
전역 우선순위는 ASS → SRT → SMI이며 작품별로 변경할 수 있어요.
사용자가 원하면 같은 제작자의 다른 형식도 추가 적용할 수 있지만, 복수 적용 상태에서 재생기의 실제 선택 순서까지 이 우선순위로 제어한다고 표시하지 않아요.
다른 제작자의 자막과 선택하지 않은 형식은 보관 영역에서 웹으로 선택할 수 있어요.

추가 적용은 기존 적용본을 자동 제거하지 않아요.
교체는 이전 적용 묶음과 새 적용 묶음의 차이를 보여주며, 제작자나 형식이 바뀌어 이전 적용 파일을 영상 폴더에서 제거해야 한다면 그 경로도 승인 대상에 포함해요.
이는 보관본 삭제가 아니며, 관계없는 파일을 이름만 추측해서 정리하지 않아요.
기존 파일과 새 파일의 비교 및 승인 유효성은 [구현 명세의 교체 비교와 승인](../specs/web-gui-subtitles.md#교체-비교와-승인)을 따라요.

이전 수정본과 관련 자산은 사용자가 정리하기 전까지 보관해 다시 적용할 수 있게 해요.
작품의 보관 영역에서 내용이 같은 폰트는 한 번만 저장하고 여러 자막 버전이 함께 참조해요.
파일명이 같아도 내용이 다르면 다른 자산이며, 한 버전을 정리할 때 다른 보관본이 참조하는 폰트까지 삭제하지 않아요.

폰트 중복 저장 방지와 네트워크 재다운로드 방지는 별개예요.
출처가 파일별 수신과 검증 가능한 변경 정보를 제공하면 기존 폰트를 재사용하고 추가·변경된 파일만 받아요.
파일명만으로 변경 없음을 판단하지 않아요.
통째 묶음으로만 수신할 수 있는 출처는 예외로 전체 다운로드를 허용하고, 받은 뒤 내용이 같은 폰트는 기존 자산을 재사용해 중복 보관하지 않아요.
전체 묶음을 수신했다는 사실과 실제로 새로 추가된 자산을 구분해서 보여주며, 이 예외를 불필요한 개별 파일 재다운로드로 확대하지 않아요.

이 기록은 선택한 방향이며 아직 구현된 동작은 아니에요.
폰트를 보관하는 것과 실제 재생기에 적용하는 것은 별도로 검증해야 하며, 서버 전역 폰트 설치나 원본 영상 재먹스는 포함하지 않아요.
