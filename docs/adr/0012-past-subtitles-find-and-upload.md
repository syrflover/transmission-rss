# 연결 전에 올라온 자막은 직접 찾기와 올리기로 받아요

[자막 명세](../specs/subtitles.md#자막-후보-조회)는 작품의 누락 회차마다 자막 후보가 있다고 전제했어요.
2026-10-02에 확인한 Anissia 자막 정보(`/anime/caption/animeNo/<n>`, `/anime/caption/recent/<page>`)는 작품마다 제작자 한 명당 한 줄이며, 그 줄은 제작자가 마지막으로 올린 회차 표시·게시물 주소·갱신일이에요.
게시물 하나에 전 회차를 모아 두고 고쳐 가는 제작자(Blogger의 회차 ZIP)도 있고, 회차마다 새 게시물을 쓰는 제작자(erulabo·Tistory)도 있어요.
그래서 Anissia만으로는 연결하기 전에 지나간 회차의 게시물을 알 수 없어요.

자막 후보는 trss가 관찰한 제작자·회차 표시·게시물·갱신일로 정하고, 줄이 바뀔 때마다 새 관찰을 쌓아 회차별 후보 기록을 만들기로 했어요(사용자 결정, 2026-10-02).
관찰은 30분마다 Anissia의 최근 자막 목록 전체를 읽어 모든 작품의 바뀐 줄을 남기는 방식이에요.
분기 작품마다 방영 시각에 맞춰 30분·2시간·6시간으로 작품별 자막 정보를 조회하고 새 자막을 보면 다음 방영까지 멈추는 안도 있었지만, 최근 자막 목록은 한 번에 모든 작품의 변화를 주므로 요청이 훨씬 적고 작품마다 방영 시각과 멈춤 상태를 관리하지 않아도 돼요.
대신 30분 안에 같은 줄이 두 번 바뀌면 중간 상태를 놓쳐요.
연결 전에 지나간 회차는 두 경로로 받아요.

- 직접 찾기: 작품 상세에서 제작자 게시물을 서버 브라우저로 열고, 사용자가 원격 화면에서 지난 게시물로 옮겨 다운로드를 누르면 같은 서버 브라우저가 파일을 받아요.
- 올리기: 사용자가 가진 자막·폰트를 낱개·여러 개·압축 파일·폴더로 올려요. 자막과 폰트만 받고, 그 밖의 파일은 빼고 무엇을 뺐는지 알려요.

어느 경로로 받은 파일이든 [출처별 다운로드](../specs/subtitles.md#출처별-다운로드)로 받은 자막 묶음과 같은 분석·보관·적용·교체 승인을 거쳐요.

관찰만 쌓는 안은 회차마다 게시물을 쓰는 제작자의 지난 회차를 받을 수 없어요.
출처마다 제작자 블로그의 게시물 목록을 읽는 안은 가장 자동에 가깝지만, 출처마다 목록 해석 코드를 두고 블로그 구조가 바뀔 때마다 고쳐야 해요.
대신 지난 회차에는 사람의 탐색이나 올리기가 한 번 필요해요.

직접 찾기와 올리기는 사람이 고른 파일을 들이는 별도 입력 경로예요.
출처별 다운로드에서 서버가 게시물을 열고 정상 다운로드를 시작해야 한다는 요구를 대신하지 않으며, 자동 수신의 검증을 이 경로의 성공으로 채우지 않아요.

Anissia 줄을 관찰로 쌓는 부분은 [0035](../tickets/0035-candidate-observation.md)에서(2026-10-02), 자막 올리기는 [0047](../tickets/0047-subtitle-upload.md)에서(2026-10-03), 직접 찾기는 [0046](../tickets/0046-find-in-browser.md)에서(2026-10-04) 구현했어요.
직접 찾기를 실제 제작자 블로그에서 확인하는 일은 0046에 남아 있어요.
현재 요구는 [자막 명세](../specs/subtitles.md#직접-찾기와-자막-올리기)에 있어요.
