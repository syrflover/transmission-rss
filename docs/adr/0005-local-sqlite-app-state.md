# 앱 상태는 로컬 SQLite에 저장해요

앱이 소유하는 설정·작품 연결·회차 대응·작업·승인·보관 이력은 SQLite에 저장하기로 했어요.
DB는 앱 호스트의 로컬 영속 볼륨에 두며, 영상·자막·폰트 바이트는 기존에 선택한 파일 보관 영역에 남겨요.
컨테이너의 임시 쓰기 영역이나 실행별 Chromium 프로필을 DB 저장소로 사용하지 않아요.
보관본의 관계를 복원하기 위한 별도 목록 파일은 작품 폴더에 상시 유지하지 않아요.

기존 PostgreSQL 운영 체계를 활용하는 대안보다, 별도 DB 서버 없이 한 사용자 환경의 운영을 단순하게 유지하는 방향을 선택했어요.
SQLite WAL은 읽기와 쓰기를 병행할 수 있지만 쓰기는 한 번에 하나이고, [공식 문서](https://www.sqlite.org/wal.html)에 따라 네트워크 파일시스템에는 DB를 두지 않아요.
미디어를 SMB·NFS로 공유한다는 사실이 앱 DB도 그 공유 경로에 둔다는 뜻은 아니에요.

[별도 웹·worker 바이너리](0006-separate-web-worker-binaries.md)가 같은 호스트의 로컬 SQLite를 공유해요.
접속·트랜잭션·마이그레이션의 세부 구현과 재시작 복구 방식은 정한 실행 구성에 맞춰 구체화해요.
[YAML 가져오기·내보내기](0001-app-managed-download-rules.md)는 설정과 보관 정보의 교환 계약이며, 작업 이력이나 실제 파일을 포함한 전체 백업을 대신하지 않아요.
현재 요구와 완료 조건은 [웹 앱 공통 명세](../specs/web-app.md#구현-경계와-실행-순서)에 있으며, 아직 구현된 동작은 아니에요.
