# 웹도 서버 브라우저 네트워크에 들어가고, 브라우저 쪽 연결은 받지 않아요

원격 인증 화면(0040)에서 웹은 서버 브라우저 실행의 CDP에 닿아 화면을 받고 입력을 넘겨야 해요. [서버 브라우저 ADR](0002-server-browser-subtitle-authentication.md)은 브라우저를 worker와만 나누는 네트워크(`browser_net`)에 뒀어요.
2026-10-03에 trss-web도 `browser_net`에 넣어 실행기의 토큰 보호 CDP 중계에 직접 닿게 했어요(사용자 결정). worker가 화면을 중계하는 길은 worker에 HTTP 서버와 두 번의 프레임 중계가 생겨서 고르지 않았어요. 실행의 시작·종료는 계속 worker만 해요.

로그인이 없는 웹이 브라우저와 같은 네트워크에 있게 되므로, 웹은 `browser_net` 쪽에서 들어온 연결을 HTTP를 읽기 전에 모두 끊어요. 게시 포트의 연결이 `browser_net`을 거쳐 들어오는 배치(웹의 `trss_net`에 `gw_priority`가 없음)에서는 모든 사용자가 거절되므로 웹이 시작하지 않아요.
이 거절은 브라우저가 호스트 LAN 주소로 게시된 포트를 거쳐 오는 연결을 가려내지 못해요(받는 쪽에는 `trss_net` 게이트웨이로 보여요). 그 길은 브라우저의 모든 연결이 실행기의 송신 프록시를 거쳐 공개 주소에만 닿게 하고, 웹이 Host·Origin을 검사해서 막아요(0053).

규칙과 확인 결과는 [작업과 인증 명세](../specs/jobs.md#작업-화면-안의-인증과-브라우저-수명)와 [접근 경계와 기기](../specs/web-app.md#접근-경계와-기기)에 있어요.
