# 다운로드 규칙을 앱에서 관리해요

현재 trss는 `CHANNELS_CONFIG_URL`이 가리키는 외부 YAML을 실행마다 읽어요.
웹 GUI에서 작품과 다운로드 규칙을 편집·저장해 바로 사용하는 경험을 위해, 앞으로 실행의 기준은 앱이 관리하는 설정으로 전환하기로 했어요.
기존 YAML 가져오기와 설정 내보내기를 제공해 기존 설정을 옮기고 파일로 보관할 수 있게 해요.

외부 YAML을 계속 기준으로 두고 웹에서는 편집본만 내보내는 대안은 파일·Git 중심 관리 흐름을 유지하지만, 웹 편집 후 외부 파일에 별도로 반영해야 해요.
이 추가 단계를 없애는 앱 중심 관리 방식을 선택했으므로, 외부 YAML 변경을 계속 자동 반영하는 기존 동작은 유지하지 않아요.

기존 YAML과 새 앱 설정 YAML 모두 가져오기 미리보기에서 현재 설정과 비교하고, 사용자가 선택한 항목만 추가하거나 지정한 기존 항목을 교체해요.
선택하지 않은 항목과 파일에 없는 기존 설정은 남기며, 작업 이력이나 실제 영상·자막 파일을 삭제하지 않아요.

기존 YAML은 RSS 채널·규칙 설정에만 적용하고, 채널 단위로 추가·교체하므로 자막 연결 설정은 건드리지 않아요.
가져오는 채널 안의 규칙은 파일 순서를 유지하며 임의로 병합하지 않아요.
현재 설정에는 안정적인 채널·규칙 ID가 없고 먼저 일치한 규칙이 적용되므로, 이름이나 유사한 조건을 추측해 합치면 실행 결과가 달라질 수 있어요.

내보내기는 새 앱 설정 YAML만 제공하고, 구버전 trss용 채널·규칙 YAML 내보내기는 제공하지 않아요.
앱 설정에는 채널·규칙, 감시 폴더, 작품 연결, 회차 대응과 자막 정책을 포함해요.
작업 이력과 받은 파일 전체의 백업은 이 내보내기에 포함하지 않아요.
기존 형식에는 새 자막 설정을 담을 수 없으므로, 구버전 실행 호환보다 새 앱 설정 보존을 선택했어요.

이 기록은 선택한 방향이며 아직 구현된 동작은 아니에요.
앱 내부 저장소는 [로컬 SQLite](0005-local-sqlite-app-state.md)로 정했으며, 새 YAML의 구체적인 스키마는 이후 구현 설계에서 정해요.
현재 요구와 완료 조건은 [구현 명세](../specs/web-gui-subtitles.md#앱-설정과-다운로드-규칙)에 있고, 선택 배경과 조사 근거는 [주제 문서](../brainstorm/web-gui-subtitles.md)에 있어요.
