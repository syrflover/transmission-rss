# 앱 설정과 보관 정보를 관리하고 교환해요

현재 trss는 `CHANNELS_CONFIG_URL`이 가리키는 외부 YAML을 실행마다 읽어요.
웹 GUI에서 작품과 다운로드 규칙을 편집·저장해 바로 사용하는 경험을 위해, 앞으로 실행의 기준은 앱이 관리하는 설정으로 전환하기로 했어요.
기존 YAML 가져오기와 새 앱 YAML 가져오기·내보내기를 제공해 설정과 자막 보관 정보를 옮길 수 있게 해요.

외부 YAML을 계속 기준으로 두고 웹에서는 편집본만 내보내는 대안은 파일·Git 중심 관리 흐름을 유지하지만, 웹 편집 후 외부 파일에 별도로 반영해야 해요.
이 추가 단계를 없애는 앱 중심 관리 방식을 선택했으므로, 외부 YAML 변경을 계속 자동 반영하는 기존 동작은 유지하지 않아요.

기존 YAML과 새 앱 YAML 모두 가져오기 미리보기에서 현재 정보와 비교하고, 사용자가 선택한 항목만 추가하거나 지정한 기존 항목을 교체해요.
선택하지 않은 항목과 파일에 없는 기존 설정은 남기며, 작업 이력이나 실제 영상·자막 파일을 삭제하지 않아요.

기존 YAML은 RSS 채널·규칙 설정에만 적용하고, 채널 단위로 추가·교체하므로 자막 연결 설정은 건드리지 않아요.
가져오는 채널 안의 규칙은 파일 순서를 유지하며 임의로 병합하지 않아요.
현재 설정에는 안정적인 채널·규칙 ID가 없고 먼저 일치한 규칙이 적용되므로, 이름이나 유사한 조건을 추측해 합치면 실행 결과가 달라질 수 있어요.

새 앱 형식은 기존 YAML 구조에 묶이지 않고 구성하며, 채널 안의 규칙별 선택 가져오기도 지원해요.
선택하지 않은 규칙은 유지하고, 추가·교체할 규칙과 최종 평가 순서를 미리보기에서 확인해요.
버전과 안정적인 항목 ID를 사용하고, 이름 유사성으로 항목을 합치지 않아요.

내보내기는 채널·규칙, 감시 폴더, 작품 연결, 회차 대응과 자막 정책에 더해 보관본의 제작자·출처·회차·수정본·자산·폰트 연결 정보까지 포함하는 새 앱 YAML이에요.
설정만 내보내는 안보다, 실제 파일을 옮긴 뒤 보관 목록과 관계까지 복원할 수 있는 정보 교환을 선택했어요.
다운로드 시도·실패 등 작업 이력, 작업 큐, 과거 승인, 영상·자막·폰트 바이트는 포함하지 않아요.
구버전 trss용 YAML 내보내기와 전체 DB·파일 백업도 제공 범위가 아니에요.
앱의 채널·작품·자막·브라우저 정책과 배포 환경별 설정을 분리해요.
Transmission 접속 주소·기존 속도 제한·큐 크기, 서버 포트와 DB 위치는 환경 변수·배포 설정에 남기고 새 YAML에 포함하지 않아요.
연결 설정까지 함께 옮기는 대안보다 새 환경에서 배포값을 따로 설정하는 방식을 선택해, 가져온 정보가 이전 Transmission을 의도치 않게 가리키는 위험을 줄여요.

보관 정보의 기준은 SQLite이며 작품 폴더에 별도의 복원용 목록을 상시 저장하지 않아요.
파일은 `.trss-subtitles/`를 포함한 작품 폴더로 따로 옮기고, 가져오기에서 새 위치와 실제 파일을 대조해요.
보관 정보 복원만으로 자막을 새로 다운로드·적용하거나 이전 승인 권한을 복원하지 않아요.

이 기록은 선택한 방향이며 아직 구현된 동작은 아니에요.
앱 내부 저장소는 [로컬 SQLite](0005-local-sqlite-app-state.md)로 정했으며, 새 YAML의 교환 계약은 아래 명세에서 다뤄요.
현재 요구와 완료 조건은 [구현 명세](../specs/web-gui-subtitles.md#앱-설정과-다운로드-규칙)에 있고, 선택 배경과 조사 근거는 [주제 문서](../brainstorm/web-gui-subtitles.md)에 있어요.
