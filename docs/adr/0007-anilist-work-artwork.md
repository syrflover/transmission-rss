# 작품 표지의 초기 제공자로 AniList를 사용해요

애니메이션 중심의 개인용 trss에서 작품 표지를 검색하고 자동 지정하기 위해 AniList를 초기 제공자로 선택했어요.
[공개 작품 조회에는 인증이 필요하지 않아](https://docs.anilist.co/guide/auth/) API 키 발급·관리 없이 연동할 수 있으며, 사용자는 검색 결과를 다시 고르거나 이미지 파일을 직접 업로드할 수 있어요.
처음부터 여러 제공자를 통합하지 않아요.

TMDB의 번역·별칭 검색도 대안이지만, 현재 범위에서 키 설정·출처 표시·6개월 캐시 관리를 추가할 만큼의 이점을 확인하지 못했어요.
TheTVDB의 프로젝트 키·라이선스 또는 구독 조건도 첫 표지 연동에 추가하지 않아요.
이는 설치·운영 단순성을 우선한 선택이며, 실제 한국어 애니메이션 검색 정확도를 비교한 결과는 아니에요.
제공자별 근거와 조건은 [주제 문서의 비교](../brainstorm/web-gui-subtitles.md#표지-제공자-비교)에 남겨요.

표지는 작품을 구분하기 위한 표시 정보이고, Anissia 연결이나 영상·자막의 회차 대응을 결정하는 근거가 아니에요.
명확한 후보만 자동 지정하고 모호하면 비워두며, 수동 선택·업로드·명시적인 비우기를 이후 자동 검색 결과로 덮어쓰지 않아요.
직접 지정은 파일 업로드로 한정하고 임의 이미지 URL 입력은 두지 않으며, 이미지 바이트는 각 작품 폴더의 `.trss-artwork/`에 앱이 관리하는 경로로 둬요.
선택 상태와 검증할 이미지 관계는 DB와 YAML의 설정·보관 정보로 유지하고, 별도 작품별 사이드카 목록이나 YAML에 이미지 바이트를 담지 않아요.
구체적인 판정·파일 수명·가져오기와 화면 완료 조건은 [구현 명세](../specs/web-gui-subtitles.md#작품-표지의-선택과-교환-필드)를 따라요.

등록된 작품과 사용자가 요청한 검색에 필요한 범위로 조회하며, 제공자의 전체 작품 목록·이미지를 대량 수집하거나 API를 원격 백업 저장소로 사용하지 않아요.
[AniList 이용 조건](https://docs.anilist.co/guide/terms-of-use)이 적용되며, 키가 필요 없거나 고정 보관 기간이 명시되지 않았다는 사실을 이미지의 무제한 보관·재배포 허가로 간주하지 않고 실제 적용 조건을 구현 과정에서 확인해야 해요.
프로토타입용 개별 ID 조회와 표지 수신은 [주제 문서의 시안 근거](../brainstorm/web-gui-subtitles.md#화면-구성-제안)에 기록하며, 제품의 자동 검색·선택·보관·복구 흐름이나 실물 모바일 동작을 검증한 결과로 간주하지 않아요.
