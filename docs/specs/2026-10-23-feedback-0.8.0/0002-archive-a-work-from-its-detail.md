# 0002 작품 상세에서 작품을 보관 폴더로 옮겨요

- 상태: 대기
- 출처: [명세의 보관](spec.md#보관), [보관 ADR](../../adr/0022-archiving-deletes-rules-and-follows-the-folder.md), 사용자 피드백 9·11번(2026-10-23)
- 막는 티켓: 없음

## 작업

작품 상세에 `보관 폴더로 옮기기`를 만들어, 규칙이 없어도 작품을 보관할 수 있게 해요. 사용자가 정한 것은 다음과 같아요(2026-10-23).

- 그 작품 폴더에 받는 규칙이 있으면 수집 중인 것과 `멈춤`인 것을 모두 보여주고, 확인받은 뒤 함께 지우고 옮겨요.
- 옮기지 못하면 까닭과 `다시 옮기기`를 작품 상세에 보여줘요. 규칙은 이미 지워졌으므로 재시도할 곳은 작품이에요.

지금의 폴더 이동은 규칙에 매인 명령(`rule_archive`, 방향 `archive`·`restore`)이에요. 이 티켓은 작품 폴더를 대상으로 하는 이동 명령을 만들고, 규칙을 지운 뒤에 그 명령을 접수해요. 새 회차가 옛 자리에 들어오지 않게, 규칙을 먼저 지우고 폴더를 옮겨요. 실제 이동(Transmission의 위치 옮기기, `.trss/`, 같은 이름 폴더의 합침과 겹침 검사, 같은 파일시스템의 이름 바꾸기, 중단 뒤 이어 하기)은 지금의 [보관과 복원의 폴더 이동](../../requirements/collection.md#보관과-복원의-폴더-이동)의 코드를 그대로 써요. [0003](0003-archive-deletes-the-rule.md)의 규칙 보관도 이 명령으로 폴더를 옮겨요.

`그 작품 폴더에 받는 규칙`은 저장 폴더의 첫 부분이 그 작품 폴더인 규칙이에요(모든 채널). 동작은 수집 폴더 바로 아래의 작품이고 보관 폴더가 정해져 있을 때만 보여요. 옮길 곳이 없으면 두지 않는다는 것은 명세가 정한 구현 결정이에요.

## 완료 기준

- [ ] 작품 상세에서 `보관 폴더로 옮기기`를 누르면, 그 작품 폴더에 받는 규칙을 채널, 저장 폴더, 상태와 함께 보여주는 확인이 떠요. 받는 규칙이 없으면 옮긴다는 확인만 떠요. 확인하면 규칙을 모두 지운 뒤 이동 명령을 접수하고, 취소하면 아무것도 바뀌지 않아요. API 테스트로 확인해요.
- [ ] 이동이 끝나면 작품 폴더가 보관 폴더에 있고, 작품 ID, 시즌 연결, 표지 선택, 제작자 지정, 수집 이력이 그대로예요. Transmission의 그 작품 토렌트는 새 위치를 가리켜요. 지금의 보관 이동 테스트와 같은 가짜 Transmission으로 확인해요.
- [ ] 겹치는 파일, 다른 파일시스템, Transmission이 답하지 않음으로 옮기지 못하면, 작품 상세가 그 까닭과 `다시 옮기기`를 보여줘요. 겹친 파일을 치운 뒤 `다시 옮기기`가 옮겨요. 옮기는 동안에는 `보관 폴더로 옮기는 중이에요`를 보여줘요.
- [ ] 옮기는 동안 trss가 멈추면 다음 실행에서 남은 것만 이어 옮겨요. 테스트로 확인해요.
- [ ] 수집 폴더 밖의 작품(보관 폴더나 다른 감시 폴더의 작품)과, 보관 폴더를 정하지 않은 설치에서는 동작이 보이지 않아요.
- [ ] 개발 환경(서버 DB 사본)에서 작품 하나를 옮겨 보고, 확인 창, 이동 상태 문장, 옮긴 뒤의 작품 상세를 결과에 적어요.
- [ ] [라이브러리 명세의 작품 상세 화면](../../requirements/library.md#작품-상세-화면)과 [RSS 수집 명세의 보관과 복원의 폴더 이동](../../requirements/collection.md#보관과-복원의-폴더-이동)에 이 동작을 적고, 검증 표의 행을 더해요.
- [ ] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.
