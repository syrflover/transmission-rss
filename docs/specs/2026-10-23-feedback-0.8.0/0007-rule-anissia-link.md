# 0007 규칙을 Anissia 전체 목록의 작품에도 이어요

- 상태: 대기
- 출처: [명세의 규칙의 Anissia 연결](spec.md#규칙의-anissia-연결), [용어집의 방영작 구독](../../glossary.md), 사용자 피드백 8번(2026-10-23)
- 막는 티켓: 없음

## 작업

구독이 아닌 규칙의 상세에는 `편성표와 연결`이 있어요(`web/src/screens/collect/rules/LinkToSchedule.tsx`). 편성표에서 작품과 자막 제작자를 고르면 그 규칙이 구독이 돼요. 고를 수 있는 것은 이번 분기 편성표에 있는 작품뿐이에요. 2026-10-23 서버의 수집 중인 일반 규칙은 `Mushoku Tensei/Season 03`과 `Re Zero kara Hajimeru Isekai Seikatsu/Season 04` 둘이에요.

사용자가 정한 것은 다음과 같아요(2026-10-23).

- 이 동작의 이름을 `Anissia 연결`로 바꾸고, 작품 상세의 시즌 연결 창처럼 `전체 목록`과 `편성표` 두 탭에서 골라요. `전체 목록`은 사용자가 쓴 검색어로 Anissia 전체 목록을 찾고, 종영작도 보여줘요.
- 이 변경에서 전체 목록을 쓰는 곳은 이 연결뿐이에요. 구독 화면과, 이미 구독인 규칙을 다시 잇는 길([web-redesign/0129](../2026-09-30-web-redesign/0129-relink-subscription.md))은 그대로예요.

작품 상세의 연결 창은 서버가 고른 작품이 화면이 보여 준 목록(요일, 또는 검색어와 페이지)에 있는지 확인하고, 그 응답으로 Anissia 작품의 정보를 저장해요. 규칙의 연결도 같은 방식으로 해요. 고른 뒤 자막 제작자를 정하는 단계와, 일치 문구·저장 폴더·검사 순서를 바꾸지 않는 것은 지금과 같아요.

편성표에 없는 작품에 이은 구독은 이렇게 보여야 해요. Anissia에는 작품 하나만 묻는 요청이 없어서, 하루 한 번의 갱신은 요일별 편성표로만 작품 정보를 다시 받아요(`trss-collect`의 `anissia` 모듈). 그래서 Anissia가 `END`라고 준 작품과 종영일이 지난 작품은 바로 `종영`이고, 종영일이 없는 작품은 어느 요일에서도 찾지 못한 갱신 뒤에 `종영`이 돼요.

[0006](0006-schedule-search-every-weekday.md)도 이 창의 `편성표` 탭을 고쳐요. 두 티켓이 같은 칸을 고치므로 함께 진행하지 말고 하나씩 해요.

## 완료 기준

- [ ] 구독이 아닌 규칙의 상세에 `Anissia 연결`이 있고, `전체 목록`과 `편성표` 두 탭이 있어요. `전체 목록`은 창을 열 때 검색하지 않고, 사용자가 쓴 검색어로 찾으며, 종영작도 보여줘요. 안내 문장은 편성표가 아니라 Anissia 작품을 고른다고 말해요.
- [ ] 전체 목록에서 고른 작품으로 규칙이 구독이 되고, 일치 문구·저장 폴더·검사 순서는 그대로예요. 서버는 요청이 말한 목록에 없는 작품을 거절하고, 고른 작품의 정보를 저장해요. 가짜 Anissia로 API 테스트를 해요.
- [ ] 편성표에 없는 작품에 이은 구독은 구독 카드에 `종영`으로 보이고, 이번 주 편성에 카드가 없으며, 보관 제안을 받아요. 종영일이 지난 작품과, 갱신이 어느 요일에서도 찾지 못한 작품을 모두 테스트로 확인해요.
- [ ] 개발 환경(서버 DB 사본)에서 일반 규칙 하나를 전체 목록의 종영작에 이어 보고, 규칙 상세와 구독 탭, 보관 제안을 결과에 적어요.
- [ ] [RSS 수집 명세](../../requirements/collection.md)의 방영작 구독과 수집 화면(`편성표와 연결`)을 고치고, 검증 표의 행을 고쳐요.
- [ ] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.
