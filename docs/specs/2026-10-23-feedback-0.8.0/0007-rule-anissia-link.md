# 0007 규칙을 Anissia 전체 목록의 작품에도 이어요

- 상태: 완료
- 출처: [명세의 규칙의 Anissia 연결](spec.md#규칙의-anissia-연결), [용어집의 방영작 구독](../../glossary.md), 사용자 피드백 8번(2026-10-23)
- 막는 티켓: 없음

## 작업

구독이 아닌 규칙의 상세에는 `편성표와 연결`이 있어요(`web/src/screens/collect/rules/LinkToSchedule.tsx`). 편성표에서 작품과 자막 제작자를 고르면 그 규칙이 구독이 돼요. 고를 수 있는 것은 이번 분기 편성표에 있는 작품뿐이에요. 2026-10-23 서버의 수집 중인 일반 규칙은 `Mushoku Tensei/Season 03`과 `Re Zero kara Hajimeru Isekai Seikatsu/Season 04` 둘이에요.

사용자가 정한 것은 다음과 같아요(2026-10-23).

- 이 동작의 이름을 `Anissia 연결`로 바꾸고, 작품 상세의 시즌 연결 창처럼 `전체 목록`과 `편성표` 두 탭에서 골라요. `전체 목록`은 사용자가 쓴 검색어로 Anissia 전체 목록을 찾고, 종영작도 보여줘요.
- 이 변경에서 전체 목록을 쓰는 곳은 이 연결뿐이에요. 구독 화면과, 이미 구독인 규칙을 다시 잇는 길([web-redesign/0129](../2026-09-30-web-redesign/0129-relink-subscription.md))은 그대로예요.

작품 상세의 연결 창은 서버가 고른 작품이 화면이 보여 준 목록(요일, 또는 검색어와 페이지)에 있는지 확인하고, 그 응답으로 Anissia 작품의 정보를 저장해요. 규칙의 연결도 같은 방식으로 해요. 고른 뒤 자막 제작자를 정하는 단계와, 일치 문구·저장 폴더·검사 순서를 바꾸지 않는 것은 지금과 같아요.

편성표에 없는 작품에 이은 구독은 이렇게 보여야 해요. Anissia에는 작품 하나만 묻는 요청이 없어서, 하루 한 번의 갱신은 요일별 편성표로만 작품 정보를 다시 받아요(`trss-collect`의 `anissia` 모듈). 그래서 Anissia가 `END`라고 준 작품과 종영일이 지난 작품은 바로 `종영`이고, 종영일이 없는 작품은 어느 요일에서도 찾지 못한 갱신 뒤에 `종영`이 돼요.

[0006](0006-schedule-search-every-weekday.md)도 이 창의 `편성표` 탭을 고쳐요. 두 티켓이 같은 칸을 고치므로 함께 진행하지 말고 하나씩 해요.

## 완료 기준

- [x] 구독이 아닌 규칙의 상세에 `Anissia 연결`이 있고, `전체 목록`과 `편성표` 두 탭이 있어요. `전체 목록`은 창을 열 때 검색하지 않고, 사용자가 쓴 검색어로 찾으며, 종영작도 보여줘요. 안내 문장은 편성표가 아니라 Anissia 작품을 고른다고 말해요.
- [x] 전체 목록에서 고른 작품으로 규칙이 구독이 되고, 일치 문구·저장 폴더·검사 순서는 그대로예요. 서버는 요청이 말한 목록에 없는 작품을 거절하고, 고른 작품의 정보를 저장해요. 가짜 Anissia로 API 테스트를 해요.
- [x] 편성표에 없는 작품에 이은 구독은 구독 카드에 `종영`으로 보이고, 이번 주 편성에 카드가 없으며, 보관 제안을 받아요. 종영일이 지난 작품과, 갱신이 어느 요일에서도 찾지 못한 작품을 모두 테스트로 확인해요.
- [x] 개발 환경(서버 DB 사본)에서 일반 규칙 하나를 전체 목록의 종영작에 이어 보고, 규칙 상세와 구독 탭, 보관 제안을 결과에 적어요.
- [x] [RSS 수집 명세](../../requirements/collection.md)의 방영작 구독과 수집 화면(`편성표와 연결`)을 고치고, 검증 표의 행을 고쳐요.
- [x] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.

## 결과

### 만든 것

규칙 상세의 `편성표와 연결`이 `Anissia 연결`이 됐어요. 창에는 작품 상세의 시즌 연결 창과 같은 `전체 목록`과 `편성표` 두 탭이 있고, `전체 목록`이 먼저 열려요. `전체 목록`은 `작품 찾기` 칸에 쓴 검색어로 Anissia 전체 목록을 찾아 `종영`한 작품도 요일과 함께 보여주고, 창을 열 때는 찾지 않아요. `편성표` 탭은 [0006](0006-schedule-search-every-weekday.md)의 편성표 고르기 그대로예요. 두 탭은 함께 남아 있어서 탭을 오가도 검색과 고른 작품이 남고, 탭 아래의 `고른 작품:` 줄이 지금 고른 작품을 말해요. 안내 문장은 "Anissia에서 작품과 자막 제작자를 고르면 이 규칙이 그 작품의 구독이 돼요"로 바꿨어요.

`전체 목록`은 0006의 검색 API에 `ended=true`를 붙여 `종영`을 빼지 않고 받아요. 연결 요청(`POST /api/rules/{id}/subscription`)은 0006부터 고른 곳(요일, 또는 검색어와 쪽)을 받아 Anissia에서 다시 읽으므로, 서버의 확인과 저장은 바꾸지 않았어요. 그 확인은 `종영`을 빼기 전의 쪽을 보므로 종영작도 받아요. 구독이 아닌 규칙만 받는 서버 문장들(`자막 받기`, `제작자 변경`, 이미 구독인 규칙의 거절)도 `편성표와 연결`을 `Anissia 작품에 연결`로 바꿨어요.

`작품 찾기` 칸과 검색 결과는 `web/src/screens/collect/subs/add/AnissiaSearch.tsx`로 옮겨, 편성표 고르기와 `전체 목록` 탭이 함께 써요. 두 탭 단추도 같은 파일로 옮겨 시즌 연결 창과 함께 써요.

### 정한 것

- `전체 목록` 탭도 `작품 찾기` 칸처럼 입력을 멈추고 0.7초 지나거나 Enter나 `검색`을 누를 때 찾아요. 시즌 연결 창의 `전체 목록`은 Enter나 `검색`으로만 찾지만, 같은 칸을 쓰는 편성표 고르기와 다르게 움직이지 않게 했어요(구현 결정).
- 요일 탭을 바꿔도 고른 작품을 지우지 않아요. 0.8.0까지는 연결 요청이 그때 열린 요일을 보냈기 때문에 요일을 바꾸면 고른 작품을 지웠는데, 0006부터는 고른 곳을 고를 때 함께 기억해요(구현 결정).

### 테스트

2026-10-23에 3bfaac8a 위의 작업 트리에서 `cargo test --workspace`가 모두 통과했어요(3,227개 통과, 12개 무시, 테스트 바이너리 27개의 합 37.93초, `dev/measure/when-quiet.sh`로 다른 빌드가 없을 때 측정했어요). `cargo clippy --workspace --all-targets`에 경고가 없고, `npm test`(318개)와 `npm run typecheck`도 통과했어요. 원본 로그는 이 PC의 `dev/local/measure/feedback-0.8.0-0007/`에 있어요.

- `trss` `src/web/subscriptions_api/tests.rs` `a_search_with_the_ended_ones_keeps_the_anime_that_have_ended`는 `ended=true` 검색이 Anissia가 끝낸 작품과 종영일이 지난 작품을 `end`로 남기는 것을 겨눠요. `ended`를 무시하는 코드에서는 `[3320, 3005]`가 나와 실패해요.
- 같은 파일 `rule_detail::a_rule_linked_to_an_anime_the_schedule_does_not_list_reads_as_ended`는 검색 쪽에서 고른 두 작품에 규칙을 이은 뒤 구독 목록의 `run`, 이번 주 편성의 카드, 보관 제안을 겨눠요. 종영일이 지난 작품은 바로 `end`, 카드 없음, `ended` 제안이에요. 종영일이 없는 `결방` 작품은 처음에 `off`이고 목요일 카드가 있다가, 갱신이 찾지 못했다고 기록하면 `end`, 카드 없음, `unlisted` 제안이 돼요.
- 연결 요청이 그 쪽에 없는 작품을 거절하고 검색에서 받은 정보를 저장하는 것은 0006의 `rule_detail::a_rule_is_linked_to_an_anime_found_by_a_search_checked_against_that_page`가 겨눠요.

### 개발 환경 확인

2026-10-23에 서버 DB 사본(2026-10-22에 받은 것)으로 띄운 개발 환경을 이 작업 트리로 다시 만들어, 내장 브라우저와 실제 Anissia로 확인했어요.

- 규칙 `Mushoku Tensei/Season 03`의 상세에 `방영 미정` 옆 `Anissia 연결`이 있었어요. 열자 `전체 목록` 탭이 눌려 있고 빈 `작품 찾기` 칸이 보였고, 보낸 요청은 숨은 `편성표` 탭의 금요일 편성 하나뿐이고 검색은 없었어요.
- `전체 목록`에 `무직`을 쓰자 `ended=true` 검색으로 5편이 떴어요. `무직 전생 III`(`신작`)을 뺀 4편에 `종영`이 붙었고, 줄마다 `월요일 00:00 · 2023년 7월 3일 시작 · 2024년 7월 1일 종영`처럼 요일과 종영일이 있었어요.
- `무직 전생 II`를 고르자 `고른 작품:` 줄이 그 작품을 말했고, `편성표` 탭으로 갔다 돌아와도 검색어와 고른 작품이 남았어요.
- 자막을 `받지 않음`으로 두고 연결하자, 규칙의 일치 문구 `Mushoku Tensei S3`, 저장 폴더 `Mushoku Tensei/Season 03`, 검사 순서 1번, `수집 중`은 그대로였어요. 구독에 저장된 Anissia 정보는 2276, 월요일(1) 00:00, 2023-07-03부터 2024-07-01, `END`였어요.
- 구독 탭의 카드에는 `종영`과 `2024년 7월 1일 종영`이 보였어요. 이번 주 편성에는 이 작품의 카드가 없었고, 보관 제안이 "Anissia에서 방영이 끝났어요. 종영일은 2024년 7월 1일이에요."로 떴어요. 이 구독은 개발 환경에 남겨 뒀어요.
- 390px 폭에서 규칙 `Re Zero kara Hajimeru Isekai Seikatsu`의 `전체 목록`에 `제로부터`를 쓰자 19편이 가로로 넘치지 않고 떴어요. 이 규칙은 잇지 않았어요.
- 참고(실제 Anissia): `마녀`, `무직`, `는`의 첫 쪽이 준 `END` 44편 가운데 종영일이 없는 작품은 1편이었어요.

### 한계

- 서버와 실제 기기에서 확인하지 않았어요. [0011](0011-deploy-and-check-on-server.md)에서 봐요.
- 두 탭과 `고른 작품:` 줄, `전체 목록`의 검색은 화면 코드라 웹 테스트가 없어요.
- 종영일 없이 Anissia가 `END`로 준 작품에 이으면, 다음 날 갱신이 어느 요일에서도 찾지 못하기 전까지 그 요일의 이번 주 편성 카드가 남고 보관 제안이 없어요. 구독 카드는 처음부터 `종영`이에요. 테스트하지 않았고, 위의 검색에서 그런 작품은 44편 가운데 1편이었어요.
