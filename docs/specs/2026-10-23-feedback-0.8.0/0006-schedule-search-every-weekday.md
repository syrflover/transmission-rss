# 0006 편성표의 `작품 찾기`가 Anissia 검색으로 모든 요일에서 찾아요

- 상태: 대기
- 출처: [명세의 편성표 검색](spec.md#편성표-검색), [명세의 작품 찾기의 포커스](spec.md#작품-찾기의-포커스), 사용자 피드백 2·3번(2026-10-23)
- 막는 티켓: 없음

## 작업

편성표에서 작품을 고르는 칸(`web/src/screens/collect/subs/add/PickAnime.tsx`)은 Anissia의 요일별 편성표를 한 요일씩 받아요. `작품 찾기`는 받아 둔 그 요일 목록 안에서만 걸러요. 그래서 다른 요일의 작품을 찾으려면 요일 탭을 바꿔야 하고, 결과에는 요일이 없어요. 이 칸은 구독 화면, 규칙 상세의 연결, 작품 상세 시즌 연결 창의 `편성표` 탭이 함께 써요.

사용자가 정한 것은 다음과 같아요(2026-10-23).

- `작품 찾기`는 쓴 검색어로 Anissia 전체 목록을 찾고, `종영`을 뺀 작품을 모든 요일에서 보여줘요. 결과마다 요일을 보여줘요.
- 한국어 제목으로만 찾아지는 것은 감수해요. 모든 요일 편성표를 받아 거르는 안(처음 18초쯤)과 하루 한 번 저장하는 안은 고르지 않았어요.

검색에는 작품 상세의 연결 창이 쓰는 Anissia 전체 목록 검색(`trss-anissia`의 `search_anime`, `/anime/list/<page>?q=`, 30개씩)을 써요. 그 창의 검색 API는 작품과 시즌에 매여 있으므로, 구독 화면에서도 쓸 수 있는 검색 API가 필요해요. 2026-10-23 조회에서 검색 결과는 편성표와 같은 필드를 줬어요. `신작` 작품은 `week` 8, 상태는 `ON`·`OFF`·`END`예요.

구독 요청은 지금 작품을 고른 요일을 함께 보내요. 검색으로 고른 작품은 검색어와 페이지를 보내고, 서버는 그 목록에 작품이 있는지 확인해요. 작품 상세의 연결 창이 쓰는 확인 방식과 같아요.

검색은 Enter나 `검색` 버튼을 누를 때, 또는 입력을 멈추고 잠시 지났을 때 해요. 글자마다 Anissia에 묻지 않으려는 구현 결정이에요. Anissia 요청 간격(2초)과 `429` 대기는 다른 Anissia 요청과 함께 지켜요.

2번(글자를 모두 지우면 포커스가 풀림)은 재현하지 못했어요. 사용자는 PC의 Firefox와 iOS 홈 화면 앱을 쓰고, 어느 쪽에서 봤는지는 기억하지 못해요. 이 칸을 다시 만들면서 포커스가 유지되는지 확인해요. iOS는 [0011](0011-deploy-and-check-on-server.md)에서 봐요.

## 완료 기준

- [ ] 구독 화면에서 검색어를 쓰면 모든 요일에서 찾은 작품이 나오고, `종영`인 작품은 빠져요. 검색어를 지우면 고른 요일 탭의 편성이 다시 보여요. 규칙 상세의 연결과 작품 상세 시즌 연결 창의 `편성표` 탭도 같아요.
- [ ] 결과의 줄마다 요일(`일`–`토`, `기타`, `신작`)이 방영 시각, 시작일, 종영일과 함께 보이고, `구독 중`과 `결방` 표시는 지금과 같아요.
- [ ] 30개를 넘는 결과는 `결과 더 보기`로 이어 받아요. 검색칸 옆에 한국어 제목으로 찾아진다는 안내가 있어요.
- [ ] 검색이 실패하면 까닭과 재시도가 보이고, 요일 탭으로 고르는 길은 그대로 쓸 수 있어요.
- [ ] 검색으로 고른 작품으로 구독을 만들 수 있고, 서버는 요청이 말한 목록에 없는 작품을 거절해요. 가짜 Anissia로 API 테스트를 해요.
- [ ] 검색 결과를 요일과 함께 만드는 부분과 `종영`을 빼는 부분을 테스트로 확인해요.
- [ ] `작품 찾기`에 글자를 썼다가 백스페이스로 모두 지워도 입력칸이 포커스를 잃지 않아요. 개발 환경의 Chromium에서 확인하고, PC의 Firefox에서도 확인해요(사용자에게 부탁하거나 Firefox를 띄울 수 있으면 직접). 원인을 찾으면 결과에 적고, 찾지 못하면 확인한 환경을 적어요.
- [ ] [RSS 수집 명세의 방영작 구독](../../requirements/collection.md#방영작-구독)과 [라이브러리 명세의 작품 연결과 제외](../../requirements/library.md#작품-연결과-제외)에서 편성표 고르기를 고치고, 검증 표의 행을 고쳐요.
- [ ] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.
