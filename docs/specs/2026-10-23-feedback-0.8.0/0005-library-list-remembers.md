# 0005 라이브러리 목록이 정렬, 보기, 필터, 폴더 고르기를 이 브라우저에 기억해요

- 상태: 완료
- 출처: [명세의 라이브러리 목록의 기억](spec.md#라이브러리-목록의-기억), 사용자 피드백 6번(2026-10-23)
- 막는 티켓: [0004](0004-library-folder-choice.md)(폴더 고르기)

## 작업

지금 라이브러리 목록은 보기·정렬·검색어·필터를 페이지가 열려 있는 동안만 기억해요(`web/src/screens/library/prefs.ts`, 사용자 결정 2026-10-04). 새로고침하면 표지 격자, 최근 자막 추가순, 빈 검색, `전체`로 돌아가요.

사용자가 바꾼 것은 다음과 같아요(2026-10-23).

- 정렬, 보기 방식, 필터, [0004](0004-library-folder-choice.md)의 폴더 고르기를 이 브라우저에 저장해서, 새로고침하거나 새 탭으로 열어도 마지막 값으로 시작해요.
- 기기와 브라우저마다 따로 저장해요. 화면 모드를 `이 기기에만` 저장하는 것과 같아요.
- 검색어는 지금처럼 페이지가 열려 있는 동안만 기억해요.

브라우저 저장소는 사생활 보호 모드 등에서 없거나 읽기·쓰기가 실패할 수 있어요. 그때와, 저장된 값이 지금은 없는 정렬·보기·필터일 때는 그 항목만 기본값으로 시작해요. 화면 모드를 저장하는 코드가 이미 이 경우를 다루니, 같은 방식을 써요.

## 완료 기준

- [x] 정렬, 보기 방식, 필터, 폴더 고르기를 바꾼 뒤 새로고침하거나 새 탭으로 열면 그 값으로 시작해요. 검색어는 새로고침하면 비어요.
- [x] 저장소를 쓸 수 없거나 저장된 값이 알 수 없는 값이면 그 항목만 기본값(최근 자막 추가순, 표지 격자, `전체`)으로 시작하고 화면이 깨지지 않아요. 보관 폴더가 없어 폴더 고르기가 없으면 `전체`로 봐요. 웹 단위 테스트로 확인해요.
- [x] 작품 상세에 갔다가 뒤로 오면 보기·정렬·검색·필터·폴더 고르기·스크롤 위치가 지금처럼 그대로예요.
- [x] [라이브러리 명세의 라이브러리 화면](../../requirements/library.md#라이브러리-화면)에서 2026-10-04의 결정을 이 결정으로 바꿔 적고, 검증 표의 행을 고쳐요.
- [x] `npm test`, `npm run typecheck`가 통과해요.

## 결과

### 만든 것

라이브러리 목록은 보기·정렬·필터·폴더 고르기를 이 브라우저의 localStorage에 `trss-library-list-v1` 키로 한 JSON 값에 저장해요. 페이지를 열 때 이 값을 항목마다 따로 읽어서, 지금 목록에 없는 값이 있으면 그 항목만 기본값인 표지 격자·최근 자막 추가순·`전체`로 시작해요. 저장소를 쓸 수 없거나 값이 JSON이 아니면 모두 기본값이에요. 검색어는 저장하지 않고 지금처럼 페이지가 열린 동안만 기억해요.

저장하고 읽는 코드는 화면 모드의 저장 코드와 같은 방식이에요. 화면 코드를 가져오지 않는 `web/src/lib/stored-choices.ts`에 두어 `node --test`로 돌고, 목록은 `web/src/screens/library/prefs.ts`에서 고를 수 있는 값과 기본값을 넘겨요.

### 정한 것

- 보관 폴더가 없어 저장한 폴더가 `전체`로 돌아가면, 그 `전체`도 저장해요. 화면에 보이는 값과 저장한 값이 같게 하려는 거예요(구현 결정).
- 저장한 폴더가 `전체`로 돌아가는 동안에는 목록을 비워 둬요. 저장한 폴더의 작품이나 `보관 폴더에 있는 작품이 없어요.`가 잠깐 보였다가 바뀌지 않게 하려는 거예요(구현 결정).
- 이미 열려 있는 다른 탭은 한 탭에서 바꾼 값을 따라 바뀌지 않고, 새로 열 때 읽어요. 티켓은 새로 열 때의 시작 값만 정했어요(구현 결정).

### 테스트

2026-10-23에 c61bcfd1 위의 작업 트리에서 `npm test`(318개)와 `npm run typecheck`가 통과했어요. 웹만 바꿔서 `cargo test --workspace`는 돌리지 않았어요.

- `web` `src/lib/stored-choices.test.ts`는 저장한 값을 다시 읽는 것, 저장한 것이 없을 때의 기본값, 모르는 값이 그 항목만 기본값이 되고 다른 항목은 남는 것, JSON이 아니거나 객체가 아닌 값, 저장소가 막혔거나 없을 때 읽기는 기본값이고 쓰기는 오류를 내지 않는 것을 겨눠요. 항목마다 따로 읽지 않고 하나라도 모르면 모두 기본값으로 돌리게 바꾼 복사본과, 쓰기의 오류를 잡지 않게 바꾼 복사본에서 각각 해당 테스트가 실패했어요.

### 개발 환경 확인

2026-10-23에 서버 DB 사본(2026-10-22에 받은 것)으로 띄운 개발 환경의 trss(0004 확인 때 만든 이미지)에 이 작업 트리의 웹을 vite로 붙여 확인했어요. 내장 브라우저 창이 숨어 있어서 대부분의 조작은 페이지 안에서 DOM 이벤트로 했어요.

- `제목순`·`목록`·`보관`·`자막 없음`과 검색어 `a`를 건 뒤 새로고침하자, 넷은 그대로 `작품 6편`이었고 검색칸은 비었어요. 저장된 값에도 검색어가 없었어요.
- 새 탭으로 열자 저장한 `목록`·`제목순`·`보관`으로 시작해 `작품 82편`이었어요.
- 저장한 값의 보기·정렬·폴더를 `tiles`·`rating`·`elsewhere`로 바꾸고 새로고침하자, 표지 격자·최근 자막 추가순·`전체`가 되고 `자막 없음`은 남았어요. `{not json`이면 모두 기본값으로 `작품 92편`을 보여 줬어요.
- `목록`·`제목순`·`보관`·검색어 `a`를 건 채 작품에 갔다가 뒤로 오자 모두 그대로였어요. 1280×800에서 1000px 내려가 연 작품에서 돌아오자 스크롤도 1000px이었고, 그 작품이 같은 높이에 있었어요.
- 참고(가짜 출처): 페이지의 `fetch`를 바꿔 목록 답이 보관 폴더가 없는 것처럼 오게 하자, 저장한 `보관`으로 한 번 읽은 뒤 `전체`로 다시 읽었고, 저장한 값도 `전체`가 되고 폴더 고르기가 사라졌어요.

### 한계

- 서버와 실제 기기에서 확인하지 않았어요. [0011](0011-deploy-and-check-on-server.md)에서 봐요.
- 저장소를 쓸 수 없는 브라우저(사생활 보호 창, 사이트 데이터 끔)는 단위 테스트로만 봤어요.
- 보관 폴더가 없을 때 `전체`로 돌아가는 것은 화면 테스트가 없어요. 개발 환경의 설정에서 보관 폴더를 지우면 그 감시 폴더와 작품 82편이 라이브러리에서 빠지므로, 실제로 지워 보지 않고 목록 답을 바꿔 넣어 봤어요.
