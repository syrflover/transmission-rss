# 0004 라이브러리가 수집 폴더와 보관 폴더의 작품을 가려 보여줘요

- 상태: 완료
- 출처: [명세의 보관](spec.md#보관), [보관 ADR](../../adr/0022-archiving-deletes-rules-and-follows-the-folder.md), 사용자 피드백 11번(2026-10-23)
- 막는 티켓: 없음

## 작업

보관된 작품은 작품 폴더가 보관 폴더에 있는 작품이에요. 라이브러리에서 이것을 보고 가려 볼 수 있게 해요. 사용자가 정한 것은 다음과 같아요(2026-10-23).

- `전체·수집·보관` 폴더 고르기를 지금의 필터(`전체`·`방영 중`·`자막 다 갖춤`·`자막 일부`·`자막 없음`·`확인 필요`)와 따로 둬서, 둘을 함께 적용할 수 있어요.
- 보관된 작품의 카드에 `보관` 배지를 붙여요.

목록은 서버가 정렬·필터·검색해서 페이지로 나눠 줘요(`GET /api/library/works`). 폴더 고르기도 서버가 걸러야 페이지와 개수가 맞아요. 작품이 어느 감시 폴더에 있는지는 목록의 각 작품이 이미 갖고 있고, 수집 폴더와 보관 폴더는 앱 설정에 있어요. 2026-10-23 서버에는 수집 폴더에 10개, 보관 폴더에 82개가 있었어요.

보관 폴더를 정하지 않았으면 고르기를 두지 않는다는 것은 명세가 정한 구현 결정이에요. 다른 감시 폴더의 작품은 `전체`에만 나와요. 고른 값을 새로고침 뒤에도 기억하는 것은 [0005](0005-library-list-remembers.md)가 해요.

## 완료 기준

- [x] 목록 API가 폴더 고르기 값을 받아, `수집`이면 수집 폴더의 작품만, `보관`이면 보관 폴더의 작품만, `전체`면 모든 작품을 돌려줘요. 필터·검색·정렬·페이지 나눔과 함께 쓰여요. trss-library와 trss 테스트로 확인해요.
- [x] 라이브러리 화면에 필터와 따로 `전체·수집·보관` 고르기가 있고, 기본은 `전체`예요. 보관 폴더를 정하지 않은 설치에서는 고르기가 없어요.
- [x] 보관 폴더에 있는 작품은 격자와 목록의 카드, 작품 상세의 머리에 `보관` 배지가 붙어요. 작품이 옮겨지면 배지도 따라 바뀌어요.
- [x] 개발 환경(서버 DB 사본)에서 `보관` + `자막 없음`처럼 둘을 함께 골라 보고, 개수와 배지를 결과에 적어요. 휴대폰 폭(390px)에서 필터 줄이 넘치지 않는지도 봐요.
- [x] [라이브러리 명세의 라이브러리 화면](../../requirements/library.md#라이브러리-화면)과 작품 상세 머리에 고르기와 배지를 적고, 검증 표의 행을 더해요.
- [x] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.

## 결과

### 만든 것

목록 API(`GET /api/library/works`)가 `place`(`all`·`collect`·`archive`)를 받아요. 서버가 설정의 수집 폴더나 보관 폴더를 작품의 감시 폴더 경로와 견줘 거른 뒤 필터·검색·정렬·페이지 나눔을 하므로, 개수와 페이지가 고른 폴더에 맞아요. 경로는 끝의 `/`를 빼고 견줘요. 설정은 입력한 그대로 저장하고 감시 폴더는 끝의 `/`를 지우기 때문이에요. 정하지 않은 폴더를 고르면 작품이 없어요.

답에는 작품마다 `archived`(감시 폴더가 보관 폴더)와, 페이지마다 `has_archive_folder`가 붙어요. 작품 상세(`GET /api/library/works/{id}`)에도 `archived`가 붙어요. trss-library는 수집 폴더와 보관 폴더를 모르고, 웹이 넘긴 경로로만 걸러요(`InFolder`).

라이브러리 화면은 보관 폴더가 정해져 있을 때만 검색칸 옆에 보기 전환과 같은 모양의 `전체·수집·보관`을 둬요. 고른 폴더는 보기·정렬·검색·필터처럼 페이지가 열린 동안 기억해요. 보관 폴더가 없어진 뒤 남은 고르기는 `전체`로 돌아가요. 폴더만 골랐는데 작품이 없으면 `보관 폴더에 있는 작품이 없어요.`처럼 알려요. 보관된 작품의 카드는 격자에서 제목 아래, 목록에서 제목 옆에 테두리만 있는 `보관` 배지를 달고, 작품 상세 머리도 작품명과 원제 아래에 같은 배지를 달아요.

### 정한 것

- 폴더 고르기는 필터 칩과 떨어뜨려 검색칸 옆에 보기 전환과 같은 모양으로 둬요. 둘 다 `전체`를 가져서, 붙여 두면 하나의 고르기로 읽히기 때문이에요(구현 결정).
- `보관` 배지는 할 일 배지와 달리 테두리만 있는 조용한 배지예요. 처리할 것이 아니라 작품이 있는 자리를 알리기 때문이에요(구현 결정).
- 새로 열면 폴더 고르기도 `전체`로 시작해요. 보기·정렬·검색·필터의 규칙(사용자 결정, 2026-10-04)을 따랐고, 새로고침 뒤에도 기억하는 것은 [0005](0005-library-list-remembers.md)가 바꿔요(구현 결정).

### 테스트

2026-10-23에 2470d33d 위의 작업 트리에서 `cargo test --workspace`가 모두 통과했어요(3,221개 통과, 12개 무시, 테스트 바이너리 27개의 합 36.6초, `dev/measure/when-quiet.sh`로 다른 빌드가 없을 때 측정했어요). `cargo clippy --workspace --all-targets`에 경고가 없고, `npm test`(313개)와 `npm run typecheck`도 통과했어요. 원본 로그는 이 PC의 `dev/local/measure/feedback-0.8.0-0004/`에 있어요.

- `trss-library` `src/store/library/page.rs` `the_folder_keeps_one_watch_folders_works_and_applies_with_the_filter_and_the_search`는 끝의 `/`가 있는 경로로 한 감시 폴더만 거르는 것, 경로가 같은 글자로 시작하는 다른 폴더를 빼는 것, 필터·검색과 함께 거르는 것, 정하지 않은 폴더가 아무것도 내지 않는 것을 겨눠요.
- `trss` `src/web/library_api/tests.rs` `the_place_keeps_the_collect_or_the_archive_folders_works_and_marks_the_archived`는 `place`의 세 값, 다른 감시 폴더가 `전체`에만 나오는 것, `archived`와 `has_archive_folder`, 보관 폴더를 지운 뒤의 답을 겨눠요. 같은 파일의 `a_bad_parameter_is_a_400_with_a_sentence`에 모르는 `place`를 더했어요.
- `trss` `tests/it/archive_move.rs` `a_work_moved_from_its_detail_loses_its_rules_at_once_and_the_worker_moves_its_folder`는 진짜 worker가 옮기기 전에는 작품 상세의 `archived`가 거짓이고, 옮긴 뒤에는 참인 것을 겨눠요.

### 개발 환경 확인

2026-10-23에 서버 DB 사본(2026-10-22에 받은 것)으로 띄운 개발 환경에서, 이 작업 트리로 이미지를 다시 만들어 확인했어요.

- 목록 API에서 `전체` 92편 가운데 `수집`이 10편, `보관`이 82편이었고, `archived`가 참인 작품도 82편이었어요. 2026-10-23 서버의 나눔(수집 폴더 10개, 보관 폴더 82개)과 같아요.
- 화면에서 `보관`과 `자막 없음`을 함께 고르자 `작품 6편`이 떴고, 격자와 목록의 카드마다 `보관` 배지가 있었어요. `수집`과 `자막 없음`은 목록 API에서 0편이었어요.
- 390px 폭에서 페이지가 가로로 넘치지 않았어요(`scrollWidth` 390). 폴더 고르기와 정렬이 한 줄, 보기 전환이 다음 줄이고, 필터 칩은 두 줄로 감겼어요.
- 보관 폴더의 `Kore Kaite Shine` 상세 머리에 원제 아래 `보관` 배지가 있었어요. 뒤로 가자 `보관`·`목록`·`자막 없음`과 `작품 6편`이 그대로였어요. 수집 폴더의 `Sekai Saikyou no Majo, Hajimemashita` 상세는 `archived`가 거짓이었어요.

### 한계

- 서버에서 확인하지 않았어요. [0011](0011-deploy-and-check-on-server.md)에서 봐요.
- 폴더 고르기, `보관` 배지, 보관 폴더가 없어진 뒤 `전체`로 돌아가는 것은 화면 테스트가 없어요. 마지막 것은 개발 환경에서도 해 보지 않았어요.
- 개발 환경에서 작품을 옮긴 뒤 배지가 붙는 화면은 보지 않았어요. 서버 답의 `archived`가 바뀌는 것은 테스트로 봤고, 옮긴 뒤 목록과 상세를 다시 읽는 것은 [0002](0002-archive-a-work-from-its-detail.md)의 동작이에요.
