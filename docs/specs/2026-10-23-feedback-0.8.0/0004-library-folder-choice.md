# 0004 라이브러리가 수집 폴더와 보관 폴더의 작품을 가려 보여줘요

- 상태: 대기
- 출처: [명세의 보관](spec.md#보관), [보관 ADR](../../adr/0022-archiving-deletes-rules-and-follows-the-folder.md), 사용자 피드백 11번(2026-10-23)
- 막는 티켓: 없음

## 작업

보관된 작품은 작품 폴더가 보관 폴더에 있는 작품이에요. 라이브러리에서 이것을 보고 가려 볼 수 있게 해요. 사용자가 정한 것은 다음과 같아요(2026-10-23).

- `전체·수집·보관` 폴더 고르기를 지금의 필터(`전체`·`방영 중`·`자막 다 갖춤`·`자막 일부`·`자막 없음`·`확인 필요`)와 따로 둬서, 둘을 함께 적용할 수 있어요.
- 보관된 작품의 카드에 `보관` 배지를 붙여요.

목록은 서버가 정렬·필터·검색해서 페이지로 나눠 줘요(`GET /api/library/works`). 폴더 고르기도 서버가 걸러야 페이지와 개수가 맞아요. 작품이 어느 감시 폴더에 있는지는 목록의 각 작품이 이미 갖고 있고, 수집 폴더와 보관 폴더는 앱 설정에 있어요. 2026-10-23 서버에는 수집 폴더에 10개, 보관 폴더에 82개가 있었어요.

보관 폴더를 정하지 않았으면 고르기를 두지 않는다는 것은 명세가 정한 구현 결정이에요. 다른 감시 폴더의 작품은 `전체`에만 나와요. 고른 값을 새로고침 뒤에도 기억하는 것은 [0005](0005-library-list-remembers.md)가 해요.

## 완료 기준

- [ ] 목록 API가 폴더 고르기 값을 받아, `수집`이면 수집 폴더의 작품만, `보관`이면 보관 폴더의 작품만, `전체`면 모든 작품을 돌려줘요. 필터·검색·정렬·페이지 나눔과 함께 쓰여요. trss-library와 trss 테스트로 확인해요.
- [ ] 라이브러리 화면에 필터와 따로 `전체·수집·보관` 고르기가 있고, 기본은 `전체`예요. 보관 폴더를 정하지 않은 설치에서는 고르기가 없어요.
- [ ] 보관 폴더에 있는 작품은 격자와 목록의 카드, 작품 상세의 머리에 `보관` 배지가 붙어요. 작품이 옮겨지면 배지도 따라 바뀌어요.
- [ ] 개발 환경(서버 DB 사본)에서 `보관` + `자막 없음`처럼 둘을 함께 골라 보고, 개수와 배지를 결과에 적어요. 휴대폰 폭(390px)에서 필터 줄이 넘치지 않는지도 봐요.
- [ ] [라이브러리 명세의 라이브러리 화면](../../requirements/library.md#라이브러리-화면)과 작품 상세 머리에 고르기와 배지를 적고, 검증 표의 행을 더해요.
- [ ] `cargo test --workspace`, `npm test`, `npm run typecheck`가 통과해요.
