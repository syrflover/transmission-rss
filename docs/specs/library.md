# 라이브러리와 작품 명세

## 목표와 범위

로컬 영상 폴더에서 작품(Work)·시즌(Season)·에피소드(Episode)를 발견하고, 자막을 원하는 작품만 Anissia·회차 대응(Episode Mapping)으로 연결해 영상·자막 보유를 한눈에 보게 해요.
라이브러리는 전체 작품의 둘러보기와 찾기를, 작품 상세는 한 작품의 회차·자막·할 일·파일을 한 흐름으로 맡아요.

이 문서는 작품 발견·연결·회차 대응·표지·정리와 라이브러리·작품 상세 화면의 요구를 담당해요.
공통 탐색·문구·표기와 구현 경계는 [웹 앱 공통 명세](web-app.md)를, 자막의 보관·적용·교체 승인은 [자막 명세](subtitles.md)를, 영상 수집과 수정본 대체는 [RSS 수집 명세](collection.md)를, YAML 필드는 [설정과 이전 명세](settings.md#앱-yaml의-구성)를 따라요.

## 요구사항과 완료 기준

### 작품 발견과 감시 폴더

- Transmission 목록에 없는 기존 영상과 감시 폴더도 trname의 작품·시즌·회차 구조를 기준으로 발견해요.
  신규 trss 영상·기존 trss 영상·독립 감시 폴더를 각각 사용해 웹의 작품 상태와 대상 경로가 실제 파일에 대응하는지 확인해요.
- 감시 폴더를 추가할 때 이미 등록한 폴더, 등록한 폴더의 안쪽 폴더, 앱이 읽을 수 없는 경로를 까닭과 함께 문장으로 알리고 추가하지 않아요.
  추가할 수 있으면 발견한 작품 수를 함께 알려요.
- 설정의 [수집 폴더와 보관 폴더](collection.md#수집-폴더와-보관-폴더)는 늘 감시 폴더예요(사용자 결정, 2026-10-01).
  보관·복원으로 작품 폴더가 두 폴더 사이를 오가도 같은 작품으로 라이브러리에 남게 하려는 거예요.
  설정에서 두 폴더를 바꾸면 감시 폴더도 따라 바뀌고, 이 두 폴더는 등록 해제할 수 없으며 그 까닭을 폴더 줄에 보여줘요.
- 감시 폴더의 등록 해제는 디스크의 파일을 건드리지 않고 그 폴더의 작품만 라이브러리에서 빼며, 저장한 자막 기록은 남긴다고 제자리에서 확인한 뒤 해요.
- 폴더마다 경로, 작품 수, 연결한 작품 수, 새로 발견한 작품 수, 마지막 확인 시각과 `다시 확인`·`등록 해제`를 보여줘요.
- 감시 폴더의 변경은 inotify 알림으로 받아 바뀐 작품만 곧바로 다시 읽고, 알림으로 알 수 없는 때(worker 시작, 알림 큐 넘침, 감시를 걸지 못한 폴더)와 1시간마다의 안전망은 폴더 수정 시각으로 바뀐 폴더를 찾아요(사용자 결정, 2026-10-01).
  폴더 수정 시각은 바뀐 폴더를 찾는 데만 쓰고 추가 시각으로 쓰지 않아요.
  감시 폴더 관리 화면의 위치는 [설정 화면](settings.md#설정-화면)을 따라요.

### 작품 연결과 제외

발견한 작품은 미연결로 두고, 방영작이나 사용자가 자막을 원하는 작품만 Anissia·회차 대응을 연결해요.
첫 실행에서 모든 작품을 일괄 확인하는 대안보다 처음 부담이 작고, 자막을 주로 분기 방영작과 가끔 추가하는 옛날 작품에만 정리한다는 사용 흐름에 맞춘 선택이에요.
미연결 작품은 자막 후보를 자동 조회하지 않으며, 관리하지 않을 작품의 제외는 별도 기능 대신 이 기본 상태로 다뤄요.

- 방영작은 [구독](collection.md#방영작-구독)할 때 Anissia 연결이 확정돼요.
  구독하지 않은 작품은 로컬 작품·시즌에 대응하는 Anissia 작품 후보를 제안하고 사용자가 최초 한 번 확인해요.
- 같은 작품의 다음 회차에서 확인한 연결을 재사용하며, 이름이 비슷하다는 이유만으로 다른 작품·시즌에 확정 연결하지 않아요.
- 같은 회차의 중복 영상이 발견돼도 임의의 대상에 배치하지 않아요.
  같은 릴리스의 높은 수정본은 [영상 수정본의 대체](collection.md#영상-수정본의-대체)를 따르고, 다른 그룹의 같은 회차처럼 나머지 중복의 선택 흐름은 보류해요.

### 자막의 회차 대응

- 작품·시즌을 최초 연결할 때 출처별 회차 대응도 사용자에게 확인받고 기억해요.
  다음 회차부터는 확인한 대응을 재사용해 매번 다시 묻지 않으며, 번호가 같다는 이유만으로 사용자 확인을 대신하지 않아요.
- 예외로 [방영작 구독](collection.md#방영작-구독)의 구독 제작자 출처는, Anissia 회차와 시즌 회차의 근거(AniList 회차 수와 규칙의 [회차 변환](collection.md#영상-회차-변환))가 서로 맞으면 묻지 않고 Anissia 근거의 기본 대응을 자동으로 정해요.
  구독이 Anissia 작품과 시즌의 연결을 이미 확정했고, 확인을 기다리면 구독 제작자 자동 수신이 첫 회차마다 멈추기 때문이에요.
  자동으로 정한 대응은 `자동` 표시와 근거를 함께 보여주고 사용자가 고칠 수 있으며, 근거가 없거나 어긋나거나 첨부의 회차가 대응과 다르면 `회차 확인 필요`로 물어요.
  자막 누적 13화가 영상 `S02E01`인 사례와 일반적인 같은 번호 사례를 각각 확인하고, 대응 후에도 불명확한 파일은 이유를 표시해 보류해요.
- 회차 대응을 수정하면 해당 대응에 연결된 기존 보관본과 미완료 작업을 새 기준으로 재평가해요.
  원래 출처 회차와 실제 적용했던 경로의 기록을 새 대응으로 덮어쓰지 않으며, 원래 회차 정보가 불명확하면 추측하지 않고 보류해요.
  대상이 달라진 배치 계획은 다시 확인받고, 이전 교체 승인을 재사용하지 않아요.
  이미 적용한 파일은 그대로 두며, 대응 설정을 바꾸는 것만으로 파일을 옮기거나 복사·삭제하지 않아요.

대응은 한 출처 연결(Subtitle Source Binding)과 회차 근거(`anissia` 후보의 회차 또는 첨부에서 확인한 회차)마다 기본 대응 하나와 명시적 예외로 이뤄져요.
기본 대응은 정수 차이를 적용하거나 명시한 대응만 사용하며, 명시적 예외는 기본 차이보다 먼저 적용해요.
같은 출처 연결과 근거에 여러 기본 대응을 겹쳐 두지 않아요.
숫자 회차의 비교 키는 부동소수점 변환 없이 불필요한 앞자리 0과 소수 끝의 0만 제거해 만들고, 원래 문자열은 보존해요.
따라서 `013`·`13.0`은 같은 숫자 키이며, 서로 다른 결과를 가진 중복 예외로 등록할 수 없어요.
숫자가 아닌 회차 표시는 명시적 문자열 대응만 사용하고, `13.5`를 `13`이나 `14`로 반올림하지 않아요.

적용 순서는 확인한 작품·시즌·출처 연결 확인 → 해당 근거의 회차 관찰값 확인 → 명시적 대응 조회 → 정수 회차에 한해 기본 차이 적용 → 대상 회차와 영상의 모호성 확인이에요.
예외가 없는 소수·특수 회차, 음수 결과, 표현 범위를 넘는 값, 미확인 출처나 여러 대상은 보류해요.
차이 −12의 `13 → 1`·`14 → 2`, `13.5`의 명시적 예외 유무, 잘못된 출처·시즌, 후보 번호와 첨부 번호의 불일치를 구분해 확인해요.
이 대응은 숫자 해석과 연결의 계약이며, 미지원 영상 이름이나 특수편을 자동 식별한다는 약속은 아니에요.
자막의 회차 대응은 영상 이름을 바꿀 때 쓰는 규칙의 [회차 변환](collection.md#영상-회차-변환)과 다른 값이며, 서로 전용하거나 복사하지 않아요.

### 작품 표지

[표지 ADR](../adr/0007-anilist-work-artwork.md)에 따라 등록된 작품에 필요한 AniList 검색으로 명확한 표지만 자동 지정하고, 사용자는 검색 결과를 직접 선택하거나 이미지 파일을 업로드할 수 있어요.
직접 지정은 파일 업로드만 지원하며, 임의의 이미지 URL을 입력하는 기능은 두지 않아요.
표지 선택은 작품 단위의 표시용이며, AniList ID를 Anissia 연결이나 영상·자막의 작품·시즌·회차 대응 근거로 사용하지 않아요.
시즌 번호나 trname 폴더 이름을 AniList의 `Media` ID로 변환하지 않아요.
모호한 후보나 이미지 가용성 문제는 작품명과 영상·자막 상태를 가리지 않고 영상·자막 작업을 보류하지 않아요.
선택 상태의 교환 필드와 불변 관계는 [설정과 이전 명세](settings.md#작품-표지-필드)에 있어요.

#### 자동 판정

자동 검색은 서버가 등록된 작품에 필요한 조회로 소유하고, 사용자가 요청한 해당 작품의 검색도 같은 경계에서 처리해요.
파일 업로드에 URL을 붙여 서버가 임의 주소를 가져오게 하지 않고, 제공자 이미지 주소도 확인된 AniList 응답에서 얻은 허용된 원격 경로로만 가져와요.
제공자의 전체 이미지·목록을 수집하거나 검색 API를 백업으로 사용하지 않아요.

로컬 작품·시즌에 확인된 제목 관찰값과 AniList 제목 표기를 비교하고, 정규화 후의 정확한 제목 대응과 시즌·파트·리메이크 구별 정보가 모순 없이 후보 하나를 지지할 때만 자동 선택해요.
제목 비교는 Unicode NFC 정규화·대소문자 접기·양끝 공백 제거·연속 공백 하나로 축약만 적용하며, 구두점·괄호 내용·시즌·파트·숫자를 제거하거나 번역·음역·철자 교정을 하지 않아요.
검색 첫 결과나 유사도 순위로 선택하지 않으며, 사용한 제목 조회의 페이지가 남았거나 실패·요청 상한으로 후보 집합을 끝까지 확인하지 못하면 유일하다고 판정하지 않아요.
후보 집합을 확인했어도 구별 정보가 빠졌거나 충돌하면 비워 두어요.
Anissia의 `subject`, 선택적인 `originalSubject`와 `startDate`는 해당 작품·시즌에 연결이 확인된 경우에만 힌트로 사용해요.
시작일을 전체 시리즈의 방영일로 바꾸거나 `updDt`를 방영일로 쓰지 않아요.
로컬 시즌이 여러 개라는 것만으로 자동 선택을 막지 않고, 작품 폴더 이름과 정확히 맞는 유일한 항목(대개 1기)의 표지를 써요(사용자 결정, 2026-10-01). 표지는 작품 단위의 표시용이라 틀려도 바로 바꿀 수 있고, 막으면 긴 작품 대부분이 빈 표지로 시작하기 때문이에요.
시즌마다 확인된 제목 관찰값이 서로 다른 후보를 가리키거나 여러 후보를 남기면 작품 단위 표지를 자동 선택하지 않으며, 사용자의 직접 선택을 기다려요.
후보 판정이 명확해도 검증된 이미지 바이트를 준비하기 전에는 새 이미지를 사용 가능한 표지로 표시하지 않아요.

`auto`는 후보 선택 방식이지 수신 작업의 실행 권한이 아니에요.
앱에서 새 작품을 등록하거나 사용자가 표지 검색·복구를 요청한 별도 동작만 수신 작업을 만들며, 가져오기는 등록 이벤트·수신 예약을 만들지 않아요.
가져온 자동 상태와 누락 이미지는 주기 검사·화면 열기·재시작만으로 수신하지 않고, 별도의 검색·복구 요청을 기다려요.
이미 선택된 AniList ID는 이미지가 누락되거나 검색 순위가 바뀐 것만으로 다른 ID로 다시 지정하지 않고, 자동 재수신은 선택된 ID의 이미지만 대상으로 해요.

#### 이미지 파일의 수명

표지 이미지는 [앱 데이터 폴더](../adr/0008-trss-folder-and-app-data-files.md)에 앱이 만든 경로로 두며, 업로드 원래 이름·원격 URL·외부 ID를 파일 경로 권위로 사용하지 않아요.
작품 폴더를 옮기거나 이름을 바꿔도 표지 연결은 DB의 작품 ID로 유지돼요.
업로드는 사용자 파일명·요청 MIME이나 확장자 대신 실제 바이트의 형식 서명과 헤더로 `jpeg`·`png`·`webp`를 판별하고, 비이미지·헤더가 손상된 파일·허용 한도 초과를 거부해요.
픽셀 데이터까지 디코딩하지는 않아요(사용자 결정, 2026-10-01). 앱은 받은 바이트를 바꾸지 않고 저장·제공하므로 디코딩은 중간이 깨진 파일을 거르는 데만 쓰이는데, 그 대가로 이미지 한 장에 수십 MiB의 메모리가 들기 때문이에요. 중간이 깨진 이미지는 화면에서 깨져 보이거나 표지 대신 빈 자리로 보이고, 사용자가 다시 올려요.
원격 제공자 이미지에도 크기·형식·헤더 검사와 응답 자원 한도를 적용하고, 받은 바이트 수가 응답이 알린 길이와 다르면 거부하며, 바이트·픽셀·시간 등 유한한 상한은 구현 환경에서 명시하고 정상 이미지와 경계·초과 입력으로 검증해요.
새 바이트를 비공개 임시 위치에 준비·검증하고 충돌 없는 앱 소유 목적지에 공개한 뒤, 선택 버전과 현재 이미지 참조를 확인해 DB 선택을 반영해요.
공개 전이나 선택 반영 전 오류·중단은 기존 선택과 이미지 표시를 보존하며, 앱 소유 여부가 확인되지 않은 파일을 덮어쓰거나 이름만 보고 정리하지 않아요.
이미지 응답을 제공할 때도 현재 선택의 참조와 파일 객체·경계·기대 바이트 및 안전한 이미지 형식을 검증하고, 누락·불일치·미검증·중간 변경을 이전 검증 결과만 믿고 내보내지 않아요.
늦은 자동 검색·이미지 수신, 두 화면의 수동 변경 및 가져오기가 겹치면 확인한 선택 버전으로 비교해 먼저 확정된 새 선택을 존중하고, 오래된 결과를 재조회·재확인 없이 적용하지 않아요.
이미지 바이트가 누락된 수동 선택도 자동 후보로 대체하지 않고 복구할 파일과 검증 상태를 보여줘요.
사용자가 표지를 비우면 자동 검색까지 막는 `disabled`로 전환하며, 다시 자동 선택을 원하면 별도로 자동 상태로 바꿔요.
표지의 교체 이력·갤러리 기능은 제공하지 않아요.
이전 이미지의 정리는 앱이 만들고 소유가 확인된 파일로 제한하고, 남은 선택·가져오기 계획·진행 또는 복구 중인 파일 동작의 참조가 없어졌는지 확인한 다음 수행해요.
참조 검사는 이미지 ID뿐 아니라 모든 작품의 실제 경로·파일 객체를 기준으로 하며, 복제로 ID가 달라져도 같은 물리 파일을 가리키는 참조를 포함해요.
경로 별칭이나 파일 객체의 동일성을 확정할 수 없으면 정리를 보류해요.
정리와 새 참조 생성이 겹치지 않게 하며, 외부 파일이나 불명확한 중간 파일을 강제로 삭제하지 않아요.

### 시즌 정보

시즌 정보(방영·분량·제작사·장르·원제·영문명·줄거리)는 로컬 시즌마다 연결한 AniList 항목에서 가져와요(사용자 결정, 2026-10-01).
옛날 작품까지 채울 수 있는 대신 사용자가 고를 일이 생기는 쪽을 골랐어요.
이 연결은 표시용이며 작품 단위 [표지](#작품-표지) 선택과 따로 저장하고, 영상·자막의 작품·시즌·회차 대응 근거로 쓰지 않아요. 예외는 [자막의 회차 대응](#자막의-회차-대응)이 근거로 쓰는 AniList 회차 수예요.

- 한 로컬 시즌에 AniList 항목을 하나 이상 순서대로 연결해요(사용자 결정, 2026-10-01). TheTVDB 시즌 하나가 AniList에서 1쿨·2쿨 두 항목으로 나뉘는 일이 흔하기 때문이에요.
  여러 항목이면 방영은 첫 항목의 시작일부터 마지막 항목의 종료일까지, 분량은 회차 수의 합, 제작사·장르는 순서를 지킨 합친 목록이에요. 한 항목의 회차 수가 미상이면 분량도 미상이에요.
  제작사는 AniList가 애니메이션 제작사로 표시한 주 제작사만이며, 자막 제작자와 섞지 않아요.
- 가장 앞 시즌은 작품 폴더 이름을 [자동 판정](#자동-판정)과 같은 규칙(정규화 후 정확히 같은 제목의 후보가 하나이고 검색을 끝까지 읽음)으로 맞춰 하나일 때만 앱이 연결하고, `자동` 표시와 함께 사용자가 고칠 수 있어요.
- 그다음 시즌은 앞 시즌에 연결한 마지막 항목의 AniList 속편(`SEQUEL`) 관계를 따라 후보를 시즌 정보 자리에 조용히 제안하고, 사용자가 확인해야 연결돼요(사용자 결정, 2026-10-01). 분할 방영·총집편·극장판이 끼어 있어도 틀린 정보가 저절로 붙지 않게 하려는 거예요.
  제안이 없거나 맞지 않으면 사용자가 검색해 골라요. 확인을 기다리는 제안은 할 일로 올리지 않아요.
- 작품 상세의 `작품 줄거리`는 선택한 시즌에 연결한 첫 항목의 설명이에요(사용자 결정, 2026-10-01). 시즌을 바꾸면 시즌 정보 칸과 함께 바뀌어요.
  AniList 설명의 줄바꿈·문단과 태그 안의 글자는 남기고, 태그 자체는 보여주지 않으며 마크업을 만들거나 실행하지 않아요.
- 라이브러리의 `방영연도순`은 최신 로컬 시즌의 첫 항목 시작 연도이고, `방영 중`은 최신 로컬 시즌의 항목 가운데 방영 중(`RELEASING`)인 것이 있는 작품이에요. 검색은 작품명과 함께 연결한 항목의 원제·영문명·로마자 제목으로도 찾아요.
- 방영 전·방영 중 항목의 정보는 하루 한 번 다시 받고, 끝난 항목은 사용자가 요청할 때만 다시 받아요. AniList 요청은 표지와 같은 간격·`429` 대기를 함께 지켜요.
- 연결이 없거나 받기 전이면 시즌 정보 칸은 `미상`이고, 다른 시즌의 정보나 파일 상태로 채우지 않아요.

### 라이브러리 화면

라이브러리는 전체 작품을 한 목록으로 보여주고, 표지 격자와 목록 보기를 사용자가 바꿀 수 있어요.
선택한 보기는 다음 접속에도 유지해요.
목록은 서버가 정렬·필터·검색한 결과를 페이지로 나눠, 끝에 닿으면 다음 페이지를 이어서 불러와요(사용자 결정, 2026-10-01). 작품 수와 작품마다 붙는 정보가 늘어도 한 번에 받는 양이 커지지 않게 하려는 거예요.
라이브러리의 작품은 500편을 넘을 것으로 보고, 약 520편의 자료로 격자·목록·정렬·검색이 느려지거나 스크롤 위치를 잃지 않는지 확인해요.

- 격자 보기는 표지와 제목 아래에 영상·자막 상태를 두 줄로 보여주고, 할 일이 있으면 그 배지를 표지 왼쪽 위에 올려요.
- 목록 보기는 48px 폭의 표지와 제목·영상·자막 상태를 한 줄에 둬요.
- 이미지가 없거나 불러오지 못해도 작품명과 영상·자막 상태를 확인하고 작품을 열 수 있어야 해요.
- 항목 전체로 작품 상세에 진입하고, 올려 두면 제목 밑줄 대신 항목 배경을 밝혀요.
- 목록 안에서 회차 상태를 펼치지 않고 작품 상세로 바로 이동해요.

자막 보유는 `보관`·`적용`의 별도 회차 수 대신 `자막 1–10화`처럼 실제로 받은 자막의 회차 범위로 보여줘요.
중간 회차가 없으면 구간을 나눠 보여주고, 여러 파일·수정본이 있는 같은 회차는 한 번만 세며, 여러 시즌의 같은 번호는 시즌별로 구분해요.
확인된 자막도 검사할 기존 파일·복원 기록도 없을 때 `자막 없음`으로 표시해요.
파일 누락·검증 실패·회차를 확인하지 못한 기록이 있으면 확인된 회차 범위와 별개로 `자막 확인 필요`를 표시하고 상세에서 원인을 보여주며, 미확인 파일을 임의의 회차 범위로 합산하거나 단순히 없는 것으로 숨기지 않아요.
관리 전부터 존재한 자막도 현재 파일과 회차가 확인되면 포함하고, 발견만 한 후보나 누락·손상·미확인 파일을 받은 자막으로 세지 않아요.
목록의 정보·보유 범위는 등록된 최신 로컬 시즌 번호를 기준으로 하고, 특정 시즌의 후보·문제를 가리키는 링크는 그 명시된 대상을 유지해요.

정렬은 `제목순`·`방영연도순`·`최근 작품 추가순`·`최근 영상 추가순`·`최근 자막 추가순`이고, 기본은 최근 자막 추가순이에요.
제목은 오름차순, 방영연도는 최신 등록 시즌의 방영연도 내림차순, 추가순은 각 추가 시각 내림차순이며, 영상·자막 추가순은 등록된 모든 시즌의 해당 추가 기록 중 가장 최근 값을 사용해요.
날짜 미상은 알려진 날짜 뒤에 두고 같은 값은 제목으로 정렬하며, 날짜가 없다는 이유로 작품을 목록에서 제외하지 않아요.
추가 기록과 출처 갱신일·파일시스템 수정 시각을 혼동하지 않아요.
영상·자막 파일의 추가 시각은 앱이 감시 폴더를 확인하다 그 파일을 처음 본 시각이고, 감시 폴더를 등록할 때의 첫 확인에 이미 있던 파일은 미상이에요. 작품 추가 시각도 같은 규칙으로 첫 확인 뒤 새로 나타난 작품 폴더만 가져요.
필터는 `전체`·`방영 중`·`자막 다 갖춤`·`자막 일부`·`자막 없음`·`확인 필요`이고, 정렬과 함께 사용할 수 있어요.
제목·원제·영문명으로 작품과 등록 시즌을 찾아요.
작품 상세 방문·뒤로 가기에서 검색·필터·스크롤 위치를 잃지 않으며, 정렬 변경만으로 작업 선택이나 다운로드·승인이 생기지 않아요.
선택한 정렬은 다음 접속에도 유지하고, 다섯 기준의 서로 다른 기대 순서를 가진 자료로 상세 이동·뒤로 가기·새로고침·같은 브라우저의 새 페이지까지 확인해요.
보기와 정렬의 유지는 브라우저 로컬 범위이며 기기 간 동기화는 요구하지 않아요.

### 작품 상세 화면

작품 상세는 탭 없이 한 번에 스크롤하는 흐름이에요.
위에서부터 머리, 시즌 타일과 시즌 정보, `할 일`, 회차 목록을 두고, 넓은 화면에서는 오른쪽에 카드 열을, 휴대폰에서는 목록 아래에 접힌 구역을 둬요.
[할 일](jobs.md#할-일)이나 편성에서 특정 시즌·회차를 가리켜 들어오면 그 시즌을 선택하고 해당 위치로 스크롤하며 초점을 옮겨요.

#### 머리와 시즌

- 머리에는 표지·한국어 작품명·원제와 선택한 시즌의 자막 제작자를 둬요.
  자막 제작자는 시즌마다 다르거나 한 시즌에 여럿일 수 있으므로 선택한 시즌의 제작자를 모두 보여주고, 구독 제작자가 정해지지 않았으면 `제작자 미정`, 직접 넣은 파일처럼 제작자를 모르면 `제작자 알 수 없음`이에요.
  제작자는 머리의 `제작자 변경`에서 바꿔요.
- 표지는 눌러서 크게 볼 수 있어요.
- 시즌 정보는 `방영`·`분량`·`제작사`·`장르` 순서의 이름표 달린 칸이고, 회차 목록과 같은 폭에서 네 칸, 좁으면 두 칸으로 보여요.
  애니메이션 제작사와 자막 제작자를 구분하고, 모르는 메타데이터를 다른 시즌이나 파일 상태로 채우지 않아요.
  아이콘에는 의미를 설명하는 텍스트를 함께 둬요.
- `AniList` 링크는 시즌이 하나든 여럿이든 시즌 정보 제목 줄 한 곳에 두고, 선택한 시즌의 AniList 대상으로 이동해요.
  작품의 대표 AniList 링크와 다른 시즌의 링크가 서로 다른 대상을 가리켜도 각각 올바른 대상으로 이동해야 하며, 링크를 눌러도 선택 시즌은 바뀌지 않아요.
  선택 시즌의 표시용 AniList 연결은 작품 단위 표지 선택과 구분하며, 표지 ID나 외부 방영 분기·배열 순서로 로컬 시즌과 영상·자막의 대응을 추정하지 않아요.
- 시즌 타일은 여러 시즌의 보유 범위를 시즌별로 보여주고, 타일 가장자리까지 전체가 선택 영역이에요.
  선택된 타일에만 체크를 표시하고, 선택 전후 같은 타일의 너비·높이가 바뀌지 않아야 해요.
  넓은 화면에서는 여러 시즌 타일을 함께 보여주고, 휴대폰에서는 현재 시즌 타일과 `시즌 변경`으로 여는 아래 시트를 보여줘요.
  시트는 선택하면 닫히고, 시즌이 많으면 시트 안에서 세로로 스크롤하며 가로 스크롤은 만들지 않아요.
  단일 시즌에서는 타일과 시트 버튼을 숨기되 시즌 정보·보유 범위와 AniList 접근을 유지해요.
- 시즌 변경은 내용·선택 표시를 함께 갱신해요.
  키보드·터치로 선택, 현재 시즌 재선택, Escape·배경·닫기 버튼으로 닫기를 각각 수행해 조작 가능한 초점이 남는지 확인해요.
  닫힌 시트의 초점은 여는 버튼으로 돌아가고, 뒤로 가기로 다른 작품에 이동하면 이전 시트가 남거나 숨은 요소에 초점이 머물지 않아야 해요.

#### 할 일과 회차 목록

위쪽 `할 일`에는 회차 확인·인증·교체 승인처럼 사용자가 해야 하는 것만 색을 입힌 카드로 두고, 추가 상태가 없는 작품에는 빈 제목·목록·여백을 만들지 않아요.
교체 승인 카드는 `현재`·`새 자막`의 받은 시각 한 줄과 `추가 2`·`변경 12` 같은 변경 사항 숫자 태그만 두고 `비교`로 [작업 상세](jobs.md#작업-상세)를 열어요.
인증 카드는 인증 방식과 요청 시각을 두고 `인증`으로 작업 상세를 열어요.
회차 확인 카드는 확인할 RSS 항목 이름 조각을 제목으로 보여줘요.

회차 목록은 최신 화부터 보여주고, 사용자가 `1화부터`로 바꿀 수 있어요.
할 일은 목록 위에 따로 모으므로 목록 자체는 회차 번호 순서예요.
회차 줄은 회차, 방영일, `영상 ✓`·`자막 −` 같은 보유 표시와 예외 배지를 한 줄에 두고, 줄을 누르면 설명 한 줄과 이름표 달린 칸(영상 파일·자막 파일·받은 시각 등)을 펼쳐요.
보유 표시의 체크는 본문 글자와 비슷한 크기로 두고, `영상`·`자막` 라벨은 보유 여부와 관계없이 같은 크기이며, 보조기술에는 보유·없음의 의미를 전달해요.
자막 체크는 확인된 파일 보유만 뜻하며 배치 완료·후보 발견·교체 승인을 뜻하지 않아요.
보기만 하거나 골라도 되는 상태는 색 없이 해당 회차 줄에 조용히 적어요.
정상 회차에 적용 위치나 같은 폴더에 배치했다는 설명을 반복하지 않아요.
극장판은 `본편`으로 구분해요.

| 입력·상태 | 필요한 화면 결과 |
| --- | --- |
| 영상이 있고 자막은 4·6화만 없는 비연속 누락 | 두 회차 줄에 `영상 ✓`·`자막 −`를 표시하고, 보유 범위를 연속 구간으로 합치지 않아요. |
| 구독 제작자가 올리지 않은 회차에 다른 제작자의 자막 후보가 있음 | 할 일로 올리거나 색을 입히지 않고 회차 줄에 후보가 있다고 적으며, 펼친 자리에 `받기`를 둬요. 후보를 받은 자막 범위나 보유 체크에 넣지 않아요. |
| 자막은 받았지만 영상이 없는 영상 대기(Awaiting Video) | `영상 −`·`자막 ✓`와 `영상 대기` 배지를 두고, 펼친 자리에 영상이 아직 없는 까닭과 받은 자막 파일을 보여줘요. 현재 배치된 자막이라고 표시하지 않아요. |
| 현재 자막을 유지한 채 새 자막의 교체 승인을 기다림 | 회차 줄에 `교체 승인` 배지를 두고 위쪽 할 일에 교체 승인 카드가 있어요. 현재 제작자·형식은 그대로 남고 보기·정렬·시즌 변경만으로 교체하지 않아요. |
| 받은 영상의 회차를 확정하지 못함 | 위쪽 할 일에 `회차 확인 필요` 카드를 두고, 임의의 회차에 붙이거나 확정적인 누락으로 단정하지 않아요. |
| 영상 수정본의 대체가 실패해 같은 회차에 두 영상 파일이 있음 | 회차 줄에 `받기 실패` 배지를 두고, 펼친 자리에 두 파일과 까닭을 보여줘요. 두 파일 중 하나를 임의로 현재 영상으로 삼지 않아요. 이전 영상을 지운 뒤 새 영상도 없어져 대체를 끝낸 회차도 같은 배지와 까닭(이전 영상 `지움`, 새 영상 `없어짐`)으로 보여요. |
| 영상이 높은 수정본으로 대체됨 | 회차 줄에 `v1 › v2` 태그와 흐린 `9월 2일 02:05 수정본으로 교체`를 둔 버전 줄로 조용히 알려요. 경고 문장이나 색은 쓰지 않아요. |
| 방영 전 회차 | 영상 `방영 전`과 `자막 대기`를 조용하게 둬요. |

#### 오른쪽 카드 열

넓은 화면에서는 시즌 타일·시즌 정보도 할 일·회차와 같은 왼쪽 열에 두고, 오른쪽 카드 열은 표지·제목 아래에서 시즌 타일(시즌이 하나면 시즌 정보)의 윗면에 맞춰 시작해요.
오른쪽 카드 열은 따로 스크롤하지 않고 화면과 함께 스크롤해요.
휴대폰에서는 같은 카드를 회차 목록 아래의 접힌 구역으로 둬요.

- `작품 정보`는 줄거리를 담아요.
  `작품 줄거리`에는 제공된 원문의 전문과 문단을 보여주고, 외국어 소개도 임의로 번역·축약하지 않으며, 소개가 없으면 만들어 채우지 않아요.
  긴 여러 문단·문자 참조·태그가 섞인 입력으로 문단과 원문 내용이 남는지 확인하되 스크립트·SVG 등 실행 가능한 마크업은 생성하거나 실행하지 않아요.
- `수집`은 이 작품의 규칙과 [수집 화면](collection.md#수집-화면)의 규칙 상세로 가는 링크예요.
- `자막`은 받은 자막을 제작자별로 묶고, 영상 옆에 둔 사본을 `적용`이라고 불러요.
  적용 위치와 보관 위치를 구분해 보여주고, 적용됐다는 사실을 재생기가 그 트랙을 실제로 선택했다는 뜻으로 표시하지 않아요.
  지난 수정본은 [자막 명세](subtitles.md#보관본과-적용본)대로 받은 날짜로 불러요.
- `최근 활동`은 몇 줄만 보여준 뒤 전체 기록을 따로 열어 종류별로 걸러 보고 해당 회차로 이동해요.
- `파일`은 작품 폴더와 파일 대응, 정리할 파일을 보여줘요.

### 보관 파일의 정리

보관 파일의 정리는 작품 상세의 `파일` 카드에서 그 작품의 지난 자막 수정본과 영상 대기 자막을 대상으로 파일 하나씩 해요.
정리는 누른 자리에서 대상 파일을 이름으로 밝히는 확인을 거치며, 전체 정리 대상을 한 목록에서 한 번에 지우는 기능은 두지 않아요.
실수로 넓게 지울 위험 때문에 선택한 제한이에요.
설정에는 작품별 용량과 정리할 수 있는 항목의 요약만 두어 해당 작품으로 이동해요.
자막을 정리하면 다른 자막이 쓰지 않는 폰트와 그 수정본만 쓰던 첨부도 함께 정리하며, 정리의 안전 조건은 [자막 명세의 보관본](subtitles.md#보관본과-적용본)을 따라요.
영상 수정본으로 대체한 이전 영상은 [대체 시점에 삭제](collection.md#영상-수정본의-대체)되므로 정리 대상이 아니에요.

## 남은 구체화

- 가져온 자료의 추가 시각을 앱 YAML로 교환·복원하는 방식은 [내보내기](settings.md#내보내기)·[가져오기](settings.md#앱-yaml)를 구현할 때 정하며, 출처 갱신일이나 파일 수정 시각으로 임의 대체하지 않아요.
- [시즌 정보](#시즌-정보)의 AniList 연결을 앱 YAML로 교환하는 필드는 [내보내기](settings.md#내보내기)를 구현할 때 정해요. 작품당 현재 표지의 `artwork`·`artwork_image`를 시즌 정보로 전용하지 않아요.
- 제품의 AniList 검색 정확도·이미지 수신·보관 경로, 구현 환경의 유한 자원 상한과 파일시스템 공개·복구 동작은 구현·검증이 필요해요.
  제공자 조건의 실제 적용을 확인하되, 고정 보관 기간이 문서에 없다는 사실을 무제한 보관·재배포 허가로 해석하지 않아요.
