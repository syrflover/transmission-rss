# 변경 명세와 티켓

이 폴더는 변경마다의 명세와 티켓을 담아요. 변경 명세는 한 번의 일이 무엇을 바꾸고 언제 끝났다고 볼지를 적고, 티켓은 그 일을 실행할 조각이에요.
지금 동작의 요구는 `docs/requirements/`의 주제별 명세 여섯 개가 담고, 명세마다 맡은 범위는 [웹 앱 공통 명세의 목표와 범위](../requirements/web-app.md#목표와-범위)에 있어요. 변경이 요구를 바꾸면 그 문서도 함께 고쳐요.

끝난 변경이 남긴 관찰 가운데 실제 서버를 쓰며 계속 지켜볼 것은 티켓으로 두지 말고 [열린 관찰 목록](../observations.md)에 모으세요.

## 변경 폴더

- 명세를 저장하거나 티켓을 쓰는 변경만 폴더를 만드세요. 둘 다 없는 변경은 폴더가 없어요.
- 폴더 이름은 `docs/specs/<YYYY-MM-DD>-<이름>/`으로 지으세요. 날짜는 폴더를 만든 날로 하고, 이름은 명세나 결과를 따라 영어로 지으세요.
- 날짜를 뺀 이름이 `docs/specs/`나 `docs/archive/specs/`에 이미 있으면, 시각을 붙이지 말고 더 구체적인 이름을 고르세요. 폴더 밖에서는 날짜를 뺀 이름으로 부르기 때문이에요.
- 폴더 이름은 만든 뒤에 바꾸지 마세요. 보관한 뒤에도 폴더 밖에서 부르는 이름이 그대로 맞게 하려는 거예요.
- 명세는 `spec.md`에 두고, 티켓은 그 옆에 두세요. 명세 없이 결과 하나를 위한 티켓만 둔 폴더도 있어요.

## 티켓

- 티켓 하나를 파일 하나에 두고, `0001-short-name.md`처럼 폴더 안에서 매긴 번호와 영어 이름으로 지으세요.
- 맨 위에 `상태`(`대기`·`진행 중`·`완료`·`보류`·`취소`), 출처, 막는 티켓을 적으세요. 막는 티켓이 없으면 바로 시작할 수 있어요.
- 상태를 모은 목록은 따로 두지 마세요. 목록은 티켓과 어긋나기 쉬워요.
- 본문은 `작업`과 `완료 기준`이고, 완료 기준은 checkbox 목록이에요. 상자는 그 기준을 뒷받침하는 증거를 적는 commit에서 체크하세요.
- 끝낸 티켓에는 `결과` 절을 더해 검증한 것, 검증하지 못한 것, 남은 일을 적으세요. 그 뒤에는 결과를 나중 작업에 맞춰 고쳐 쓰지 마세요.
- 구현이 주제별 명세와 어긋나면 명세를 구현에 맞춰 고치지 말고, 사용자 결정이나 결함으로 다루세요.

## 폴더 밖에서 부르는 이름

같은 폴더의 명세와 티켓끼리는 파일 이름으로 링크하세요.
폴더 밖에서는 변경을 날짜를 뺀 폴더 이름(`web-redesign`)으로, 티켓을 그 이름과 번호(`web-redesign/0129`)로 부르세요.
문서에서는 그 이름을 파일로 가는 링크의 글로 쓰고, commit 메시지와 code 주석에는 경로 없이 이름만 쓰세요. 보관하면 폴더가 옮겨지는데, 그때 고쳐지는 것은 문서의 링크뿐이에요.

## 끝난 변경의 보관

변경의 범위가 끝나거나 취소되거나 다른 변경으로 대체되면, 그 사실을 기록하는 변경에서 폴더 전체를 `docs/archive/specs/`로 옮기고 들어오고 나가는 링크를 고치세요.
명세에 끝나지 않은 범위가 남아 있으면, 티켓이 모두 끝났어도 폴더는 그대로 둬요.
보관한 문서는 QMD의 `archive` 컬렉션에 들어가 기본 검색에서 빠지고, 컬렉션을 지정하면 찾을 수 있어요.
