# 설정과 이전 명세

## 목표와 범위

외부 YAML을 읽기만 하던 실행 기준을 앱이 소유하는 설정으로 옮기고, 기존 설정과 보관 관계를 잃지 않고 가져오거나 다른 환경으로 옮길 수 있게 해요.
설정 화면은 자주 열지 않으므로 들어가지 않고도 지금 상태를 읽을 수 있어야 하고, 가져오기는 사용자가 고른 것만 바꾸며 무엇이 없어지는지 적용 전에 보여줘야 해요.

이 문서는 앱 소유 설정과 배포 설정의 경계, 공통 정책, 설정 화면, 앱 YAML의 구성과 필드, 가져오기·내보내기, 처음 실행의 요구를 담당해요.
YAML 필드의 동작 의미는 해당 기능 문서에 있어요: 채널·규칙·구독은 [RSS 수집 명세](collection.md), 작품·회차 대응·표지는 [라이브러리와 작품 명세](library.md), 보관본·폰트는 [자막 명세](subtitles.md#보관본과-적용본)예요.
결정 기록은 [앱 설정 ADR](../adr/0001-app-managed-download-rules.md)과 [저장소 ADR](../adr/0005-local-sqlite-app-state.md), 근거와 선택 배경은 [웹 재설계 주제 문서](../brainstorm/web-redesign.md#설정-화면의-구성)에 있어요.

## 요구사항과 완료 기준

### 앱이 소유하는 설정

- 실행 기준은 앱이 관리하는 설정으로 전환해요.
  웹에서 저장한 채널·규칙·구독을 다음 처리에 사용하고, 기존 `CHANNELS_CONFIG_URL`의 외부 YAML 변경이 앱 설정을 계속 덮어쓰는 경로는 남기지 않아요.
- Transmission 접속 주소·기존 속도 제한·큐 크기, 서버 포트와 DB·앱 데이터 폴더 위치는 환경 변수·배포 설정으로 분리하며, 웹이나 앱 YAML의 가져오기·내보내기로 변경하지 않아요.
  새 환경에서 이 값은 별도로 설정하고, 기존 RSS 처리의 Transmission 설정 적용 동작은 유지해요.
- 설정 변경은 [웹 명령과 상태 갱신](web-app.md#웹-명령과-상태-갱신)의 버전 계약을 따라요.

### 공통 정책

- 자막 형식 우선순위는 `ASS`·`SRT`·`SMI`를 각각 한 번씩 담은 순서이고, 위아래 이동으로 바꿔요.
  작품별로 전역 순서를 재정의한 작품을 목록으로 보여주고 그 작품으로 이동해요. 작품의 순서는 작품 상세의 [`자막` 카드](library.md#오른쪽-카드-열)에서 정하고 되돌려요(0072).
- 브라우저 유휴 시간(기본 5분)과 동시 작업 수(기본 1개)는 양의 정수이며, 구현에서 명시한 지원 상한 안에서만 저장해요.
  유휴 시간이 지나면 원격 브라우저가 닫히지만 인증 필요 작업은 남고 작업을 열면 다시 준비된다는 것을 한 문장으로 알려요([브라우저 수명](jobs.md#작업-화면-안의-인증과-브라우저-수명)).
- 자막 형식과 브라우저는 한 정책 버전을 함께 쓰므로 저장 줄도 하나예요.
  값을 바꾸면 `저장`·`되돌리기`가 있는 저장 줄이 나타나고, 마지막 저장 시각을 보여줘요.
- 다른 화면이 먼저 저장해 저장이 거부되면 입력한 값을 버리지 않고 서버 값과 나란히 보여주며, 까닭을 문장으로 알린 배너와 `서버 값 사용`·`내 값으로 다시 저장`을 둬요.
  `내 값으로 다시 저장`은 새 서버 버전을 기준으로 다시 저장하는 명시적인 동작이며, 거부된 요청을 자동으로 재시도하지 않아요.

| 입력·상태 | 필요한 결과 |
| --- | --- |
| 형식 순서를 SMI를 두 번 넣어 저장하려 함 | 화면에서 만들 수 없고, API로 보내도 변경 없이 거부돼요. |
| 두 화면에서 같은 정책 버전을 열고 한쪽이 먼저 저장 | 다른 쪽 저장은 거부되고 입력값과 서버 값이 나란히 남아요. 어느 값도 조용히 덮어쓰이지 않아요. |
| 동시 작업 수를 0이나 상한 초과로 입력 | 저장하지 않고 허용 범위를 문장으로 알려요. |

### 설정 화면

설정은 항목 목록에 현재 값을 보여주고, 항목을 누르면 내용이 열리는 목록·상세형이에요.
PC에서는 수집 화면 규칙 탭처럼 왼쪽 목록과 오른쪽 내용이고, 휴대폰에서는 항목이 뒤로 가기가 되는 자기 화면으로 열려요.
목록의 각 항목은 `ASS → SMI → SRT`·`폴더 2개`·`마지막 내보내기 9월 1일 12:10`처럼 들어가지 않고 읽을 수 있는 현재 값을 보여줘요.

| 묶음 | 항목 | 내용 |
| --- | --- | --- |
| 공통 정책 | 자막 형식·브라우저 | [공통 정책](#공통-정책)이에요. |
| 수집 | 수집 폴더 | 수집 폴더와 보관 폴더이며, 요구는 [수집 폴더와 보관 폴더](collection.md#수집-폴더와-보관-폴더)에 있어요. 목록에는 `Shows (current) · 보관 Shows`처럼 두 폴더의 이름을 보여줘요. |
| 라이브러리 | 감시 폴더 | 폴더 목록·추가·다시 확인·등록 해제이며, 요구는 [작품 발견과 감시 폴더](library.md#작품-발견과-감시-폴더)에 있어요. |
| 라이브러리 | 파일 용량과 정리 | 보관한 자막·폰트·첨부·표지의 용량과 정리할 것이 있는 작품 목록이에요. 작품·종류·개수·용량을 줄마다 보여주고 그 작품으로 이동만 하며, 정리는 [작품 상세에서 파일 하나씩](library.md#보관-파일의-정리) 한다고 한 문장으로 알려요. 여러 파일을 한 번에 지우는 기능은 두지 않아요. |
| 데이터 | 내보내기·가져오기 | [내보내기](#내보내기)와 [가져오기](#가져오기)예요. |
| 배포 | 배포 설정 | Transmission 주소·서버 포트·DB 위치 같은 배포 값을 읽기 전용으로 보여주고, 배포 설정에서만 바뀐다고 한 문장으로 알려요. 비밀 값은 가려요. |

화면 모드는 상단의 전환 버튼이 맡으므로 설정에 두지 않아요.

### 앱 YAML의 구성

앱 YAML은 `version: 1`과 `settings`·`library` 영역으로 구성해요.
규칙은 채널 안의 순서 있는 목록으로 두고, 보관 정보는 작품별로 묶어 설정의 작품 ID를 참조해요.
DB 테이블을 그대로 덤프하는 형식이 아니며, YAML의 버전은 앱 릴리스나 SQLite 스키마 버전과 구분해요.
아래 필드 이름은 교환 계약의 방향이며, 표에 없는 세부 이름은 구현 전에 이 문서에서 확정해요.

| 영역 | 담는 정보와 관계 |
| --- | --- |
| `settings.collection` | 수집 폴더 `folder`와 보관 폴더 `archive_folder`예요. 보관 폴더를 두지 않으면 `null`이에요. |
| `settings.channels` | 안정적인 채널 ID, 선택적 표시 이름 `name`, `url`·`excludes`, 쿼리 값별 비밀 여부, 지난 회차 검색 형식, 채널 안의 순서 있는 `rules` 목록이에요. |
| `settings.channels[].rules` | 안정적인 규칙 ID, 기존 `match`·`regex`·`case_insensitive`·`directory`·`episode`의 의미, 규칙 상태와 선택적 구독 정보예요. `directory`는 수집 폴더 기준이에요. |
| `settings.watch_folders` | 감시 폴더의 안정적인 ID와 앱에서 접근하는 경로예요. |
| `settings.works` | 작품 ID와 작품 폴더, 작품 안의 시즌 및 확인한 Anissia 연결·출처별 회차 대응, 작품 표지 선택 상태를 담아요. |
| `settings.subtitle_policy` | 전역 형식 우선순위이며, 작품별 재정의는 해당 작품 설정에 둬요. |
| `settings.browser` | 유휴 시간을 초로 나타내는 `idle_timeout_seconds`와 동시 작업 상한 `max_concurrent_jobs`예요. |
| `library.works` | 설정의 작품 ID별로 보관본·수정본·출처·자산과 폰트 연결 및 현재 표지 이미지의 메타데이터를 묶어요. 실제 적용 여부를 확정하는 권한이나 작업 재개 지시는 담지 않아요. |

#### 채널과 규칙 필드

| 위치 | 필드와 의미 |
| --- | --- |
| `channels[].name` | 채널의 표시 이름이며 선택이에요. 앞뒤 공백을 지우고, 비었거나 없으면 `null`이에요. 이름이 없으면 화면은 `url`의 호스트를 보여줘요. |
| `channels[].url` | 비밀로 표시한 쿼리 값을 비운 URL이에요. 비밀인 쿼리 이름을 `secret_query` 목록에 담고, 내보내기에는 비밀 값을 싣지 않아요([채널 URL의 비밀 값](collection.md#채널-url의-비밀-값)). |
| `channels[].past_search` | `[SubsPlease] {match} 1080p` 같은 지난 회차 검색 형식이며, 없으면 `null`이에요. `{match}`는 규칙의 일치 문구로 바꾸는 자리예요. |
| `rules[].state` | `active`·`paused`·`archived`이에요. `paused`는 `영상 받기`를 끈 규칙이고 `archived`는 보관한 규칙이며, 둘 다 순서를 유지한 채 수집하지 않아요([방영작 구독](collection.md#방영작-구독), [규칙 보관](collection.md#규칙-보관)). |
| `rules[].match` | 제목 대기 구독은 빈 문자열이 아니라 `null`이에요. `null`인 규칙은 어떤 항목에도 맞지 않아요. |
| `rules[].episode_auto` | 회차 변환을 자동으로 정했으면 `true`이고, 사용자가 직접 넣었으면 `false`예요([영상 회차 변환](collection.md#영상-회차-변환)). |
| `rules[].subscription` | 방영작 구독이면 `anissia_anime_no`, 자막을 받는 방식 `subtitles`(`follow`·`undecided`·`none`, 각각 제작자 따라 받기·제작자 미정·받지 않음), 따라갈 자막 제작자 `creator`(`follow`면 값이 있고 `undecided`면 `null`이며, `none`이면 `자막 받기`를 끄기 전의 제작자를 남겨 다시 켤 때 되돌려요), 규칙이 받은 영상이 속하는 `season_id`(아직 없으면 `null`)를 담고, 구독이 아닌 규칙은 `null`이에요. `season_id`가 있으면 그 시즌의 `anissia_anime_no`와 같아야 하며, 다르면 가져오기를 거부해요. |

기존 `episode`는 영상 이름 변경에 전달하는 값이며, 자막 출처의 회차 대응으로 전용하거나 복사하지 않아요.
앱이 회차 변환을 정하기 전의 값과 앱이 그 규칙을 이미 한 번 정했다는 사실은 내보내지 않아요. 그 전 값은 이 설치의 worker가 붙인 영상 이름을 [되돌리는](collection.md#영상-회차-변환) 데만 쓰는데, 가져온 설치에는 그 영상의 수집 이력이 없기 때문이에요. `episode_auto`가 `true`인 규칙을 가져오면 앱이 이미 정한 규칙으로 보고 다시 자동으로 정하지 않아요.
ID가 없는 기존 YAML에서 새 앱 항목을 추가할 때도 새 ID를 발급하고, 기존 파일에 없는 작품 연결·회차 대응을 추측해 생성하지 않아요.
수집 이력, 작업 이력·큐·과거 승인은 앱 YAML에 담지 않아요.

#### 작품·회차 대응 필드

ID는 비어 있지 않은 문자열이며, 문서 안에서 항목을 선언하는 ID는 중복될 수 없어요.
참조는 해당 종류와 작품 범위의 항목으로 연결되어야 하며, 표시 이름·경로·외부 사이트의 번호를 앱 ID로 대신하지 않아요.
아래의 선택적 관찰값은 생략하거나 `null`이면 미상이며, 빈 문자열이나 추측값으로 사실을 만들어 채우지 않아요.
대응의 적용 순서·숫자 키·보류 조건은 [자막의 회차 대응](library.md#자막의-회차-대응)을 따라요.

| 위치 | 필드와 의미 |
| --- | --- |
| `settings.works[]` | `id`, 앱이 접근하는 작품 폴더 `directory`, `seasons`, 선택적 작품별 `subtitle_policy`와 `artwork`예요. 자막 정책이 없으면 전역 값을 사용해요. |
| `seasons[]` | `id`, 0 이상 정수인 `number`, 작품 폴더 기준 상대 경로 `directory`, 확인한 `anissia_anime_no`, `sources`, `episode_mappings`예요. 미연결 Anissia 번호는 `null`이에요. |
| `sources[]` | `id`와 출처를 구분하는 `label`, 관찰한 `creator`·`site`를 담는 자막 출처 연결(Subtitle Source Binding)이에요. 한 웹사이트의 모든 제작자·릴리스가 같은 회차 체계를 쓴다고 간주하지 않아요. |
| `episode_mappings[]` | `id`, 같은 시즌의 `source_id`, 번호의 근거인 `basis`, `mode`, `overrides`와 조건부 `offset`, 구독 제작자 출처의 대응을 근거로 자동으로 정했는지 나타내는 `auto`예요([자막의 회차 대응](library.md#자막의-회차-대응)). |
| `basis` | Anissia 후보의 회차를 쓰는 `anissia` 또는 첨부에서 확인한 회차를 쓰는 `attachment`예요. |
| `mode`·`offset` | `offset` 모드는 정수 차이 `offset`을 적용하고, `explicit` 모드는 명시한 대응만 사용하므로 `offset` 필드를 두지 않아요. |
| `overrides[]` | 출처의 회차 문자열 `source_episode`와 0 이상 정수인 `local_episode`의 쌍이며, 기본 차이보다 먼저 적용하는 명시적 대응이에요. |

#### 작품 표지 필드

표지의 선택 동작과 파일 수명은 [작품 표지](library.md#작품-표지)를 따라요.
선택 상태는 `settings.works[].artwork`에, 현재 이미지의 관계와 기대 바이트 정보는 `library.works[].artwork_image`에 두고, 실제 이미지 바이트는 YAML에 담지 않아요.
새 내보내기는 모든 설정 작품에 `artwork` 객체를 쓰고, 보관 자막이 없어도 대응하는 `library.works[]` 항목과 명시적인 `artwork_image` 값 또는 `null`을 써요.
예전 `version: 1` 입력에서 작품의 두 표지 필드가 모두 생략됐으면 자동 미선택 상태로 읽으며, 해당 작품의 보관 항목 자체가 없는 경우도 `artwork_image` 생략으로 취급해요.
한쪽 필드만 생략됐거나 `artwork: null`인 입력은 거부하고, 명시적인 `artwork_image: null`은 아래 상태 관계에 따라 검증해요.

| 위치 | 필드와 불변 관계 |
| --- | --- |
| `settings.works[].artwork` | `mode`는 `auto`·`manual`·`disabled`, `source`는 선택이 있으면 `anilist`·`upload`, `anilist_media_id`는 AniList 작품을 선택했을 때만 유효한 양의 정수 제공자 ID, `image_id`는 현재 이미지의 앱 ID이며, 제공자 ID는 앱 ID가 아니에요. |
| `library.works[].artwork_image` | 작품당 현재 이미지 하나 또는 `null`이며 `id`, `origin`(`anilist`·`upload`), 앱 데이터 폴더 기준 `relative_path`, 0 이상 정수 `byte_size`, 소문자 64자리 16진수 `sha256`, 검증한 이미지 `format`(`jpeg`·`png`·`webp`)을 담고, `id`는 앱이 발급하며 파일명이나 제공자 ID를 대신 쓰지 않아요. |

- `mode: auto`의 미선택 상태는 `source`·`anilist_media_id`·`image_id`가 모두 `null`이고 `artwork_image`도 `null`이에요.
- 명확한 후보를 자동 선택하면 `mode: auto`, `source: anilist`, 선택한 `anilist_media_id`를 기록하며, 이미지가 아직 준비되지 않았거나 사라졌을 때도 그 선택은 유지해요.
  이 경우에만 `source: anilist`·`anilist_media_id`가 있고 `image_id`와 `artwork_image`가 `null`일 수 있어요.
- `mode: manual`은 사용자가 고른 AniList 작품이면 `source: anilist`와 그 `anilist_media_id`, 직접 올린 파일이면 `source: upload`와 `anilist_media_id: null`을 기록해요.
- `mode: disabled`는 `source`·`anilist_media_id`·`image_id`가 `null`이고 `artwork_image`도 `null`이에요.
- 선택된 이미지의 `image_id`는 같은 작품 `artwork_image.id`를 참조하고, 파일이 없어도 이 참조와 기대 크기·해시·출처를 유지해요.
  이미지가 있으면 `origin`은 선택의 `source`와 같아야 해요.
- `auto`와 `upload`의 조합, 선택 없는 `manual`, 이미지 메타데이터 참조가 없는 `manual`은 허용하지 않아요.
- 표지의 이력은 YAML에도 남기지 않아요.

가져오기에서 `settings.works`의 선택적 추가·지정 교체와 `library.works`의 관계를 같은 계획에서 검토하며, 선택하지 않은 작품의 표지와 파일은 유지해요.
복제한 작품의 앱 ID·`artwork_image.id`·`image_id` 참조는 함께 새로 발급·연결하고, 기존 작품 교체는 작품 ID를 유지하되 이미지 ID의 충돌·참조를 검증해요.
이 과정은 가져온 상대 경로의 물리적 파일을 새 ID 이름으로 바꾸거나 옮겼다는 뜻이 아니며, 경로가 현재 앱 데이터 폴더에서 검증되지 않으면 이미지를 사용 가능으로 표시하지 않아요.

| 입력·상태 | 필요한 결과 |
| --- | --- |
| 보관 항목 자체가 없는 예전 작품, 두 표지 필드 생략 | 자동 미선택으로 복원해요. 새 내보내기의 빈 작품도 명시적인 자동 미선택 객체와 `artwork_image: null`로 왕복해요. |
| `artwork: null`, 한쪽 생략, `auto`·업로드 조합, 이미지 참조 없는 수동 상태, 어긋난 참조·ID | 변경 없이 거부해요. |

#### 보관 관계 필드

| 위치 | 필드와 의미 |
| --- | --- |
| `library.works[]` | 설정의 작품을 가리키는 `work_id`, `packages`·`stored_subtitles`·`assets` 목록과 위에서 정의한 `artwork_image`예요. 기록이 전혀 없는 작품의 세 목록은 `[]`이에요. |
| `packages[]` | `id`, 수신 경로 종류 `source_kind`, 관찰한 게시물 `source_page`, 선택적 `received_at`, `entries`예요. 수신 시각은 시간대가 명시된 시각이며 모르면 비워 둬요. |
| `entries[]` | `asset_id`, 출처가 제공한 원래 파일명·묶음 내부 이름인 `original_name`, 선택적 `source_file_date`예요. 같은 폰트가 다른 이름·보고 날짜로 들어와도 각 출처의 관찰값을 보존해요. |
| `assets[]` | `id`, `kind`, 기준 위치 `base`, 그 기준의 `relative_path`, 0 이상 정수 `byte_size`, 소문자 64자리 16진수 `sha256`예요. |
| `kind`·`base` | `subtitle`·`font`는 미지원 형식의 자막을 포함해 `base: work`이고 작품 폴더의 `.trss/subtitles/` 안에 있어요. `attachment`·`companion`·`other`는 `base: app_data`이고 앱 데이터 폴더 안에 있어요. `kind`만으로 실제 형식이나 자동 적용 지원을 확정하지 않아요. |
| `stored_subtitles[]` | 특정 보관 수정본의 `id`, `package_id`, `subtitle_asset_id`, 선택적 `source_id`, 원래 회차 관찰값 `source_episodes`, 현재 연결의 근거 `assignment`, 관찰한 `format`·`encoding`·`creator`·`language`·`purpose`·`release`·`revision_label`, `font_asset_ids`·`attachment_asset_ids`·`companion_asset_ids`예요. |
| `source_episodes` | 관찰 가능한 `anissia`·`attachment` 회차를 각각 원래 문자열로 담아요. 모르는 번호를 다른 쪽 값이나 현재 적용 경로로 채우지 않아요. |
| `assignment` | `mode: mapped`이면 `mapping_id`를 참조하고 그 대응의 `basis`와 원래 회차로 현재 대상을 계산해요. `mode: explicit`이면 사용자가 직접 연결한 `season_id`·`episode`를 담아요. 미연결은 `null`이며 두 방식을 섞지 않아요. |
| 출처 관찰 정보 | 보관본의 선택적 `anissia_observation`에 `anime_no`·`episode`·`creator`·`website`·`updDt_raw`를 보존해요. 특정 파일과 해당 후보의 관계를 확인하지 못했다면 이 객체로 연결을 확정하지 않아요. |

경로와 표시 이름을 ID로 쓰지 않으므로, 파일 이름 변경이 곧 다른 작품이나 자산의 생성은 아니에요.
보관본의 ID가 수정본을 구분하며, `revision_label`은 관찰한 표시에 불과해요.
날짜·파일명·크기로 이전 수정본과의 계보를 추측해 생성하지 않으며, 서로 다른 보관본이 같은 바이트의 자산을 참조할 수 있어요.
의존 자산 목록은 `null`이면 관계 미확인, `[]`이면 분석에서 연결된 자산이 없었다는 뜻이고, 사용자 기기에 필요한 폰트가 없다는 뜻은 아니에요.
같은 제작자 폴더의 검증된 동일 폰트는 한 자산으로 재사용하고, 가져오기 계획에서도 새 보관본의 ID 발급과 기존 폰트 자산의 재사용을 구분해 참조를 연결해요.
패키지의 `entries`는 미선택·미지원 파일의 출처도 남기며, 패키지에 포함됐다는 사실로 적용 권한을 만들지 않아요.

`updDt_raw`는 원문을 남겨 `Asia/Seoul` 규칙으로 해석하고, 부재와 해석 실패를 구분해요.
`source_file_date`는 제공된 원문 `raw`, 근거 `origin`, 확인 가능한 시간대 `timezone`을 가진 관찰값이며, 모르는 시간대를 서버 시간대로 보충하지 않아요.
Anissia 후보 갱신일·출처에서 보고한 파일 날짜·앱 수신 시각·현재 파일시스템 시각을 서로 대체하거나 최초 공개일로 단정하지 않아요.
게시물 출처에 쿠키·인증 토큰·만료되는 서명 다운로드 URL을 저장해 내보내지 않아요.

#### 가져오기 검증과 파일 가용성

필수 필드·자료형·열거값·참조 종류·작품 범위와 선택한 항목의 참조 연결을 변경 전에 검증해요.
새 형식의 알 수 없는 필드, 중복 YAML 키, 잘못된 값은 조용히 무시하지 않고 해당 위치를 표시해 반영을 거부해요.
미지원 버전이나 중복 ID를 가진 입력은 변경 없이 거부해요.
형식 우선순위는 지원하는 `ass`·`srt`·`smi`를 각각 한 번 포함하고, 브라우저 시간·동시 작업 수는 양의 정수이며 지원 상한을 넘어설 수 없어요.

`base: work`의 상대 경로는 확인한 작품 폴더의 `.trss/subtitles/` 밖으로, `base: app_data`와 표지의 상대 경로는 앱 데이터 폴더 밖으로 나갈 수 없어요.
절대 경로·`..`·심볼릭 링크를 통한 이탈을 허용하지 않으며, `original_name`과 업로드 파일명은 표시용 원문이지 파일을 쓸 경로가 아니에요.

구조와 참조가 올바른 보관 정보는 실제 파일이 없어도 복원하되, 파일의 크기와 SHA-256을 대조해 `available`·`missing`·`mismatch`·`unverified`로 현재 가용성을 구분해요.
화면에서는 `확인`·`누락`·`내용 다름`과 개수, 해당 목록으로 보여줘요.
접근 거부나 검사 실패는 `missing`이나 동일 내용으로 바꾸지 않아요.
이 가용성은 가져온 선언을 신뢰하는 값이 아니라 현재 환경에서 새로 검사한 결과이며, YAML로 이전 환경의 검증 완료 상태를 가져오지 않아요.
파일이 누락되거나 내용이 다르면 관계와 기대 크기·해시는 유지하고, 올바른 파일을 옮긴 뒤 다시 검증할 수 있게 해요.
관계·자료형·경로 자체가 잘못된 입력까지 정상 메타데이터로 받아들이는 예외는 아니에요.
미선택 기록이나 기대 해시를 실제 파일에 맞춰 자동 수정하지 않으며, 사용할 수 없는 자산의 적용을 막아요.
바이트 일치는 파일의 가용성만 확인하므로, 실제 자막 형식·내용 판독과 지원 여부도 확인해야 적용할 수 있어요.
가져온 표지의 `available`은 일반 파일의 위치·크기·SHA-256 및 형식 서명·헤더로 판별한 실제 이미지 형식([이미지 파일의 수명](library.md#이미지-파일의-수명))을 현재 앱 데이터 폴더에서 확인한 결과에만 부여하고, 검사 실패는 선택 자체를 삭제하거나 임의의 제공자 이미지로 교체하는 대신 표지 미표시와 복구 가능한 상태로 보여줘요.
같은 이름·다른 바이트, 다른 이름·보고 날짜로 받은 같은 폰트의 자산 재사용과 출처별 관찰값 보존, 누락 후 올바른 파일 추가, 내용 불일치 후 재검증, 선택하지 않은 참조의 보존을 각각 확인해요.

### 내보내기

- 내보내기는 채널·규칙·구독, 감시 폴더, 작품 연결, 회차 대응·자막 정책·표지 선택과 보관 자막·폰트·첨부·표지 이미지의 관계 및 제작자·출처·회차·수정본 정보를 담아요.
  새 환경에서 실제 파일과 함께 가져와 설정과 보관 관계를 복원할 수 있어야 해요.
  수정본 정보에는 erulabo 수신 기록의 Drive 파일 ID(`drive_id`)를 넣지 않아요. 열쇠 구실을 하는 주소라서 로그와 같이 내보내기에도 남기지 않아요([구독 제작자 자동 수신](subtitles.md#구독-제작자-자동-수신)).
- 작업 이력·큐·과거 승인, 수집 이력, 채널 URL의 비밀 값, 영상·자막·폰트·표지 이미지 바이트는 담지 않아요.
  화면에는 담는 것을 개수로, 담지 않는 것을 목록으로 보여주고 마지막 내보내기 시각을 둬요.
- 구버전 trss용 YAML이나 전체 DB·파일 백업으로 안내하지 않아요.
  작품 폴더의 `.trss/`는 작품 폴더와 함께 옮기고, 표지·첨부는 앱 데이터 폴더의 파일 영역을 상대 경로 그대로 새 환경의 파일 영역에 복사해야 복원된다는 것을 문장으로 알려요.
  DB 파일 자체를 옮기라고 안내하지 않아요.
- 내보내기는 일관된 DB 읽기 시점의 설정·보관 관계를 사용하되, 실제 파일을 함께 백업했다는 뜻은 아니에요.
- 보관 정보는 SQLite에만 유지하고 작품 폴더에 복원용 목록이나 사이드카 매니페스트를 상시 저장하지 않아요.

### 가져오기

가져오기는 `파일 선택` → `검토` → `결과`의 세 단계이며, 단계 표시와 아래 동작 줄은 [지난 회차 검색](collection.md#지난-회차-검색)의 단계 흐름과 같은 모양이에요.
가져오는 행위는 다운로드·자막 적용·파일 정리·표지 수신을 실행하지 않고 과거 승인을 되살리지 않으며, 결과 단계에서 이를 문장으로 알려요.
선택하지 않은 항목, 가져온 파일에 없는 기존 설정·보관 정보, 작업 이력, 실제 영상·자막 파일은 교체로 명시한 경우를 빼고 적용 전후에 그대로 남아요.
이름·조건 유사성으로 규칙을 임의 병합하거나 자막 연결 설정을 바꾸지 않아요.

- **파일 선택**: 파일을 고르면 기존 YAML인지 앱 YAML인지 알아보고, 읽을 수 없거나 거부할 파일은 까닭을 실패로 보여주며 아무것도 바꾸지 않고 다음 단계로 가지 않아요.
- **결과**: 추가·교체·그대로 남은 것과 없앤 규칙의 개수를 문장과 개수로 보여줘요.

#### 기존 YAML

기존 YAML은 transmission-rss에서 쓰던 형식이에요.
채널 단위로 가져오고 채널 순서와 채널 안의 규칙 순서를 파일 그대로 보존하며, 기본값이 생략된 기존 YAML을 읽을 수 있어야 해요.

- 이미 있는 채널은 `교체`·`추가`·`건너뛰기` 중 하나를 채널마다 고르고, 각 선택지는 무엇을 하는지 문장으로 설명해요.
  - `교체`는 채널을 파일 내용으로 통째로 바꿔요.
    파일에 없는 지금 규칙은 없어지고, 그 규칙으로 받은 파일과 보관 기록은 남아요.
    교체를 고르면 없어질 규칙 이름을 검토 단계에서 바로 보여주고, 결과에는 없앤 개수를 따로 적어요.
    제목 대기 구독은 기존 YAML에 쓸 수 없어서 교체해도 없애지 않고 규칙·구독·편성 연결을 그대로 남겨요(사용자 결정, 2026-10-02).
    검토 단계는 `제목 대기 구독 2개는 그대로 남겨요.`처럼 남는 개수를 알리고(0개면 알리지 않아요), 결과에도 적어요.
    구독인 규칙의 저장 폴더는 규칙을 저장할 때와 같은 작품 폴더 검사를 거쳐요. 파일의 폴더가 수집 폴더 자체(폴더 없음, `.`)이거나 `..`를 담으면 그 구독은 지금 저장 폴더를 그대로 두고(나머지 값은 파일대로 바꿔요), 검토 단계와 결과가 그 사실을 구독마다 알려요. 이 때문에 가져오기가 실패하지는 않아요.
  - `추가`는 채널과 규칙을 새 ID를 붙인 복사본으로 더하며, 기존 채널과 규칙은 건드리지 않아요.
  - `건너뛰기`는 그 채널을 가져오지 않고, 그 채널의 구독 제안도 함께 빼요.
- 이미 있는 채널의 선택지는 아무것도 고르지 않은 상태로 시작하고, 모든 채널을 고르기 전에는 `가져오기`를 누를 수 없어요.
  규칙을 없애는 교체가 기본으로 골라져 있으면 모르고 넘어갈 수 있기 때문이에요.
  파일에 있는 규칙만 바꾸고 나머지를 남기는 안은 `교체`라는 이름과 동작이 어긋나고 채널 안 규칙 순서가 섞여서 두지 않아요.
- 지금 없는 채널은 묻지 않고 새로 추가해요.
- 가져온 채널의 URL 쿼리 값은 모두 비밀로 두고 시작해요.
- 채널의 `directory`는 [수집 폴더](collection.md#수집-폴더와-보관-폴더)에 맞춰요. 수집 폴더가 아직 없으면 파일의 채널 폴더로 정하고(채널마다 다르면 공통 상위 폴더), 수집 폴더 안의 채널 폴더는 규칙 저장 폴더 앞에 남은 부분을 붙여 가져와요. 수집 폴더 밖의 채널은 검토 단계에서 까닭과 함께 알리고 가져오지 않아요.
- `match`가 빈 규칙이 있는 파일은 파일 선택 단계에서 그 규칙의 위치와 까닭을 알리고 가져오지 않아요.
  transmission-rss에서는 모든 항목에 맞는 규칙이지만 앱에는 그런 규칙이 없고 빈 일치 문구는 `제목 대기`라서, 어느 쪽으로 읽어도 파일의 뜻이 바뀌기 때문이에요.
- 규칙 목록은 평가 순서와 일치 문구·저장 폴더·회차 변환을 보여주고, 규칙 위 주석에서 Anissia 작품 주소와 자막 제작자를 읽어 구독 제안을 만들어요.
  주석은 사람이 쓴 형식이라 약한 근거이므로, 체크한 제안만 구독으로 만들고 나머지는 규칙만 가져와요.

| 주석 | 필요한 결과 |
| --- | --- |
| Anissia 주소와 제작자를 읽음 | 방영 요일·시간과 제작자를 보인 구독 제안이며, 처음부터 체크돼 있어요. |
| Anissia 주소는 읽었지만 제작자가 없음 | `제작자 미정` 구독 제안이며, 제작자를 나중에 정해야 하므로 처음에는 체크하지 않아요. |
| 주석이 있지만 읽을 수 없음 | `주석을 읽을 수 없음`과 `Anissia 주소 형식이 달라서` 같은 까닭을 문장으로 보여주고, 규칙만 가져와요. |
| 주석 없음 | `주석 없음`으로 표시하고 규칙만 가져와요. |

채널마다 제안을 `모두 선택`·`모두 해제`할 수 있고, 네 경우의 개수를 개수 칩으로 보여줘요.

#### 앱 YAML

- 채널 안에서 규칙별로 골라 추가하거나 지정한 기존 규칙을 교체하며, 선택하지 않은 규칙은 유지해요.
  추가·교체되는 규칙과 최종 평가 순서를 적용 전에 보여줘요.
- 항목의 안정적인 ID와 참조를 보존하되, 같은 이름·조건만으로 기존 항목에 덮어쓰지 않아요.
  추가로 복제하는 항목에는 새 ID를 부여하고 그 참조를 함께 연결하며, 지정한 기존 항목을 교체할 때는 그 항목의 ID를 유지해요.
- 비어 있는 채널 URL의 비밀 값은 검토 단계에서 다시 입력받고, 입력하지 않은 채널은 비밀 값이 비어 있어 수집할 수 없다고 알려요.
  지정한 기존 채널을 교체할 때 비밀 값만 비어 있으면 지금 저장된 비밀 값을 유지하고, 그 사실을 검토 단계에서 보여줘요.
- 보관 정보는 [가용성 검사](#가져오기-검증과-파일-가용성) 결과를 `확인`·`누락`·`내용 다름`의 개수와 목록으로 보여주며, 누락·내용 다름을 정상 복원으로 표시하지 않아요.
- 참조가 풀리지 않은 감시 폴더는 필요한 연결(경로와 그 폴더를 쓰는 작품 수)로 보여주고, 기존 감시 폴더를 골라 연결하기 전에는 적용을 막아요.
- 작품 폴더를 옮긴 환경에서는 작품의 `directory`를 새 위치로 지정하고 `.trss/`의 상대 경로를 새 폴더에서 다시 검사해요.
  새 폴더에 파일이 없으면 관계·기대 내용 정보는 보존하되 누락으로 표시하고, 기존 위치의 파일을 자동으로 옮기거나 삭제하지 않아요.

| 입력·상태 | 필요한 결과 |
| --- | --- |
| 지금 채널 A에 규칙 5개, 기존 YAML의 A에 규칙 3개(겹치는 것 2개)를 교체로 고름 | 검토 단계에 없어질 규칙 3개의 이름이 보이고, 결과에 없앤 규칙 3개가 따로 적혀요. 그 규칙으로 받은 파일과 보관 기록은 남아요. |
| 지금 채널 A에 일반 규칙 하나와 제목 대기 구독 하나, 기존 YAML의 A에 다른 규칙 하나를 교체로 고름 | 일반 규칙은 파일의 규칙으로 바뀌고 제목 대기 구독은 규칙·구독·편성 연결이 그대로 남아요. 검토 단계에 `제목 대기 구독 1개는 그대로 남겨요.`가 보여요. |
| 지금 채널 A의 구독 규칙에 대해 기존 YAML의 같은 규칙이 저장 폴더로 수집 폴더 자체를 가리키는데 교체를 고름 | 그 구독의 저장 폴더는 지금 값 그대로이고(규칙 상세에서 계속 저장할 수 있어요), 검토 단계와 결과가 그 사실을 알려요. 구독이 아닌 규칙은 파일의 폴더를 써요. |
| 이미 있는 채널 두 개 중 하나만 고름 | `가져오기`가 비활성이고 남은 채널 수를 문장으로 알려요. |
| 앱 YAML에서 규칙 하나만 골라 추가 | 새 ID의 규칙 하나만 더해지고, 최종 평가 순서가 적용 전에 보여요. 선택하지 않은 규칙과 기존 규칙은 그대로예요. |
| 앱 YAML의 감시 폴더 `/mnt/nas/anime`가 이 환경에 없음 | 적용이 막히고, 기존 감시 폴더를 고르면 적용할 수 있어요. |
| 미지원 `version`, 중복 ID, 알 수 없는 필드 | 파일 선택 단계에서 위치와 까닭을 보여주고 아무것도 바꾸지 않아요. |

### 처음 실행

처음 실행은 이번 주 편성 자리에 `처음 설정` 체크리스트를 보여주고, 단계는 `감시 폴더 등록`과 `기존 설정 가져오기` 두 개예요.
설치 때 한 번 거치는 과정이라, 강제 마법사 대신 건너뛸 수 있는 체크리스트로 둬요.

- 각 단계의 버튼은 설정의 감시 폴더와 가져오기로 이어지고, 폴더를 하나 추가하거나, 가져오기를 적용해서 채널·규칙·구독을 하나라도 만들거나 바꾸면 그 단계가 끝나요. 모든 채널을 건너뛰어 아무것도 만들지 않은 적용은 단계를 끝내지 않아요.
  기존 YAML이 없으면 가져오기를 건너뛰고 나중에 수집 화면에서 구독을 추가하면 된다고 문장으로 알려요.
- 각 단계는 건너뛸 수 있고 건너뛴 것을 되돌릴 수 있으며, 두 단계가 모두 끝나거나 건너뛰면 체크리스트가 사라지고 이번 주 편성이 나와요.
  사라진 체크리스트는 폴더나 채널을 나중에 지워도 다시 나오지 않고, 마지막 단계를 건너뛰어 사라진 직후에는 그 자리의 안내 줄에서만 되돌릴 수 있어요(사용자 결정, 2026-10-01). 가져오기는 언제든 설정에서 할 수 있기 때문이에요.
- 구독 제안의 확인은 가져오기 검토 단계에서 하므로 별도 단계로 두지 않아요.
- 처음 실행 중에는 수집한 것이 없으므로 이번 주 편성의 수집 상태·다음 분기 구독과 휴대폰 요약 줄, 할 일 개수 배지를 두지 않아요.
- 설정도 연결한 작품이 없는 상태로 보여, 작품별 형식 지정과 정리할 작품은 비어 있고 보관 파일 용량은 0이며, 내보내기는 마지막 내보내기가 없고 담기는 것도 그때까지 등록한 폴더와 가져온 채널·규칙 수만 세요.
- 처음 실행의 기존 YAML 가져오기는 현재 채널이 없어 채널마다 교체·추가·건너뛰기를 묻지 않고 모두 추가해요.

## 남은 구체화

- `secret_query`·`past_search`·`episode_auto`·`subscription`·`base`·`episode_mappings[].auto`처럼 이번에 더한 필드의 정확한 이름과 모양은 교환 형식을 구현하기 전에 이 문서에서 확정해요.
  이 필드들은 `version: 1`이 아직 구현되지 않았으므로 새 버전을 만들지 않고 `version: 1`에 넣어요.
- 기존 YAML 주석에서 Anissia 주소·요일·시간·제작자를 읽는 형식은 2026-09-29에 읽은 사용자의 채널 설정 한 벌의 관례예요.
  다른 사람의 주석 형식은 읽지 못한 주석으로 다뤄요.
