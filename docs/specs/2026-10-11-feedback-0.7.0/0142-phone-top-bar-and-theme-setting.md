# 0142 휴대폰의 상단바를 없애고 화면 모드를 설정으로 옮겨요

- 상태: 완료 (2026-10-13, 개발 환경에서 확인. 실제 기기와 서버 확인은 [0143](0143-deploy-feedback-fixes.md)에서 해요. 아래 "결과")
- 출처: [메뉴와 탐색](../../requirements/web-app.md#메뉴와-탐색), [설정 화면](../../requirements/settings.md#설정-화면)의 화면 모드(2026-10-11에 바뀐 요구), 0.7.0을 써 본 사용자 피드백(2026-10-11)
- 막는 티켓: 없음

## 작업

0.7.0은 모든 폭에서 위에 붙는 상단바에 앱 이름, 상단 메뉴, 화면 모드 버튼을 둬요(`web/src/app/AppShell.tsx`). 휴대폰에서는 상단 메뉴가 숨고 하단 메뉴가 있어서, 상단바에는 이름과 화면 모드 버튼만 남아 화면 한 줄을 차지해요.

사용자가 정한 것은 다음과 같아요(2026-10-11).

- 휴대폰에서는 상단바를 없애요. PC와 태블릿의 상단바는 메뉴만 남기고 앱 이름과 화면 모드 버튼을 빼요.
- 화면 모드(시스템·라이트·다크)는 설정 화면으로 옮겨요. 지금처럼 그 기기의 브라우저에만 저장해요(`localStorage`의 `trss-theme-v1`, `web/src/lib/theme.ts`).

명세에 리드가 적은 것도 있어요. 사용자가 다르게 정하면 명세와 함께 고쳐요.

- 설정 목록에 `화면` 묶음의 `화면 모드` 항목을 두고, 이 기기에만 적용된다는 문장을 둬요. 내보내기에는 싣지 않아요.

다음은 이 티켓에서 정해요.

- **휴대폰의 위쪽 여백.** 상단바가 없어지면 화면 제목이 기기의 안전 영역에 닿아요. 위쪽 안전 영역(`env(safe-area-inset-top)`)을 어디서 지킬지 정해요.
- **목록의 현재 값.** 설정 목록은 들어가지 않고 읽을 수 있는 현재 값을 보여줘요. 화면 모드 항목의 값(`시스템`·`라이트`·`다크`)을 서버 값이 아닌 브라우저 값으로 읽는 첫 항목이라, 목록 코드(`web/src/screens/settings/items.ts`)가 이를 어떻게 다룰지 정해요.

## 완료 기준

- 휴대폰 폭(720px 이하)에는 상단바가 없고, PC와 태블릿의 상단바에는 메뉴만 있어요.
- 설정의 `화면 모드`에서 모드를 바꾸면 바로 적용되고, 새로고침과 화면 이동 뒤에도 남아요. 시스템 모드는 기기 설정을 따라가요.
- 다섯 폭(1440·1024·768·390·320px)의 라이트·다크에서 가로 넘침이 없어요. 휴대폰의 화면 제목이 안전 영역에 가려지지 않아요.
- 화면 모드를 읽고 쓰는 코드를 `web` 테스트가 확인해요.
- [웹 앱 공통 명세](../../requirements/web-app.md#검증-표)와 [설정 명세](../../requirements/settings.md#검증-표)의 검증 표에서 이 요구의 행을 고쳐요. [개요](../../overview.md#화면)의 설정 줄에 화면 모드를 더해요.

## 결과

### 정한 것

- **휴대폰의 위쪽 여백.** 휴대폰 폭에서는 `--topbar-h`가 위쪽 안전 영역(`env(safe-area-inset-top, 0px)`)이에요(`web/src/index.css`). `main`이 그만큼 위를 띄우고, 수집 탭처럼 위에 붙는 것과 스크롤 위치도 같은 변수를 써서 안전 영역 아래에 멈춰요. PC와 태블릿의 상단바는 높이를 `--topbar-h`(63px)로 고정했어요. 0.7.0의 상단바는 폭에 따라 65px·62px이라 같은 변수로 위치를 정하는 수집 탭과 1–2px 어긋났어요.
- **목록의 현재 값.** 화면 모드 줄은 브라우저에 저장한 값을 바로 읽어서(`useThemePreference`), 서버 값을 읽는 다른 줄과 달리 불러오는 동안의 빈 자리가 없어요(`web/src/screens/settings/SettingsList.tsx`).
- 저장소를 읽고 쓰는 코드는 브라우저 없이 테스트할 수 있게 `web/src/lib/theme-store.ts`로 나눴어요. 상단의 전환 버튼(`ThemeToggle.tsx`)과 순환 함수는 지웠어요.

### 개발 환경 확인 (2026-10-13)

f75ec6d에 이 변경을 얹은 작업 트리를 Vite 개발 서버로 띄워 내장 브라우저(Chromium)로 봤어요.

| 확인 | 결과 |
| --- | --- |
| 상단바 | 1440·1024·768px에서 메뉴만 있는 63px 상단바였어요. 390·320px에서는 상단바가 없고 화면 제목이 위에서 18–20px에 있었어요. |
| 가로 넘침 | 다섯 폭의 라이트·다크에서 `/`, `/library`, `/todo`, `/collect/subs`, `/collect/rules`, `/settings`, `/settings/theme` 일곱 경로, 70개 조합 모두 넘침이 없었어요. 같은 페이지 안에 폭을 정한 iframe으로 열어 측정했어요. |
| 모드 바꾸기 | `라이트`를 고르자 바로 `data-theme`가 `light`가 됐고, `trss-theme-v1`에 `light`가 저장됐고, 목록 값이 `라이트`가 됐어요. 다른 화면으로 옮기거나 새로 열어도 남았어요. |
| 시스템 모드 | 기기 설정을 다크·라이트로 흉내 내고 새로 열자 각각 다크·라이트였어요. |
| 위쪽 안전 영역 | Chromium의 안전 영역은 0이라 `--topbar-h`를 34px로 덮어써 흉내 냈어요. 제목이 52px로 내려갔고 수집 탭의 `top`이 34px였어요. |
| 콘솔 | 오류가 없었어요. |

`npm test`의 226개와 `npm run typecheck`가 통과했어요. 새 테스트는 `src/lib/theme-store.test.ts`의 4개로, 저장한 모드를 다시 읽는 것, 모르는 값과 막힌 저장소를 `시스템`으로 읽는 것, `index.html`의 첫 그리기 전 스크립트가 같은 키를 읽는 것을 확인해요.

### 확인하지 않은 것

- 열어 둔 화면에서 기기 설정을 바꿀 때 `시스템` 모드가 따라가는 것이에요. 내장 브라우저의 색 모드 흉내가 `prefers-color-scheme`의 `change` 이벤트를 보내지 않아서, 새로 단 listener도 불리지 않았어요. 이 부분의 코드(`initTheme`)는 0.7.0과 같아요.
- 실제 휴대폰의 위쪽 안전 영역과 실제 기기의 모드 바꾸기예요. [0143](0143-deploy-feedback-fixes.md)의 서버 확인에서 봐요.
- 상단바와 설정의 모드 항목은 화면 테스트가 없어요.
