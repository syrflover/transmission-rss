# trss 개요

trss가 무엇을 하고, 어떤 부분으로 이뤄졌고, 어디서 무엇을 보면 되는지를 한 장에 모은 문서예요.
기능마다의 규칙은 [명세](#문서-지도)가, 설치와 운영 방법은 [readme](../readme.md)가 담당해요. 이 문서는 그 문서들로 들어가는 입구예요.

## 하는 일

trss는 애니메이션 영상과 한국어 자막을 모아 정리하는 앱이에요. 한 사람이 LAN이나 VPN 안에서 써요.

1. RSS 채널의 릴리스 가운데 다운로드 규칙에 맞는 것을 Transmission에 넣어 받아요.
2. 받은 영상과 원래 있던 영상 폴더에서 작품·시즌·에피소드를 찾아 라이브러리로 보여줘요.
3. 작품에 맞는 한국어 자막을 찾아 받아요. 받은 자막은 작품 폴더의 `.trss/`에 보관본으로 두고, 영상 옆에 적용본을 둬요. 그 회차에 자막이 이미 있으면 차이를 보여주고, 사용자가 승인한 것만 바꿔요.
4. 사람이 해야 하는 일은 할 일 화면에 모아요. CAPTCHA 풀기, 교체 승인, 회차 확인 같은 일이에요.

## 구성 요소

| 구성 요소 | 하는 일 |
| --- | --- |
| `trss-web` | 화면과 API를 맡아요. 사용자의 명령은 접수만 하고, 실행은 worker가 해요 |
| `trss-worker` | 5분마다 RSS를 읽는 수집 주기를 돌려요. 감시 폴더의 변화를 읽고, 웹이 접수한 명령과 자막 작업을 실행해요 |
| `trss-browser` | 서버 브라우저(Chromium)가 도는 컨테이너예요. worker가 작업마다 브라우저를 띄우고, 사용자는 웹의 원격 화면에서 CAPTCHA를 풀어요 |
| Transmission | 토렌트를 받아요. trss와 따로 도는 컨테이너예요 |
| 앱 데이터 폴더 | web과 worker가 함께 쓰는 앱 DB(`trss.db`, SQLite), 작품 표지(`artwork/`), 자막 묶음의 설명·라이선스 같은 부속 파일(`subtitle-files/`), 받은 묶음을 잠시 두는 수신 영역(`receive/`)이 있어요 |
| 미디어 디스크 | 수집 폴더와 작품 폴더예요. 보관본은 작품 폴더의 `.trss/`에, 적용본은 영상 옆에 있어요. 재생기는 이 디스크를 NFS로 읽어요 |
| 외부 서비스 | RSS 피드, Anissia(편성표·자막 제작자·최근 자막), AniList(표지·시즌 정보), 자막 출처(Blogger·Google Drive, Tistory, Naver, erulabo)예요 |

## 흐름

```
RSS 피드 ──다운로드 규칙──▶ Transmission ──▶ 수집 폴더
                                               │
                         기존 영상 폴더 ───────┤ 감시 폴더
                                               ▼
                               라이브러리: 작품 · 시즌 · 에피소드
                                               │ Anissia 연결, 회차 대응
                                               ▼
 Anissia 최근 자막 ──▶ 자막 후보 ──▶ 자막 작업 ◀── 직접 찾기 · 자막 올리기
                     구독 제작자는 자동,  │
                     그 밖은 사용자가 고름 │ 출처에서 받기
                                          │ (erulabo는 원격 화면에서 사람이 인증)
                                          ▼
               수신 영역 ──▶ 묶음 분석 ──▶ 보관본(.trss/) ──▶ 적용본(영상 옆)
                                           자막이 이미 있으면 교체 승인을 거쳐요
                                           영상이 아직 없으면 영상 대기로 둬요
```

| 할 일과 작업 | 할 일 일곱 종류, 자막 작업과 작업 상세, 서버 브라우저 인증, 중단 뒤 이어 하기 | [작업과 인증 명세](specs/jobs.md) |
| 설정과 이전 | 앱 설정과 공통 정책, 기존 YAML 가져오기, 앱 YAML 내보내기와 가져오기(아직 만들지 않았어요), 처음 실행 | [설정과 이전 명세](specs/settings.md) |
| 웹 공통 | 접근 경계, 메뉴, 이번 주 편성, 문구와 표기, 웹 명령과 상태 갱신 | [웹 앱 공통 명세](specs/web-app.md) |

## 화면

| 메뉴 | 보는 것 |
| --- | --- |
| 이번 주 편성 | 구독한 방영작의 이번 주 회차를 요일별로 묶어 영상·자막 상태와 함께 봐요. 수집 상태의 요약이 PC에서는 옆 열에, 휴대폰에서는 위 한 줄에 있어요 |
| 라이브러리 | 작품 격자와 할 일 배지예요. 작품 상세에서는 한 작품의 회차·자막·할 일·파일을 봐요 |
| 할 일 | 사람이 처리하거나 정할 것과, 자막 작업의 진행이에요 |
| 수집 | `구독`·`규칙`·`기록`·`채널` 탭과, 탭 위의 수집 상태판이에요 |
| 설정 | 공통 정책, 수집 폴더, 감시 폴더, 파일 용량, 내보내기·가져오기, 배포 설정(읽기 전용)이에요 |

## 지금 상태를 보는 곳

- **수집이 도는지:** 이번 주 편성 화면이나 수집 화면의 상태판을 봐요. RSS를 확인한 시각과 다음 확인 시각, 최근 7일에 받은 개수, Transmission의 받는 중·시딩 수가 있어요. worker가 멈추면 `RSS 확인이 멈췄어요.`가 강조 색으로 떠요.
- **자막이 왜 안 들어왔는지:** 할 일 화면을 봐요. 실패한 자막 작업은 할 일로 따로 올리지 않고, 같은 화면의 자막 작업 맨 위에 `실패`로 있어요.
- **서버의 메모리·디스크·컨테이너 재시작:** 화면에는 없어요. 컨테이너 로그로 봐요([readme](../readme.md#run-stop-update)). 화면에 더할지는 실제 서버에서 써 본 뒤 정해요.
