# 웹 화면 재설계와 기획 보완

## 현재 방향

[기존 주제 문서](web-gui-subtitles.md)에서 채택한 사쿠라 시안의 정보 구조와 시각 언어를 모두 새로 설계해요.
요약 홈·다섯 개 주 메뉴·작품 상세 탭 같은 화면 구조도 다시 검토 대상이며, 기존 시안을 부분 수정하는 방향이 아니에요.
사쿠라 시안에서 무엇이 불만인지는 특정하지 않았으므로, 새 방향은 기존 시안의 결함 교정이 아니라 실제 사용 흐름에서 출발해요.

기획은 기존 명세를 유지하면서 빠진 흐름을 보완해요.
이 문서의 제안은 [구현 명세](../specs/web-gui-subtitles.md)를 자동으로 바꾸지 않으며, 수렴한 뒤 명세에 반영할 때 대체 범위를 정해요.

### 유지하는 것과 대체될 것

재설계는 명세의 기능 계약을 유지해요.
받은 자막과 후보·미확인 파일의 구분, 예외 상태의 구분, 교체 승인과 명령·버전 계약, 원격 인증 화면의 trss 내부 조작, 색만으로 상태를 전달하지 않는 접근성 요구가 여기에 해당해요.

명세의 [화면 구성](../specs/web-gui-subtitles.md#화면-구성)과 [시각적 방향과 테마](../specs/web-gui-subtitles.md#시각적-방향과-테마) 중 사쿠라 시안에 묶인 배치·치수·색상 값은 새 방향이 수렴하면 대체될 후보예요.
라이트·다크와 시스템 설정 추종처럼 시안과 독립적인 요구를 유지할지는 새 방향과 함께 확인해요.

## 선택과 근거

### 화면 구조

홈은 이번 주 방영작의 이번 화 영상·자막 상태를 요일별로 보여주고, 할 일은 두지 않아요(사용자 결정).
할 일은 메뉴의 개수 배지와 할 일 화면이 맡고, 홈의 작품 카드에는 `인증 필요`·`회차 확인 필요` 같은 상태 줄만 남아요.
홈 맨 위의 `이번 주 편성`은 화면 제목이라 다른 화면의 제목과 같은 크기로 보여줘요.
상단 메뉴와 휴대폰 하단 메뉴의 이름도 화면 제목에 맞춰 `이번 주 편성`이에요.
라이브러리는 전체 작품의 표지 그리드로 둘러보기와 옛날 작품 찾기를 맡고, 수집 화면은 RSS 채널·규칙·수집 이력을 함께 다뤄요.
라이브러리의 표지 그리드와 명세의 표지 목록형은 사용자가 고를 수 있게 둘 다 두는 것이 사용자의 제안이에요.
최근 들어온 작품·다 갖춘 작품·둘러보기·이름 찾기를 어떤 구조로 담을지는 선반형·한 목록형·시기별 묶음형 시안으로 비교해요.
네 가지 여는 계기를 한 화면으로 대표하지 않고 화면별로 나눠 맡기는 선택이며, 완결작만 볼 때는 홈의 비중이 줄어드는 비용이 있어요.

할 일 화면은 명세의 작업 목록도 맡아요.
위에는 인증·승인·미확정·제안처럼 사용자가 처리할 것을, 아래에는 진행 중·최근 완료·실패한 자막 작업을 두어 자막이 왜 들어오지 않았는지를 한 곳에서 찾게 해요.
화면이 길어지는 비용은 처리할 것을 위에 두는 순서로 다뤄요.
사용자는 세 구조 시안 중 이 두 구역형(R)을 골랐어요.
위에는 할 일을, 아래 `자막 작업`에는 `실패` → `대기 중` → `진행 중` → `최근 완료` 순서로 작업 줄을 두고, 완료는 다섯 개만 보인 뒤 무한 스크롤로 이어져요.
인증·교체 승인을 기다리는 작업 줄도 다른 작업 줄처럼 펼치고, 펼친 자리에는 설명과 작업 상세로 가는 `자세히`만 둬요(사용자 결정).
`인증`·`비교`는 위의 할 일 카드에만 두어 한 화면에 같은 동작을 두 번 두지 않아요.
처음에는 이 줄이 ↑로 할 일 카드를 가리켰지만, 줄마다 누른 결과가 달라지고 작업 상세가 생긴 뒤에는 이유가 약해져 바꿨어요.
실패한 자막 작업은 할 일로 올리지 않아요(사용자 결정).
`자막 작업`의 맨 위가 `실패`라서 할 일로 따로 올리지 않아도 놓치지 않는다는 판단이에요.
할 일은 수집이나 적용을 막는 `처리 필요`(인증 필요·받기 실패·교체 승인·회차 확인 필요)와 미뤄도 되는 `제안`(자막 구독·보관 제안)으로 나눠요.
홈에서 가져온 카드는 종류가 작은 회색 글씨라 가장 약하고, 34px 표지가 제목 옆 도장처럼 붙어 왼쪽 선이 흐트러지고, 급한 일과 제안이 같은 무게로 보였어요.
처리 필요는 표지를 카드 높이의 세로 열로 두는 카드로, 제안은 그 아래 얇은 줄 목록으로 보여줘요(사용자 결정).
작업 줄과 같은 줄형으로 모두 바꾸는 안도 비교했지만, 급한 일이 눈에 덜 띄어 카드를 남겼어요.
카드는 위에 종류 배지와 시각, 그 아래 제목, 대상, 사유 순서예요.
처리 필요 안에서는 빨간 종류(인증 필요·받기 실패)를 먼저 두고, 이 둘만 카드 테두리도 빨갛게 해요.
처리 필요의 버튼은 모두 파랑, 제안의 버튼은 무채색이에요.
대상과 사유는 ` · `로 한 줄에 잇지 않고 정보 종류마다 모양을 달리해요(사용자 요청).
회차는 굵게, 제작자는 자막 아이콘과 함께, `한 번 받기` 같은 맥락은 작은 태그로 대상 줄에 두고, `CAPTCHA`·`Transmission 연결 거부` 같은 사유는 다음 줄에 둬요.
자막 구독은 제작자가 정해지지 않은 작품이라, 후보의 이름을 적지 않고 `1–4화  자막 후보 1명`처럼 회차와 후보 수만 둬요(사용자 결정).
후보 이름은 자막 아이콘과 함께 두든 이름표 뒤에 두든 제작자가 이미 정해진 것처럼 읽혀, 후보는 `제작자 지정`을 누른 뒤 고르는 화면에서 보여줘요.
종류와 `제작자 지정` 버튼이 이미 말하는 `제작자 미정`도 적지 않아요.
교체 승인의 사유 줄은 `대사 추가 2`·`대사 변경 12`·`타이밍 3` 태그예요.
설명은 종류 이름을 되풀이하지 않고, 표지가 없으면 종류 아이콘 대신 다른 화면과 같은 중립 아이콘을 둬요.
인증 카드에 붙던 `가장 시급` 배지는 빨간 강조와 맨 앞 순서가 이미 같은 뜻이고, 인증 카드마다 붙어 여러 장이면 뜻이 맞지 않아 두지 않아요.

비교한 출발점은 다음과 같고, 각 방향의 장점을 화면별로 나눠 가져왔어요.

| 방향 | 사용자 가치 | 비용 |
| --- | --- | --- |
| 미디어 라이브러리형 | 표지 그리드로 작품을 둘러보는 즐거움과 작품 식별이 쉬워요. | 인증·승인 같은 할 일이 한 단계 깊어져요. |
| 작업 인박스형 | 인증·승인·미확정·새 후보를 연속으로 빠르게 처리해요. | 작품을 둘러보는 경험이 약해요. |
| 방영 편성표형 | 요일별 방영 리듬에 맞춰 이번 화의 영상·자막 도착을 한눈에 봐요. | 완결작과 기존 라이브러리는 부차적인 화면이 돼요. |
| 밀도 높은 도구형 | 한 화면에서 가장 많은 상태를 빠르게 훑어요. | 표지와 장식이 거의 없어 개성이 약해요. |

### 작품 연결과 제외

발견한 작품은 미연결로 두고, 방영작이나 사용자가 자막을 원하는 작품만 Anissia·회차 대응을 연결해요.
첫 실행에서 모든 작품을 일괄 확인하는 대안보다 처음 부담이 작고, 자막을 주로 분기 방영작과 가끔 추가하는 옛날 작품에만 정리한다는 사용 흐름에 맞아요.
미연결 작품은 자막 후보를 자동 조회하지 않으며, 관리하지 않을 작품의 제외는 별도 기능 대신 이 기본 상태로 다뤄요.

### 방영작 구독

방영작 구독은 Anissia 편성표에서 작품을 고르고, 다운로드 규칙의 일치 조건은 RSS 채널의 릴리스 제목에서 고르는 흐름으로 시작해요.
[현재 채널 설정](#현재-채널-설정에-드러난-수작업)의 주석으로 하던 수작업을 앱으로 옮기는 방향이며, Anissia 연결은 구독 시점에 확정돼요.
SubsPlease 외의 채널도 사용하므로 릴리스 제목의 선택 대상은 특정 사이트가 아니라 선택한 채널이에요.
구독은 규칙을 만드는 일이므로 수집 화면에서 시작하고, 홈의 다음 분기 구독 영역에는 편성표에서 추가하는 바로가기를 둬요.

릴리스 제목은 실제 RSS 항목에서만 고르며, 비공식 편성 엔드포인트나 직접 입력에 의존하지 않아요.
첫 화 전에 구독한 작품은 일치 조건이 빈 제목 대기 상태로 시작해요.
worker는 규칙과 일치하지 않은 항목까지 RSS 수집 이력에 기록하고, 제목 대기 구독이 있는 동안 이력에 처음 나타난 작품 제목을 할 일로 알려요.
사용자가 그 항목을 고르면 규칙이 완성되고, 이미 기록된 해당 작품의 지난 항목을 미리보기로 보여준 뒤 확인하면 받아요.
미리보기는 `[Batch]` 같은 원치 않는 항목을 걸러낼 기회이며, 규칙 완성만으로 지난 항목을 바로 받지 않아요.
Anissia 작품과 새 제목의 연결은 제안일 뿐 사용자가 확정해요.

이 소급 적용은 trss가 기록한 항목에만 동작해요.
RSS 피드는 대부분 최신 회차만 담고, trss가 기록을 시작하기 전이나 늦게 구독한 작품의 지난 회차는 이력에 없으므로 이 경로로 받을 수 없어요.
사용자는 그런 지난 회차를 다른 방식으로 찾아 받아야 한다고 지적했고, 과거 설정에 주석으로 남은 nyaa 검색 RSS가 그 수작업의 흔적이에요.

지난 회차는 규칙의 조건으로 nyaa 검색 RSS를 만들어 한 번만 읽고, 상시 채널로 남기지 않는 방식으로 확보해요.
규칙에는 작품 제목만 있고 릴리스 그룹·화질은 채널 URL에 들어 있으므로, 채널마다 `[SubsPlease] {match} 1080p` 같은 지난 회차 검색 형식을 둬요.
검색 결과는 실제 규칙 판정을 거쳐 이력의 지난 항목과 같은 미리보기에 보여주고, 사용자가 확인한 항목만 Transmission에 추가해요.
늦게 구독한 방영작과 첫 화 전에 구독한 신작이 같은 확인 흐름으로 이어지며, 옛날 작품도 규칙을 만든 뒤 같은 방식으로 받을 수 있어요.
2026-09-29에 `[SubsPlease] Sayonara Lara 1080p` 검색 RSS가 01–12화 항목을 모두 반환하는 것을 확인했어요.
같은 날 `[SubsPlease] One Piece 1080p` 검색 RSS는 75개 항목만 반환했고, `p=2`를 붙여도 같은 첫 페이지를 돌려줘 RSS로는 다음 페이지를 받을 수 없었어요.
이 검색에는 `One Piece Log - …` 같은 다른 작품도 섞여, 부분 문자열 일치 조건만으로는 다른 작품을 걸러내지 못한다는 것도 드러났어요.

규칙의 일치 조건은 작품이 아니라 릴리스 제목의 흐름을 가리키므로, 과거 검색에서는 같은 제목의 다른 시즌과 파생작이 함께 나와요.
2026-09-29의 `[SubsPlease] Sono Bisque Doll 1080p` 검색에서는 같은 제목의 1기 01–12화와 2기 13–24화, 수정본 `14v2`, 범위가 겹치는 공식 `(01-12) Batch`와 비공식 `(01-24) Unofficial Batch`가 한 결과에 섞였어요.
그래서 지난 회차 검색는 trss가 제안한 회차 범위를 사용자가 확인하는 것으로 시작해요.
범위는 `릴리스 13–24 → S02E01–12`처럼 릴리스 회차와 폴더 회차의 대응이며, AniList 회차 수와 규칙의 회차 변환, 구독 뒤 처음 본 RSS 항목의 회차를 근거로 제안하고, 근거가 없으면 사용자가 적어요.
범위 밖 결과는 미리보기에서 접어 개수만 보여주고, 빠진 회차는 범위에서 이미 있는 회차를 뺀 것으로 계산해요.

검색 결과 미리보기는 폴더나 Transmission에 아직 없는 개별 회차만 기본으로 선택해요.
이미 있는 회차와 배치 토렌트는 표시하되 선택을 해제해 두고, 사용자가 원하면 직접 골라요.
같은 회차의 수정본이 여러 개면 가장 높은 수정본만 기본으로 선택해요.
지금 worker는 Transmission의 같은 토렌트 해시 거부에만 기대 중복을 피하므로, 다른 릴리스로 이미 받은 회차는 회차 번호와 작품 폴더의 실제 파일로 판단해야 해요.
채널에 검색 형식이 없으면 규칙의 일치 조건으로 채운 검색어를 그 자리에서 고쳐 한 번 검색하며, 결과는 같은 규칙 판정과 미리보기를 거쳐요.

빠진 회차가 75개를 넘는 장편도 사용자가 검색을 나누지 않게 해요.
첫 검색 결과가 75개로 차서 잘렸을 수 있으면, trss가 확인한 범위에서 아직 없는 회차 번호를 계산해 `One Piece - (1000|1001|1002)`처럼 회차 번호를 묶은 검색을 이어서 보내고 결과를 같은 미리보기에 합쳐요.
2026-09-29에 이 묶음 검색 RSS가 지정한 1000–1002화만 반환하는 것을 확인했고, RSS의 정렬 인자는 무시되며 HTML 검색 페이지는 다음 페이지를 제공하지만 화면 구조에 기대므로 쓰지 않아요.
회차 표기는 `- 01`처럼 릴리스마다 다르므로 첫 검색 결과의 실제 제목에서 읽은 형식을 쓰고, 추가 검색은 간격을 두고 순서대로 보내요.
한 묶음에 넣을 회차 수와 요청 간격은 정하지 않았어요.

### 회차 변환의 자동 적용

새 시즌의 첫 릴리스 번호가 이전 시즌까지의 AniList 회차 합계에 1을 더한 값과 같으면 회차 변환을 묻지 않고 자동으로 적용해요.
2기가 24화로 끝나고 새 시즌이 `- 25`로 시작하면 −24, 첫 릴리스가 `- 01`이면 0이에요.
사용자는 이 경우가 모호하지 않으니 제안 대신 자동으로 적용하자고 했어요.
처음 본 릴리스가 시즌 첫 화가 아니거나, 분할 방영이 같은 시즌 폴더에서 번호를 이어가는 경우처럼 근거가 서로 맞지 않으면 번호만으로 새 시즌인지 판단할 수 없어요.
그런 경우에만 제안으로 보여주고 사용자가 확인해요.
자동으로 적용한 값은 `자동` 표시와 근거를 함께 보여주고, 직접 입력으로 바꿀 수 있어요.

### 영상 수정본의 대체

폴더에 있는 회차 영상보다 높은 수정본(`14v2` 등)이 나오면, 지난 회차 검색와 방영 중 RSS 모두 같은 규칙으로 수정본을 자동으로 받아 기존 영상을 대체해요.
대체는 수정본의 수신과 확인이 끝난 뒤에 하며, 새 영상은 같은 회차 이름을 쓰므로 옆에 적용된 자막은 그대로 이어져요.
수정본에서 자막 타이밍이 어긋날 수 있으므로 작품 상세에 영상이 수정본으로 바뀌었다는 사실을 조용히 알려요.
알림은 경고 문장 없이 해당 회차 줄에 `v1 › v2`와 흐린 `9/2 02:05 수정본으로 교체`를 둔 버전 줄로 보여줘요.
이 결정은 명세가 보류한 중복 영상 선택 흐름 중 같은 릴리스의 수정본 경우를 정하며, 다른 그룹의 같은 회차처럼 나머지 중복은 계속 보류해요.

trss는 받은 영상의 이름을 `trname`으로 회차 이름으로 바꾸므로 파일 이름으로는 원래 수정본을 알 수 없어요.
trss가 받은 영상은 수집 이력의 원래 릴리스 이름과 파일의 CRC32를 기록해 버전을 알아요.
버전을 모르는 기존 영상은 파일 내용의 CRC32를 계산해 릴리스 이름 끝의 `[E2675E51]` 같은 값과 대조해요.
구버전의 값과 같으면 자동으로 대체하고, 최신 수정본과 같으면 건너뛰며, 어느 것과도 다르면 버전 미상으로 표시하고 선택을 해제해 둬요.
2026-09-29에 AnimeTosho가 실제 파일에서 계산해 공개한 CRC32로 이 관례를 대조했어요.
`[SubsPlease] Sono Bisque Doll wa Koi wo Suru - 13 (1080p) [E2675E51].mkv`와 `[Erai-raws] Snowball Earth - 06 [1080p CR WEBRip HEVC AAC][MultiSub][1BBD34E6].mkv`의 계산값이 각각 이름의 값과 같았어요.
그룹별 표본 하나씩의 확인이며, 모든 릴리스가 이 관례를 지킨다는 보장은 아니에요.
Erai-raws처럼 대괄호가 여러 개인 이름에서는 확장자 앞의 8자리 16진수 대괄호를 CRC 값으로 읽어요.

지금 worker가 방영 중 RSS의 수정본을 받으면 기존 회차 이름과 겹쳐 이름 바꾸기가 실패하고 두 파일이 남을 가능성이 있지만, 재현하지 않은 추정이에요.

### 자막 제작자 자동 수신

구독할 때 따라갈 자막 제작자를 정하고, 그 제작자의 새 회차 자막은 후보가 나타나면 자동으로 받아요.
기존 명세는 자막 후보 자동 선택을 범위 밖으로 두었지만, 사용자가 이미 구독 시점에 제작자를 정해 설정 주석에 적어온 근거로 이 결정을 다시 열었어요.
자동 수신은 구독 제작자의 아직 받지 않은 회차에 한정하며, 필요한 CAPTCHA는 할 일로 올라와요.
받은 회차의 자막 수정본 교체와 다른 제작자의 자막은 기존 명세의 선택·교체 승인을 유지해요.
제작자가 방영 중에 바뀌면 사용자가 구독을 고쳐야 한다는 비용이 있어요.

다른 제작자의 자막 후보는 구독 제작자의 자막과 같게 다루지 않아요(사용자 결정).
구독 제작자가 있는 작품에서는 구독 제작자가 올리지 않은 회차의 다른 제작자 후보가 골라도 되는 선택지일 뿐이라, 할 일로 올리거나 색을 입히지 않고 작품 상세의 해당 회차 줄에 조용히 적은 뒤 펼친 자리에서 `받기`를 둬요.
작품과 제작자의 연결은 구독할 때와, 규칙 상세의 자막 제작자 줄·작품 상세 머리의 `변경`에서 해요.
제작자 미정인 작품에 자막 후보가 처음 나타나면 그때가 연결할 때이므로, 후보 수와 관계없이 작품마다 하나의 `자막 구독` 할 일로 알려요.
자막 후보가 하나도 없는 작품은 제작자 미정이어도 할 일을 만들지 않아요(사용자 결정).
구독 제작자가 오래 올리지 않을 때 다른 후보를 할 일로 올리는 안은 기간 규칙이 새로 필요해 고르지 않았어요.

### 자막 보관 위치와 수정본

자막 수정본은 대개 같은 게시물에서 파일이나 링크만 바뀌거나 수정본 파일이 더해지는 방식으로 올라오고, 새 게시물로 올라오는 경우는 드물어요(사용자 보고).
그래서 수정본은 이전 보관본과 원래 파일명이 같은 경우가 흔해요.

작품 폴더에는 숨김 폴더 `.trss/` 하나만 두고, 그 안에는 자막과 폰트만 보관해요(사용자 결정).
표지·자막 묶음의 설명·라이선스 같은 첨부·그 밖의 메타데이터는 SQLite DB 옆의 앱 데이터 폴더에 둬요.
재생기가 쓰는 것은 영상 옆 적용본뿐이고 표지는 DB에서 작품 ID로 연결되므로, 작품 폴더를 옮겨도 연결이 끊기지 않아요.
대신 작품 폴더만 다른 서버로 복사하면 사용자가 고른 표지는 따라가지 않으며, 앱 데이터 폴더는 DB와 함께 백업해야 해요.

- 자막은 `.trss/subtitles/제작자/원래 파일명`처럼 제작자 폴더 아래에 평평하게 두고, 같은 이름·다른 내용의 파일은 `원래 파일명 (2)`처럼 번호를 붙여요(사용자 결정).
  어느 회차의 몇 번째 수정본인지는 DB가 기록하며, 폴더만 봐서는 수정본의 순서를 알기 어려워요.
- 폰트는 그 폰트를 쓰는 자막과 한 묶음으로 다뤄요(사용자 결정).
  같은 제작자 폴더에 자막과 나란히 두고, 이름과 내용이 같은 폰트는 한 번만, 이름만 같은 폰트는 번호를 붙여 둬요.
  자막과 폰트의 관계는 DB가 기록하고, 자막을 정리하면 다른 자막이 쓰지 않는 폰트도 함께 정리해요.
  두 제작자가 같은 폰트를 쓰면 두 벌을 두는 비용이 있고, 폴더만으로는 어느 폰트가 어느 자막의 것인지 보이지 않아요.

명세의 `.trss-subtitles/`·`.trss-artwork/`와 `subtitles/제작자/시즌·회차/수정본/원래파일명`·`fonts/`·`attachments/` 배치, 내보내기의 작품 폴더 이동 설명은 명세에 반영할 때 이에 맞춰 고쳐야 해요.

### 방영 종료 후 규칙 보관

방영이 끝난 작품의 규칙은 자동으로 끄지 않고, Anissia의 방영 종료나 마지막 수신 이후 새 항목이 없는 상태를 근거로 규칙 보관을 할 일로 제안해요.
사용자가 한 번에 보관하고 나중에 되살릴 수 있으며, 방영 연장이나 분할 방영을 잘못 끄는 위험을 자동 보관 대신 사용자 확인으로 피해요.

### RSS 수집 이력

수집 이력 화면은 네 가지 용도를 모두 맡아요.
규칙 불일치·제외 조건·Transmission 추가 실패처럼 항목이 받아지지 않은 이유를 확인하고, 규칙에 맞지 않은 항목을 규칙 없이 한 번 받고, 이력의 항목에서 새 규칙이나 제목 대기 구독의 일치 조건을 만들고, 언제 어떤 회차가 추가됐는지 시간순으로 훑어봐요.

규칙과 일치하지 않은 항목을 포함한 모든 기록을 삭제 없이 계속 보관해요.
놓친 항목 받기와 소급 적용은 기록이 남아 있는 동안만 가능하므로, 오래된 작품도 기록된 항목이면 다시 받을 수 있게 하는 선택이에요.
채널 하나가 한 해에 수천 건 정도라 용량 부담은 작다고 추정했으며 실제 증가량은 측정하지 않았어요.
길어진 목록은 화면에서 최근 순서와 필터로 다뤄요.

### 수집 화면의 구성

수집 화면은 `구독`·`규칙`·`기록`·`채널` 탭으로 나눠요.
작품 한 줄에 규칙과 구독을 묶고 기록·채널을 보조 화면으로 둔 작품 중심 시안과 비교해 사용자가 작업별 탭을 골랐어요.
구독은 Anissia와 연결된 규칙이므로 같은 작품이 `구독`과 `규칙` 두 탭에 나타나는 비용이 있어요.

시안 검토에서 사용자가 정한 화면 원칙은 다음과 같아요.

- 목록은 `더 보기` 버튼 대신 끝에 닿으면 이어서 불러오는 무한 스크롤로 보여주고, 내용을 펼치거나 이어 붙일 때 스크롤 위치를 옮기지 않아요.
  수집 화면만이 아니라 모든 목록에 적용해요.
- 제목 후보와 보관 제안은 급히 처리할 일처럼 보이지 않게 중립적으로 보여줘요.
- 분기가 끝나면 보관 제안이 한꺼번에 몰려 제목 후보 같은 다른 항목을 가리므로, 보관 제안은 개수와 `모두 보관`·`선택 보관`만 담은 한 줄로 접어 두고, PC에서는 제목 후보 옆에 나란히 둬요.
  보관 제안이 하나뿐이면 고를 것이 없으므로 접지 않고 그 작품 한 줄과 `보관` 버튼만 둬요(사용자 결정).
  펼치면 모든 규칙이 미리 선택된 체크 목록이 나오고, 남길 규칙만 체크를 풀어 `N개 보관`으로 한 번에 처리해요.
- 구독할 때 자막 제작자를 모르면 제작자 미정으로 구독하고, 자막이 올라오면 `자막 구독` 할 일로 알려줘요.
  2026-09-29 조회에서 Anissia 4분기 60편 중 자막 제작자가 등록된 작품은 20편이었어요.
- 구독 취소처럼 되돌리기 어려운 동작은 위험을 드러내는 모양으로 두고, 결과를 설명하는 확인을 거쳐요.
  확인은 별도 창 대신 누른 자리에서 한 번 더 물어요.
- 제목 후보와 보관 제안은 경고색이 아니라 우선순위에 따른 차분한 강조색으로 구분해요.
  3차 시안은 사용자 입력이 있어야 수집이 시작되는 제목 후보에 파랑, 정리 성격의 보관 제안에 보라를 쓰고, 되돌리기 어려운 동작만 빨강으로 둬요.
- 화면만 옮기는 이동 버튼은 색 없이 두고, 보관·받기·구독 취소처럼 상태를 바꾸는 동작 버튼은 맥락 강조색의 테두리와 글자로 드러내요.
  꽉 찬 색은 그 화면의 주 동작과 제자리 확인의 최종 버튼에만 쓰고, 옅은 배경으로 채운 동작 버튼은 목록에서 반복될 때 산만해서 쓰지 않아요.
- 목록의 줄마다 같은 버튼을 반복하지 않아요.
  카드는 제목을 눌러 규칙을 열고, 기록은 줄을 눌러 그 항목으로 할 수 있는 일을 펼쳐요.
  제목 대기 구독에 연결할 수 있는 기록처럼 핵심 동작이 있는 줄만 동작을 바로 보여줘요.
- 상태 표시는 테두리와 아이콘이 있는 배지로, 제목 옆의 개수 나열은 개수 칩으로 보여줘요.
- 수집 화면 위쪽 상태는 한 판 안에 RSS 채널 상태, 최근 7일 동안 받은 개수와 날짜별 막대, Transmission의 받는 중·시딩 수로 나눠 보여줘요.
  실패·중복이 있으면 그 개수에서 기록의 해당 필터로 바로 가요.
  휴대폰에서는 이 상태를 한 줄 요약으로 접어 두고 눌러서 펼쳐요.
  PC에서는 탭을 오가도 탭 줄이 움직이지 않도록 모든 탭에서 같은 모양으로 두고, 규칙 탭의 목록·상세 칸이 그만큼 낮아지는 비용을 받아들여요.
- 규칙 상세는 바꾼 내용이 있을 때만 아래에 저장 줄을 붙여 보여주고, 보관·삭제는 상세 맨 아래의 관리 줄에 둬요.
- 규칙 상세 맨 위에는 큰 포스터 옆에 방영 요일·분기, 자막 제작자와 변경, 받은 회차 진행, 마지막 수집의 네 줄을 모든 규칙에 똑같이 둬서 열자마자 규칙이 제대로 돌고 있는지 보여줘요. 값이 없으면 "미정", "아직 없음"처럼 채워서 줄 수를 유지하고, 포스터 아래 끝은 마지막 수집 줄에 맞춰요. 그래서 포스터 크기가 규칙마다 같아요. 폰에서는 상태·제목·원제를 전체 너비로 올리고 포스터와 네 줄만 나란히 둬요.
  편성표와 연결되지 않은 규칙은 그 자리에 `편성표와 연결`을 둬요.
- 총 회차를 모르는 작품도 진행 막대를 보여주고, 남은 부분을 점선으로 두어 `9 / ?화 받음`처럼 표시해요.
- 규칙의 폴더는 `저장 폴더`라고 불러요.
- Transmission 추가 실패처럼 사용자가 손봐야 하는 수집 실패는 할 일로 올려요(사용자 결정).
  규칙 불일치와 제외는 실패가 아니므로 기록에만 남기고, 수집 상태 판의 `실패·중복 N개`는 그대로 기록 필터로 이어져요.
- 채널 주소의 비밀 값은 목록에서 가린 값과 자물쇠 표시만 두고, 설명은 비밀 값을 다시 입력하는 편집 화면과 채널 탭 아래의 한 줄에 둬요.
- PC의 규칙 탭은 규칙 목록과 규칙 상세가 각자 스크롤하고, 규칙을 고를 때 화면이 움직이지 않아요.
- 설명 문구는 구역마다 짧은 한 문장 이하로 줄이고, 카드마다 같은 설명을 반복하지 않아요.
  이후 [화면 간 공통 규칙](#화면-간-공통-규칙)의 문구 규칙에 따라 구역 설명은 제목만으로 오해될 때만 짧은 명사구로 남겨요.
- 채널 안의 검사 순서는 두 규칙이 같은 항목에 맞을 때만 결과를 바꾸므로 규칙 목록의 줄마다 순서 번호를 두지 않아요.
  순서와 순서 바꾸기는 규칙 상세와 `검사 순서` 정렬에 두고, 다른 규칙이 먼저 가져가는 항목이 있는 규칙에만 목록에서 `겹침` 표시를 붙여요.
  명세는 규칙 목록에 적용 채널과 평가 순서를 표시하도록 요구하므로, 명세에 반영할 때 이 요구를 고쳐야 해요.

### 작품 상세의 구성

작품 상세는 탭 없이 한 번에 스크롤하는 흐름으로 보여줘요.
명세의 탭 구조(회차·자막 후보·자막·작품 설정), 탭 없는 한 흐름, 회차 격자에서 한 화를 골라 보는 구조의 세 시안을 비교했어요.
사용자는 처음에 탭 구조를 골랐다가 한 흐름이 더 낫다고 판단했어요.

- 머리에는 표지·제목·원제와 선택한 시즌의 자막 제작자 이름을 두고, 그 아래 시즌 정보를 `방영`·`분량`·`제작사`·`장르` 순서의 이름표 달린 칸으로 보여줘요.
  자막 제작자는 시즌마다 다르거나 한 시즌에 여럿일 수 있으므로 선택한 시즌의 제작자를 모두 보여주고, 구독 제작자가 정해지지 않았으면 `제작자 미정`, 직접 넣은 파일처럼 제작자를 모르면 `제작자 알 수 없음`으로 보여줘요.
- `AniList` 링크는 시즌이 하나든 여럿이든 시즌 정보 제목 줄 한 곳에 두고, 시즌 타일은 가장자리까지 전체가 선택 영역이에요.
  명세는 타일 우상단에 AniList 링크를 두도록 요구하므로, 명세에 반영할 때 이 요구를 고쳐야 해요.
- 위쪽 `할 일`에는 회차 확인·인증·교체 승인처럼 사용자가 해야 하는 것만 색을 입힌 카드로 두고, 수정본 교체·영상 대기·자막 누락·다른 제작자의 자막 후보처럼 보기만 하거나 골라도 되는 상태는 회차 목록의 해당 줄에 조용히 적어요.
  색은 사용자가 할 일이 있다는 뜻으로만 써요.
- 회차 목록은 최신 화부터 보여주고, 사용자가 `1화부터`로 바꿀 수 있어요.
  할 일은 목록 위에 따로 모으므로 목록 자체는 회차 번호 순서이고, 명세의 점검 우선 정렬 고정 요구는 명세에 반영할 때 이에 맞춰 고쳐야 해요.
- 교체 승인 카드는 작업 상세와 같이 내용 변경 중심으로, `현재`·`새 자막`의 받은 시각 한 줄과 변경 사항 숫자 태그만 두고 `비교`로 작업 상세를 열어요.
  승인하면 새 자막으로 교체된다는 것은 `교체 승인` 배지가 이미 말하므로 승인 조건 줄은 두지 않아요.
  처음에는 `사용 중`·`새 버전` 자막을 나란히 두었지만, 작업 상세에서 파일 비교를 한 줄로 줄이면서 함께 맞췄어요(사용자 결정).
- 받은 자막은 제작자별로 묶고, 영상 옆에 둔 사본은 명세의 보관본·적용본에 맞춰 `적용`이라고 불러요.
- 넓은 화면에서는 시즌 타일·시즌 정보도 할 일·회차와 같은 왼쪽 열에 두고, 오른쪽 카드 열은 표지·제목 아래에서 시즌 타일(시즌이 하나면 시즌 정보)의 윗면에 맞춰 시작해요.
  시즌 정보가 화면 전체 폭으로 늘어나 한눈에 들어오지 않았기 때문이며, 시즌 정보는 회차 목록과 같은 폭에서 네 칸으로 보이고 그 폭이 좁으면 두 칸으로 바뀌어요.
  시즌 타일도 같은 폭을 나눠 채우고, 오른쪽 카드 열은 따로 스크롤하지 않고 화면과 함께 스크롤해요.
- 오른쪽 열(휴대폰에서는 목록 아래의 접힌 구역)에는 작품 정보·수집·자막·최근 활동·파일 카드를 두고, 최근 활동은 몇 줄만 보여준 뒤 전체 기록을 따로 열어 종류별로 걸러 보고 해당 회차로 이동해요.
  최근 활동을 카드로 두는 것은 사용자의 제안이에요.
- 표지는 눌러서 크게 볼 수 있어요.
- 버튼 이름은 [화면 간 공통 규칙](#화면-간-공통-규칙)의 문구 규칙을 따라 `시즌 변경`·`제작자 변경`처럼 써요.
  처음에는 `바꾸기` 같은 기존 버튼 동사를 그대로 두었지만, `변경`과 섞여 쓰인다는 지적으로 바꿨어요.

### 설정 화면의 구성

설정은 명세의 세 탭(공통 정책·감시 폴더·가져오기와 내보내기) 대신, 항목 목록에 현재 값을 보여주고 항목을 누르면 내용이 열리는 목록·상세형이에요(사용자 결정).
명세대로의 탭형, 모든 구역을 한 페이지에 펼치는 한 페이지형과 비교했어요.
설정은 자주 열지 않는 화면이라 열자마다 `ASS → SMI → SRT`·`폴더 2개`·`마지막 내보내기 9/1 12:10`처럼 지금 상태를 들어가지 않고 읽을 수 있는 쪽을 골랐고, 값 하나를 바꾸려면 한 번 더 눌러야 하는 비용을 받아들였어요.
PC에서는 수집 화면 규칙 탭처럼 왼쪽 목록과 오른쪽 내용이고, 휴대폰에서는 항목이 뒤로 가기가 되는 자기 화면으로 열려요.
명세의 세 탭 구성은 명세에 반영할 때 고쳐야 해요.

- 목록은 네 묶음이에요: 공통 정책(자막 형식·브라우저), 라이브러리(감시 폴더·파일 용량과 정리), 데이터(내보내기·가져오기), 배포(배포 설정, 읽기 전용).
- 자막 형식과 브라우저는 한 정책 버전을 함께 쓰므로 저장 막대도 하나예요.
  다른 화면이 먼저 저장해 저장이 거부되면 입력한 값을 남긴 채 서버 값과 나란히 보여주고, `서버 값 사용`과 `내 값으로 다시 저장` 중에 골라요.
- 감시 폴더를 추가할 때 이미 등록한 폴더, 등록한 폴더의 안쪽 폴더, 앱이 읽을 수 없는 경로를 문장으로 알려요.
  등록 해제는 파일을 건드리지 않고 그 폴더의 작품만 라이브러리에서 빼며 보관 기록은 남는다고 확인한 뒤 해요.
- 파일 용량과 정리는 `.trss` 폴더의 자막·폰트·표지 용량과 정리할 것이 있는 작품 목록이며, [정리 위치](#정리-위치)대로 작품 화면으로 이동만 해요.
- 가져오기는 파일 선택, 검토, 결과의 세 단계예요.
  기존 YAML은 채널마다 교체·추가·건너뛰기를 고르고, 규칙 주석에서 만든 구독 제안을 확인해요.
  교체는 채널을 파일 내용으로 통째로 바꾸므로 파일에 없는 지금 규칙은 없어지고, 그 규칙으로 받은 파일과 보관 기록은 남아요(사용자 결정).
  교체를 고르면 없어질 규칙 이름을 검토 단계에서 바로 보여주고, 결과에는 없앤 개수를 따로 적어요.
  이미 있는 채널의 선택지는 아무것도 고르지 않은 상태로 시작하고, 채널마다 고르기 전에는 `가져오기`를 누를 수 없어요(사용자 결정).
  규칙을 없애는 교체가 기본으로 골라져 있으면 모르고 넘어갈 수 있기 때문이에요.
  파일에 있는 규칙만 바꾸고 나머지를 남기는 안은 `교체`라는 이름과 실제 동작이 어긋나고 채널 안 규칙 순서가 섞여서 고르지 않았어요.
  앱 YAML은 채널 안에서 규칙을 골라 최종 평가 순서를 미리 보고, 보관 파일의 확인·누락·내용 다름을 보여주며, 참조가 풀리지 않은 감시 폴더를 기존 폴더로 연결하기 전에는 적용을 막아요.
  결과는 추가·교체·그대로 남은 것을 문장과 개수로 보여주고, 가져오기가 다운로드·적용·파일 정리를 실행하지 않는다고 알려요.
- 화면 모드는 상단의 전환 버튼이 맡으므로 설정에 두지 않아요.

### 화면 간 공통 규칙

홈·수집·작품 상세 시안을 나란히 맞추면서 다음을 정했어요.

- 시즌은 설명·버튼·타일 모두 `시즌`이라고 불러요.
  타일도 `1기`가 아니라 `시즌 1`이고, 저장 폴더의 `Season N`과 명세의 용어에 맞춰요.
- 회차의 보유 표시는 홈의 `영상 받음`에 맞춰 `영상 ✓`·`자막 −`로 쓰고, 영상이 아직 없는 자막은 `영상 대기` 배지로 보여줘요.
  `파일`은 작품 상세의 폴더·정리 카드 이름과 실제 파일 이름을 가리킬 때만 써요.
  명세는 `파일 ✓`·`파일 대기`를 쓰므로 명세에 반영할 때 고쳐야 해요.
- 할 일 가운데 빨간 강조는 수집을 막는 `인증 필요`와 `받기 실패`에만 쓰고, `회차 확인 필요`는 교체 승인처럼 차분한 파랑으로 둬요.
- 휴대폰에서 시즌 고르기처럼 짧은 선택만 아래에서 올라오는 시트로 열고, 나머지 창은 모두 수집 화면의 시트 머리(왼쪽 제목, 오른쪽 닫기)를 써요.
  뒤로 화살표는 같은 창 안에서 이전 단계로 돌아갈 때만 써요.
- 상태 배지는 테두리와 아이콘이 있는 한 가지 모양만 쓰고, 한 상태를 화면마다 다른 모양으로 그리지 않아요.
  물음표 아이콘은 `확인 필요`에만, 바깥으로 나가는 화살표는 AniList·Transmission 같은 외부 링크에만 써요.
- 받은 영상·자막의 체크 표시는 작품 상세의 보유 표시처럼 모든 화면에서 초록으로 보여줘요.
  홈·라이브러리는 표시를 글자 앞에, 작품 상세의 회차 줄은 글자 뒤에 두는 차이가 남아 있어요.
- 개수는 항목·규칙·파일에 `개`, 기록에만 `건`을 쓰고, 날짜 머리는 `9월 28일 (월)`처럼 쓰되 올해가 아니면 연도를 붙여요.
- 명세나 앞선 결정에 있는 문구라도 화면끼리 어긋나면 하나로 맞춰요.
  - 한 상태는 할 일 종류·회차 배지·기록에서 같은 이름을 써요.
    교체 승인은 모두 `교체 승인`이고, 명세의 `교체 승인 대기` 배지는 명세에 반영할 때 고쳐야 해요.
  - 회차를 정하지 못한 파일은 편성·할 일·작품 상세의 문제와 활동 기록 모두 `회차 확인 필요`예요.
    작품 상세의 문제 제목은 `회차 미정 영상` 대신 확인할 RSS 항목 이름 조각을 보여줘요.
    할 일 종류로 쓰던 `회차 미확정`은 없애요.
  - 기다리는 상태는 `제목 대기`·`영상 대기`·`자막 대기`처럼 `무엇 + 대기`로 쓰고, 방영 전후를 가리지 않고 `자막 대기` 뒤에 제작자를 둬요.
    자막 출처에 연결되지 않아 다시 확인을 기다리는 작업도 `자막 대기`이고, 까닭은 줄의 설명에 적어요(사용자 결정).
    명세의 대기 사유 `연결 확인`은 명세에 반영할 때 고쳐야 해요.
  - 시각은 할 일 카드·작업 목록·작업 상세·작품 상세 모두 `오늘 13:40`·`어제 00:05`·`9/13 12:35`로 쓰고, `2시간 전` 같은 상대 표기는 쓰지 않아요.
  - `실패` 배지는 수집 기록과 자막 작업이 같은 모양(빨간 테두리·경고 아이콘)을 써요.
  - 작품 상세 위쪽 구역도 홈·메뉴와 같은 `할 일`이라고 불러요.
  - 제작자 미정인 작품에 자막 후보가 나타난 할 일은 `교체 승인`·`보관 제안`처럼 `무엇 + 동작` 모양의 `자막 구독`이에요.
- 카드 전체가 링크인 작품 카드·목록 카드는 올려 두면 제목에 밑줄을 긋지 않고 카드 배경을 한 단계 밝혀요.
  회차 줄·시트 목록이 이미 쓰는 배경 변화와 같은 방식이고, 밑줄은 문장 속 글자 링크에만 남겨요.
- 화면 문구는 짧은 명사형으로 쓰고, 문장은 최소로 해요(사용자 결정).
  - 같은 뜻은 한 단어로 쓰고, 한자어 용어가 있으면 그것을 써요: `바꾸기`·`바뀜`은 `변경`, `지우기`는 `삭제`, `고르기`는 `선택`이에요.
    `교체`·`유지`는 쓰면서 같은 성격의 동작을 `바꾸기`로 쓰던 혼용을 없애기 위해서예요.
  - `받기`·`다시 받기`·`받는 중`은 이미 정한 용어라 예외로 남기고(사용자 결정), `보기`·`열기`·`닫기`·`자세히`처럼 자연스러운 한자어가 없는 동사도 그대로 써요.
  - 버튼 이름은 `~하기`를 붙이지 않고 `인증`·`비교`·`연결`·`보관`·`검색`·`시즌 변경`처럼 명사로 끝내요.
    같은 뜻의 짝은 `검색`(찾기), `발견`(찾음), `생성`(만들기), `복원`(되돌리기), `대기 중`(기다리는 중)으로 맞춰요.
  - 버튼·배지·상태 줄·항목 값·기록 줄은 짧은 명사구로 써요.
  - 모든 화면에서 여러 정보를 ` · `로 한 줄에 잇지 않고, 정보 종류마다 모양을 달리해 간격으로 나눠요(사용자 결정).
    회차는 굵게, 제작자는 자막 아이콘과 함께, 형식·버전·맥락은 작은 태그로, 개수는 `추가 2`·`변경 12` 같은 숫자 태그로, 이름표가 필요한 값은 흐린 이름표 뒤에 둬요.
    `영상 받는 중`과 `완료 즉시 적용`처럼 상태와 그 결과를 잇던 설명은 두 줄로 나눠 첫 줄을 상태로, 다음 줄을 흐리게 둬요.
    기록 줄은 일어난 일을 먼저 쓰고 덧붙이는 정보는 흐리게 옆에 둬요.
    홈·라이브러리·수집도 같은 방식이에요(사용자 결정): 채널은 태그로, 방영 시작일·연도·근거처럼 덧붙이는 값은 흐리게, `마지막`·`다음` 실행 시각은 이름표 뒤에 둬요.
  - 해요체 문장은 빈 화면·알림·확인 질문·실패 이유 설명, 그리고 상태 배너·구역 안내처럼 넓은 설명 영역에 써요.
    짧은 명사구는 버튼·배지·목록 줄처럼 좁은 자리의 규칙이고, 넓은 영역을 명사구로 줄이면 휑하고 뜻이 모자라므로 까닭과 결과를 한두 문장으로 써요(사용자 결정).
    수집 규칙 편집의 상태 배너는 위 배지가 이미 상태 이름을 말하므로, 제목을 `이 규칙을 보관할까요?`·`이 제목이 맞나요?`·`첫 화를 기다리고 있어요`·`보관한 규칙이에요`처럼 질문이나 설명으로 쓰고 본문에 까닭과 누른 뒤의 결과를 적어요.
    보관 제안의 두 번째 버튼은 무엇을 유지하는지 드러나게 `유지` 대신 `수집 유지`예요.
  - 설명 줄은 배지·단계·시각·항목 결과가 이미 말하는 것을 되풀이하지 않고, 영상 대기 이유나 연결 실패처럼 새 정보가 있을 때만 둬요.
  - 구역 제목 옆 설명은 제목만으로 오해될 때만 짧은 명사구로 남겨요.
  - 교체 비교에서 새로 추가된 대사의 이전 줄은 글자 대신 긴 가로 막대로 표시하고, 막대는 바뀐 대사의 취소선과 같은 회색·굵기로 맞춰요(사용자 결정).
- 같은 개념은 수집 화면의 이름을 따라 `일치 문구`·`보관 제안`·`제작자 미정`·`받기`로 쓰고, 영상이 아닌 자막 후보는 `자막 후보`라고 불러 제목 후보와 구분해요.

### 첫 실행의 기존 설정 가져오기

첫 실행은 홈의 이번 주 자리에 `처음 설정` 체크리스트를 보여주고, 단계는 `감시 폴더 등록`과 `기존 설정 가져오기` 두 개예요.
처음에는 구독 제안 확인을 세 번째 단계로 제안했지만, [설정의 가져오기](#설정-화면의-구성) 검토 단계에서 주석으로 만든 구독 제안을 이미 체크해 고르므로 가져오기 단계에 합쳤어요.
각 단계의 버튼은 설정의 감시 폴더와 가져오기로 이어지고, 폴더를 하나 추가하거나 가져오기를 적용하면 그 단계가 끝나요.
각 단계는 건너뛸 수 있고 건너뛴 것을 되돌릴 수 있으며, 두 단계가 모두 끝나거나 건너뛰면 체크리스트가 사라지고 이번 주 편성이 나와요.
첫 실행 중에는 아직 수집한 것이 없으므로 홈의 수집 상태·다음 분기 구독과 휴대폰 요약 줄, 할 일 개수 배지를 두지 않아요.
설정도 아직 연결한 작품이 없는 상태로 보여서 작품별 형식 지정과 정리할 작품은 비어 있고 `.trss` 파일은 0이며, 내보내기는 마지막 내보내기가 없고 담기는 것도 그때까지 등록한 폴더와 가져온 채널·규칙 수만 세요.
가져오기는 현재 채널이 없어 채널마다 교체·추가·건너뛰기를 묻지 않고 모두 추가해요.
사용자는 형태를 정하지 않고 판단을 맡겼으며, 설치 때 한 번 거치는 과정이라 선택의 비용이 작다는 이유로 강제 마법사 대신 건너뛸 수 있는 체크리스트를 골랐어요.


기존 YAML을 가져올 때 규칙 위 주석의 Anissia 작품 주소와 자막 제작자를 읽어 구독 연결을 제안하고, 사용자가 확인한 것만 반영해요.
이번 분기 작품이 첫 실행부터 구독 상태가 되는 대신, 사람이 쓴 주석 형식에 기대는 약한 연결이므로 읽지 못한 주석은 제안 없이 규칙만 가져와요.

### 정리 위치

보관 파일의 정리는 작품 상세에서 그 작품의 이전 수정본·영상 대기 파일을 대상으로 하고, 설정에는 작품별 용량과 정리할 수 있는 항목의 요약을 두어 해당 작품으로 이동해요.
전체 정리 대상을 한 목록에서 한 번에 지우는 대안은 실수로 넓게 지울 위험 때문에 선택하지 않았어요.

### 채널 URL의 비밀 값

앱 YAML 내보내기는 채널 URL의 쿼리 값을 가리고, 가져올 때 비어 있는 값을 다시 입력받아요.
공개 위치에 내보낸 파일을 두어도 피드 토큰이 노출되지 않는 대신 이전 과정에 입력 단계가 하나 늘어요.
어떤 쿼리 값이 비밀인지 구분하는 기준은 아직 정하지 않았어요.

### 시각 언어의 결정 방법

사쿠라 시안의 불만을 말로 특정하지 못했으므로, 같은 홈 화면을 여러 시각 방향으로 만든 버려도 되는 시안을 나란히 보고 반응으로 정해요.

1차 비교는 포스터 에디토리얼·다크 시네마·종이 편성표 세 방향이었으며, 사용자는 다크 시네마의 테마를 가장 선호했어요.
실제 제품은 라이트·다크 모드를 모두 지원해야 하므로, 다크 시네마의 시각 언어를 라이트 모드로도 옮겨야 해요.
이번 주 편성의 배치는 테마와 별개로 판단했어요.
휴대폰에서는 날짜 열 옆에 작품 행을 쌓는 에디토리얼 시안의 배치를 선호하고, 더 넓은 화면에서는 한 줄에 여러 작품을 줄바꿈해 보여주되 가로 스크롤은 만들지 않아요.
오늘 방영작을 큰 표지로 따로 강조한 영역은 너무 크다는 반응이라 작은 표시로 줄여요.
편성이 길면 그 아래 영역에는 거의 접근하지 않을 것이라는 판단에 따라, 다음 분기 구독과 RSS·Transmission 상태를 편성 아래에 두지 않는 방향을 2차 시안에서 확인해요.
2차 시안에서는 PC에서 편성 옆의 좁은 열, 휴대폰에서 할 일 아래 한 줄 요약으로 옮기는 안을 제안했어요.

2차 시안에 대한 사용자 결정은 다음과 같아요.

- 수집 상태(RSS·Transmission)를 다음 분기 구독보다 먼저 보여줘요.
  좁은 열에서 채널 태그가 줄바꿈되어, 받은 개수 줄에는 채널 이름 없이 개수만 둬요(사용자 결정).
  받은 개수는 수집 화면과 같은 기록에서 센 `최근 7일 받음`이고(휴대폰 요약은 `7일`), 확인 시각도 수집 화면처럼 `확인`·`다음`으로 불러요(사용자 결정).
  처음에는 홈만 월–일 기준 `이번 주 17개 추가`를 따로 적어 수집 화면의 `최근 7일 받음 21개`와 숫자가 어긋났어요.
- 시스템·라이트·다크 전환은 세 칸짜리 선택지가 아니라 한 칸을 차지하는 토글로 만들어요.
- 오늘 편성 뒤에 표지 색을 번지게 한 노란 배경은 없애요.

3차 시안에서는 라이트 모드가 무난한 관리 화면처럼 보이지 않도록 배경과 카드 면의 명도 차이를 키우고 카드·표지에 그림자를 주었어요.
방영 전 작품을 작은 압축 카드로 줄이는 안도 냈지만, 사용자는 방영 전 작품도 방영한 작품과 같은 카드로 보여주기로 했어요.
방영 전 카드는 영상 `방영 전`과 자막 `자막 대기`와 제작자를 조용한 상태로 보여줘요.

3차 시안에 대한 사용자 결정은 다음과 같아요.

- 다크 모드에서 배경과 카드가 잘 구분되지 않으므로 카드 면을 조금 밝게 해요.
- 긴 편성에서 오늘로 바로 가는 수단이 필요해요.
  편성 위에 오늘 방영작을 따로 보여주는 안과 오늘 날짜로 이동하는 기능 중 어느 쪽이든 괜찮다고 했어요.

4차 시안은 오늘 방영작을 편성 위에 반복하지 않고 `이번 주 편성` 제목 옆의 `오늘로 이동` 버튼으로 오늘 행에 스크롤하고 초점을 옮기는 안을 골랐어요.
1차 비교에서 오늘 방영작을 따로 크게 강조한 영역이 너무 크다는 반응이 있었기 때문이에요.
사용자는 4차 시안을 받아들일 만하다고 보았고, 라이트 모드의 깊이와 이동 버튼도 그대로 두었어요.

4차 시안의 자체 검토에서 찾은 문제를 5차 시안에서 모두 고치기로 했어요.

- 휴대폰용 하단 메뉴가 나오지 않는 태블릿 폭(721–979px)에서는 상단 메뉴 이름이 세로로 쪼개졌어요.
  이 폭에서는 아이콘만 보이고 이름은 보조 기술에만 남겨요.
- 한국어 제목과 문장이 단어 중간에서 줄바꿈됐어요.
  줄바꿈은 띄어쓰기 단위로 해요.
- 1100px 미만에서 할 일이 가로 스크롤 줄이 되어 카드가 잘렸고, 넓은 화면에서는 오른쪽이 비었어요.
  할 일은 편성처럼 여러 줄로 감싸는 격자로 보여줘요.
- 편성에서 `자막 아직`이 `인증 필요`와 같은 강조로 보여 실제 예외가 묻혔어요.
  `자막 아직`은 제작자를 기다리는 평범한 상태로 조용하게 두고, 강조는 `인증 필요`·`회차 확인 필요`·`영상 받는 중`에만 써요.
- 방영이 없는 날은 날짜와 요일, `방영 없음`만 담은 얇은 한 줄로 줄여요.
- 작품이 연결되지 않은 할 일은 표지 자리에 할 일 종류의 아이콘을 두어 다른 할 일과 모양을 맞춰요.

이후 홈에서 할 일을 뺐으므로 격자 결정은 할 일 화면의 카드에 이어졌고, 표지 자리의 종류 아이콘은 할 일 화면을 다시 짜면서 중립 아이콘으로 바꿨어요.

시안은 로컬 `.scratch/redesign-home-2/prototype`에 있으며, 작품·편성·제작자·표지는 2026-09-29에 조회한 실제 자료이고 수신 상태와 할 일은 시뮬레이션이에요.
이 반응은 사용자 한 명의 시안 검토이며 실제 사용 관찰이 아니에요.

## 근거

### 사용 흐름 (사용자 보고)

- 새 화가 나올 때, 인증·승인 같은 할 일이 생겼을 때, 볼 작품을 고를 때, 규칙·설정을 손볼 때 모두 웹을 열어요.
  한 계기가 지배적이지 않으므로 한 방향만으로 모든 계기를 대표하기 어려워요.
- 휴대폰과 PC를 비슷하게 사용해요.
- 현재 방영작과 기존 라이브러리의 관리 비중은 비슷해요.
- 기존 작품은 많지만 자막 정리는 주로 분기 방영작에 집중하고, 옛날 작품은 가끔 몇 개씩 추가해 봐요.
  발견한 모든 작품이 자막 관리를 필요로 하지는 않는다는 근거예요.
- 라이브러리의 작품은 아직 많지 않지만 나중에는 500편을 넘을 것으로 봐요.
- 볼 작품을 고를 때 최근 들어온 작품, 자막까지 다 갖춘 작품, 표지를 보며 둘러보기, 이름으로 찾기를 모두 써요.
- 영상은 Infuse에서 NFS로 열어 보고 있어서 TRSS가 시청 기록을 알 수 없어요.
  Jellyfin 도입을 고민하고 있지만 정하지 않았어요.

### 현재 채널 설정에 드러난 수작업

[README가 가리키는 채널 설정](https://github.com/syrflover/syrflover/blob/master/transmission-rss-channels.yaml)을 2026-09-29에 읽기 전용으로 확인했어요.
규칙은 `Q. 2026/3` 같은 분기 주석으로 묶여 있고, 각 규칙 위에 Anissia 편성의 요일·시간, 따라갈 자막 제작자, Anissia 작품 주소를 주석으로 적어요.
일치 조건은 SubsPlease 릴리스의 작품 제목이고, 경로는 `작품/Season 01` 형태이며, SubsPlease에 없는 작품은 erai-raws 채널의 규칙으로 받아요.
과거 규칙에는 `episode: -24`처럼 누적 회차를 시즌 회차로 바꾸는 값도 있어요.
사용자는 이미 Anissia 편성 → 자막 제작자 → RSS 릴리스 제목 → 작품 폴더의 연결을 구독 시점에 손으로 관리하고 있다는 근거예요.

SubsPlease RSS는 최근 릴리스만 담으므로 첫 화가 나오기 전의 신작은 RSS 항목에서 고를 수 없어요.
SubsPlease 사이트의 `/api/?f=schedule`은 2026-09-29 조회에서 `Asia/Seoul` 기준 요일별 제목·시간·페이지 식별자를 반환했지만, 문서화된 공개 API인지와 형식의 안정성은 확인하지 않았어요.

## 미결 사항

### 기획 보완 대상

이번 범위에서 보완하는 흐름 중 다음이 남았어요.

- **첫 실행 체크리스트**: 두 단계 형태를 통합 시안에 붙였어요.

중복 영상의 선택 흐름과 외부 알림은 기존 명세의 보류를 유지해요.

### 디자인

- 자막을 기다리는 상태의 문구는 사용자 지적에 따라 `자막 아직`에서 바꿨고, 지금은 [화면 간 공통 규칙](#화면-간-공통-규칙)의 `자막 대기`예요.
- 수집 화면은 3차 시안(작업별 탭)을 여러 차례 고친 뒤 사용자가 이 정도면 됐다고 했어요.
  수집 실패는 할 일로 올리고, 검사 순서는 목록에서 빼고 겹칠 때만 표시하기로 했어요.
- 작품 상세는 한 흐름 시안(M)에 [작품 상세의 구성](#작품-상세의-구성)의 결정을 반영했고, 시즌 정보와 오른쪽 카드 열의 배치를 고친 뒤 사용자가 이 정도면 된 것 같다고 했어요.
  홈(5차)·수집·작품 상세는 [화면 간 공통 규칙](#화면-간-공통-규칙)에 맞춘 뒤 한 시안 `trss.html`로 합쳐, 메뉴와 카드·할 일 링크로 화면을 오가요.
  합친 시안은 모든 화면의 가상 시각을 홈 편성과 같은 2026-09-16(수) 23:50으로 맞췄어요.
  이 시각에서는 라라가 11화까지 모두 받아져 있어 `아직 RSS에 없는 방영분` 사례는 최강 찌꺼기 황자 10화의 영상 대기로만 남았어요.
  회차 스틸 이미지는 출처와 이용 조건이 풀리지 않아 시안에 넣지 않았어요.
- 라이브러리는 선반형·한 목록형·시기별 묶음형 시안 중 한 목록형(P)이 가장 낫다고 했고, 시기별 묶음형(Q)도 괜찮다고 했어요.
  P를 통합 시안의 라이브러리로 옮겨 기존 화면과 맞췄고, 사용자가 이 정도면 괜찮다고 했어요.
  표지 보기에서는 할 일 배지를 표지 왼쪽 위에 올리고 영상·자막을 홈 카드처럼 두 줄로 보여줘요.
  목록 보기의 표지 폭은 48·60·72px를 비교한 뒤 사용자가 48px를 골랐어요.
  세 시안 모두 표지 격자와 목록을 바꿔 볼 수 있고, 약 520편의 작품(AniList 실제 작품에 보유·자막 상태를 시뮬레이션)으로 확인해요.
- 할 일 화면을 준비하며 통합 시안의 할 일을 여섯 종류로 맞췄어요.
  수집 실패를 할 일로 올리기로 했지만 홈에 빠져 있던 `받기 실패`(수집 기록의 LIAR GAME 26화 한 번 받기 실패)와, 새 종류 `자막 구독`(제작자 미정인 클레바테스Ⅱ에 자막 후보가 올라온 경우)을 홈·라이브러리에 더했어요.
  홈이 Anissia의 빈 제작자 표시 `xx`를 그대로 보여주던 것도 `자막 대기`와 `제작자 미정`으로 고쳤어요.
- 할 일 화면은 두 구역형(R)·탭형(S)·작품별 묶음형(T) 시안 중 사용자가 R이 가장 낫다고 했어요.
  R을 통합 시안의 할 일 화면으로 옮기며 기존 화면에 맞췄어요: 머리는 라이브러리·수집처럼 제목과 한 줄 설명, 소제목은 작품 상세처럼 숫자만 든 개수 칩, 작업 줄은 라이브러리 목록처럼 48px 표지와 배경 변화, 펼친 내용은 작품 상세 회차처럼 설명 한 줄과 이름표 달린 칸이에요.
  완료된 작업은 소제목이 이미 완료를 말하므로 줄마다 배지를 붙이지 않아요.
  시안의 자막 작업은 진행 1·대기 5·실패 2·완료 115개예요.
  이어서 홈에서 할 일 구역을 빼고 `이번 주 편성`을 라이브러리·할 일·수집 제목과 같은 24px 화면 제목으로 올렸어요.
- 작업 상세는 모든 자막 작업이 같은 페이지를 쓰고, 원격 인증과 비교·승인은 그 페이지의 한 상태로 두는 방향으로 한 흐름형(U)·작업대형(V) 시안을 만들었어요.
  사용자는 인증을 PC와 휴대폰에서 비슷하게 한다고 했고, 휴대폰에서는 서버의 Chromium 창 크기를 기기 폭에 맞춰 원격 화면이 휴대폰 배치로 보이게 하기로 했어요(사용자 결정).
  기기를 바꿔 열면 창 크기가 다시 바뀌는 비용이 있어요.
  명세가 첫 화면에 대상·실제 변경 경로·판단 한계를 요구하므로, 경로를 뒤 단계로 미루는 단계형은 비교하지 않았어요.
  사용자는 흐름형(U)을 골랐어요.
  PC에서는 U가 훨씬 나았는데, 그 이유의 상당 부분은 작업대형(V)에서 기다리거나 끝난 작업의 왼쪽 작업 영역이 휑했기 때문이에요.
  휴대폰에서는 V가 머리를 짧게 두어 첫 화면에 사람 확인 상자가 보이는 장점이 있었어요.
  그래서 U를 바탕으로 통합 시안에 `#/job/<작업>` 화면을 넣고, 휴대폰에서는 머리를 줄이고 단계를 한 줄 요약으로 접어 첫 화면에서 인증할 수 있게 했어요.
  할 일 카드와 작품 상세 할 일 카드의 `인증`·`비교`, 자막 작업 줄의 `자세히`가 이 화면으로 이어져요.
  390×844 휴대폰에서 사람 확인 상자가 첫 화면에 보이는 것을 헤드리스 Chromium으로 확인했고, 실제 휴대폰에서는 확인하지 않았어요.
  교체 승인 화면은 내용이 너무 많다는 사용자 지적에 따라 줄였어요.
  사용자가 판단하는 것은 새 버전의 내용이므로, 변경 사항(대사·타이밍·스타일·폰트)을 본문으로 둬요(사용자 결정).
  네 항목은 처음에 접어 `추가 2`·`변경 12`·`삭제 0` 같은 숫자 태그 요약만 보여주고, 항목마다 펼쳐 상세를 봐요(사용자 결정).
  같은 제작자가 같은 게시물에서 파일만 바꾼 경우 두 파일의 정보는 거의 같으므로, 파일 비교는 머리 아래 `현재`·`새 자막`마다 받은 시각·크기·줄 수를 한 줄씩 두는 버전 줄로 줄이고, 제작자·형식·게시물이 다르거나 기존 파일의 출처를 모를 때만 나란한 비교를 보여줘요.
  대상은 머리에 합쳐요.
  버전 줄과 교체·유지 버튼은 한 카드로 묶어, 왼쪽에 `현재`·`새 자막` 두 줄과 출처 변화를, 오른쪽에 버튼을 둬요(사용자 결정).
  무엇 사이에서 고르는지는 버전 줄이, 무엇을 하는지는 버튼 이름이 이미 말하므로 `적용본 새 자막으로 교체 · 보관본 유지` 같은 설명 줄은 두지 않아요(사용자 결정).
  교체해도 현재 보관본이 남는다는 사실은 늘 같은 규칙이라 결정 카드에서 되풀이하지 않고 경로 구역에 남겨요.
  PC에서 화면 아래에 고정한 교체·유지 버튼은 눈에 들어오지 않았으므로(사용자 지적), PC에서는 이 카드가 머리 바로 아래에 있고 스크롤하면 화면 위쪽에 붙어 따라와요.
  휴대폰에서는 카드는 제자리에 두고 버튼 두 개만 손이 닿는 화면 아래, 하단 메뉴 바로 위에 고정해요.
  실제 변경의 파일 경로는 첫 화면에 보여주지 않아요(사용자 결정).
  자막 버전은 `v1`·`v2` 같은 번호 대신 `현재`·`새 자막`이라는 역할로 부르고, 버튼도 `현재 유지`·`새 자막으로 교체`예요(사용자 결정).
  교체 승인에서 고르는 것은 늘 지금 쓰는 자막과 새로 받은 자막이라 번호로는 어느 쪽이 현재인지 한 번 더 따져야 했기 때문이에요.
  대사 비교의 두 줄은 글자 대신 `−`·`+`와 취소선·밑줄로 구분하고, 새로 추가된 대사의 이전 줄은 긴 가로 막대로 둬요.
  지난 수정본을 고를 때처럼 번호가 필요해 보이는 곳도 받은 날짜로 부르는 방향을 제안해요.
  영상 릴리스의 `v2`는 릴리스 이름에 붙는 표기라 그대로 써요.
  승인 직전의 재확인은 사용자가 할 일이 없는 안전장치라 평소에는 보여주지 않고, 재확인에서 새 수정본 같은 변화를 찾았을 때만 결정 카드에 `새 수정본 발견`과 `다시 비교 필요`로 이유를 보여줘요(사용자 결정).
  이전 적용본을 지우거나 TRSS가 관리하지 않는 파일을 덮어쓰는 것처럼 예상과 다른 변경일 때만 정확한 경로를 경고로 보여주는 방향을 제안해요.
  명세는 첫 화면에 실제 변경 경로를 요구하므로 명세에 반영할 때 고쳐야 해요.
  승인 계획 ID와 판은 서버가 오래된 승인을 거부하는 데 쓰는 내부 값이라 화면에 보여주지 않아요.
  판단 한계에 늘 붙던 일반적인 주의 문장은 지워요(사용자 결정).
  명세의 판단 한계는 출처 미상·분석 불가·릴리스 불일치 가능성 같은 실제 조건을 표시하라는 요구로 읽어, 그런 조건이 있을 때만 경고로 보여주고 첫 화면에 늘 두는 구역으로 두지 않는 방향을 제안해요.
  명세의 첫 화면 판단 한계 요구도 명세에 반영할 때 이에 맞춰 고쳐야 해요.
  경로는 고정폭 글꼴이 보기 좋지 않다는 지적에 따라 모든 화면에서 본문 글꼴로 보여주고, 해시·시각표 같은 값만 고정폭으로 남겨요.
  할 일에서 작품 상세나 할 일 카드로 들어올 때 잠깐 파란 테두리로 도착 위치를 보여주던 강조는 없애고, 스크롤과 초점 이동만 남겨요(사용자 결정).
  빨간 인증 카드에 파란 테두리가 겹쳐 교체 승인처럼 보이는 혼동도 함께 사라져요.
