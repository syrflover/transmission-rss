# 웹 화면 재설계와 기획 보완

## 현재 방향

[기존 주제 문서](web-gui-subtitles.md)에서 채택한 사쿠라 시안의 정보 구조와 시각 언어를 모두 새로 설계해요.
요약 홈·다섯 개 주 메뉴·작품 상세 탭 같은 화면 구조도 다시 검토 대상이며, 기존 시안을 부분 수정하는 방향이 아니에요.
사쿠라 시안에서 무엇이 불만인지는 특정하지 않았으므로, 새 방향은 기존 시안의 결함 교정이 아니라 실제 사용 흐름에서 출발해요.

기획은 기존 명세를 유지하면서 빠진 흐름을 보완해요.
이 문서의 제안은 [구현 명세](../specs/web-gui-subtitles.md)를 자동으로 바꾸지 않으며, 수렴한 뒤 명세에 반영할 때 대체 범위를 정해요.

### 유지하는 것과 대체될 것

재설계는 명세의 기능 계약을 유지해요.
받은 자막과 후보·미확인 파일의 구분, 예외 상태의 구분, 교체 승인과 명령·버전 계약, 원격 인증 화면의 trss 내부 조작, 색만으로 상태를 전달하지 않는 접근성 요구가 여기에 해당해요.

명세의 [화면 구성](../specs/web-gui-subtitles.md#화면-구성)과 [시각적 방향과 테마](../specs/web-gui-subtitles.md#시각적-방향과-테마) 중 사쿠라 시안에 묶인 배치·치수·색상 값은 새 방향이 수렴하면 대체될 후보예요.
라이트·다크와 시스템 설정 추종처럼 시안과 독립적인 요구를 유지할지는 새 방향과 함께 확인해요.

## 선택과 근거

### 화면 구조

홈은 이번 주 방영작의 이번 화 영상·자막 상태를 요일별로 보여주고, 그 위에 할 일이 있을 때만 인증·승인·미확정 줄을 둬요.
라이브러리는 전체 작품의 표지 그리드로 둘러보기와 옛날 작품 찾기를 맡고, 수집 화면은 RSS 채널·규칙·수집 이력을 함께 다뤄요.
네 가지 여는 계기를 한 화면으로 대표하지 않고 화면별로 나눠 맡기는 선택이며, 완결작만 볼 때는 홈의 비중이 줄어드는 비용이 있어요.

할 일 화면은 명세의 작업 목록도 맡아요.
위에는 인증·승인·미확정·제안처럼 사용자가 처리할 것을, 아래에는 진행 중·최근 완료·실패한 자막 작업을 두어 자막이 왜 들어오지 않았는지를 한 곳에서 찾게 해요.
화면이 길어지는 비용은 처리할 것을 위에 두는 순서로 다뤄요.

비교한 출발점은 다음과 같고, 각 방향의 장점을 화면별로 나눠 가져왔어요.

| 방향 | 사용자 가치 | 비용 |
| --- | --- | --- |
| 미디어 라이브러리형 | 표지 그리드로 작품을 둘러보는 즐거움과 작품 식별이 쉬워요. | 인증·승인 같은 할 일이 한 단계 깊어져요. |
| 작업 인박스형 | 인증·승인·미확정·새 후보를 연속으로 빠르게 처리해요. | 작품을 둘러보는 경험이 약해요. |
| 방영 편성표형 | 요일별 방영 리듬에 맞춰 이번 화의 영상·자막 도착을 한눈에 봐요. | 완결작과 기존 라이브러리는 부차적인 화면이 돼요. |
| 밀도 높은 도구형 | 한 화면에서 가장 많은 상태를 빠르게 훑어요. | 표지와 장식이 거의 없어 개성이 약해요. |

### 작품 연결과 제외

발견한 작품은 미연결로 두고, 방영작이나 사용자가 자막을 원하는 작품만 Anissia·회차 대응을 연결해요.
첫 실행에서 모든 작품을 일괄 확인하는 대안보다 처음 부담이 작고, 자막을 주로 분기 방영작과 가끔 추가하는 옛날 작품에만 정리한다는 사용 흐름에 맞아요.
미연결 작품은 자막 후보를 자동 조회하지 않으며, 관리하지 않을 작품의 제외는 별도 기능 대신 이 기본 상태로 다뤄요.

### 방영작 구독

방영작 구독은 Anissia 편성표에서 작품을 고르고, 다운로드 규칙의 일치 조건은 RSS 채널의 릴리스 제목에서 고르는 흐름으로 시작해요.
[현재 채널 설정](#현재-채널-설정에-드러난-수작업)의 주석으로 하던 수작업을 앱으로 옮기는 방향이며, Anissia 연결은 구독 시점에 확정돼요.
SubsPlease 외의 채널도 사용하므로 릴리스 제목의 선택 대상은 특정 사이트가 아니라 선택한 채널이에요.
구독은 규칙을 만드는 일이므로 수집 화면에서 시작하고, 홈의 다음 분기 구독 영역에는 편성표에서 추가하는 바로가기를 둬요.

릴리스 제목은 실제 RSS 항목에서만 고르며, 비공식 편성 엔드포인트나 직접 입력에 의존하지 않아요.
첫 화 전에 구독한 작품은 일치 조건이 빈 제목 대기 상태로 시작해요.
worker는 규칙과 일치하지 않은 항목까지 RSS 수집 이력에 기록하고, 제목 대기 구독이 있는 동안 이력에 처음 나타난 작품 제목을 할 일로 알려요.
사용자가 그 항목을 고르면 규칙이 완성되고, 이미 기록된 해당 작품의 지난 항목을 미리보기로 보여준 뒤 확인하면 받아요.
미리보기는 `[Batch]` 같은 원치 않는 항목을 걸러낼 기회이며, 규칙 완성만으로 지난 항목을 바로 받지 않아요.
Anissia 작품과 새 제목의 연결은 제안일 뿐 사용자가 확정해요.

이 소급 적용은 trss가 기록한 항목에만 동작해요.
RSS 피드는 대부분 최신 회차만 담고, trss가 기록을 시작하기 전이나 늦게 구독한 작품의 지난 회차는 이력에 없으므로 이 경로로 받을 수 없어요.
사용자는 그런 지난 회차를 다른 방식으로 찾아 받아야 한다고 지적했고, 과거 설정에 주석으로 남은 nyaa 검색 RSS가 그 수작업의 흔적이에요.

지난 회차는 규칙의 조건으로 nyaa 검색 RSS를 만들어 한 번만 읽고, 상시 채널로 남기지 않는 방식으로 확보해요.
규칙에는 작품 제목만 있고 릴리스 그룹·화질은 채널 URL에 들어 있으므로, 채널마다 `[SubsPlease] {match} 1080p` 같은 지난 회차 검색 형식을 둬요.
검색 결과는 실제 규칙 판정을 거쳐 이력의 지난 항목과 같은 미리보기에 보여주고, 사용자가 확인한 항목만 Transmission에 추가해요.
늦게 구독한 방영작과 첫 화 전에 구독한 신작이 같은 확인 흐름으로 이어지며, 옛날 작품도 규칙을 만든 뒤 같은 방식으로 받을 수 있어요.
2026-09-29에 `[SubsPlease] Sayonara Lara 1080p` 검색 RSS가 01–12화 항목을 모두 반환하는 것을 확인했어요.
같은 날 `[SubsPlease] One Piece 1080p` 검색 RSS는 75개 항목만 반환했고, `p=2`를 붙여도 같은 첫 페이지를 돌려줘 RSS로는 다음 페이지를 받을 수 없었어요.
이 검색에는 `One Piece Log - …` 같은 다른 작품도 섞여, 부분 문자열 일치 조건만으로는 다른 작품을 걸러내지 못한다는 것도 드러났어요.

규칙의 일치 조건은 작품이 아니라 릴리스 제목의 흐름을 가리키므로, 과거 검색에서는 같은 제목의 다른 시즌과 파생작이 함께 나와요.
2026-09-29의 `[SubsPlease] Sono Bisque Doll 1080p` 검색에서는 같은 제목의 1기 01–12화와 2기 13–24화, 수정본 `14v2`, 범위가 겹치는 공식 `(01-12) Batch`와 비공식 `(01-24) Unofficial Batch`가 한 결과에 섞였어요.
그래서 지난 회차 찾기는 trss가 제안한 회차 범위를 사용자가 확인하는 것으로 시작해요.
범위는 `릴리스 13–24 → S02E01–12`처럼 릴리스 회차와 폴더 회차의 대응이며, AniList 회차 수와 규칙의 회차 변환, 구독 뒤 처음 본 RSS 항목의 회차를 근거로 제안하고, 근거가 없으면 사용자가 적어요.
범위 밖 결과는 미리보기에서 접어 개수만 보여주고, 빠진 회차는 범위에서 이미 있는 회차를 뺀 것으로 계산해요.

검색 결과 미리보기는 폴더나 Transmission에 아직 없는 개별 회차만 기본으로 선택해요.
이미 있는 회차와 배치 토렌트는 표시하되 선택을 해제해 두고, 사용자가 원하면 직접 골라요.
같은 회차의 수정본이 여러 개면 가장 높은 수정본만 기본으로 선택해요.
지금 worker는 Transmission의 같은 토렌트 해시 거부에만 기대 중복을 피하므로, 다른 릴리스로 이미 받은 회차는 회차 번호와 작품 폴더의 실제 파일로 판단해야 해요.
채널에 검색 형식이 없으면 규칙의 일치 조건으로 채운 검색어를 그 자리에서 고쳐 한 번 검색하며, 결과는 같은 규칙 판정과 미리보기를 거쳐요.

빠진 회차가 75개를 넘는 장편도 사용자가 검색을 나누지 않게 해요.
첫 검색 결과가 75개로 차서 잘렸을 수 있으면, trss가 확인한 범위에서 아직 없는 회차 번호를 계산해 `One Piece - (1000|1001|1002)`처럼 회차 번호를 묶은 검색을 이어서 보내고 결과를 같은 미리보기에 합쳐요.
2026-09-29에 이 묶음 검색 RSS가 지정한 1000–1002화만 반환하는 것을 확인했고, RSS의 정렬 인자는 무시되며 HTML 검색 페이지는 다음 페이지를 제공하지만 화면 구조에 기대므로 쓰지 않아요.
회차 표기는 `- 01`처럼 릴리스마다 다르므로 첫 검색 결과의 실제 제목에서 읽은 형식을 쓰고, 추가 검색은 간격을 두고 순서대로 보내요.
한 묶음에 넣을 회차 수와 요청 간격은 정하지 않았어요.

### 회차 변환의 자동 적용

새 시즌의 첫 릴리스 번호가 이전 시즌까지의 AniList 회차 합계에 1을 더한 값과 같으면 회차 변환을 묻지 않고 자동으로 적용해요.
2기가 24화로 끝나고 새 시즌이 `- 25`로 시작하면 −24, 첫 릴리스가 `- 01`이면 0이에요.
사용자는 이 경우가 모호하지 않으니 제안 대신 자동으로 적용하자고 했어요.
처음 본 릴리스가 시즌 첫 화가 아니거나, 분할 방영이 같은 시즌 폴더에서 번호를 이어가는 경우처럼 근거가 서로 맞지 않으면 번호만으로 새 시즌인지 판단할 수 없어요.
그런 경우에만 제안으로 보여주고 사용자가 확인해요.
자동으로 적용한 값은 `자동` 표시와 근거를 함께 보여주고, 직접 입력으로 바꿀 수 있어요.

### 영상 수정본의 대체

폴더에 있는 회차 영상보다 높은 수정본(`14v2` 등)이 나오면, 지난 회차 찾기와 방영 중 RSS 모두 같은 규칙으로 수정본을 자동으로 받아 기존 영상을 대체해요.
대체는 수정본의 수신과 확인이 끝난 뒤에 하며, 새 영상은 같은 회차 이름을 쓰므로 옆에 적용된 자막은 그대로 이어져요.
수정본에서 자막 타이밍이 어긋날 수 있으므로 작품 상세에 영상이 수정본으로 바뀌었다는 사실을 조용히 알리는 것을 기본값으로 제안해요.
이 결정은 명세가 보류한 중복 영상 선택 흐름 중 같은 릴리스의 수정본 경우를 정하며, 다른 그룹의 같은 회차처럼 나머지 중복은 계속 보류해요.

trss는 받은 영상의 이름을 `trname`으로 회차 이름으로 바꾸므로 파일 이름으로는 원래 수정본을 알 수 없어요.
trss가 받은 영상은 수집 이력의 원래 릴리스 이름과 파일의 CRC32를 기록해 버전을 알아요.
버전을 모르는 기존 영상은 파일 내용의 CRC32를 계산해 릴리스 이름 끝의 `[E2675E51]` 같은 값과 대조해요.
구버전의 값과 같으면 자동으로 대체하고, 최신 수정본과 같으면 건너뛰며, 어느 것과도 다르면 버전 미상으로 표시하고 선택을 해제해 둬요.
2026-09-29에 AnimeTosho가 실제 파일에서 계산해 공개한 CRC32로 이 관례를 대조했어요.
`[SubsPlease] Sono Bisque Doll wa Koi wo Suru - 13 (1080p) [E2675E51].mkv`와 `[Erai-raws] Snowball Earth - 06 [1080p CR WEBRip HEVC AAC][MultiSub][1BBD34E6].mkv`의 계산값이 각각 이름의 값과 같았어요.
그룹별 표본 하나씩의 확인이며, 모든 릴리스가 이 관례를 지킨다는 보장은 아니에요.
Erai-raws처럼 대괄호가 여러 개인 이름에서는 확장자 앞의 8자리 16진수 대괄호를 CRC 값으로 읽어요.

지금 worker가 방영 중 RSS의 수정본을 받으면 기존 회차 이름과 겹쳐 이름 바꾸기가 실패하고 두 파일이 남을 가능성이 있지만, 재현하지 않은 추정이에요.

### 자막 제작자 자동 수신

구독할 때 따라갈 자막 제작자를 정하고, 그 제작자의 새 회차 자막은 후보가 나타나면 자동으로 받아요.
기존 명세는 자막 후보 자동 선택을 범위 밖으로 두었지만, 사용자가 이미 구독 시점에 제작자를 정해 설정 주석에 적어온 근거로 이 결정을 다시 열었어요.
자동 수신은 구독 제작자의 아직 받지 않은 회차에 한정하며, 필요한 CAPTCHA는 할 일로 올라와요.
받은 회차의 자막 수정본 교체와 다른 제작자의 자막은 기존 명세의 선택·교체 승인을 유지해요.
제작자가 방영 중에 바뀌면 사용자가 구독을 고쳐야 한다는 비용이 있어요.

### 방영 종료 후 규칙 보관

방영이 끝난 작품의 규칙은 자동으로 끄지 않고, Anissia의 방영 종료나 마지막 수신 이후 새 항목이 없는 상태를 근거로 규칙 보관을 할 일로 제안해요.
사용자가 한 번에 보관하고 나중에 되살릴 수 있으며, 방영 연장이나 분할 방영을 잘못 끄는 위험을 자동 보관 대신 사용자 확인으로 피해요.

### RSS 수집 이력

수집 이력 화면은 네 가지 용도를 모두 맡아요.
규칙 불일치·제외 조건·Transmission 추가 실패처럼 항목이 받아지지 않은 이유를 확인하고, 규칙에 맞지 않은 항목을 규칙 없이 한 번 받고, 이력의 항목에서 새 규칙이나 제목 대기 구독의 일치 조건을 만들고, 언제 어떤 회차가 추가됐는지 시간순으로 훑어봐요.

규칙과 일치하지 않은 항목을 포함한 모든 기록을 삭제 없이 계속 보관해요.
놓친 항목 받기와 소급 적용은 기록이 남아 있는 동안만 가능하므로, 오래된 작품도 기록된 항목이면 다시 받을 수 있게 하는 선택이에요.
채널 하나가 한 해에 수천 건 정도라 용량 부담은 작다고 추정했으며 실제 증가량은 측정하지 않았어요.
길어진 목록은 화면에서 최근 순서와 필터로 다뤄요.

### 수집 화면의 구성

수집 화면은 `구독`·`규칙`·`기록`·`채널` 탭으로 나눠요.
작품 한 줄에 규칙과 구독을 묶고 기록·채널을 보조 화면으로 둔 작품 중심 시안과 비교해 사용자가 작업별 탭을 골랐어요.
구독은 Anissia와 연결된 규칙이므로 같은 작품이 `구독`과 `규칙` 두 탭에 나타나는 비용이 있어요.

시안 검토에서 사용자가 정한 화면 원칙은 다음과 같아요.

- 목록은 `더 보기` 버튼 대신 끝에 닿으면 이어서 불러오는 무한 스크롤로 보여주고, 내용을 펼치거나 이어 붙일 때 스크롤 위치를 옮기지 않아요.
  수집 화면만이 아니라 모든 목록에 적용해요.
- 제목 후보와 보관 제안은 급히 처리할 일처럼 보이지 않게 중립적으로 보여줘요.
- 분기가 끝나면 보관 제안이 한꺼번에 몰려 제목 후보 같은 다른 항목을 가리므로, 보관 제안은 개수와 `모두 보관`·`하나씩 보기`만 담은 한 줄로 접어 두고 펼쳐야 작품별로 보여요.
- 구독할 때 자막 제작자를 모르면 제작자 미정으로 구독하고, 자막이 올라오면 할 일로 알려줘요.
  2026-09-29 조회에서 Anissia 4분기 60편 중 자막 제작자가 등록된 작품은 20편이었어요.
- 구독 취소처럼 되돌리기 어려운 동작은 위험을 드러내는 모양으로 두고, 결과를 설명하는 확인을 거쳐요.
  확인은 별도 창 대신 누른 자리에서 한 번 더 물어요.
- 제목 후보와 보관 제안은 경고색이 아니라 우선순위에 따른 차분한 강조색으로 구분해요.
  3차 시안은 사용자 입력이 있어야 수집이 시작되는 제목 후보에 파랑, 정리 성격의 보관 제안에 보라를 쓰고, 동작 버튼은 맥락의 강조색 테두리로, 되돌리기 어려운 동작만 빨강으로 둬요.
- 상태 표시는 테두리와 아이콘이 있는 배지로, 제목 옆의 개수 나열은 개수 칩으로 보여줘요.
- 수집 화면 위쪽의 RSS·Transmission·채널 상태는 글줄 대신 작은 상태 칸으로 보여줘요.
- 총 회차를 모르는 작품도 진행 막대를 보여주고, 남은 부분을 점선으로 두어 `9 / ?화 받음`처럼 표시해요.
- 규칙의 폴더는 `저장 폴더`라고 불러요.
- 채널 주소의 비밀 값은 목록에서 가린 값과 자물쇠 표시만 두고, 설명은 비밀 값을 다시 입력하는 편집 화면과 채널 탭 아래의 한 줄에 둬요.
- PC의 규칙 탭은 규칙 목록과 규칙 상세가 각자 스크롤하고, 규칙을 고를 때 화면이 움직이지 않아요.
- 설명 문구는 구역마다 짧은 한 문장 이하로 줄이고, 카드마다 같은 설명을 반복하지 않아요.

2차 시안에서 확인할 제안은 다음과 같아요.

- 채널 안의 검사 순서는 두 규칙의 일치 문구가 겹칠 때만 의미가 있으므로 규칙 목록에서는 빼고, 규칙 상세와 `검사 순서` 정렬에서만 보여줘요.
  명세는 규칙 목록에 적용 채널과 평가 순서를 표시하도록 요구하므로, 이 제안을 받아들이면 명세를 고쳐야 해요.
- Transmission 추가 실패처럼 사용자가 손봐야 하는 수집 실패는 할 일로 올려 홈에서도 보이게 해요.
  규칙 불일치와 제외는 실패가 아니므로 기록에만 남겨요.

### 첫 실행의 기존 설정 가져오기

첫 실행은 홈의 이번 주 자리에 감시 폴더 등록, 기존 YAML 가져오기, 구독 제안 확인의 세 단계를 준비 체크리스트로 보여주는 방향을 제안해요.
각 단계는 건너뛸 수 있고, 모두 끝나거나 건너뛰면 체크리스트가 사라지고 이번 주 편성이 나와요.
사용자는 형태를 정하지 않고 판단을 맡겼으며, 설치 때 한 번 거치는 과정이라 선택의 비용이 작다는 이유로 강제 마법사 대신 건너뛸 수 있는 체크리스트를 골랐어요.


기존 YAML을 가져올 때 규칙 위 주석의 Anissia 작품 주소와 자막 제작자를 읽어 구독 연결을 제안하고, 사용자가 확인한 것만 반영해요.
이번 분기 작품이 첫 실행부터 구독 상태가 되는 대신, 사람이 쓴 주석 형식에 기대는 약한 연결이므로 읽지 못한 주석은 제안 없이 규칙만 가져와요.

### 정리 위치

보관 파일의 정리는 작품 상세에서 그 작품의 이전 수정본·영상 대기 파일을 대상으로 하고, 설정에는 작품별 용량과 정리할 수 있는 항목의 요약을 두어 해당 작품으로 이동해요.
전체 정리 대상을 한 목록에서 한 번에 지우는 대안은 실수로 넓게 지울 위험 때문에 선택하지 않았어요.

### 채널 URL의 비밀 값

앱 YAML 내보내기는 채널 URL의 쿼리 값을 가리고, 가져올 때 비어 있는 값을 다시 입력받아요.
공개 위치에 내보낸 파일을 두어도 피드 토큰이 노출되지 않는 대신 이전 과정에 입력 단계가 하나 늘어요.
어떤 쿼리 값이 비밀인지 구분하는 기준은 아직 정하지 않았어요.

### 시각 언어의 결정 방법

사쿠라 시안의 불만을 말로 특정하지 못했으므로, 같은 홈 화면을 여러 시각 방향으로 만든 버려도 되는 시안을 나란히 보고 반응으로 정해요.

1차 비교는 포스터 에디토리얼·다크 시네마·종이 편성표 세 방향이었으며, 사용자는 다크 시네마의 테마를 가장 선호했어요.
실제 제품은 라이트·다크 모드를 모두 지원해야 하므로, 다크 시네마의 시각 언어를 라이트 모드로도 옮겨야 해요.
이번 주 편성의 배치는 테마와 별개로 판단했어요.
휴대폰에서는 날짜 열 옆에 작품 행을 쌓는 에디토리얼 시안의 배치를 선호하고, 더 넓은 화면에서는 한 줄에 여러 작품을 줄바꿈해 보여주되 가로 스크롤은 만들지 않아요.
오늘 방영작을 큰 표지로 따로 강조한 영역은 너무 크다는 반응이라 작은 표시로 줄여요.
편성이 길면 그 아래 영역에는 거의 접근하지 않을 것이라는 판단에 따라, 다음 분기 구독과 RSS·Transmission 상태를 편성 아래에 두지 않는 방향을 2차 시안에서 확인해요.
2차 시안에서는 PC에서 편성 옆의 좁은 열, 휴대폰에서 할 일 아래 한 줄 요약으로 옮기는 안을 제안했어요.

2차 시안에 대한 사용자 결정은 다음과 같아요.

- 수집 상태(RSS·Transmission)를 다음 분기 구독보다 먼저 보여줘요.
- 시스템·라이트·다크 전환은 세 칸짜리 선택지가 아니라 한 칸을 차지하는 토글로 만들어요.
- 오늘 편성 뒤에 표지 색을 번지게 한 노란 배경은 없애요.

3차 시안에서는 라이트 모드가 무난한 관리 화면처럼 보이지 않도록 배경과 카드 면의 명도 차이를 키우고 카드·표지에 그림자를 주었어요.
방영 전 작품을 작은 압축 카드로 줄이는 안도 냈지만, 사용자는 방영 전 작품도 방영한 작품과 같은 카드로 보여주기로 했어요.
방영 전 카드는 영상 `방영 전`과 자막 `자막 대기 · 제작자`를 조용한 상태로 보여줘요.

3차 시안에 대한 사용자 결정은 다음과 같아요.

- 다크 모드에서 배경과 카드가 잘 구분되지 않으므로 카드 면을 조금 밝게 해요.
- 긴 편성에서 오늘로 바로 가는 수단이 필요해요.
  편성 위에 오늘 방영작을 따로 보여주는 안과 오늘 날짜로 이동하는 기능 중 어느 쪽이든 괜찮다고 했어요.

4차 시안은 오늘 방영작을 편성 위에 반복하지 않고 `이번 주 편성` 제목 옆의 `오늘로 이동` 버튼으로 오늘 행에 스크롤하고 초점을 옮기는 안을 골랐어요.
1차 비교에서 오늘 방영작을 따로 크게 강조한 영역이 너무 크다는 반응이 있었기 때문이에요.
사용자는 4차 시안을 받아들일 만하다고 보았고, 라이트 모드의 깊이와 이동 버튼도 그대로 두었어요.

4차 시안의 자체 검토에서 찾은 문제를 5차 시안에서 모두 고치기로 했어요.

- 휴대폰용 하단 메뉴가 나오지 않는 태블릿 폭(721–979px)에서는 상단 메뉴 이름이 세로로 쪼개졌어요.
  이 폭에서는 아이콘만 보이고 이름은 보조 기술에만 남겨요.
- 한국어 제목과 문장이 단어 중간에서 줄바꿈됐어요.
  줄바꿈은 띄어쓰기 단위로 해요.
- 1100px 미만에서 할 일이 가로 스크롤 줄이 되어 카드가 잘렸고, 넓은 화면에서는 오른쪽이 비었어요.
  할 일은 편성처럼 여러 줄로 감싸는 격자로 보여줘요.
- 편성에서 `자막 아직`이 `인증 필요`와 같은 강조로 보여 실제 예외가 묻혔어요.
  `자막 아직`은 제작자를 기다리는 평범한 상태로 조용하게 두고, 강조는 `인증 필요`·`회차 확인 필요`·`영상 받는 중`에만 써요.
- 방영이 없는 날은 날짜와 요일, `방영 없음`만 담은 얇은 한 줄로 줄여요.
- 작품이 연결되지 않은 할 일은 표지 자리에 할 일 종류의 아이콘을 두어 다른 할 일과 모양을 맞춰요.

시안은 로컬 `.scratch/redesign-home-2/prototype`에 있으며, 작품·편성·제작자·표지는 2026-09-29에 조회한 실제 자료이고 수신 상태와 할 일은 시뮬레이션이에요.
이 반응은 사용자 한 명의 시안 검토이며 실제 사용 관찰이 아니에요.

## 근거

### 사용 흐름 (사용자 보고)

- 새 화가 나올 때, 인증·승인 같은 할 일이 생겼을 때, 볼 작품을 고를 때, 규칙·설정을 손볼 때 모두 웹을 열어요.
  한 계기가 지배적이지 않으므로 한 방향만으로 모든 계기를 대표하기 어려워요.
- 휴대폰과 PC를 비슷하게 사용해요.
- 현재 방영작과 기존 라이브러리의 관리 비중은 비슷해요.
- 기존 작품은 많지만 자막 정리는 주로 분기 방영작에 집중하고, 옛날 작품은 가끔 몇 개씩 추가해 봐요.
  발견한 모든 작품이 자막 관리를 필요로 하지는 않는다는 근거예요.

### 현재 채널 설정에 드러난 수작업

[README가 가리키는 채널 설정](https://github.com/syrflover/syrflover/blob/master/transmission-rss-channels.yaml)을 2026-09-29에 읽기 전용으로 확인했어요.
