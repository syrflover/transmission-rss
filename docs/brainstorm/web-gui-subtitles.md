# 웹 GUI와 자막 수작업 개선

## 현재 방향

현재 사용자는 자막(Subtitle)을 하나씩 수동으로 다운로드하고 정리하고 있어요.
웹 GUI로 사용 편의성을 높이고, 자막 수작업을 줄이며, 함께 개선할 기능을 탐색하고 싶어 해요.
사용자는 보통 Anissia에서 자막을 찾을 수 있다고 설명했어요.
현재 정리 방식은 trname을 사용하고 자막을 영상 옆에 같은 이름으로 두는 방식이에요.
원하는 자막 처리는 사용자가 후보를 고르면 다운로드와 정리를 자동으로 처리하고, 여러 항목을 일괄 작업할 수 있는 형태예요.
CAPTCHA처럼 사람이 해야 하는 작업은 수동으로 처리해요.
웹 GUI는 사용자 혼자 집 안 네트워크나 VPN에서 사용해요.
구체적인 첫 출시 범위와 수동 작업 이후의 연결 방식은 아직 정하지 않았어요.

현재 사용자의 실제 작업 흐름을 기준으로 개선 방향을 정해요.
웹 GUI를 제공하는 것과 자막 수작업을 없애는 것은 별개의 효과이므로, 화면 추가만으로 문제가 해결된다고 가정하지 않아요.

## 선택지와 근거

웹 GUI에는 작품별 상태 확인, 작품·다운로드 규칙 관리, 자막 작업 처리 세 용도가 모두 필요하다는 사용자 선택이 있어요.
세 용도 사이의 우선순위와 첫 출시의 세부 범위는 아직 정하지 않았어요.
후보 선택은 사용자에게 남기고 반복적인 다운로드·정리를 줄이는 방향으로 정했어요.
후보까지 자동으로 선택하는 방향은 현재 선택에 포함하지 않아요.
일괄 작업은 필요하지만 작품·회차·자막 제작자 중 무엇을 기준으로 묶어 선택할지는 아직 정하지 않았어요.
사람이 처리해야 하는 CAPTCHA 등의 단계는 자동 우회하지 않고 수동으로 처리하는 방향이에요.
수동 다운로드 결과를 GUI에 전달할지, 사용자가 브라우저에서 처리한 뒤 자동 작업을 재개할지는 아직 정하지 않았어요.

| 항목 | 현재 방향 | 남은 선택 |
| --- | --- | --- |
| 웹 관리 화면 | 작품별 상태, 작품·다운로드 규칙, 자막 작업을 모두 다뤄요. | 각 화면의 세부 기능과 첫 출시 범위를 정해야 해요. |
| 자막 선택과 일괄 처리 | 사용자가 후보를 선택하고 이후 반복 작업을 자동화해요. | 일괄 선택 단위와 여러 파일이 들어 있는 다운로드의 처리 기준을 정해야 해요. |
| 자막 배치 | 현재처럼 영상 옆에 같은 이름으로 정리하는 흐름을 기준으로 해요. | 연결할 영상이 애매한 경우와 기존 자막이 있을 때의 처리를 정해야 해요. |
| 수동 개입 | 사람이 필요한 단계는 수동으로 처리해요. | 수동 처리 후 자동 정리로 돌아오는 방식을 정해야 해요. |
| 사용 범위 | 한 사람이 집 안 네트워크나 VPN에서 사용해요. | 구체적인 접근 보호 방식은 아직 정하지 않았어요. |

추가 후보로는 자막이 없는 회차 표시, 자막 수정본 확인, 실패 원인과 재시도, 다운로드 규칙의 적용 결과 미리보기가 있어요.
각 후보의 필요성과 첫 출시 포함 여부는 아직 확인하지 않았어요.

## 현재 제품의 근거와 한계

- [README](../../readme.md)는 RSS 피드(RSS Feed)의 항목을 규칙에 따라 Transmission에 추가하고 파일명을 변경하는 도구로 설명해요.
  현재 사용 안내는 Docker Compose, 환경 변수와 원격 YAML 설정 중심이에요.
- [예약 실행 스크립트](../../scripts/cron.sh)는 5분 간격 실행과 로그 파일 출력을 설정해요.
  저장소 조사에서는 trss 자체 웹 GUI를 찾지 못했어요.
- [주 실행 경로](../../src/main.rs)의 파일명 변경은 파일이 하나인 토렌트(Torrent)를 대상으로 해요.
  피드에서 사라진 관리 대상 토렌트를 Transmission에서 제거할 때 로컬 데이터는 삭제하지 않아요.
  따라서 이 기능을 자막 정리나 미디어 파일 자동 삭제 기능으로 간주하지 않아요.
- [Anissia 연동 코드](../../src/anissia.rs)에는 자막 메타데이터와 다운로드 관련 코드가 있지만 미완성 부분이 있고, [Cargo 설정](../../Cargo.toml)의 선택 기능으로 분리돼 있어요.
  현재 사용 가능한 종단 간 자막 자동화로 간주하지 않아요.

위 내용은 저장소의 문서와 코드 조사 결과예요.
프로그램 실행이나 외부 자막 출처의 접근·다운로드 가능성은 검증하지 않았어요.
수동 작업, Anissia 사용, trname 사용과 영상 옆 같은 이름의 자막 배치는 사용자 보고예요.
주 실행 경로에서도 영상 파일명 변경에 trname을 사용하는 것을 확인했지만, 사용자의 별도 수동 명령이나 실제 파일 구조는 확인하지 않았어요.
실제 다운로드 대상 사이트도 아직 확인하지 않았어요.

## 미해결 사항

- Anissia에서 연결되는 실제 게시물·파일 출처와 압축 파일 사용 여부를 확인해야 해요.
- 일괄 선택 단위와 수동 다운로드 후 정리 흐름은 아직 정하지 않았어요.
- 새 다운로드만 다룰지, 이미 보관 중인 영상의 누락 자막도 채울지 정하지 않았어요.
- 웹 GUI의 세 용도는 모두 필요하지만, 첫 출시에서의 깊이와 우선순위는 정하지 않았어요.
- 영상·자막 연결이 애매할 때의 처리, 기존 파일 보존·교체 기준, 수정 자막 처리, 지원 출처와 접근 보호 방식은 아직 정하지 않았어요.

출처별 자동 수집 가능성이 방향을 좌우한다면, 먼저 실제 사용하는 출처와 대표 게시물의 다운로드 경로를 읽기 전용으로 조사하는 것이 작은 확인 방법이에요.
메타데이터가 있다는 사실만으로 파일 다운로드나 올바른 영상 연결까지 가능하다고 판단하지 않아요.
