# 웹 GUI와 자막 수작업 개선

## 현재 방향

현재 사용자는 자막(Subtitle)을 하나씩 수동으로 다운로드하고 정리하고 있어요.
웹 GUI로 사용 편의성을 높이고, 자막 수작업을 줄이며, 함께 개선할 기능을 탐색하고 싶어 해요.
사용자는 보통 Anissia에서 자막을 찾을 수 있다고 설명했어요.
구체적인 첫 출시 범위와 자동화 수준은 아직 정하지 않았어요.

현재 사용자의 실제 작업 흐름을 기준으로 개선 방향을 정해요.
웹 GUI를 제공하는 것과 자막 수작업을 없애는 것은 별개의 효과이므로, 화면 추가만으로 문제가 해결된다고 가정하지 않아요.

## 선택지와 근거

웹 GUI에는 작품별 상태 확인, 작품·다운로드 규칙 관리, 자막 작업 처리 세 용도가 모두 필요하다는 사용자 선택이 있어요.
세 용도 사이의 우선순위와 첫 출시의 세부 범위는 아직 정하지 않았어요.
자막 처리를 보조할지 자동화할지는 아래의 열린 선택지예요.

| 방향 | 기대하는 사용자 가치 | 아직 확인할 사항 |
| --- | --- | --- |
| 웹 관리 화면 | 설정 파일이나 로그를 직접 열지 않고 작품별 상태와 설정을 확인해요. | 주로 바꾸는 설정과 확인하고 싶은 상태가 무엇인지 확인해야 해요. |
| 자막 작업 보조 | 여러 자막 후보를 한곳에서 확인하고 선택한 파일을 내려받아 정리해요. | Anissia에서 연결되는 실제 파일 출처와 현재 선택·정리 기준을 확인해야 해요. |
| 자막 자동 수집·정리 | 조건에 맞는 자막을 찾아 영상 옆에 배치하고, 사람이 처리할 예외만 남기는 방향이에요. | 출처별 수집 가능성, 영상과의 연결 기준, 잘못 연결되거나 기존 파일과 충돌할 때의 허용 범위를 확인해야 해요. |

추가 후보로는 자막이 없는 회차 표시, 자막 수정본 확인, 작품별 다운로드 상태, 실패 원인과 재시도, 다운로드 규칙의 적용 결과 미리보기가 있어요.
각 후보의 필요성은 아직 확인하지 않았으며, 모두 첫 출시 범위에 포함하는 제안은 아니에요.

## 현재 제품의 근거와 한계

- [README](../../readme.md)는 RSS 피드(RSS Feed)의 항목을 규칙에 따라 Transmission에 추가하고 파일명을 변경하는 도구로 설명해요.
  현재 사용 안내는 Docker Compose, 환경 변수와 원격 YAML 설정 중심이에요.
- [예약 실행 스크립트](../../scripts/cron.sh)는 5분 간격 실행과 로그 파일 출력을 설정해요.
  저장소 조사에서는 trss 자체 웹 GUI를 찾지 못했어요.
- [주 실행 경로](../../src/main.rs)의 파일명 변경은 파일이 하나인 토렌트(Torrent)를 대상으로 해요.
  피드에서 사라진 관리 대상 토렌트를 Transmission에서 제거할 때 로컬 데이터는 삭제하지 않아요.
  따라서 이 기능을 자막 정리나 미디어 파일 자동 삭제 기능으로 간주하지 않아요.
- [Anissia 연동 코드](../../src/anissia.rs)에는 자막 메타데이터와 다운로드 관련 코드가 있지만 미완성 부분이 있고, [Cargo 설정](../../Cargo.toml)의 선택 기능으로 분리돼 있어요.
  현재 사용 가능한 종단 간 자막 자동화로 간주하지 않아요.

위 내용은 저장소의 문서와 코드 조사 결과예요.
프로그램 실행이나 외부 자막 출처의 접근·다운로드 가능성은 검증하지 않았어요.
수동 작업과 Anissia 사용은 사용자 보고예요.
실제 다운로드 대상 사이트와 파일 구조는 아직 확인하지 않았어요.

## 미해결 사항

- 자막을 발견하는 곳부터 다운로드, 압축 해제 여부, 파일명 변경, 이동, 재생 확인까지 실제 작업 흐름을 알아야 해요.
- 가장 부담스러운 단계가 탐색, 개별 다운로드, 영상과의 연결·정리, 누락·수정본 확인 중 어디인지 아직 몰라요.
- 웹 GUI의 세 용도는 모두 필요하지만, 첫 출시에서의 깊이와 우선순위는 정하지 않았어요.
- 개인용인지 다른 사용자도 쓰는지, 어디서 접속할지, 현재 영상 보관·재생 환경은 아직 확인하지 않았어요.
- 자동화 수준, 기존 파일 보존·교체 기준, 지원 출처, 첫 출시 범위는 실제 흐름과 우선순위를 확인한 뒤 결정할 사항이에요.

출처별 자동 수집 가능성이 방향을 좌우한다면, 먼저 실제 사용하는 출처와 대표 게시물의 다운로드 경로를 읽기 전용으로 조사하는 것이 작은 확인 방법이에요.
메타데이터가 있다는 사실만으로 파일 다운로드나 올바른 영상 연결까지 가능하다고 판단하지 않아요.
