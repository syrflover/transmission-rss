# 웹 GUI와 자막 수작업 개선

## 현재 방향

현재 사용자는 자막(Subtitle)을 하나씩 수동으로 다운로드하고 정리하고 있어요.
웹 GUI로 사용 편의성을 높이고, 자막 수작업을 줄이며, 함께 개선할 기능을 탐색하고 싶어 해요.
사용자는 보통 Anissia에서 자막을 찾을 수 있다고 설명했어요.
실제로 이용하는 자막 출처로 [erulabo](https://erulabo.com/)를 제시했어요.
현재 대상 영상의 폴더와 파일명은 모두 trname 방식으로 정리돼 있으며, 자막도 영상 옆에 같은 이름으로 두고 있어요.
자막 제작자와 회차 범위로 후보를 묶어 선택하고, 선택한 항목의 다운로드와 정리를 자동으로 일괄 처리하는 방향이에요.
CAPTCHA처럼 사람이 해야 하는 단계는 사용자가 해결한 뒤 자동 다운로드를 재개하는 경험을 원해요.
직접 받은 파일을 GUI에 넣는 방식으로 이 요구를 대체하지 않아요.
웹 GUI는 사용자 혼자 집 안 네트워크나 VPN에서 사용해요.
대상 영상은 앞으로 trss가 받는 영상, trss로 받은 기존 영상, trss 이용 여부와 무관하게 사용자가 지정한 폴더의 영상을 모두 포함해요.
제품 방향과 필수 지원 출처는 정했으며, 인증 후 자동 배치를 실현할 운영 방식은 실제 동작 검증 뒤에 선택하기로 했어요.

현재 사용자의 실제 작업 흐름을 기준으로 개선 방향을 정해요.
웹 GUI를 제공하는 것과 자막 수작업을 없애는 것은 별개의 효과이므로, 화면 추가만으로 문제가 해결된다고 가정하지 않아요.

## 선택지와 근거

웹 GUI에는 작품별 상태 확인, 작품·다운로드 규칙 관리, 자막 작업 처리 세 용도가 모두 필요하다는 사용자 선택이 있어요.
세 용도와 아래 네 가지 추가 기능을 모두 원하는 범위로 선택했으며, 남은 것은 세부 동작과 운영 방식이에요.
후보 선택은 사용자에게 남기고 반복적인 다운로드·정리를 줄이는 방향으로 정했어요.
후보까지 자동으로 선택하는 방향은 현재 선택에 포함하지 않아요.
일괄 선택은 한 작품의 자막 제작자와 회차 범위를 기준으로 묶고, 필요한 후보를 개별 조정하는 방식이에요.
사람이 처리해야 하는 CAPTCHA 등의 단계는 자동 우회하지 않고 수동으로 처리해요.
사용자는 직접 다운로드한 파일을 GUI에 넣는 방식보다, 인증만 해결한 뒤 자동 다운로드를 재개하는 방식을 선택했어요.
사이트별로 인증과 다운로드가 연결되는 조건을 확인해야 하며, 이 선택은 아직 실현 가능성을 검증한 결과가 아니에요.
기존 영상과 지정 폴더 전체도 대상이므로, Transmission의 현재 목록에 없는 파일도 작품·회차와 연결해야 해요.
영상 연결은 임의의 폴더·파일명 추측보다 이미 정리된 trname 구조를 읽는 것을 기준으로 해요.
로컬 작품·시즌에 대응하는 Anissia 작품 후보를 제안하고 사용자가 최초 한 번 확인해요.
확인한 연결은 기억해서 이후 회차마다 다시 묻지 않아요.
사용자는 이 정리 방식 때문에 같은 회차의 영상이 여러 개 있는 경우는 거의 없다고 설명했어요.
중복 영상을 일반적인 사용 흐름의 중심에 두지 않으며, 실제 발생 시의 세부 처리는 보류해요.
배치하려는 자막이 이미 있으면 교체 후보를 모아 사용자 확인을 받은 뒤 허용한 항목만 교체해요.

| 항목 | 현재 방향 | 남은 선택 |
| --- | --- | --- |
| 웹 관리 화면 | 작품별 상태, 작품·다운로드 규칙, 자막 작업을 다뤄요. 설정은 [앱에서 관리하고 YAML 가져오기·내보내기를 제공해요](../adr/0001-app-managed-download-rules.md). | 저장 방식과 가져오기·내보내기의 세부 계약은 설계 단계에서 구체화해야 해요. |
| 자막 선택과 일괄 처리 | 제작자·회차 범위로 묶어 선택하고 이후 작업을 자동화해요. | 여러 파일이 들어 있는 다운로드의 처리 기준을 정해야 해요. |
| 자막 배치 | trname 방식의 영상에서 작품·시즌 연결을 최초 확인하고, 기존 자막 교체는 모아서 확인해요. | 회차 번호가 다른 경우의 연결 보정과 압축 묶음 내 파일 선택 기준은 아직 구체화하지 않았어요. |
| 수동 개입 | 사람이 인증을 해결한 뒤 자동 다운로드와 배치를 이어가요. | 서버 전용 브라우저와 사용자 브라우저 확장 중 어느 방식을 쓸지는 실제 동작 검증 뒤에 결정해요. |
| 사용 범위 | 한 사람이 집 안 네트워크나 VPN에서 사용하며, 앱 자체 로그인 대신 VPN·앞단 인증으로 접근을 제한해요. | 배포 환경에서 앱에 직접 접근하는 우회 경로가 생기지 않도록 경계를 유지해야 해요. |

Transmission은 trss에서 상태를 확인하고 기존 Transmission 화면으로 이동하는 범위로 정했어요.
시작·일시정지·삭제를 trss에 중복 구현하는 방향은 선택하지 않았어요.

다음 네 가지 추가 기능을 모두 범위에 포함하기로 했어요.

- 누락 자막 모아보기: 보유 영상 중 자막 없는 회차를 모아 후보 선택·일괄 작업으로 연결해요.
- 실패·인증 대기 작업 관리: 막힌 이유와 상태를 모아 보고 해당 작업에서 인증이나 재시도를 이어가요.
- 수정 자막 확인: 이미 받은 자막의 갱신 후보를 보여주고 교체는 사용자 확인을 거쳐요.
- 다운로드 규칙 미리보기: 규칙 변경 시 현재 RSS 항목 중 무엇이 선택되고 어디에 저장될지 실행 전에 보여줘요.

### 지원 출처와 후보 갱신

첫 지원 범위에는 erulabo, Blogger·Google Drive, Tistory 일반 첨부·WinPNG, Naver 블로그 첨부를 모두 포함해요.
실제 이용하는 erulabo만 먼저 지원하는 대안 대신, 조사에서 다룬 출처 유형을 폭넓게 지원하는 방향을 선택했어요.
이는 필요한 지원 범위의 결정이며, 현재 이 경로들이 구현되거나 다운로드 검증을 통과했다는 뜻은 아니에요.

화면을 닫아도 주기적으로 누락·수정 자막 후보를 확인하고 모아둬요.
다음에 웹 화면을 열면 확인할 후보를 볼 수 있어야 해요.
주기적인 후보 탐색이 다운로드·교체의 자동 승인을 뜻하지 않으며, 자막 선택과 기존 파일 교체 확인은 계속 사용자에게 남겨요.
구체적인 조회 간격과 외부 알림 채널은 정하지 않았어요.

## 현재 제품의 근거와 한계

- [README](../../readme.md)는 RSS 피드(RSS Feed)의 항목을 규칙에 따라 Transmission에 추가하고 파일명을 변경하는 도구로 설명해요.
  현재 사용 안내는 Docker Compose, 환경 변수와 원격 YAML 설정 중심이에요.
- [예약 실행 스크립트](../../scripts/cron.sh)는 5분 간격 실행과 로그 파일 출력을 설정해요.
  저장소 조사에서는 trss 자체 웹 GUI를 찾지 못했어요.
- [주 실행 경로](../../src/main.rs)의 파일명 변경은 파일이 하나인 토렌트(Torrent)를 대상으로 해요.
  피드에서 사라진 관리 대상 토렌트를 Transmission에서 제거할 때 로컬 데이터는 삭제하지 않아요.
  따라서 이 기능을 자막 정리나 미디어 파일 자동 삭제 기능으로 간주하지 않아요.
- [Anissia 연동 코드](../../src/anissia.rs)에는 자막 메타데이터와 다운로드 관련 코드가 있지만 미완성 부분이 있고, [Cargo 설정](../../Cargo.toml)의 선택 기능으로 분리돼 있어요.
  현재 사용 가능한 종단 간 자막 자동화로 간주하지 않아요.

위 내용은 저장소의 문서와 코드 조사 결과예요.
프로그램 실행이나 실제 자막 파일 다운로드는 검증하지 않았어요.
수동 작업, Anissia 사용, 모든 대상 폴더·파일명의 trname 정리, 같은 회차 중복 영상이 거의 없다는 설명은 사용자 보고예요.
주 실행 경로에서도 영상 파일명 변경에 trname을 사용하는 것을 확인했지만, 사용자의 실제 파일 구조를 직접 검사한 것은 아니에요.
공개 Anissia API와 연결된 일부 게시물을 읽기 전용으로 조사했으며, 사용자가 실제로 이용하는 출처로 erulabo를 제시했어요.

### trname 형식

[현재 의존성이 고정한 trname README](https://github.com/syrflover/trname/blob/6169808/readme.md)는 TheTVDB 시즌 명명에 맞춘 `작품/Season 01/작품 S01E01.mkv`와 같은 구조를 보여줘요.
영상과 자막은 확장자를 제외한 이름이 같아요.
이 문서는 Movie·OVA 같은 Special은 지원하지 않는다고 명시하지만, 사용자가 설치한 trname의 버전까지 확인한 것은 아니에요.
이 형식은 로컬 작품·시즌·회차를 읽는 근거이며, Anissia의 작품 식별자와 회차 번호가 자동으로 일치한다는 증거는 아니에요.

### 공개 자막 경로 조사

2026-09-25에 [Anissia 최근 자막 API](https://api.anissia.net/anime/caption/recent/0)와 연결된 공개 게시물 세 개를 읽기 전용으로 조사했어요.
API는 작품·회차·제작자·갱신 시각과 외부 게시물 주소를 반환했어요.
다음은 지원 완료 목록이 아니라 관찰한 파일 접근 방식이에요.

| 관찰 대상 | 확인한 결과 | 확인하지 않은 범위 |
| --- | --- | --- |
| [Blogger 게시물](https://csora556.blogspot.com/2026/07/season-3.html) | Google Drive의 폰트, 1–12화 묶음, 12화 링크가 있으며 자막 미리보기 제목은 ZIP과 ASS 파일을 가리켜요. | 미리보기 링크가 실제 다운로드 URL인 것은 아니에요. 실제 파일 다운로드는 하지 않았고, Drive 후속 화면 조사 일부는 시간 초과로 끝났어요. |
| [Tistory 게시물](https://harne1.tistory.com/762)과 [WinPNG Viewer 스크립트](https://tistory1.daumcdn.net/tistory/913196/skin/images/Viewer.js?_version_=1790231817) | PNG를 읽어 브라우저에서 파일을 해석하고 다운로드 링크나 ZIP을 생성하는 경로예요. | 실제 이미지 해석과 자막 파일 내용은 검증하지 않았어요. 해석 실패 시 파일 키를 묻는 코드는 있지만 CAPTCHA 관찰은 아니에요. |
| [Naver 게시물](https://blog.naver.com/gkdlfn0850/224418549305) | 내부 게시물 프레임에 `DBB 48.smi` 첨부와 `download.blog.naver.com/open/…` 링크가 있어요. 요청별로 중간 토큰이 달랐어요. | 토큰의 유효기간·세션 종속성, 파일 다운로드 성공은 확인하지 않았어요. 안부게시판 CAPTCHA 프레임은 자막 다운로드 CAPTCHA의 증거가 아니에요. |

세 경로에서 실제 다운로드 인증 요구나 인증 후 재개 성공을 관찰한 것은 아니에요.
따라서 현재 증거로 CAPTCHA가 항상 필요하다거나, 브라우저 인증 후 서버가 곧바로 이어받을 수 있다고 결론 내리지 않아요.
인증 상태가 브라우저 세션이나 접속 IP에 연결된다면 별도 서버 요청에도 효력이 있는지는 따로 확인해야 해요.
이를 구분하는 다음 증거는 실제 사용하는 대표 경로에서 정상적인 브라우저 다운로드와, 인증이 나타난 경우 사용자가 해결한 뒤 같은 세션의 재개를 관찰하는 것이에요.
서버가 이어받는 방식이라면 서버의 별도 요청도 성공하는지 확인해야 하며, WinPNG는 별도로 이미지 해석과 추출 파일 목록을 확인해야 해요.
이 다운로드·인증·추출 실험은 아직 수행하지 않았어요.

### 주요 출처 erulabo의 보안 확인

사용자가 제시한 [erulabo](https://erulabo.com/)의 [Anissia 연결 게시물](https://erulabo.com/854)에는 보안 확인 후 다운로드가 시작된다는 안내가 있어요.
2026-09-25에 해당 게시물과 [다운로드 스크립트](https://erulabo.com/js/download.js?v=20260923-1)를 읽기 전용으로 조사했어요.

- 클라이언트 코드는 자막 카드를 누르면 Cloudflare Turnstile을 실행하고, 완료 콜백의 토큰으로 `/file/<id>/token`에 요청해요.
  요청에는 CSRF 정보가 포함돼요.
- 성공 응답의 `download_url`로 새 탭을 열거나 현재 위치를 이동해요.
  인증 완료 후 사용자가 파일을 직접 업로드하거나 별도 다운로드 버튼을 다시 누르는 단계는 이 클라이언트 경로에 없어요.
- 이 코드는 사용자 인증 후 사이트가 다운로드로 이어가는 흐름의 근거예요.
  trss가 그 파일을 받아 영상 옆에 자동 배치할 수 있다는 실행 증거는 아니에요.

실제 인증 위젯 실행, 토큰 제출, 다운로드 응답·리다이렉트·파일 내용은 확인하지 않았어요.
반환 URL의 유효기간, 세션·IP 종속성, 프로그램이 관리하는 브라우저에서의 동작과 다운로드 수신은 미검증이에요.
인증한 브라우저에서 파일까지 받아 trss에 전달하는 방식과, 브라우저에서 얻은 권한으로 별도 서버가 받는 방식은 보안 경계와 운영 부담이 달라요.
후자가 가능하다고 가정해 구현 방향을 확정하지 않아요.
자동 배치는 이미 선택한 요구사항이므로, 일반 외부 브라우저로 파일을 받은 뒤 사용자가 옮기는 방식으로 대체하지 않아요.

## 미해결 사항

- 인증 운영 방식은 실제 동작 검증 뒤에 선택하기로 보류했어요.
  서버 전용 브라우저는 서버 자원·운영 부담이 있고, 사용자 브라우저 확장은 설치·사이트 권한·브라우저별 지원 부담이 있어요.
  erulabo에서 사용자가 정상적으로 인증한 뒤 파일을 받아 trss의 배치 단계로 전달할 수 있는지 확인한 결과가 이 선택의 재개 조건이에요.
- 필수 출처마다 다운로드 경로와 반환 파일을 검증해야 해요.
  erulabo의 인증·반환 URL, Drive의 개별 파일·묶음, Tistory 일반 첨부, WinPNG의 해석·추출, Naver 첨부의 다운로드를 구분해서 확인해야 해요.
  Tistory 일반 첨부는 요구 범위에 있지만 이번 조사에서 별도 표본의 다운로드 경로를 확인하지 않았어요.
- 확인한 작품·시즌 연결 안에서 회차 번호를 보정하는 방식과 압축 묶음의 선택 회차 파일 처리 기준은 설계 단계에서 구체화해야 해요.
- 후보 조회 간격과 외부 알림 채널은 미정이에요.
  주기적으로 후보를 모아 웹에서 보여주는 요구는 확정이며, 외부 알림 채널은 현재 필수 요구에 포함하지 않았어요.
- 같은 회차 중복 영상은 드문 경우로 두고 세부 처리를 보류해요.

조사한 공개 경로는 일반 첨부 링크뿐 아니라 Drive 미리보기와 브라우저 내 WinPNG 해석까지 포함하므로, 하나의 링크 추출 방식으로 모두 처리된다고 가정하지 않아요.
메타데이터가 있다는 사실만으로 파일 다운로드나 올바른 영상 연결까지 가능하다고 판단하지 않아요.
