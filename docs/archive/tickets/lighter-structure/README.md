# 구조 가볍게 하기

이 변경은 2026-10-22에 닫았어요. 완료 기록은 [티켓 목록의 구조 가볍게 하기](../../../specs/2026-09-30-web-redesign/spec.md#구조-가볍게-하기)에, 요구별 결과와 남은 일은 [구조 가볍게 하기 명세의 결과](lighter-structure.md#결과)에 있어요. 아래는 이 변경을 진행하는 동안 티켓 목록에 있던 범위, 진행과 티켓이에요. 범위 밖이라 남은 [0165](../../../specs/2026-10-22-cut-replacement-leftovers/0165-cut-replacement-leftovers.md)는 티켓 목록에 있어요.

사용자가 코드를 읽고 고치는 비용, 기능 하나를 더하는 단계, 테스트에 드는 계산 자원, 서버 운영을 줄이려고 구조를 바꾸기로 했어요. 수집과 자막 기능은 모두 두고, 기능 안의 규칙도 그대로예요(사용자 결정, 2026-10-21).

- web과 worker를 한 프로세스로 합쳐요([한 프로세스 ADR](../../../adr/0019-one-process-for-web-and-worker.md)).
- 실행 도중 끊긴 자막 작업은 멈춰 두고 사람이 다시 시작해요([끊긴 작업 ADR](../../../adr/0020-interrupted-jobs-wait-for-a-restart.md)).
- 화면의 TypeScript 타입을 Rust 응답 구조체에서 생성 도구로 만들어요([모듈 구성](../../../requirements/web-app.md#공통-라이브러리의-모듈-구성)).
- 기능 크레이트는 묶지 않고 그대로 둬요(사용자 결정, 2026-10-22). 합친 뒤 [다시 측정한 값](lighter-structure.md#다시-측정한-값)에서 `trss-core`를 고친 뒤의 `cargo test --workspace --no-run -j 4`는 증분 캐시를 다시 쓰면 13.7초에서 15.7초가 되고, 증분 컴파일을 끄면 81.2초에서 53.1초가 됐어요. cold가 줄어든 것은 크레이트를 합쳐서가 아니라 0160이 바꾼 설정 덕분이에요.

이 일은 0.7.0 피드백의 남은 티켓(0140·0143), [리팩터링 뒤의 명세 차이 수정](../../../specs/2026-09-30-web-redesign/spec.md#리팩터링-뒤의-명세-차이-수정)의 대기 티켓, 목표 6보다 먼저 해요(사용자 결정, 2026-10-21). 남은 티켓을 새 구조에서 만들려는 거예요.
요구와 완료 기준, 순서, 결정은 [구조 가볍게 하기 명세](lighter-structure.md)에 있어요.

크레이트를 합치는 0145 뒤로는 세 갈래를 나란히 할 수 있어요. 한 프로세스와 인계 없애기(0146–0150), 끊긴 자막 작업(0151–0153), 화면 타입 생성(0157–0158)이에요. 화면 알림(0154–0156, 0164)은 명령을 바로 실행하는 0147 뒤에 하는데, 0155와 0156은 DB 연결이 바뀐 표를 알리는 0164 뒤에 해요([명세의 결정](lighter-structure.md#결정)). 타입 생성의 마지막인 0159는 이벤트 타입까지 생성하려고 화면 알림 뒤에 해요. 서버에서 `RENAME_EXCHANGE`를 확인하는 0151은 0144 뒤에 바로 할 수 있어요. 일괄 보관을 서버로 옮기는 0163은 0154 뒤에 바로 할 수 있어요. 0160–0162는 코드를 바꾸는 다른 티켓을 모두 마친 뒤예요. 0153이 남긴 한계를 고치는 0165는 명세의 범위 밖이라 0162 뒤에 해요(사용자 결정, 2026-10-22).
