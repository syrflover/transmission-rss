# 0149 화면과 서버가 보내는 문구에서 worker를 빼요

- 상태: 완료
- 출처: [구조 가볍게 하기 명세의 한 프로세스와 이름](lighter-structure.md#한-프로세스와-이름)의 문구
- 막는 티켓: [0146](0146-one-trss-process-and-container.md)(한 프로세스)

## 작업

합친 뒤에는 따로 도는 worker가 없으므로, 문구에 `worker`가 나오면 사용자가 없는 것을 찾게 돼요. 행위자가 필요한 곳은 `trss`로 쓰고, 그렇지 않은 곳은 행위자를 빼요.

2026-10-21에 찾은 곳은 화면 9곳, 서버 4곳이에요. 화면의 9곳 중 수집 멈춤 문구는 [0148](0148-one-instance-lock-and-cycle-stall.md)이 판정과 함께 바꾸고, 이 티켓은 나머지 8곳과 서버 4곳을 바꿔요. 서버의 4곳은 명령을 더 시도하지 않는다는 사유, Anissia를 읽지 않는다는 사유, 수집 기록이 없는 채널의 안내, 압축을 다시 푸는 때의 안내예요.

코드 주석과 식별자는 이 티켓의 범위가 아니에요.

## 완료 기준

- [x] 화면에 보이는 문구와 서버가 화면에 보내는 문구(오류, 사유, 안내)에 `worker`가 없어요. 결과에 찾은 방법과 바꾼 곳을 적어요.
- [x] 바뀐 문구를 확인하던 테스트를 같은 커밋에서 고쳐요.
- [x] 명세가 바뀐 문구를 그대로 적은 곳이 있으면 같은 커밋에서 고쳐요.
- [x] 문구 말고 화면과 API의 동작은 그대로예요. 화면 테스트와 `npm run typecheck`가 통과해요.

## 결과

2026-10-21에 화면 문구 8곳과 서버가 화면에 보내는 문구 4곳에서 `worker`를 뺐어요. 행위자가 없으면 사용자가 할 일로 읽힐 수 있는 곳은 `trss`로 쓰고, 나머지는 행위자를 뺐어요. 화면이 이미 `trss가 관리하지 않는 파일을 덮어써요`처럼 소문자 `trss`를 쓰고 있어서 그대로 따랐어요.

### 찾은 방법

- 화면: `web/src`의 `.ts`·`.tsx` 파일에서 대소문자 없이 `worker`를 찾고, 주석 줄을 뺐어요.
- 서버: `crates`의 `.rs` 파일에서 한글과 `worker`가 함께 있는 줄과, `worker`가 든 문자열을 찾고 주석 줄을 뺐어요. 영어 문자열 다섯 곳 중 넷은 테스트 코드의 메시지이고, 하나(`Remote screens: … an earlier worker's browser are closed`)는 로그라서 화면에 가지 않아요.

### 바꾼 곳

| 곳 | 전 | 후 |
| --- | --- | --- |
| 규칙 미리보기, 기록 없는 채널 | `worker가 채널을 한 번 읽으면 여기서 볼 수 있어요.` | `trss가 채널을 한 번 읽으면 여기서 볼 수 있어요.` |
| 규칙 미리보기, 가린 제목 | `… worker의 판정과 다르게 보일 수 있어요.` | `… 수집할 때의 판정과 다르게 보일 수 있어요.` |
| 수집 상태판, 확인 시각이 없을 때 | `worker가 확인하면 여기에 보여요.` | `trss가 확인하면 여기에 보여요.` |
| 수집 상태판, Transmission 수가 없을 때 | `worker가 확인하면 여기에 보여요.` | `trss가 확인하면 여기에 보여요.` |
| 구독 추가의 지난 회차 받기 | `worker가 하나씩 추가해요. …` | `trss가 하나씩 추가해요. …` |
| 구독 추가의 제목 고르기, 기록 없는 채널 | `worker가 채널을 한 번 읽은 뒤에 다시 와요.` | `trss가 채널을 한 번 읽은 뒤에 다시 와요.` |
| 할 일의 작업 줄, 대기 중 | `worker가 곧 받기 시작해요.` | `곧 받기 시작해요.` |
| 할 일의 압축 파일 줄, 다음 시도 | `… 또는 worker가 다시 시작할 때` | `… 또는 trss가 다시 시작할 때` |
| 명령을 더 시도하지 않는 사유(`trss-core` `commands/repo.rs`) | `worker가 이 명령을 처리하다 여러 번 멈춰서 더는 시도하지 않아요.` | `trss가 이 명령을 처리하다 여러 번 멈춰서 더는 시도하지 않아요.` |
| Anissia를 읽지 않는 사유(`trss` `worker/commands.rs`) | `이 worker는 Anissia를 읽지 않아요.` | `trss가 Anissia를 읽지 않게 시작됐어요.` |
| 수집 기록이 없는 채널의 안내(`trss` `web/subscriptions_api.rs`) | `… worker가 채널을 한 번 읽은 뒤에 첫 화 전 작품을 구독해 주세요. …` | `… trss가 채널을 한 번 읽은 뒤에 첫 화 전 작품을 구독해 주세요. …` |
| 압축을 다시 푸는 때의 안내(`trss-jobs` `place/unpack.rs`) | `… 1시간 뒤나 worker가 다시 시작할 때 다시 풀어요` | `… 1시간 뒤나 trss가 다시 시작할 때 다시 풀어요` |

이미 DB에 적힌 사유와 기록은 바꾸지 않아서, 이 커밋 전에 끝난 명령과 작업 기록은 예전 문구를 그대로 보여요.

### 테스트와 문서

문구를 확인하던 테스트 둘, 곧 `web/src/screens/todo/unpack.test.ts`의 다음 시도 문구와 `trss-jobs` `tests/it/unpack.rs`의 작업 기록 문구를 고쳤어요. 명세 중에는 [자막 명세의 압축 해제](../../../specs/subtitles.md#압축-해제의-격리와-한도)가 다음 시도 문구를 그대로 적고 있어서 고쳤어요. 명세가 내부 구성 요소의 이름으로 쓰는 `worker`는 문구가 아니라서 그대로 뒀어요.

2026-10-21에 `cargo test --locked --workspace -j 4`를 돌렸더니 통과 3,055개, 실패 0개, 건너뛴 것 14개였고, 테스트 바이너리 시간의 합은 43.7초였어요. `cargo clippy --workspace --all-targets -j 4`에 경고가 없고, 웹의 `npm run typecheck`와 `npm test`(238개)도 통과했어요. 화면에서 바뀐 문구를 눈으로 보지는 않았어요. 바꾼 것은 문자열뿐이고 조건과 동작은 그대로예요.
