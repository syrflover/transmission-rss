# 결과 목표 3. 자막 후보와 수신

이 목표는 2026-10-04에 닫았어요. 완료 기록(관찰한 것, 시험으로 확인한 것, 남은 것)은 [티켓 목록의 목표 3](../../../tickets/README.md#3-자막-후보와-수신)에 있어요. 아래는 이 목표를 진행하는 동안 티켓 목록에 있던 범위, 결정, 진행 순서와 티켓이에요.

자막 후보를 찾고, 구독 제작자는 자동으로, 그 밖에는 사용자가 골라 받으며, 인증은 trss 안에서 끝내요.
이 목표의 수신은 받은 묶음을 앱 데이터 폴더의 수신 영역에 두는 데까지이며, 분석·보관·적용은 결과 목표 4예요. 출처별 다운로드의 "적용까지 이어지는지"의 확인은 목표 4에서 끝나요.

- 시즌의 [Anissia 연결](../../../specs/library.md#작품-연결과-제외), 작품 상세의 [자막 후보 구역](../../../specs/library.md#자막-후보-구역)과 [제작자 지정](../../../specs/library.md#머리와-시즌)

- 기반: [기능별 크레이트 workspace](../../../adr/0011-feature-crate-workspace.md), [웹 명령의 즉시 실행](../../../specs/web-app.md#웹-명령과-상태-갱신)

2026-10-02의 결정이에요(사용자 결정).

- Anissia 자막 정보는 제작자마다 마지막 게시물 한 줄뿐이라, 후보는 trss가 30분마다 최근 자막 목록을 읽어 모든 작품의 변화를 쌓아 만들고, 연결 전의 지난 회차는 직접 찾기와 올리기로 받아요([ADR 0012](../../../adr/0012-past-subtitles-find-and-upload.md)).
- 구독 제작자의 수정본도 자동으로 받고 교체는 승인을 기다려요([ADR 0009](../../../adr/0009-follow-subtitle-creator.md)). Anissia 줄이 그대로인 수정은 받은 뒤 14일 동안 하루 한 번 파일 정보를 다시 읽어 찾아요(0050).
- 후보는 작품 상세에서 고르고, 구독하지 않은 작품의 Anissia 연결은 전체 목록 검색이 기본이에요(편성표에서도 골라요).
- 올리기는 자막·폰트만 받고 나머지는 빼고 알려요. 제작자 모르는 자막에는 Anissia 제작자를 붙일 수 있어요.
- 웹 명령은 접수 즉시 실행해요. 수집 주기의 잠금 밖에서 도는 실행 기반은 자막 작업에도 필요해요.
- 목표 3의 기능 작업 전에 저장소를 기능별 크레이트의 workspace로 나눠요([ADR 0011](../../../adr/0011-feature-crate-workspace.md)).

2026-10-03의 결정이에요(사용자 결정).

- 구독 제작자 출처의 회차 대응은 규칙의 회차 변환 대신 방영 시각으로 정하고, 분명하지 않으면 미정으로 두어 사용자가 자막 후보 구역에서 정해요. 회차별 예외도 둬요(0051·0052).
- 제작자를 붙인 자막이 있는 회차는, 붙인 뒤에 새로 나온 구독 제작자의 줄을 수정본으로 자동으로 받아요(0048).
- 올린 압축 파일 가운데 ZIP이 아닌 것(RAR·7z·gzip·bzip2·xz·tar)은 그대로 두고, 푸는 것은 결과 목표 4의 묶음 분석이에요(0047).
- 서버 브라우저가 호스트 LAN 주소로 게시된 포트에 닿으므로, 브라우저의 송신을 실행기의 프록시로 제한하고 웹에 Host·Origin 검사를 더해요. 0040보다 먼저, 다음 릴리스 전에 끝내요(0053).

순서는 크레이트 이동(0029–0030)과 명령 실행 기반(0031)이 먼저이고, 그동안 확인할 일 0032·0033을 따로 진행해요.
그 뒤 연결·후보(0034–0035, 0037)와 작업 기반(0036)이 나란히 가고, 0033의 실패 분류로 공통 수신 결과(0038)를 정한 다음 출처별 경로(0041–0044)를 병행해요.
서버 브라우저는 0032 → 0039 → 0053 → 0040 순서이며, erulabo(0041)와 직접 찾기(0046)가 그 위에, 사람 없이 뷰어를 쓰는 WinPNG(0043)가 0039 위에 있어요. 새 창의 설정(0054) 뒤에 원격 화면의 뒤로·앞으로·탭(0055)이 오고, 멈춘 페이지(0056) 뒤에 페이지 창(0057)이 와요. Drive·Tistory 일반·Naver(0038·0042·0044)는 HTTP라 서버 브라우저를 기다리지 않아요.
구독 제작자 출처의 회차 대응은 방영 시각으로 정하고(0051), 정하지 못하거나 어긋나면 `회차 확인 필요`로 물어 자막 후보 구역에서 정해요(0052). 받은 파일 이름의 회차가 대응과 다른지 견주는 확인은 목표 4의 묶음 분석과 함께 해요. 대응을 바꾸면 보관본과 배치 계획·교체 승인을 새 기준으로 다시 보는 [요구](../../../specs/library.md#자막의-회차-대응)도 목표 4에서 배치와 승인을 만들 때 함께 다뤄요. 목표 3에서는 대응을 저장하는 사이에 옛 대응으로 작업이 생기지 않게만 했어요(0052).

알려진 불확실성을 먼저 확인할 일로 뺐어요: 서버 Chromium의 원격 화면 방식과 기기 폭에 맞추는 창 크기(0032), 출처별 실제 수신 경로의 재현성과 Anissia 회차 표시 `0`의 뜻(0033)이에요.
Anissia 전체 목록 검색은 공식 문서에 없는 API라 바뀔 수 있어요(0034).
