# 0047 자막과 폰트를 올려요

- 상태: 완료
- 출처: [직접 찾기와 자막 올리기](../../../specs/subtitles.md#직접-찾기와-자막-올리기), [지난 회차 ADR](../../../adr/0012-past-subtitles-find-and-upload.md)
- 막는 티켓: [0036](0036-subtitle-jobs-foundation.md)

## 작업

사용자가 가진 자막·폰트를 작품 상세의 선택한 시즌에 올려 하나의 자막 묶음으로 작업을 만들어요.

- 낱개·여러 파일·압축 파일·폴더를 받아요. 휴대폰처럼 폴더 선택이 없는 브라우저에서는 파일과 압축 파일만 올려요.
- 자막(ASS·SRT·SMI와 보관만 하는 다른 자막 형식)과 폰트만 받고, 다른 파일은 빼요(사용자 결정, 2026-10-02). 낱개·폴더는 올리기 전 목록에서 뺄 파일을 보여주고, 서버도 확장자가 아니라 내용으로 다시 가려요. 압축 파일 안의 파일을 가르는 것은 결과 목표 4의 압축 해제·묶음 분석이며, 이 티켓에서는 압축 파일을 그대로 묶음에 둬요.
- 올릴 때 그 시즌의 Anissia 제작자나 `제작자 알 수 없음`을 골라요. Anissia 연결이 없으면 `제작자 알 수 없음`만 고를 수 있어요.
- 업로드 크기·파일 수는 구현 때 유한한 값으로 정해 결과에 남겨요. 표지 업로드처럼 본문을 시간과 크기로 묶어 받아요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| ASS 2개·TTF 1개·`readme.txt`를 낱개로 올림 | 올리기 전 목록과 작업 상세에 `readme.txt` 한 개를 뺐다고 보이고, 자막 2개·폰트 1개가 한 묶음이에요. |
| 확장자를 `.ass`로 바꾼 이미지 파일 | 서버가 자막이 아니라고 보고 빼요. |
| ZIP 하나를 올림 | 묶음에 ZIP이 그대로 있고, 안의 분류는 결과 목표 4의 분석을 기다린다고 보여요. |
| 자막·폰트가 하나도 없음 | 작업을 만들지 않고 받을 파일이 없다고 알려요. |
| 한도를 넘는 크기·파일 수 | 저장 전에 거부하고 한도를 알려요. |
| 같은 올리기의 응답이 끊겨 다시 보냄 | 같은 명령 ID로 작업이 하나만 생겨요. |
| 휴대폰 | 파일·압축 파일 올리기가 되고 폴더 선택은 보이지 않아요. |

## 결과

### 만든 것 (2026-10-03)

- **올리기**: 작품 상세의 선택한 시즌에 `자막 올리기` 구역이 있어요. 파일·여러 파일·압축 파일·폴더를 고르고(터치만 있는 브라우저에는 폴더 고르기가 없어요), 그 시즌의 Anissia 제작자나 `제작자 알 수 없음`을 골라요. 올리기 전 목록에 뺄 파일과 이유가 보여요. `POST /api/subtitle-jobs/upload`(multipart)가 작업 하나를 `완료`로 만들고, 작업 상세에 `올린 파일`(자막·폰트·압축 파일)과 `뺀 파일`(이름과 이유)이 보여요.
- **내용으로 가르기**: ASS·SRT·SMI는 기존 판별, 보관만 하는 자막(WebVTT·TTML·MicroDVD·VobSub, PGS)은 내용 표시로, 폰트는 매직과 테이블 수로 알아봐요. ZIP은 구조를 확인하고(올리기 하나에 압축 해제 2GiB까지), RAR·7z·gzip·bzip2·xz·tar는 매직만 보고 그대로 둬요(사용자 결정, 2026-10-03). 나뉜 압축 파일의 뒤 조각은 첫 조각이 함께 올라왔을 때만 둬요. VobSub `.sub`는 같은 이름의 `.idx`가 있을 때만 자막이에요. 그 밖은 이유와 함께 빼요.
- **한도**: 남길 파일 500개, 이름까지 2,000개, 파일 하나 200MiB, 합계 1GiB, 본문 15분, 30초 멈춤, 최근 30초 평균 16KiB/s, 동시 2개와 대기 4개(60초, 넘으면 503)예요. 읽지 않고 쌓인 본문은 256KiB까지라, 헤더나 앞부분이 끝나지 않는 요청도 메모리를 키우지 못해요.
- **같은 요청**: 같은 명령 ID와 같은 내용은 같은 작업, 내용이 다르면 409예요. 요청이 끊겨도 마무리는 따로 돌아 끝나고, 주인 없는 임시 폴더는 한 시간마다 치워요.
- **기록**: 마이그레이션 38(`subtitle_job_files.kind`, `subtitle_job_dropped`)과 39(`archive_type`)예요.
- 규칙 전체는 [직접 찾기와 자막 올리기](../../../specs/subtitles.md#직접-찾기와-자막-올리기)와 [작업 상세](../../../specs/jobs.md#작업-상세)에 있어요.

### 검증한 것

| 완료 기준 | 근거 |
| --- | --- |
| ASS 2개·TTF 1개·`readme.txt` | web 시험(ASS 2개·TTF·브라우저가 뺀 readme), `upload.test.ts`(올리기 전 목록). 개발 환경에서 같은 구성을 올려 작업 상세에 자막 2개·폰트 1개와 뺀 `readme.txt`가 보였어요. |
| `.ass`로 바꾼 이미지 | web 시험과 판별 단위 시험. 개발 환경에서 PNG를 `fake.ass`로 올리면 "내용이 자막이나 폰트가 아니에요"로 빠졌어요. |
| ZIP 하나 | web 시험(ZIP을 그대로, 깨진 ZIP은 뺌). 개발 환경에서 RAR도 `RAR · 묶음 분석을 기다려요`로 그대로 들어갔고, 가짜 RAR는 "내용이 압축 파일이 아니에요"로 빠졌어요. |
| 자막·폰트가 없음 | web 시험(작업 없음, 400). 개발 환경에서 `readme.txt`만 올리면 400과 "받을 자막이나 폰트가 없어요"였어요. |
| 한도를 넘음 | web 시험(개수·이름 수·파일·합계·알린 길이), `the_limits_are_held_as_the_bytes_come`, 끝나지 않는 헤더와 앞부분이 2MiB 안에서 거절되고 최고 메모리가 16MiB 아래인 시험 |
| 응답이 끊겨 다시 보냄 | web의 다시 보내기·내용 불일치·동시 전달 시험, 요청이 버려져도 마무리되는 시험. 개발 환경에서 같은 ID로 다시 보내면 같은 작업 ID가 200으로 왔어요. |
| 휴대폰 | `canPickFolder` node 시험. 개발 환경 브라우저에서 PC 폭에는 `폴더 고르기`가 있고 휴대폰 흉내(375×812, 터치)에는 없었어요. |

작업 공간 시험 1,802개가 통과하고(실제 네트워크 시험 3개는 무시), web node 시험 9개가 통과하고, clippy 경고가 없고, 웹 빌드가 돼요. 실제 브라우저에서 파일 고르기 창으로 올린 것은 확인하지 못했어요(개발 환경 확인은 같은 API를 직접 불렀어요). 휴대폰은 실제 기기가 아니라 흉내예요.

### 독립 리뷰

신뢰 경계와 자원, 내용 판별, 마이그레이션, 같은 요청, 0045 자동 수신과의 관계를 두고 리뷰를 받았어요. 처음 리뷰는 **막는 결함 하나**를 찾았고, 고친 뒤 다시 확인받았어요.

| 지적 | 처리 |
| --- | --- |
| multipart 헤더·앞부분이 끝없이 메모리에 쌓임(리뷰어가 511MiB까지 재현) | 읽지 않은 본문 256KiB, 청크 본문도 합계 한도, 이름 길이 한도 |
| 요청이 끊기면 파일 이동·기록이 반쯤 남고, 임시 폴더를 치우는 곳이 없음 | 마무리를 따로 돌리고, 시작할 때와 한 시간마다 주인 없는 폴더를 치워요 |
| ZIP 압축 해제가 ZIP마다 1GiB라 올리기 하나로 수백 GiB | 올리기 하나에 2GiB를 함께 써요 |
| 느리게 보내는 두 요청이 자리를 15분 차지, 대기 무제한 | 최근 30초 평균 속도, 대기 4개·60초 |
| 본문 중간의 거절이 브라우저에 네트워크 오류로 보일 수 있음 | 8MiB·2초까지 읽고 답해요. 화면은 두 번 실패하면 나눠 올리라고 안내해요 |
| 화면의 같은 요청 판단에 뺀 이름이 빠짐 | 넣었어요 |
| 회차 없는 항목을 모든 작업에서 숨김 | 올리기 작업에서만이에요 |
| MPEG 영상을 VobSub로 받음 | 같은 이름의 `.idx`가 있을 때만이에요 |
| 나뉜 압축 파일의 뒤 조각을 뺌 | 첫 조각이 있으면 둬요 |

리뷰는 올리기 항목이 0045의 자동 수신에서 회차를 가진 것으로 세지지 않는 것도 확인했어요(관찰 ID가 없어요).

### 남은 한계

- RAR·7z 등은 매직만 확인해요. 안을 푸는 것은 결과 목표 4예요.
- 나뉜 ZIP(`.zip`+`.z01`)은 구조를 확인하지 않아요. `.partN.rar`는 조각마다 RAR 매직이 있어 첫 조각 없이도 남아요.
- 올리기 진행 막대가 없어요(`fetch`라서요). 아주 큰 본문이 중간에 거절되면 브라우저가 네트워크 오류로만 보여줄 수 있어요.
- 텍스트 자막의 257바이트 자리에 `ustar`가 있으면 tar로 읽혀요(사실상 없음).
- 이름 2,000개를 4KiB씩 채우고 1GiB 가까이 올리면 본문 여유 8MiB를 넘어 거절될 수 있어요.
