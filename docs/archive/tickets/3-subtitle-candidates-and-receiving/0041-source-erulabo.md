# 0041 erulabo 자막을 인증 뒤 서버 브라우저로 받아요

- 상태: 완료 (2026-10-03, 사람이 실제 erulabo의 확인을 풀어 서버 브라우저가 ZIP을 받았어요. 아래 "결과")
- 출처: [출처별 다운로드](../../../specs/subtitles.md#출처별-다운로드)(erulabo), [주요 출처 erulabo의 보안 확인](../../../brainstorm/web-gui-subtitles.md#주요-출처-erulabo의-보안-확인)
- 막는 티켓: [0038](0038-receive-result-tistory.md)(공통 수신 결과), [0040](0040-remote-auth-screen.md)

## 작업

사용자가 주로 쓰는 출처예요. 서버 브라우저가 게시물을 열고 정상 다운로드 카드를 화면 가운데로 스크롤해 눌러 Turnstile이 나오면 작업을 `인증 필요`로 멈추고, 사용자가 원격 화면에서 직접 푼 뒤 같은 브라우저가 받은 파일을 수신 영역으로 가져와요.
CAPTCHA를 자동으로 풀거나 브라우저 속성을 위장하지 않아요.
발급된 다운로드 URL은 60초 유효(2026-09-26 관찰)이므로 따로 저장하거나 나중에 다시 요청하지 않아요.
Turnstile은 누른 카드 안에 뜨므로, 카드를 가운데에 두면 PC와 휴대폰 첫 화면에 인증 상자가 보여요(0032). 인증 뒤의 실제 파일은 Google Drive 주소로 왔어요. 제작자의 수정 방식을 알기 위해, 받을 때 Drive 파일 ID와 응답의 수정 시각·크기·SHA-256을 수신 기록에 남겨요(사용자 결정, 2026-10-02). ID는 0050의 관찰에만 쓰고, 다시 받는 일은 늘 인증을 거쳐요. 로그·설정 내보내기에는 남기지 않아요.
원하는 회차의 카드를 고르는 단서는 0033의 단계 목록을 따라요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 실제 웹 화면에서 후보 선택 → `인증 필요` → 직접 CAPTCHA 해결 → 서버 수신 | 수동 파일 다운로드·업로드·이동 없이 수신 영역에 ZIP이 있고 크기·형식을 확인한 결과가 있어요(실제 erulabo, 실제 서버). |
| 인증 필요 상태에서 유휴 종료 뒤 다시 엶 | 인증 화면이 다시 준비되고, 풀면 받아요. |
| 만료·오류 HTML 응답 | 자막으로 기록하지 않고 실패로 끝나요. |
| 작업 기록·로그 | 토큰·서명 URL이 없고, 로그에 Drive 파일 ID가 없어요. 수신 기록에는 ID와 응답의 수정 시각·크기가 있어요. |

## 결과

### 만든 것 (2026-10-03)

- **출처**: `erulabo.com/<번호>` 게시물을 HTTP로 읽어 `#post-body`의 받기 카드 가운데 후보의 회차 카드 하나를 골라요. 그 회차 하나를 밝힌 카드가 먼저이고, 범위 카드(`(1-12)`), 회차를 밝히지 않은 하나뿐인 카드 순이에요. 게시물의 `dateModified`를 스냅샷에 남겨요. 서버 브라우저가 없으면 `자막 대기`예요.
- **확인 직전까지**: 서버 브라우저가 게시물을 열고 카드를 바로 가운데로 스크롤해, 가린 것이 없을 때만 눌러요. 마우스를 옮긴 뒤 누르기 직전에 카드가 그 자리에 있고 가려지지 않았는지 한 번 더 보고, 아니면 누르지 않아요. 확인 자리가 뜨면 작업이 `인증 필요`에서 기다리고, 화면 크기가 바뀌면 확인 자리를 다시 가운데로 옮겨요. 사이트가 30초 뒤 확인을 거두므로, 작업 화면을 열 때 살아 있는 실행의 확인이 사라졌으면 사이트의 알림이 걷힌 뒤 카드를 다시 눌러요. 브라우저가 파일을 받는 중이거나 받은 파일이 아직 넘어가지 않았으면 다시 누르지 않고, 같은 작업의 다시 누르기는 한 번에 하나예요. Turnstile 자체는 건드리지 않아요.
- **받은 뒤의 기록**: 브라우저 풀이 다운로드로 바뀐 문서의 응답(상태·형식·`Content-Length`·`Last-Modified`)과 주소를 다운로드에 붙여요. 응답이 상태를 주지 않으면 비워 두고 0으로 적지 않아요. 주소는 메모리에만 있고, Drive 파일 주소면 ID만 꺼내요. 이 값은 회차 폴더의 `.answer`를 거쳐 수신 기록의 상태·형식과 파일 스냅샷(`drive_id`·`last_modified`·`content_length`)으로 가고, 크기·SHA-256은 다른 출처처럼 수신 기록의 열이에요. 스냅샷 열에 들어가므로 마이그레이션은 없어요. 로그와 작업 기록에는 ID·주소가 없어요.
- **거절**: 확인 뒤 브라우저의 페이지(창이나 팝업의 메인 프레임)가 Drive·erulabo `/file/…`·Google 로그인 문서를 파일 대신 받으면 분류와 함께 회차 폴더의 `.refused`에 남기고, 다음 실행이 그 회차를 실패시켜요. 페이지 안의 프레임(Google 로그인·One Tap, Drive 프레임, 사이트의 `/file/<id>/error`를 연 프레임)이 받은 문서는 보지 않아요. 분류는 jobs 명세의 표를 따라요. Drive의 `401`·`403`·`404`와 Google 로그인은 `원본 없음`, erulabo `/file/…`의 `400`·`403`·`404`·`410`과 Drive의 `400`·`410`은 `만료`, `200` HTML은 `파일 아님`, `429`·`5xx`는 `네트워크 실패`예요. 어느 것도 자동으로 다시 시도하지 않고(새 주소는 확인을 다시 거쳐야 나와서예요) 주소를 다시 요청하지 않아요. `429`·`5xx`는 항목 기록에 `사이트가 파일을 주지 못했어요`로 남아요.
- **재확인**: erulabo 파일은 인증 없이 다시 읽을 수 없다고 답해 `읽을 수 없음`이에요. `dateModified` 비교와 `drive_id`의 `HEAD`는 0050의 남은 일이에요.
- 규칙 전체는 [작업 화면 안의 인증과 브라우저 수명](../../../specs/jobs.md#작업-화면-안의-인증과-브라우저-수명)과 [공통 수신 결과와 실패 분류](../../../specs/jobs.md#공통-수신-결과와-실패-분류)에 있어요. 관찰은 [2026-10-03 기록](../../../brainstorm/web-gui-subtitles.md#2026-10-03-제품-서버-브라우저에서-확인-직전까지)에 있어요.

| 만료·오류 HTML 응답 | 네트워크 없이 브라우저 안에서 답한 erulabo 모양 게시물에서, Drive 모양 주소의 `403` HTML은 파일 없이 `만료` 거절이었어요(무시된 시험 `a_fake_erulabo_post_is_brought_to_its_check_and_its_answer_is_kept`). 그 뒤 Drive의 `401`·`403`을 jobs 명세의 표대로 `원본 없음`으로 바꿔서 이 시험의 기대도 `원본 없음`으로 고쳤고, 고친 뒤 다시 돌려 통과했어요. 거절이 회차의 실패로 이어지는 것은 작업 시험(거절 → `사이트 확인을 마쳤지만 파일 대신 웹 페이지가 왔어요` → 분류와 함께 항목 실패 → 폴더 삭제, `429`·`5xx`의 즉시 실패, 묶음이 바뀐 뒤 도착한 거절, 다시 누르기가 한 번에 하나)로 봤어요(가짜 브라우저). |

### 한계

- 사람이 푼 뒤의 실제 다운로드는 `drive.usercontent.google.com`(알려진 Drive 호스트)에서 왔고 Drive ID가 붙었어요(2026-10-03 한 번). 60초가 지난 주소의 문서와 실제 거절 문서는 보지 못했어요. 거절 판단은 페이지(메인 프레임)가 받은 Drive 호스트·erulabo `/file/…`·Google 로그인 문서로 한정했고, 다른 호스트의 오류 문서는 거절로 보지 않아 실행이 유휴 종료될 때까지 기다려요. 그런 호스트의 문서가 페이지에 오면 실행마다 한 번 호스트 이름만 서버 로그에 남겨요. 실제 확인에서 받기 호스트를 알아내려는 거예요.
- 메인 프레임만 거절로 보는 데서 남는 한계가 둘이에요. 사람이 확인을 기다리는 동안 메인 프레임을 직접 Drive 페이지로 옮기면 그 문서도 거절로 봐서 항목이 실패해요. 프레임 안에서 받은 거절은 보지 못해요.
- 항목의 다음 실행은 거절이나 받은 파일을 가져가기 전에 게시물을 HTTP로 다시 열어요. 그 사이 게시물이 열리지 않게 됐거나 바뀌었으면 남겨 둔 거절이 다른 실패로 바뀔 수 있고, 스냅샷의 `dateModified`는 이 다시 연 게시물에서 와요.
- 휴대폰 크기에서 Turnstile 위젯의 오른쪽이 화면 밖으로 나가요. 체크박스는 보여요.
- 실제 휴대폰은 확인하지 않았어요.
