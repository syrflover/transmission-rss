- 막는 티켓: [0093](0093-migrated-test-db-once.md)–[0113](0113-remaining-area-tests.md), [0115](0115-erai-magnet-revisions.md), [0117](0117-sql-statement-cache.md), [0128](0128-keep-unnamed-cycle-torrent.md), [0130](0130-receive-a-rule-in-turn.md)

## 작업

리팩터링의 다른 티켓을 모두 마친 뒤, [0092](0092-refactor-baseline.md)와 같은 명령과 빌드 상태로 다시 재요.
그다음 정리한 릴리스를 실제 서버에 올리고, 목표 5에서 기준선으로 삼은 흐름을 한 번 더 이어 봐요.

- 배포하기 전에 workspace 테스트를 musl 대상으로도 돌려요([0079](../5-deployed-verification/0079-musl-test-run.md)의 절차).
- 마이그레이션이 더해졌으면 실제 서버 DB의 새 복사본으로 먼저 확인해요([0080](../5-deployed-verification/0080-server-db-migration-check.md)의 절차).
- 태그, 이미지 게시, 실제 서버에 올리는 일은 사용자 승인을 받아요.

## 완료 기준

- [리팩터링 명세의 기록](refactoring.md#기준값과-마지막-측정)에 마지막 측정이 0092와 같은 항목으로 있어요. 테스트 시간이 줄지 않았으면 까닭이 있어요.

- [흩어진 개념 모으기](refactoring.md#흩어진-개념-모으기)의 행마다 예전 복사본이 없는지 이름으로 찾아본 결과가 결과 절에 있어요.
- 실제 서버에서 [0083](../5-deployed-verification/0083-deployed-end-to-end.md)의 흐름을 다시 이어 본 결과가 있어요. 0083과 다른 점이 있으면 원인을 가려요.

#### 확인하지 않은 것

- 0.7.0에서 구독 규칙이 새 회차를 받는 것과 구독 제작자의 자막이에요. Kurumi-chan 3화(10-15 12:30)가 첫 기회예요.
- 실제 서버의 영상 대기예요. 로컬 개발 환경과 [0067](../4-store-apply-and-replace/0067-awaiting-video.md)의 시험으로 대신했어요.
- 들인 보관본을 화면에서 다시 고르는 것이에요. 응답의 `can_apply`까지만 봤어요.

### 명세 닫기

2026-10-10에 [리팩터링 명세](refactoring.md#결과)에 요구별 결과, 티켓에서 받은 결정의 기록, 테스트나 문서가 담지 않는 요구, 남은 일, 코드 커밋 175개를 적었어요. 그리고 명세와 리팩터링 티켓 27개를 이 폴더로 옮겼어요.

- 티켓에서 받은 결정 가운데 fsync를 더한 것(0104), 큐마다의 잠금(0103), 비동기 해제(0100)는 코드를 고쳐 되돌릴 수 있어서 ADR로 적지 않았어요.
- [개요](../../../overview.md)의 검증 표 문단이 표가 생기기 전의 말이라, 여섯 명세 모두에 표가 있다고 고쳤어요.

### 남은 것

리팩터링 전체의 남은 일은 [리팩터링 명세의 남은 일](refactoring.md#남은-일)에 있어요. 이 티켓에서 남은 것은 위의 [확인하지 않은 것](#확인하지-않은-것)이에요.
