# 0064 여러 파일 묶음에서 회차의 파일을 고르고 나머지 회차를 보관해요

- 상태: 완료
- 출처: [묶음 분석](../../../specs/subtitles.md#자막-묶음-분석과-안전한-배치-판단), [파일의 회차](../../../specs/subtitles.md#파일의-회차), [고르지 않은 회차](../../../specs/subtitles.md#고르지-않은-회차), [폰트](../../../specs/subtitles.md#폰트), [할 일과 회차 목록](../../../specs/library.md#할-일과-회차-목록)
- 막는 티켓: [0063](0063-store-and-first-apply.md)

## 작업

압축이 아닌 여러 파일 묶음(Tistory 첨부 여럿, Naver의 자막과 폰트, Drive 개별 파일 여럿)을 분석해 보관하고 적용해요. 압축 파일의 멤버는 [0065](0065-archive-extraction.md)가 풀어 같은 분석에 넘겨요.

- 파일마다 종류(자막·폰트·첨부·구성 파일·그 밖)와 회차를 정해요. 회차는 0063의 규칙을 써요.
  고른 회차 밖의 같은 시즌 자막은 보관만 해요(사용자 결정, 2026-10-04). 다른 시즌이거나 회차를 정할 수 없는 자막은 보관하되 회차에 붙이지 않고 까닭을 적어요. 그 밖의 파일은 보관하지 않고 이름과 버린 이유를 적어요.
- 같은 회차·제작자의 여러 형식은 전역 형식 우선순위의 첫 형식 하나를 적용해요.
  같은 형식에 구분할 수 없는 대안이 있으면 [보류된 대안의 선택](../../../specs/subtitles.md#자막-묶음-분석과-안전한-배치-판단)으로 물어요.
- 폰트는 자막과 같은 제작자 폴더에 두고, 이름과 내용이 같은 폰트는 하나만 둬요. 첨부와 구성 파일은 앱 데이터 폴더에 둬요. 자막과 폰트·첨부의 관계를 DB에 남겨요.
- 구독 제작자의 자동 작업이 받은 묶음이면, 고르지 않은 회차에도 [자동 수신의 규칙](../../../specs/subtitles.md#구독-제작자-자동-수신)을 적용해요.
  받지 않은 회차는 적용까지 가요. 자막이 이미 있는 회차는 교체 승인을 기다리는데, [0068](0068-replacement-approval.md) 전에는 보관만 하고 기존 파일을 그대로 둬요.
- 회차 줄은 보관만 한 회차에 `보관본 있음`을 적고, 펼친 자리에 그 보관본과 `적용`을 둬요. 자막 체크와 보유 범위에는 세지 않아요.
  자막이 없는 회차의 `적용`은 바로 적용해요. 자막이 있는 회차의 `적용`이 비교로 이어지는 것은 [0072](0072-choose-stored-subtitle.md)예요.
- 작업 상세의 회차·파일별 결과에 적용한 것, 보관만 한 것, 붙이지 않은 것, 버린 것을 나눠 적어요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| Tistory 첨부 25개를 받은 회차 하나(isulbi 40, 개발 환경의 실제 묶음) | 고른 회차의 파일만 적용되고, 나머지 같은 시즌 회차는 보관만 돼요. 그 회차 줄에 `보관본 있음`이 있고 범위에는 세지 않아요. |
| 보관만 한 회차(자막 없음)에서 `적용` | 영상 옆에 적용되고 회차 줄이 `자막 ✓`가 돼요. |
| Naver의 SMI와 폰트 3개(목표 3의 `auto:14`) | 자막과 폰트가 같은 제작자 폴더에 있고, 자막과 폰트의 관계가 DB에 있어요. |
| 같은 회차의 ASS와 SRT | 형식 우선순위의 첫 형식 하나만 적용돼요. 다른 형식은 보관돼요. |
| 같은 회차·형식에 이름만 다른 두 ASS(용도 모름) | 큰 파일이나 첫 파일을 고르지 않고, 보류된 대안으로 물어요. |
| 다른 시즌 번호(`S03E01`)의 파일 | 보관하되 회차에 붙이지 않고, 까닭이 작업 상세에 있어요. |
| `.exe`가 섞인 묶음 | 그 파일은 보관하지 않고 이름과 이유가 작업 상세에 있어요. |
| 구독 제작자 자동 작업의 묶음에 받지 않은 다른 회차가 함께 있음 | 그 회차도 적용까지 가요. |

## 결과

### 만든 것 (2026-10-05)

- **DB**(마이그레이션 50 `package_assets.sql`): 계획 줄에 `asset_id`를 더했어요. 폰트·첨부·구성 파일 줄은 보관본이 아니라 그 자산을 가리켜요. 자막과 폰트·첨부의 관계는 0063이 만든 `subtitle_stored_assets`에 적어요.
- **분석**(`crates/trss-jobs/src/place/package.rs`): 게시물의 파일마다 종류(자막·폰트·첨부·구성 파일·그 밖)와 회차, 적용할 것을 정해요.
  - 후보의 파일은 0063의 `of_candidate`로 골라요. 나머지 파일은 고른 파일이 쓴 번호 체계(Anissia의 번호인지 시즌의 번호인지)로 회차를 정해요. 정할 수 없거나, 다른 시즌 표시가 있거나, 시즌 밖이면 회차에 붙이지 않고 까닭을 적어요.
  - 회차마다 형식 순서(작품의 순서, 없으면 정책, 없으면 ASS·SRT·SMI)의 첫 형식 하나를 적용해요. 같은 형식에 바이트가 다른 파일이 둘 이상이면 모두 물어요. 바이트가 같으면 첫 파일만 적용해요.
  - 구독 제작자의 자동 작업(`follow`)이면 다른 회차의 파일도 적용해요. 그 밖의 작업은 보관만 해요.
  - 후보의 회차 자체를 정할 수 없으면(대응 미정, 시즌 밖) 번호가 후보 표시와 같은 파일을 그 까닭으로 물어요. 묶음에 후보의 파일이 없으면 작업을 `일부 실패`로 끝내고 까닭을 적어요.
- **보관**(`place/mod.rs`, `records.rs`): 폰트는 자막과 같은 제작자 폴더에 둬요. 첨부와 구성 파일은 앱 데이터 폴더의 `subtitle-files/<작품 ID>/<제작자>/`에 두고, 임시 파일은 같은 파일시스템의 `subtitle-files/.tmp/`에 둬요. 효과의 `folder`가 앱 데이터 폴더라서 재시작 표는 그대로 써요. 보관이 끝나면 보관한 자막마다 그 게시물의 폰트·첨부를 잇고, 구성 파일은 이름 줄기가 같은 자막에만 이어요. 그 밖의 파일은 보관하지 않고 이름과 까닭을 적어요. web과 worker의 시작 검사(`APP_DATA_FOLDERS`)에 `subtitle-files/`를 더했어요.
- **회차 줄의 `적용`**: `records::choose_stored`는 그 보관본을 받은 작업의 계획 줄을 다시 적용으로 돌리고 작업을 대기로 되돌려요. 따로 효과를 만들지 않아요. API는 `POST /library/works/{id}/stored/{stored_id}/apply`(202, 거절하면 409, 없으면 404)이고, 작품 상세의 회차가 `stored`로 보관본 목록을 줘요.
- **웹 화면**: 회차 줄에 `보관본 있음`, 펼친 자리에 보관본마다 `적용`이 있어요. 적용할 수 없으면 그 까닭을 적어요. 작업 상세는 파일이 여럿인 묶음을 `확인 필요`·`보류`·`보관·적용 실패`·`적용함`·`보관만 함`·`회차에 붙이지 않음`·`폰트·첨부`·`버림`·`처리 대기`로 나눠 적어요.
- **가짜 출처**: `fake.trss.invalid/pack/<파일>/<파일>/…` 게시물이 이름의 확장자대로 자막·폰트·실행 파일·글 파일을 줘요.
- **명세·문서**: [파일의 회차](../../../specs/subtitles.md#파일의-회차)에 나머지 파일의 번호 체계와 시즌 표시를, [고르지 않은 회차](../../../specs/subtitles.md#고르지-않은-회차)에 회차 줄의 `적용`을, [보관본과 적용본](../../../specs/subtitles.md#보관본과-적용본)에 첨부의 자리를, [폰트](../../../specs/subtitles.md#폰트)에 관계를 적었어요. [작업 상세](../../../specs/jobs.md#작업-상세)에 묶음의 결과 무리를, [web-app](../../../specs/web-app.md)과 readme에 `subtitle-files/`의 시작 검사·백업을 적었어요.

독립 검토(2026-10-05, 복잡한 불변식 검토)는 앱 데이터 폴더의 재시작, 경로 경계, 마이그레이션과 관계 기록에서 결함을 찾지 못했어요. 아래 결함은 고쳤고, 각 시험은 고친 코드를 되돌리면 실패하는 것을 확인했어요. 고친 뒤 다시 검토해 고친 것이 맞음을 확인했어요.

- 작품 폴더가 없을 때 회차 줄의 `적용`이 아무것도 하지 않고 작업을 끝냈어요. 이제 `영상 대기`로 기다려요.
- 보류된 대안 가운데 하나(또는 다른 형식)를 회차 줄에서 골라도, 나머지 대안의 질문이 남아 작업이 `회차 확인 필요`에 머물렀어요. 이제 고른 것이 답이라 물은 대안은 보관만 해요.
- 출처의 대응이 미정이거나 후보의 회차가 시즌 밖이면, 묶음에 후보의 파일이 있는데도 `파일이 없어요`로 `일부 실패`가 됐어요. 이제 그 파일을 까닭과 함께 물어요.
- 시즌 표시가 갈리고 어느 쪽도 작업의 시즌이 아니면 묻지 않고 형식 순서로 적용했어요. 이제 그 회차의 파일을 물어요. 다른 회차의 파일은 묻지 않아요.
- 같은 보관본을 여러 작업이 받았을 때 가장 최근 작업이 보류 중이면 적용할 수 없었어요. 이제 실행 중·보류·승인 대기가 아닌 작업을 찾아 써요.
- 앱 데이터 폴더의 제작자 폴더가 대소문자만 다른 이름으로 둘 생길 수 있었어요. 이제 자막처럼 기존 폴더를 써요.

### 시험

검토 뒤 고친 코드(2026-10-05, `2636aee` 위의 작업 트리)에서 `cargo test --workspace`가 2,327개 통과, 실패 0, 무시 13개였어요. `cargo clippy --workspace --all-targets`는 경고 0이고 `cargo fmt --all --check`도 통과해요. 웹은 `npm test` 82개 통과, `bun run typecheck`가 통과했어요.

### 한계

- isulbi 40 실제 묶음의 관찰은 압축 해제(0065)와 여덟 경로 확인(0076)으로 넘어가요.
- 회차 줄의 `적용`은 자막이 있는 회차에서 거절해요. 비교로 잇는 것은 0072예요.
- 자막이 어느 폰트를 실제로 부르는지는 읽지 않고, 한 게시물의 폰트·첨부를 그 게시물의 자막 모두에 이어요.
- 한 게시물을 여러 후보가 함께 받아 통째로 묻는 경우, 받은 파일을 처음 받은 후보에게 질문을 달아요. 질문에 답하는 화면(0066)이 이 연결을 그대로 쓰는지는 그때 확인해요. 이 순서를 정하는 코드는 시험으로 덮지 않았어요.
- 두 게시물이 같은 파일을 함께 받으면 그 파일은 먼저 계획한 게시물의 것이에요. 뒤 게시물의 형식 순서와 대안 판단이 그 파일을 빼고 다시 이뤄지지는 않아요(검토 지적, 고치지 않음).
- 앱 데이터 폴더의 경로가 상대 경로(개발 실행의 기본값 `.`)이면 효과의 `folder`도 상대 경로라, 작업 디렉터리가 바뀌면 재시작이 그 효과를 보류해요. 배포의 `/data`는 절대 경로예요.
- 위 개발 환경 관찰(작업 35·21·34·37)은 모두 검토 전의 코드로 지은 이미지에서 했어요. 검토 뒤 고친 것은 단위·통합 시험으로만 확인했어요.
- 실제 서버 디스크에서의 동작은 0060의 탐침을 기다려요.
