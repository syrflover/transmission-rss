# 0078 회차를 정하지 못한 영상을 `회차 확인 필요`로 올려요

- 상태: 완료 (2026-10-06)
- 출처: [할 일](../../../specs/jobs.md#할-일)의 `회차 확인 필요`(받은 영상의 회차를 확정하지 못함), [할 일과 회차 목록](../../../specs/library.md#할-일과-회차-목록)의 회차 확인 카드. [0075](0075-todo-badges-and-cards.md)에서 이 카드를 만들 할 일이 없어 새 티켓으로 나눴어요(사용자 결정, 2026-10-06).
- 막는 티켓: [0075](0075-todo-badges-and-cards.md)(격자 배지와 작품 상세의 `할 일`)

## 작업

- 받은 영상의 회차를 정하지 못한 경우를 `회차 확인 필요` 할 일로 만들어요. 시작할 때(2026-10-06)는 이 할 일이 없었고, 이름에서 회차를 읽지 못한 영상은 작품 상세 `파일` 카드의 `회차를 확인하지 못한 파일`에만 나왔어요.
- 격자의 배지와 메뉴 개수는 다른 처리 필요와 같은 규칙을 따라요.
- 시작하기 전에 사용자와 정한 것이에요(사용자 결정, 2026-10-06).
  - 무엇을 셀지: `Season 00`이 아닌 시즌 폴더 바로 안의 영상 가운데 이름에서 회차를 읽지 못했거나(`no_episode`) 이름의 시즌이 폴더와 다른 것(`season_mismatch`)만 세요. `Season 00`, 하위 폴더, 시즌 폴더 밖, `.part`, 자막 파일은 세지 않아요.
  - 어떻게 사라지는지: 영상마다 `확인함`을 더해요. 확인은 작품과 경로에 붙고, 이름을 고치거나 옮겨도 사라지며, 같은 경로에 다른 파일이 오면 다시 물어요.
  - 카드 제목: RSS 항목 이름 대신 파일 이름 조각(시즌 폴더와 파일 이름)을 써요.

## 완료 기준

| 입력·상태 | 기대 결과 |
| --- | --- |
| 회차를 정하지 못한 영상이 있는 작품 | 격자 표지에 `회차 확인 필요` 배지가 있고, 작품 상세 `할 일`에 확인할 파일 이름 조각을 제목으로 한 카드가 있어요. 임의의 회차에 붙이거나 누락으로 단정하지 않아요. |
| 그 영상에 `확인함`을 누르거나, 이름을 고치거나 옮김 | 배지와 카드가 사라져요. |
| 확인한 경로에 다른 파일이 옴 | 다시 카드와 배지가 생겨요. |

## 결과

### 만든 것 (2026-10-06)

- **스캔**(`trss_library::discovery`): 세는 영상이면 `Unrecognized::check`에 파일 크기와 수정 시각(나노초)을 담아요. 이 영상만 스캔마다 `fs::metadata`로 읽고, 바뀌지 않은 폴더의 목록을 다시 쓰는 증분 스캔에서도 다시 읽어요. 제자리에서 덮어쓴 파일은 폴더의 수정 시각을 바꾸지 않기 때문이에요(구현 결정, 2026-10-06). 읽지 못하면 그 스캔에서는 묻지 않아요.
- **마이그레이션 62**(`library/video_check.sql`): `unrecognized_files`에 `size`·`mtime_ns`를 더하고, 사람의 확인을 담는 `unrecognized_checks`(작품, 경로, 크기, 수정 시각, 확인 시각)를 만들어요. 작품을 지우면 함께 지워져요. 마이그레이션 전의 줄은 그 작품의 다음 스캔에서 값을 얻어요.
- **확인의 수명**(`store::library::repo::sync_work`): 스캔은 작품의 줄을 다시 쓴 뒤, 그 경로에 줄이 없거나 크기·수정 시각이 다른 확인을 지워요. 크기·시각을 읽지 못한 줄은 확인을 지켜요. 보관 이동으로 두 작품을 합칠 때(`merge_work`)는 식별값과 확인을 함께 옮겨요.
- **저장소**(`store::library::checks`): `video_checks`는 폴더가 있고 등록된 감시 폴더의 작품에서 확인하지 않은 영상을 돌려줘요. `check_video`는 화면이 본 크기·시각이 지금 줄과 같을 때만 확인을 남기고, 다르면 `Changed`, 그런 영상이 없으면 `NoFile`이에요. 작품 상세의 `unrecognized`에는 `checked`가 붙어요.
- **API**: `GET /api/todo`에 종류 `video_check`를 더했어요. 영상마다 하나이고, `path`(파일 이름 조각), `season`, `reason`(문장), `at`(수정 시각), `seen`을 담아요. `seen`은 `크기:나노초` 문자열이에요. 나노초는 브라우저의 JSON 숫자로 정확히 담을 수 없어서예요(구현 결정, 2026-10-06). 배지는 `episode_check`예요. 읽기에 실패해도 나머지 할 일은 답해요.
  `POST /api/library/works/{id}/videos/check`(`{ path, seen }`)는 `204`, 영상이 바뀌었으면 `409`, 그런 영상이 없으면 `404`예요(`video_check_api`).
- **웹**: 할 일 화면과 작품 상세 `할 일`의 카드(`VideoCheckActions`)에 `파일 보기`(작품 상세 `파일` 카드)와 `확인함`이 있어요. 작품 상세 카드는 파일 이름 조각을 제목으로, 할 일 화면 카드는 작품 제목 아래 조각을 둬요. `확인함`의 답이 무엇이든 할 일 목록과 메뉴 개수를 다시 읽고, 작품 상세는 작품도 다시 읽어요. `파일` 카드의 그 파일에는 `확인함`을 조용히 적어요.
- 문서: [할 일](../../../specs/jobs.md#할-일)의 표와 영상의 회차 확인 규칙, [할 일과 회차 목록](../../../specs/library.md#할-일과-회차-목록)의 카드와 표, [오른쪽 카드 열](../../../specs/library.md#오른쪽-카드-열)의 `파일`.

개발 환경(2026-10-06, 서버 DB 복사본, 마이그레이션 62)에서 브라우저로 확인했어요.

- worker의 첫 스캔이 대상 영상 3개에만 크기·시각을 남겼어요(`Season 01/output.mkv`와 `Season 02/[SubsPlease] …` 둘). `Season 00`의 Kaguya-sama 파일 8개는 남기지 않았어요.
- 할 일 화면에 세 카드가 나왔고 메뉴 개수가 11이었어요. 격자에서 Wistoria에 `회차 확인 필요` 배지가 있었어요.
- Kusuriya 카드의 `파일 보기`가 작품 상세 `파일` 카드를 펼쳤어요. 작품 상세 `할 일`의 카드 제목은 파일 이름 조각과 `시즌 2` 태그였어요.
- `확인함`을 누르자 `할 일` 구역이 사라지고 메뉴 개수가 10이 됐어요. `파일` 카드에 `· 확인함`이 붙고, 목록 API의 Kusuriya 배지가 비었어요.
- 확인한 경로에 내용이 다른 파일을 `mv`로 덮어쓰자 5초 안에 같은 카드가 새 `seen`으로 돌아오고 확인이 지워졌어요.
- Tai-Ari의 영상을 작품 폴더 바로 아래로 옮기자 5초 안에 카드가 사라지고 `outside_season`이 됐어요.
- 리뷰 수정을 넣어 다시 빌드한 뒤, 페이지 안에서 요청의 `seen`을 옛 값으로 바꿔 `확인함`을 눌렀어요. `409`의 문장(`그 사이 이 자리에 다른 영상이 왔어요…`)이 카드에 나오고 카드는 남았어요.
- 바꾼 파일들은 원래 이름·크기·수정 시각으로 되돌렸고, 개발 DB에는 확인이 남지 않았어요.

워크스페이스 시험(2026-10-06, `cargo test -j 4 --workspace`)은 2,728개 통과, 실패 0, 무시 13이에요. `cargo clippy --workspace --all-targets -D warnings`와 `cargo fmt --all --check`도 통과했어요. 웹은 `npm run typecheck`와 `npm test`(197개 통과)를 거쳤어요. 기록은 `probe-out/0078/`에 있어요.

### 독립 검토 (2026-10-06)

`stora:reviewer`가 마이그레이션, 확인의 수명(전체·증분 스캔, `record_works`, 병합, 없어진 작품, 등록 해제), 웹과 worker의 동시 쓰기, 계약을 봤어요. 막는 결함은 없었어요.

- 고친 것: `확인함`이 통과한 뒤 작품 다시 읽기가 실패하면 확인 실패로 보이던 것, `409`·`404` 뒤 `파일` 카드를 다시 읽지 않던 것, 영상의 할 일을 읽지 못하면 할 일 목록 전체가 실패하던 것이에요. 명세에는 고친 이름도 회차가 없으면 새 경로로 다시 묻는다고 적었어요.
- 설계대로 둔 것: `touch`나 재다중화처럼 크기나 수정 시각만 바뀌어도 다시 물어요. 대상 영상마다 스캔이 `fs::metadata`를 한 번 더 부르며, 이 비용은 재지 않았어요. 등록을 다시 한 폴더는 첫 스캔 전까지 예전 값을 보여줘요.
- 남은 것: `VideoCheckActions`의 웹 시험은 없어요. 이 프로젝트의 웹 시험은 순수 함수만 다뤄요.
