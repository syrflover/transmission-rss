# 0127 적용이 끝난 회차 줄이 새로고침 없이 자막 `보유`가 돼요

- 상태: 완료 (2026-10-08)
- 출처: [0119](0119-refresh-after-stored-apply.md)의 로컬 확인(2026-10-08), [할 일과 회차 목록](../../../specs/library.md#할-일과-회차-목록), [오른쪽 카드 열](../../../specs/library.md#오른쪽-카드-열)
- 막는 티켓: 없음. 리팩터링의 [0092](../../../tickets/0092-refactor-baseline.md) 전에 고치고, 이것만으로 배포하지는 않아요(사용자 결정, 2026-10-08).

## 작업

0119는 회차 줄의 `적용`이 맡긴 작업이 끝날 때까지 기다렸다가 작품 상세를 다시 읽게 했어요.
2026-10-08 로컬 개발 환경(0.6.2와 같은 코드)에서 `All Works Maid` 9화와 10화의 보관본을 회차 줄에서 적용했어요. 두 회차 모두 자막이 없고 보관본만 있었어요. 두 번 모두 다음처럼 됐어요.

1. 줄이 `적용을 맡겼어요. 작업 보기`를 보였어요.
2. 작업이 `done`으로 끝난 뒤 2초 안에 화면이 작품 상세를 다시 읽었어요. 보관본 줄은 사라졌지만 자막은 `없음`, 자막 파일도 `없음`이었어요.
3. 새로고침하기 전까지 줄이 그대로였어요. 그사이 작품 API는 새 자막 파일을 적용본으로 돌려줬어요.

원인은 작업의 끝과 라이브러리의 기록이 따로라는 데 있어요. 작업은 적용본을 영상 옆에 쓰고 끝나고, 작업의 기록에서 그 보관본은 곧바로 적용된 것이 돼요. 라이브러리의 회차 기록은 worker의 감시 폴더 읽기가 그 파일을 읽어야 바뀌는데, inotify 알림은 작품마다 3초를 모아서 읽어요(`LiveConfig::debounce`). 10화에서 worker 로그의 작업 끝은 07:16:00.912Z, 그 작품을 읽은 때("1 files added")는 07:16:03.894Z였어요. 화면은 작업 상태를 2초마다 읽으므로 작업이 끝난 뒤 2초 안에 작품을 다시 읽고, 그때는 늘 감시 폴더 읽기 전이에요. 그래서 보관본 줄은 빠지고 자막은 아직 없는 상태가 보여, 적용하기 전보다 더 헷갈려요.

- 맡긴 적용이 끝나면 새로고침하지 않아도 회차 줄의 자막이 `보유`가 되고, 그 보관본이 적용본으로 보여요. 0119의 첫 완료 기준과 같아요.
- `자막` 카드(`SubtitlesCard.tsx`)도 같은 `ApplyStatus`로 기다리므로 같은 일이 생길 것으로 보여요. 카드에서는 재현하지 않았어요.
- 맞추는 방법은 둘이었고, 사용자가 화면이 기다리는 쪽을 골랐어요(사용자 결정, 2026-10-08).
  - 화면이 기다려요: 작업이 끝난 뒤에도 그 회차에 적용본이 보일 때까지 작품을 몇 번 더 읽어요. 웹만 바뀌고 두 화면이 함께 고쳐져요. 다른 화면은 작업이 끝난 뒤 몇 초 동안 라이브러리와 다르게 보일 수 있는 그대로예요.
  - worker가 끝내기 전에 읽어요: 적용본을 쓴 작업이 끝을 기록하기 전에 그 작품을 라이브러리에 읽어 둬요. 작업의 끝이 곧 라이브러리에 보인다는 뜻이 되어 모든 화면이 같아져요. 대신 작업 실행이 감시 폴더를 읽는 차례(`reading_section`)와 엮여요. 폴더를 옮기는 명령이 그 차례를 쥐고 있으면 작업이 기다리거나, 읽지 못한 채 끝나야 해요.
- 실패한 적용은 0119대로 줄에 까닭이 보여요. 2026-10-08 로컬에서 확인했어요.

## 결과

2026-10-08에 고쳤어요.

- `ApplyStatus`는 작업이 `done`으로 끝나면 바로 화면을 바꾸지 않고, 작품(`GET /api/library/works/{id}`)을 같은 방식으로 2초마다 읽어요. 줄에는 `적용했어요. 라이브러리에 보이기를 기다려요.`가 보여요. 읽은 작품이 적용을 보여주면 그때 화면의 작품을 다시 읽어요(`onEnded`). 실패와 사람을 기다리는 경우는 0119 그대로 바로 다시 읽어요.
- 적용을 보여준다는 판단은 `subtitles.ts`의 `appliedShown`이에요. `자막` 카드의 그 보관본(`subtitles.creators[].copies[]`)이 적용된 경로(`applied`)를 모두 어느 회차의 자막 파일로 가지면 보여준 거예요. `applied`는 작업의 기록이라 작업이 끝나면 바로 채워지고, 회차의 자막 파일은 감시 폴더를 읽은 뒤에 채워지므로 이 둘이 맞는 때를 기다려요. 보관본이 목록에 없거나(정리됨) 적용되지 않았거나, 서버가 `subtitles`를 보내지 않으면 기다릴 것이 없어서 바로 끝나요.
- 기다림의 한도는 0119와 같은 5분(`APPLY_WAIT_MS`, `적용`을 누른 때부터)이에요. 그 안에 보이지 않으면 화면의 작품은 그대로 두고 `적용했어요. 라이브러리에는 아직 보이지 않아요.`와 `작업 보기`를 남겨요. 화면을 바꾸면 보관본 줄이 사라져 이 문장도 함께 사라지기 때문이에요.
- 회차 줄(`StoredLine`)과 `자막` 카드(`CopyRow`)가 작품 ID와 보관본 ID를 넘겨요.
- [오른쪽 카드 열](../../../specs/library.md#오른쪽-카드-열)의 `자막`에 이 기다림을 더했어요.

| 완료 기준 | 근거 |

- `npm run typecheck`, `npm test`(226개), `npm run build`가 통과해요. 브라우저 콘솔에 오류가 없었어요.

### 확인하지 않은 것

- 5분 안에 라이브러리에 보이지 않는 경우(`적용했어요. 라이브러리에는 아직 보이지 않아요.`)는 만들어 보지 않았어요. 한도 판단은 0119의 `waitOver` 시험이 봐요.
