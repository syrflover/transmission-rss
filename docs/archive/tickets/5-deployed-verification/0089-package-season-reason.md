# 0089 묶음 배치에서 시즌이 다른 파일의 까닭을 맞게 적어요

- 상태: 완료 (2026-10-07)
- 출처: [자막 묶음 분석과 안전한 배치 판단](../../../specs/subtitles.md#자막-묶음-분석과-안전한-배치-판단)
- 막는 티켓: 없음

## 작업

2026-10-07 구조 조사에서 찾았어요.
여러 파일이 든 묶음을 배치할 때, 다른 회차 파일의 이름에 적힌 시즌이 기대한 시즌과 다르면 그 파일을 배치하지 않고 까닭을 보여줘요.
기대한 시즌은 후보 회차의 파일 이름에 적힌 시즌이고, 없으면 작업의 시즌이에요. 그런데 까닭 문구에는 늘 작업의 시즌을 적어요(trss-jobs의 `place/package.rs`).
그래서 후보 회차 파일의 시즌이 작업의 시즌과 다르면 문구가 비교한 시즌과 달라요. 파일이 작업의 시즌과 같은 시즌이어도 "작업의 시즌과 달라 보여요"라고 적을 수 있어요.

## 완료 기준

- 후보 회차 파일의 시즌이 작업의 시즌과 다른 묶음으로 확인하는 테스트가 있어요. 문구가 실제로 견준 시즌을 적어요. 무엇과 견줬는지(후보 회차 파일의 시즌인지, 작업의 시즌인지)도 문구에서 알 수 있어요.
- 배치하는 파일과 배치하지 않는 파일은 지금과 같아요.

## 결과

### 만든 것 (2026-10-07)

- 다른 회차 파일을 배치하지 않는 까닭이 견준 시즌과 그 출처를 적어요.
  - 후보 회차의 파일 이름에 시즌 표시가 있으면 `파일 이름이 가리키는 시즌(1)이 후보의 1화 파일에 적힌 시즌(2)과 달라 보여요`예요.
  - 없으면 `파일 이름이 가리키는 시즌(3)이 이 작업의 시즌(2)과 달라 보여요`예요. 올리기·직접 찾기(`plan_named`)가 이미 쓰던 문구와 같아요.
- 예전 문구 `시즌 {번호}이 … 시즌 {번호}과`는 번호에 따라 조사가 틀렸어요(`시즌 2과`). 새 문구는 조사가 괄호 앞의 "시즌"에 붙어서 번호와 관계없이 맞아요.
- [자막 묶음 분석과 안전한 배치 판단](../../../specs/subtitles.md#자막-묶음-분석과-안전한-배치-판단)에 까닭이 무엇과 견줬는지 적는다는 문장을 더했어요.
- 이 ticket의 `작업`과 `완료 기준`은 처음에 기대한 시즌을 "묶음 이름에 적힌 시즌"이라고 잘못 적었어요. 코드와 명세는 후보 회차의 파일 이름에 적힌 시즌과 견줘요. 그래서 두 절을 바로잡았어요.
