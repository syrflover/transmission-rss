# 0083 실제 서버에서 구독부터 자막 적용까지 이어 봐요

- 상태: 완료 (2026-10-08). 구독에서 첫 수집까지는 2화를 기다리지 않고 이미 있는 회차로, 영상 대기는 로컬 개발 환경에서 대신 봤어요(사용자 요청, 2026-10-08).
- 출처: [검증 근거와 완료 판정](../../../specs/web-app.md#검증-근거와-완료-판정), [보관본과 적용본](../../../specs/subtitles.md#보관본과-적용본), [방영작 구독](../../../specs/collection.md#방영작-구독)
- 막는 티켓: [0081](0081-deploy-new-release.md)

## 작업

목표 3·4의 관찰은 개발 환경에서 실제 외부 사이트와 서버 DB 복사본으로 했어요(사용자 결정, 2026-10-04). 명세는 실제 배포 이미지에서도 자막 기능과 화면이 동작하는지 확인하라고 해요.
새 릴리스가 올라간 실제 서버에서 사용자가 쓰는 흐름을 한 번씩 끝까지 이어 봐요. 결과는 웹 화면과 미디어 디스크의 파일로 함께 확인해요.

- 실제 방영작과 실제 제작자를 써요. 새 회차가 나오기를 기다려야 하는 관찰은, 이미 있는 회차로 같은 경로를 탈 수 있으면 그것으로 대신하고 그렇게 했다고 적어요.
- 원격 화면의 인증은 사용자가 휴대폰에서 해요.
- 0081의 배포 첫 주기(2026-10-07)에 구독 제작자(코코렛)의 자막 작업이 `FX Senshi Kurumi-chan` 1화에 돌아, 영상 옆의 적용본과 `.trss/`의 보관본을 1000:1000으로 만들었어요([0081 결과](0081-deploy-new-release.md#자막-작업과-미디어-디스크)). 이것을 "구독 제작자의 자막" 흐름의 관찰로 쓰려면 두 파일의 바이트 비교와 작품 상세의 화면 확인이 남았어요.

## 완료 기준

| 흐름 | 확인할 것 |
| --- | --- |
| 구독에서 첫 수집까지 | 편성에서 구독한 작품의 회차가 Transmission에 들어가고, 받은 영상이 라이브러리의 그 작품·시즌에 나타나요 |
| 구독 제작자의 자막 | 구독 제작자의 자막이 선택 없이 받아져 `.trss/`의 보관본과 영상 옆의 적용본이 돼요 |
| 고른 후보의 자막 | 작품 상세에서 고른 후보가 같은 곳까지 가요 |
| erulabo | 휴대폰의 원격 화면에서 사람이 CAPTCHA만 풀고, 파일이 적용본까지 가요 |
| 교체 승인 | 자막이 있는 회차에 새 자막이 오면 교체 승인에서 멈추고, 승인한 회차만 바뀌어요 |
| 영상 대기 | 영상이 없는 회차의 자막은 영상이 들어온 뒤 다시 받지 않고 적용돼요. 기다릴 회차가 없으면 확인하지 않은 것으로 남겨요 |

- 보관본과 적용본은 1000:1000이고, 영상 옆 적용본의 바이트가 보관본과 같아요.
- 흐름마다 날짜, 작품, 관찰한 화면과 파일이 결과 절에 있어요. 관찰하지 못한 흐름은 까닭과 함께 남은 일에 있어요.

### 영상 대기 (2026-10-08, 로컬 개발 환경)

실제 서버에는 자막만 있고 영상이 없는 회차가 없었어요. 드문 상황은 로컬 개발 환경에서 만들어 보기로 해서(사용자 요청, 2026-10-08), 서버 DB의 사본을 쓰는 로컬 개발 환경에서 확인했어요. 0.6.2 뒤로 `crates/`는 worker 시험 하나만 더했으므로 worker는 0.6.2와 같은 코드예요. 시각은 UTC예요.
